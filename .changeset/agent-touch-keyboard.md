'e2e': minor

The built-in agent handles a phone keyboard the way the platform does. An action result says when the on-screen keyboard closed with the action, because on a touch screen the tap that closes it is often spent on closing it and the control under the finger did not react; the model is told to act on it again rather than read an unchanged screen as success. `dismiss_keyboard` on a device whose keyboard has no dismiss key no longer reports a contradiction ("Dismissed the keyboard. failed: ..."): it names the blank point inside the focused field's scroll view that closes the keyboard, in viewport coordinates, and `tap_at` accepts a viewport point before any screenshot has been taken so that hint is one call, not a screenshot and a guess. A failed action reads "Not done (<action>): <reason>" instead of a past-tense description followed by "failed". The execution rules now require the latest result to show the asked-for outcome before a passed verdict: a result reporting no change, or only the keyboard closing, means the decisive action did not land. `scroll` repeats up to 20 screens in one call instead of 5, so a long list costs turns in proportion to its length rather than five screens at a time.
