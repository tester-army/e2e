`agent.act` takes `vision`, the option the judgments already had, and the agent's `vision` default applies to it too. That default is now `true`: every act turn and every judgment carries a masked screenshot next to the tree unless `agents.<name>.vision: false` opts the project out, or a call passes `vision: false`. A project on a text-only model must opt out. `waitFor` keeps skipping judgments while the screen is unchanged, now comparing the pixels along with the tree. `true` opens the step in pixel mode: the first screen and every action result carry a masked screenshot next to the tree, without the model spending a turn on `screenshot`. `'only'` withholds the tree from the executor for the whole step: the model sees a screenshot and nothing else, and drives the flow through a point-addressed vocabulary (`tap_at`, `type_at`, `press_at`, `select_at`, `scroll` at a point, `observe`, `navigate`). Every point is hit-tested against the tree the runner still holds, so a listed control is acted on by id underneath, recorded with a descriptor and replayed from the trace cache like any other action; result prose names what was hit by role and name, never by an id the model was not shown. A pixels-only step refuses a `Secret` in its params and a viewport an earlier fill tainted with `POLICY_DENIED` before it opens, because a fill would withhold the only evidence.

For executors: `ctx.vision` reports the mode, `observe()` captures pixels by default at `true` and returns empty `text` with no `tree` at `'only'`, and `ctx.actions.hitTest(point)` resolves a point onto the listed control and node under it without acting. A custom executor's `agent.assert` now receives `vision` instead of rejecting it.

Engines gain a `keyboard` capability (`keyboard.type`, `keyboard.press`, optional `keyboard.dismiss`): input to whatever holds focus, with no node behind it. The agent's `type` and `press` accept no target on such an engine, `type_at` and `press_at` fall back to tapping the point and typing through the keyboard when the tree lists nothing there, and `dismiss_keyboard` is offered where the engine can hide an on-screen keyboard. That is how a field drawn on a canvas, or one a platform flattens out of its accessibility tree, gets its text in both hybrid and pixels-only flows. Executors get `ctx.actions.typeText`, `pressKey`, and `dismissKeyboard`; the trace cache records and replays them as free actions.
