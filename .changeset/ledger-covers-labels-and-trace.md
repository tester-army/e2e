The secret ledger now reaches three places a registered value could still surface. A step label that spells a secret out (``agent.act(`use key ${process.env.E2E_SECRET_KEY}`)``, `app.open('/reset?token=...')`, `expect(screen.getByText(value))`) is redacted once when the step is recorded, so `report.json`, reporter events, the `--debug` step table, the AI trace run name, and the prior-step ledger the next `agent.act` reads all show `<secret:name>`. `.e2e/ai-trace.json` passes model output, tool-call arguments, errors, and provider metadata through the ledger before writing, as the report's turns already did, and the file is written owner-only (`0600`) like the cache and sessions. An executor or `defineTool` calling `attachScreenshot` after a secret fill gets `POLICY_DENIED`, as `app.screenshot()` does, and the report records the denial instead of a screenshot artifact. Both files pass the ledger once more as they are written, so a value a provider resolved after a step was recorded is covered; the AI trace's run names and scope fields are redacted like its columns; and a secret that is JSON punctuation or a property name leaves every trace column parseable, since string leaves are redacted before serialization. A run-level error (a cleanup or collection failure, serialized with no session to redact it) passes the ledger before it is recorded or streamed, and the step an `e2e mcp` session records is redacted like a run's.
