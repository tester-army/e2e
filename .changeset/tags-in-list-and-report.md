Tags travel with a test past selection. Registration derives them once (the describe chain's, outermost first, then the test's own, each once), the identity that crosses to workers and into results carries them, and everything downstream reads that one list: `e2e list` prints each tag after the target (`tests/a.e2e.ts › signs in [web] #smoke`), `--reporter json` gives every pair a `tags` array, and `run.results[]` in the report carry `tags` (`[]` when none), so a reporter can group results by tag. Report schema: a result gains an optional `tags` array of distinct names as the `tags` option defines them (none blank, no comma, no leading or trailing whitespace).
