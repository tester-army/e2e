The agent now gets a tool for every node action its engine declares, not five of sixteen. `hover` moves the pointer over a node (menus, flyouts, tooltips, hover-revealed controls) and `hover_at` does the same at a point in the screenshot; `double_tap`, `long_press`, and `right_click` are their own tools where the engine declares `doubleTap`, `longPress`, or `secondaryTap` (not a `kind` on `tap`: offered that way, a model double-clicked Save buttons); `check` sets a checkbox, switch, or radio to a state instead of flipping it; `drag` drops one node on another; `scroll_to` brings a listed node into view instead of blind scrolling; `back` goes back one step; `upload` attaches files to a file input. Each verb is offered only when the engine declares its action, dispatches as its own engine event, and records into the trace cache with the node it acted on, so a passing flow of them replays zero-turn. `upload` takes project-relative paths and refuses, before the engine sees them, a file outside the project root (through a symlink too) or one that is hidden or under a hidden directory such as `.env`, `.git`, or `.e2e`, as `POLICY_DENIED`; a missing file is `INVALID_ARGUMENT`. The names `hover`, `hover_at`, `double_tap`, `long_press`, `right_click`, `check`, `drag`, `scroll_to`, `upload`, and `back` are now the agent's own, so a project tool named like one is refused at `createAgent`, as `tap` and `scroll` already were. `e2e mcp` serves the same catalog. Tab switching is still missing: a new tab is invisible to the model.
