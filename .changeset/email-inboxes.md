Real email inboxes. `email` in the config takes a `MailProvider`: `maildev()`, shipped here, reads a local [MailDev](https://github.com/maildev/maildev) the run starts as a service, for an app whose SMTP you control, with made-up addresses and exact per-address isolation (Bcc included), and any other service plugs in as a provider. Tests get an `email` fixture: `await email.inbox()` creates a new address, and `inbox.waitForMessage({ from, subject, text, timeout })` returns each matching email once, retrying a failing provider within its deadline. Inboxes only receive, and the runner reads no codes or links out of an email: a test takes them from `message.text` (the HTML part's visible text, each link's URL after its label, or the plain part without HTML), the same text filters and the agent read, with its own pattern. Each address is given back when its attempt ends, pass, fail, timeout, or interrupt, within `cleanupTimeout`; a serial group's members share theirs. The built-in agent and `e2e mcp` get `new_email_address` and `wait_for_email`: they read only the attempt's own addresses, show the email fenced as untrusted with every secret masked, and record a replay gap, and a value a later step types or opens out of an email records one too. Both tool names are reserved for project tools. Provider failures are `EMAIL_PROVIDER_FAILED`.
