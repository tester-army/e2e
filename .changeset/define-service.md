Breaking: services are `defineService` handles. `defineService({ name, executable, ... })` declares a process, `defineService({ name, start, stop })` a function (global setup and teardown); a target lists the handles it needs in `targets: [{ services }]`. Every service a selected target needs, with everything it `dependsOn`, starts once before the first test, dependencies first, and stops at the end in reverse; a service no selected target needs does not start. `dependsOn` takes handles defined earlier and is copied when the service is defined, so there is no cycle to declare. A plain service object, a spread copy of a handle, two handles with one name, or a service that is both forms is `INVALID_CONFIG`. A function service's `start` runs under `startupTimeout` (60 s by default; expiry is `APP_UNREACHABLE` naming the service), an interrupt stops waiting on it at once and tears down what started, and a throwing `stop` is a cleanup error naming the service. A service's `teardown` runs only for a process the run spawned.

`{port}` in a service now means the service's own free port (its `readyUrl` on port 0), not the app's; a service that uses it on a fixed port or without a `readyUrl` fails with `INVALID_CONFIG`; a service that needs the app's address starts the app as a service (`const app = defineService({ ..., readyUrl: 'http://127.0.0.1:0' })`) and reads `app.port` with `dependsOn: [app]`. In `app.command`, `{port}` stays the port of `app.url`. `ports: { smtp: 0 }` declares named ports, read as `{port:smtp}`. A handle's `url`, `port`, `urlOf('smtp')`, and `portOf('smtp')` are placeholders substituted in args, env, `teardown`, and a target's `app.url`, so two browser targets can share one dev server on a free port (`app: { url: webServer.url }`); a placeholder for a service outside the reader's graph is `INVALID_CONFIG`, and one reaching navigation in a test is `INVALID_APP_URL`, as is an `app.url` placeholder that reads as no app URL (`mail.urlOf('smtp')`), named with the target. Two processes probing one fixed address (two targets' `app.command`s, a service and an `app.command`) are `INVALID_CONFIG` pointing at `defineService`, and so are `reuseExisting` on a free port, an `app.command` beside an `app.url` placeholder, a placeholder in a `readyUrl`, and a port-0 `app.url` with nothing to start on it. In `e2e mcp`, a cancelled or disconnected `open_session`, or a server shutting down, cancels an open still starting its services and stops what it started (`CANCELLED`); a function service is shared across sessions by its name and dependencies, and a session that opens beside another reads the free ports that one was assigned, so a process on a fixed port stays shared when a service it depends on asks for a free one. Services and app commands now inherit the runner's whole environment, with `env` on top, instead of `PATH`, `HOME`, and the temp-directory variables alone.
