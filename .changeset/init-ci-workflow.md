`e2e init` can write a CI pipeline: a GitHub Actions workflow or a GitLab CI/CD file with one job for each platform the config's targets run on. Web targets run in a web job; iOS and Android targets get their own jobs, which build the app, boot a simulator or an emulator, and install the app. A config with both gets all of its jobs. The wizard asks for it in a project with the web or mobile engine and preselects the service the repository points to; `--ci github-actions` or `--ci gitlab` answers the question, and `--yes` alone writes none. The mobile jobs build Expo and bare React Native apps; any other app gets a build step to replace. GitLab's mobile jobs need self-managed runners. The jobs use the project's package manager and Node version and keep the report; for a project in a subfolder the file goes to the repository root. `init` names the secret or CI/CD variable to add and warns about what would fail on the first push. It never overwrites a pipeline file: beside an existing `.gitlab-ci.yml` it writes `.gitlab/e2e.gitlab-ci.yml` and prints the `include:` to add.
