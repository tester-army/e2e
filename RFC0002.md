# RFC0002 — One seam: the backend contract

Status: draft. Builds on RFC0001 layer 2 (`e2e/backend`, `defineBackend` were
reserved there; this fills them in). Evidence: the agent-device dogfood
(PR #90) and the API review against LSP/MCP/AI SDK/Stagehand precedents.

## Problem

Two integration surfaces exist and confuse everyone, including us:

- the **driver SPI** (spec 09): heavyweight, spec-frozen, one real
  implementation, misleading as an extension point;
- **executor tools**: one-file integrations (agent-device proved it), but
  opaque to the harness — no replay, no policy, no deterministic tier, and
  every integrator rebuilds guard/accounting/observation by hand.

They describe the same thing: something that can observe and act on an app.
The default agent already wraps grammar actions into model tools; agent-device
tools map ~1:1 back onto the grammar. Unify them.

## Design in one sentence

Three roles, strictly split: the **agent** is the brain (model, prompts, and
all model-facing tools), the **backend** is the body (typed, model-free:
observe, actions, locate, lifecycle), and the **harness** is the referee
(budgets, verdicts, policy, cache, report). A backend is a validated manifest
of named capabilities — `observation`, `actions`, `location` — each unlocking
harness features and imposing duties. Tools live only on the agent; a target
with no backend at all is valid and simply runs everything opaque.

## 1. Public surface at a glance

The whole public API is seven names in two entry points, plus config:

| Export | From | Role |
| --- | --- | --- |
| `test`, `expect`, `credentials`, `defineConfig` | `e2e` | Test API (unchanged) |
| `StepExecutor`, `StepExecutorContext`, verdicts | `e2e` | Brain socket — the hand-rolled escape hatch |
| `createAgent(options)` | `e2e/agent` | The one brain builder; runs on any backend |
| `defineTool(tool, annotations)` | `e2e/agent` | Declared-semantics tool (exists today; extended) |
| `defineBackend(spec)` | `e2e/backend` | Validates a body, computes its capability set |
| `Backend`, `BackendActions`, `SemanticSnapshot`, `NodeRef` | `e2e/backend` | The body contract types |
| config `targets[].backend`, `agent: { executor?, model?, tools?, ... }` | `e2e` | Wiring |

`createToolLoopExecutor` folds into `createAgent`: with the chassis owning
observation, replayedPrefix, guard/accounting, and toolset derivation, the
middle tier's only remaining deltas are options — so they become options
(`system`, `prompt?`, `compactMessages?`, `maxTurns`). Two brain tiers, not
three: `createAgent(options)` for 99%, raw `StepExecutor` for different
species of brain. Everything else is deleted from the public surface:
`e2e/driver`, `DriverHandle`, `defineDriver`, spec 09 as contract,
`MobileTarget`/`CustomTarget`, the well-known driver registry.

## 2. The `Backend` contract

```ts
/** Capability names. Independent except for one edge: actions ⇒ observation. */
type BackendCapability = 'observation' | 'actions' | 'location';

interface Backend {
  readonly name: string;
  /**
   * Contract version literal (AI SDK / spec-09 pattern). Additive optional
   * members never bump it; changed required semantics do.
   */
  readonly spiVersion: 1;

  // No tools here, by design. A backend never talks to a model; every piece
  // of model-facing vocabulary — including a modality's extras like swipe or
  // screenshot — is an agent-side DefinedTool. One home for tools, not two.

  // ── capability: observation ───────────────────────────────────────
  /**
   * One fresh, semantic snapshot of the surface under test.
   * Unlocks: judgment tier (waitFor/extract/assert), the prompt observation
   *   (harness-embedded, replayedPrefix included), observation metrics,
   *   cache relocation, `locate`-mode tool replay.
   * Obligates: the harness bounds (maxObservationBytes) and redacts the
   *   returned text; revisions invalidate stale refs.
   */
  observe?(context: OperationContext): Promise<SemanticSnapshot>;

  // ── capability: actions (requires observation) ────────────────────
  /**
   * The typed verb set. Targets are refs from the newest observation.
   * Unlocks: harness-derived model tools (nobody hand-wraps), trace-1
   *   verb replay, origin policy on navigate, per-verb budget accounting,
   *   secret fills into verified sinks.
   * Error contract (verbatim from spec 09, load-bearing for replay):
   *   - NODE_STALE: ref no longer binds — retryable after re-observe;
   *   - ACTION_MAY_HAVE_COMMITTED: input may have reached the app —
   *     never blindly retried; replay hands off as `action-uncertain`;
   *   - UNSUPPORTED_CAPABILITY: verb declared absent — the model is told,
   *     it never flails.
   */
  readonly actions?: BackendActions;

  // ── capability: location (requires observation) ───────────────────
  /**
   * Deterministic locator resolution. Unlocks the `screen`/`expect` tier.
   * Only the built-in playwright backend implements this today; declaring
   * it is a real milestone, not a checkbox.
   */
  locate?(expression: LocatorExpression, context: OperationContext): Promise<readonly NodeRef[]>;

  // ── lifecycle (always available) ───────────────────────────────────
  /** Once per worker, before the first step. Boot devices here, not inside a step budget. */
  init?(info: BackendInitInfo): Promise<void>;
  /** Worker shutdown, bounded by cleanupTimeout; failure is a run error, not a test failure. */
  dispose?(): Promise<void>;
  /** Per-test isolation boundary; absent means state persists across tests. */
  session?: {
    start?(test: { id: string; titlePath: readonly string[] }): Promise<void>;
    end?(): Promise<void>;
  };
}

interface BackendActions {
  // Core verbs. Declare what you support; absence is reported, never inferred.
  tap?(target: NodeRef, ctx: OperationContext): Promise<void>;
  type?(target: NodeRef, value: string, ctx: OperationContext): Promise<void>;
  press?(target: NodeRef, key: string, ctx: OperationContext): Promise<void>;
  select?(target: NodeRef, value: string, ctx: OperationContext): Promise<void>;
  scroll?(direction: ScrollDirection, target: NodeRef | undefined, ctx: OperationContext): Promise<void>;
  navigate?(url: string, ctx: OperationContext): Promise<void>;
  // Mobile-shaped verbs promoted into the grammar (grammar-2). The dogfood's
  // hottest actions must be replayable or the design fails its own test.
  open?(app: string, opts: { relaunch?: boolean }, ctx: OperationContext): Promise<void>;
  back?(ctx: OperationContext): Promise<void>;
}

// There are deliberately no extension verbs. The grammar is small and closed;
// anything beyond it is an agent-side tool whose replay annotations buy the
// same caching. The graduation path replaces the escape hatch: a tool becomes
// a verb in grammar-N+1 when dogfood data shows it is hot across integrations
// (exactly how open/back earned promotion — action #1 of most mobile traces).

interface SemanticSnapshot {
  /** Monotonic; refs are valid only against the newest revision. */
  readonly revision: string;
  readonly nodes: readonly SemanticNode[];   // ref, role, name, value, rect, states
  readonly truncated: boolean;
  readonly viewport?: { width: number; height: number; scale: number };
}
```

### `defineBackend` — the loud manifest

Duck-typing is the authoring surface; `defineBackend` is where it becomes
safe. It runs at config load, synchronously, and fails the run — never
silently demotes:

```ts
const backend = defineBackend({ ... });
backend.capabilities; // ReadonlySet<BackendCapability>, printed at init and in the report
```

Validation rules:
1. `spiVersion` present and known.
2. `actions` without `observe` → INVALID_CONFIG (the one dependency edge).
3. `locate` without `observe` → INVALID_CONFIG.

(Tool validation happens at `defineTool` time, agent-side: branded
annotations required, and every `replay: { locate }` path must resolve
against the tool's `inputSchema` — a dangling path fails loudly at
definition, not silently at replay.)

## 3. Capability → feature/duty matrix

| Tier | Unlocks | Obligates |
| --- | --- | --- |
| no backend (agent tools only) | `agent.act`/`agent.assert`; guard, accounting, sanitizers, media handling — all harness-applied. Everything opaque: no replay beyond deterministic tools, no judgment tier. This is PR #90 today, as the documented entry tier. | annotations on every tool |
| `observation` | judgment tier (`waitFor`/`extract`), prompt snapshots + `replayedPrefix` rendering, observation metrics, redaction, cache relocation, `locate`-mode tool replay | snapshot bounded + redacted by harness; revision discipline |
| + `actions` | grammar toolset derived by the agent from the backend, trace-1 verb replay, origin policy, per-verb budgets, `secrets.fillWith` sinks | the stale/commit error contract |
| + `location` | `screen` fixture, `expect(...)` deterministic tier | locator semantics conformance vectors |
| lifecycle (any tier with a backend) | boot outside step budgets, no leaked sessions, per-test reset | dispose bounded by cleanupTimeout |

Degradation is failure at the earliest honest moment: a test using `screen`
on a backend without `location` fails at **selection**; `agent.waitFor` on a
target without `observation` fails immediately with `UNSUPPORTED_CAPABILITY`
and one clear sentence. Nothing silently no-ops.

Conformance vectors are keyed per capability (spec change: 09 collapses into
a "backends" chapter with `tools-1`, `observation-1`, `actions-1`,
`location-1` vector sets), so "supports actions" is testable, not marketing.

## 4. `defineTool` — extended, not reshaped

Shipped today (trace-1): `defineTool(tool, { replay: 'deterministic' | 'none', mutates, secrets })`.
Extensions:

```ts
interface ToolAnnotations {
  replay: 'deterministic'            // same input, same effect: re-invoke verbatim
        | { locate: readonly string[] }  // these input paths are observation refs;
                                         // recorded as semantic descriptors, re-resolved
                                         // via backend.observe() at replay (Stagehand pattern)
        | 'none';                    // never replayed (unchanged)
  mutates: boolean;
  secrets: boolean;
  /** Deterministic input repair before execute (junk-fill defense, from the dogfood). */
  sanitizeInput?: (input: unknown) => unknown;
  /** Declarative multimodal output: harness applies toModelOutput + history compaction. */
  media?: { type: 'image'; keepLast: number };
}
```

Replay entry types in a trace-1 trace, unified:

| Entry | Source | Replays by |
| --- | --- | --- |
| verb | `actions.*` | re-execute; targets relocate semantically |
| tool (deterministic) | `defineTool` | re-invoke with recorded input |
| tool (located) | `defineTool` | relocate declared paths via `observe()`, re-invoke |
| verification | read-only tools / recorded checks | must pass live (unchanged invariant) |
| gap | `replay: 'none'` mutating tool | replay hands off (unchanged) |

Entry identity: backend `name` + `spiVersion` + tool-schema digest + executor
identity (OQ10: recorded on the entry, never in the key). All trace-1
invariants carry: fail-to-miss, divergence never fails a step, uncertain
actions never blindly repeated.

## 5. The brain side (unchanged shape, absorbed discipline)

`StepExecutor` stays the one brain socket. `createAgent` becomes the one
builder — backend-agnostic, since its toolset derives from the target's
declared capabilities plus `agent.tools`. `createToolLoopExecutor` retires;
its deltas become options:

```ts
createAgent({
  model?,                       // defaults to config-resolved agent.model
  system?,                      // appended to base rules
  tools?,                       // extra DefinedTools (merged with config agent.tools)
  maxTurns?,
  prompt?: (context) => string, // override the default framing; the default
                                // already embeds observe() + replayedPrefix +
                                // ledger + params — overriding never loses them
  compactMessages?,
});
// verdict tool, loop guards, wind-down, guard/accounting, media compaction:
// always chassis-owned, never rebuilt by an integration.

// context additions
interface StepExecutorContext {
  // existing: step, signal, model, ledger, agentContext, budgets, actions, observe
  readonly test: { id: string; titlePath: readonly string[] };  // replaces ledger === '' inference
  readonly secrets: {
    /** Scoped reveal for backend sinks; recorded as a policy event, redacted everywhere. */
    fillWith(name: string, fill: (plaintext: string) => Promise<void>): Promise<void>;
  };
}
```

`context.observe()` and `context.actions` route to the target's backend.
The judgment tier observes through the same path, so `waitFor`/`extract`
work on every backend with `observation`.

## 6. Config

```ts
export default defineConfig({
  targets: [
    { name: 'web', platform: 'web' },                              // implicit built-in backend
    { name: 'ios-simulator', platform: 'ios', backend: agentDevice({ session: 'e2e' }) },
  ],

    maxModelCalls: 40,
    context: '...',
    tools,                          // ALL model vocabulary lives here, never on a backend
  },
  cache: 'read-write',              // now meaningful for every backend
});
```

Selection gates on capabilities: a test touching `screen` on a backend
without `location` fails at selection with UNSUPPORTED_CAPABILITY.

## 6b. Packaging — one ingestion path, first party included

Core (`e2e`) ships the referee and the brain and **zero bodies**. Every
runnable surface — including ours — arrives as an ordinary package exporting
one factory with one conventional shape:

```ts
// the integration convention, for everyone:
export function <name>(options): { backend?: Backend; tools?: Record<string, DefinedTool> };
```

| Package | Provides | Capabilities |
| --- | --- | --- |
| `@e2edev/playwright` | `playwright()` → `{ backend }` | observation + actions + location |
| `e2e-agent-device` (this repo's testbed today, its own package tomorrow) | `agentDevice()` → `{ backend, tools }` | observation + actions, tool pack |
| anything the community writes | same factory shape | whatever it declares |

Rules that keep it honest:

1. **No internal backdoor.** The playwright backend is built with the public
   `defineBackend`, validated by the same rules, graded by the same
   capability vectors. If the public path can't express the first-party
   backend, the contract is wrong — that's the feature.
2. **Zero-config stays.** `platform: 'web'` with no `backend` resolves
   `@e2edev/playwright` (optional peer, exactly today's mechanics) and calls
   its public factory. Sugar over the same door, not a second door.
3. **The quickstart ladder is the install ladder.**
   - nothing extra: `agent.tools` only — opaque, works this afternoon;
   - `npm i @e2edev/playwright`: web with the full deterministic tier;
   - `npm i e2e-agent-device`: iOS/Android at observation+actions;
   - write your own: one factory, one file, the dogfood proved the size.

Fixtures follow capabilities, not packages: `web`/`app`/`screen` are core
code implemented over the contract (`navigate` verb, `locate`), available
whenever the target's backend declares enough, absent with a selection-time
error when it doesn't.

## 7. Worked example — agent-device (rewrites PR #90's fixture)

```ts
// One factory, one shared client, two artifacts: the body and the vocabulary.
export function agentDevice(options: { session: string; platform: 'ios' | 'android' }) {
  const client = createAgentDeviceClient({ session: options.session });

  const backend = defineBackend({
    name: 'agent-device',
    spiVersion: 1,

    async init() { await client.devices.boot({ platform: options.platform }); },
    async dispose() { await client.sessions.close(); },

    async observe() {
      // sparse-deferral retry lives here, in the modality, not around a model tool
      return toSemanticSnapshot(await withSparseRetry(() => client.capture.snapshot({ interactiveOnly: true })));
    },

    actions: {
      tap:  (t) => client.interactions.press({ ref: t.ref }),
      type: (t, v) => client.interactions.fill({ ref: t.ref, text: v }),
      scroll: (d) => client.interactions.scroll({ direction: d }),
      open: (app, o) => client.apps.open({ app, relaunch: o.relaunch }),
      back: () => client.interactions.back(),
      navigate: (url) => client.apps.open({ url }),
      // press/select absent → UNSUPPORTED_CAPABILITY, honestly
    },
  });

  // Agent-side vocabulary: everything beyond the grammar. Same client via
  // closure; the backend never sees these.
  const tools = {
    swipe: defineTool(swipeTool(client), { mutates: true, secrets: false, replay: 'deterministic' }),
    alert: defineTool(alertTool(client), { mutates: true, secrets: false, replay: 'deterministic' }),
    get: defineTool(getTool(client), { mutates: false, secrets: false, replay: { locate: ['target.ref'] } }),
    screenshot: defineTool(screenshotTool(client), { mutates: false, secrets: false, replay: 'none',
      media: { type: 'image', keepLast: 1 } }),
  };

  return { backend, tools };
}

// e2e.device.config.ts
const { backend, tools } = agentDevice({ session: 'e2e-testbed-device', platform: 'ios' });
export default defineConfig({
  targets: [{ name: 'ios-simulator', platform: 'ios', backend }],
  agent: { model: 'openai/gpt-5.6-luna', maxModelCalls: 40, tools },
});
```

Deltas vs #90 as merged: 391-line fixture → ~150; custom executor gone
(stock `createAgent` runs); boot leaves the first step's budget (73s → ~18s
observed); `cache: 'off'` deleted — device traces replay; `waitFor`/`extract`
usable; `platform: 'ios'` true; secrets flows possible; the DEVICE_RULES
prompt shrinks to modality hints because the blindness it compensated for
is gone.

## 7b. Web parity — no platform above the others

Phase A still privileges web in four ways, and each has the same cure:

| Asymmetry today | Cure |
| --- | --- |
| Web targets get a driver, others get backends — two config shapes, two internal paths | Playwright re-lands as a backend through `defineBackend`; `WebTarget` becomes sugar over a backend target |
| `app` config is web-shaped (base URL, origins, readyUrl) and top-level | `app` becomes an option of the web backend; other backends declare their own app notion (bundle id, activity) |
| The `web` fixture is core code; `device` was core code that had to be deleted | **Fixture contribution** (below): platform fixtures are declared by the backend, web included |
| The zero-config default target is web | Stays — a default is not a privilege as long as it goes through the same door |

### Fixture contribution

Core keeps only the universal fixtures: `agent`, `app`, `screen`, `platform`,
`session`. Every platform-shaped surface — `web` included — is a backend
contribution, and core never learns a platform noun:

```ts
interface Backend {
  // ...
  /**
   * Named deterministic surfaces this backend contributes to TestFixtures.
   * Keys become fixture names AND capability names. Core validates shape,
   * never meaning: any record of async methods plugs in — device (home,
   * setPermission, pushNotification), desktop (windows, menus, global
   * shortcuts), anything.
   */
  fixtures?: Readonly<Record<string, BackendFixtureFactory>>;
}

type BackendFixtureFactory = (context: BackendFixtureContext) =>
  Readonly<Record<string, (...args: never[]) => Promise<unknown>>>;
```

The harness discipline is generic, so contributions get it free: every method
call on a contributed fixture is a recorded step named `<fixture>.<method>`,
bounded by `actionTimeout`, aborted with the attempt, translated onto the
error taxonomy, and visible in the reporter and report timeline. No
annotations: test-code fixture calls are deterministic by definition, so
there is no replay question — the backend owns what the calls mean, the
harness owns how they run.

Typing is a **typed `test`, never a global augmentation**. `test.extend`
(shipped) returns the same runtime `test` refined with the backend's
contributed fixtures — the fixtures still resolve from the target's backend
at runtime, `extend` only carries their types:

```ts
// tests-device/fixtures.ts
import { test as base } from 'e2e';
import type { Device } from '../fixtures/agent-device';
export const test = base.extend<{ device: Device }>();
```

This is the market-standard shape (Playwright/Vitest) and it replaces
`declare module 'e2e'` entirely: no project-global interface merge, so a
`device` access is typed only in the files that import the device `test`, and
a plain web test never sees it. `import { test } from 'e2e'` is unchanged for
the universal-fixture case (default type parameter).

Capabilities collapse into this: `backend.capabilities` is
`'observation' | 'actions' | <declared fixture names>`. `requires: [...]`
gates at selection against the target backend; undeclared access fails with
`UNSUPPORTED_CAPABILITY` naming the backend. The dormant
`DriverSession.capabilityFixtures` seam retires into this.

Sequencing, corrected: fixture contribution does NOT need to wait for
playwright-as-backend. Device and desktop backends can contribute fixtures
immediately; `web` moves out of core when playwright walks through the public
door (migration step 2'), at which point no platform is above another
structurally, not just aspirationally.

## 8. Migration

1. **Chassis absorbs discipline** (no new concepts): DefinedTool acceptance,
   async factories, sanitize/media annotations, default buildPrompt with
   replayedPrefix. Internal refactor; default agent re-lands on it.
2. **`e2e/backend` ships**: `defineBackend`, capability validation, config
   `targets[].backend`, `test.extend` typing, contributed fixtures + wired
   `locate`. **(done — this PR.)**
2'. **Playwright becomes a backend, web leaves core** (its own PR — the large
   one). `@e2edev/playwright` exports `playwright(): { backend }` through the
   public `defineBackend`. The mapping, member by member:
   - `observe`/`actions`/`locate` ← today's `DriverSession.observe`, agent
     actions, and `screen.resolve/read`; the deterministic tier is already
     backend-shaped after this PR.
   - the **`web` fixture** (`goto`, `url`, `reload`, `routes`) becomes a
     contributed fixture, declared by augmentation-free `test.extend` in web
     projects, so `TestFixtures` in core drops to the universal four + session.
   - **state** and **artifacts** are added to the contract as
     platform-NEUTRAL optional capabilities, never web-shaped members. `state`
     is opaque snapshot + restore (`capture(ctx): Promise<StateSnapshot>`,
     `restore(snapshot, ctx)`), where `StateSnapshot` is opaque bytes/JSON the
     harness never inspects — a browser's storage state, a device's app state,
     and a desktop's window state all satisfy it identically. `artifacts` is
     named evidence (`kinds: readonly string[]`, `capture(kind, ctx):
     Promise<path>`), not `screenshot()/startTrace()` — agent-device and a
     Limrun backend produce screenshots and video through the same hook web
     does. The litmus: if a Limrun backend can't implement a member without
     contorting to a browser's shape, the member is wrong. Only the genuinely
     web-specific surface — `goto`, `url`, `reload`, `routes` (network
     interception) — is the `web` contributed fixture, peer to `device`.
     Nothing web-named enters the contract.
   - `WebTarget` becomes sugar: `{ platform: 'web' }` with no `backend`
     resolves `playwright()` exactly as the driver id resolved before.
   - `app` config (base URL, origins, readyUrl) moves under the web backend's
     options; other backends declare their own app notion.
   The driver SPI (`e2e/driver`, `defineDriver`, spec 09) is deleted at the
   end of this step — one backend layer, playwright included, TesterArmy's
   Limrun/Librum backend a peer of it, no platform privileged.
3. **agent-device dogfood moves to a backend** (testbed); measure judgment
   tier + prompt observation + boot-in-init against the #90 baselines.
   `createToolLoopExecutor` deprecated once its options land on `createAgent`.
4. **grammar-2** (`open`/`back`) + tool replay entries in trace-1; device
   suites turn caching on; bench gates parity.
5. **Spec**: 09 retires into the backends chapter with per-capability
   vectors; `e2e/driver` exports removed; suiteVersion bump.

## 9. Open questions

- `select` semantics off-web (iOS pickers are flows, not verbs) — leave
  absent, or a per-platform tool pack until graduation data exists?
- Does `location` on non-web ever pay for itself, or is the judgment tier +
  replay verification the durable answer for device assertions?
- Coordinate tools (`swipe`): is trace-1's end-mismatch check enough for
  deterministic replay, or do they need a declared end-state digest?
- Per-target tool scoping: agent-owned tools lose the automatic "device tools
  never offered on web targets" property backend-owned tools had. Options:
  per-target `agent` override, or a `platforms` filter on tool packs.
  Single-modality configs (the common case) are unaffected; defer.
- Multi-backend targets (web + device in one test) — out of scope here;
  the contract doesn't preclude it, selection does.
