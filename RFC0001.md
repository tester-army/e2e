# RFC0001: e2e v2 — the agentic testing framework on the TesterArmy engine

Status: draft (Oskar, Szymon, Krzysztof). Supersedes RFC0000 (`RFC.md`) and
`PLAN.md`. Reviewed twice (adversarial + final pass, 2026-08-30/31 — threads
on PR #84); findings addressed inline, the rest are Open Questions.

**The decision.** Approving this RFC green-lights the **quiet v0 only**: the
qa-agent inversion, the shrunken public packages, `e2e` + `e2e mcp` in
existing customers' hands. It does **not** approve the public launch, the
license posture, or open-sourcing anything — those gate on OQ2/7/8 at the
public moment. OQ1 is **resolved** (2026-08-31): the core `e2e` package is
**MIT**. Two OQs must be answered **before build starts**: OQ6 (where code
tests earn receipts), OQ9 (owner + kill criteria).

## Summary

e2e is the framework for building testing agents. Four layers:

1. **Test API** — `test()`, `agent.act()`, `agent.assert()`, `agent.login()`.
   Selectors never required — determinism is compiled by the cache — but
   direct grammar actions exist for when you want it hand-written.
2. **Actions & tools** — a framework-owned action grammar; toolsets on top
   are replaceable per agent, for web and mobile, over swappable backends.
3. **Harness** — a public build of TesterArmy's `test-runner`: lifecycle,
   budgets, ledger → report, and the adaptive cache (`.e2e/cache/`).
4. **Brain socket** — agent, model, and prompts are the builder's.
   `@testerarmy/agent` (private) implements the same interface as the public
   example agent.

Kitchen public, recipes private. Build your own agent free; run ours with one
config line; leave with one config line — tests survive the swap both ways.

## State of reality (do not oversell)

The **legacy agent loop** is what's proven under customers today. The
inverted **TestRunner engine** is dev-validated, flag-gated off in prod. The
**adaptive cache** merged 2026-08-29, ramping behind a flag (live-verified
19.9s → 1.19s zero-turn; hourly-suite model spend ~8× down within an hour of
flag-on). **This RFC gates on the cache ramp and engine flag flip completing
their soak.**

## Layer 1 — test API

```ts
import { test, agent, credentials } from 'e2e';

test('member upgrades to Pro', { tags: ['billing'] }, async () => {
  await agent.login(credentials.user('member'));
  await agent.act('open billing settings and upgrade to the Pro plan');
  await agent.act('complete payment', { files: ['./fixtures/test-card.png'] });
  await agent.screenshot('post-upgrade');                    // deterministic
  await agent.evaluate(() => localStorage.getItem('plan'));  // deterministic
  await agent.assert('the billing page shows Pro as active');
});
```

```ts
// e2e.config.ts
export default defineConfig({
  target: { url: process.env.APP_URL!, platform: 'web' },
  backend: 'playwright',
  agent: testerarmy,           // ← THE SOCKET; or './agents/mine'
  cache: process.env.CI ? 'read-only' : 'read-write',
  budgets: { stepTimeoutMs: 120_000, maxActionsPerStep: 50 },
});
```

- Each `agent.*` call is one **step**; kinds mirror the platform's (`act`,
  `assert`, `login`, `files`, `screenshot`, `javascript`, `microphone`), so
  dashboard-native and code-native tests are one program in two forms.
  Dashboard tests stay first-class with no e2e requirement.
- `agent.act()` = TesterArmy's current autonomous step semantics.
  (`agent.evaluate` is the `javascript` kind; `agent.screenshot` the
  `screenshot` kind.)
- **Deterministic authoring = direct grammar access.** A test may call
  actions with explicit targets: its own deterministic step kind — zero model
  calls, resolved by the public mechanism (exactly one match or fail),
  recorded and receipted like any step, keyed by its literal target (no
  instruction digest):

  ```ts
  import { actions } from 'e2e';
  await actions.click({ role: 'button', name: 'Upgrade' });          // fails loud
  await actions.click({ role: 'button', name: 'Upgrade' },
                      { intent: 'open the upgrade flow' });          // self-heals
  ```

  **Divergence stance:** a bare grammar-direct action has no intent to hand
  off — when the page changes, it fails loud, *by design*. The optional
  `intent:` supplies recovery meaning: on failure the step is handed to the
  executor exactly like a diverged cache entry, then recaptured. Role/name
  targets are the recommended portable form; raw-selector targets are allowed
  but import Playwright's brittleness with them — the Summary's promise is
  that selectors are never *required*, not that we stop you. The v1
  locator/`expect` engine stays shelved; OQ4 covers deterministic
  *assertions* only.
- `files`/`login`/`microphone` reference platform resources; code-side source
  needs a spec (OQ6) — note the flagship example above already uses both
  (`credentials.user(…)`, `files: […]`).

## Layer 2 — actions, tools, backends

- **Action grammar (framework-owned, versioned, a closed *set* — public
  code; "closed" is the vocabulary, not the license):** click, type,
  press, scroll, navigate, upload — each with a canonical target union
  (role/name, selector, ref-derived, point). Budgets, secret gating, cache
  entries, replay, and receipts are defined over it. Small, slow-moving.
- **Toolsets (replaceable per agent):** e2e ships a lean default pack
  (`ui_click`, `ui_select`, … — thin AI SDK tools over the grammar, seeded
  from v1's written-to-be-open tool layer). `@testerarmy/agent` **fully
  replaces it** with the private production toolset compiling to the same
  grammar. Different tools, same recorded actions. **`qa-tools` is never
  published.** Public/private toolsets may even use different addressing;
  the target union canonicalizes.
- **Backends:** Playwright default; mobile backends on the same SPI; swap the
  layer below, keep the grammar above.
- **Extensions:** AI SDK `tool()` + required annotation —
  `defineTool(aiSdkTool, { replay, mutates, secrets })`. Undeclared semantics
  ⇒ cache-excluded, untrusted by default.
- **Extensions are project capabilities:** the same definition is served to
  the dev-loop MCP (`e2e mcp`) — airplane mode, physics hooks, data seeding —
  one tool, every agent, same annotations enforced everywhere. `e2e/tools/`
  is the app's testability surface; `e2e mcp` is an auto-generated,
  app-specific MCP server. Dev-loop calls run the same policy/recording
  pipeline, so a dev session can seed tests and cache.

```ts
export const seedCart = defineTool(
  tool({
    description: 'Seed the cart with a SKU via the store test API',
    inputSchema: z.object({ sku: z.string() }),
    execute: async ({ sku }, { session }) => session.fetch('/api/test/cart', { sku }),
  }),
  { replay: 'deterministic', mutates: true, secrets: false },
);
```

## Layer 3 — harness & adaptive cache

Public build of `test-runner`: plan/dispatch, step lifecycle, budgets,
retries, append-only ledger emitted as the local report (same format the
cloud stores as the run receipt).

**Verdicts are ternary: passed / failed / blocked.** Mirrors the platform's
`TEST_OUTPUT_RESULTS` (`PASS`/`FAILED`/`BLOCKED`). `blocked` means the test
could not produce a *product* verdict — missing credentials or seed data, an
environment outage, a test-setup problem, or an agent automation limit — and
carries a structured `blockedReason` (category + summary + the step error
codes that produced it). This is load-bearing for testing with agents at all:
without it, every environment hiccup reads as a red product failure and trust
in red evaporates; with it, "the app is broken" and "the test couldn't run"
are different signals with different owners. Kept distinct from the
envelope's `blocked` step *mode* (planned but never dispatched — bail,
cancel, budget), which stays out of the outcome vocabulary exactly as the
platform envelope does. Ledger, report, receipt, and exit codes all
distinguish blocked from failed.

Cache split, same rule as tools — **mechanism public, judgment private:**

- Public: entry format, key scheme, `.e2e/cache/` store (interface — the
  cloud's shared cache can replace the filesystem), the adaptive flow
  (replay zero-turn → divergence → hand step to executor mid-step →
  recapture), fail-closed invariants (identity check before every dispatch;
  never resume replay after post-mutation divergence).
- Private: relocation tactics, divergence classification, replay eligibility
  — behind a `ReplayPolicy` extension point with a conservative default.
  **Replay hit-rate is part of what the paid agent is** — a benchmark metric.
- Scope honesty (review B3): entries today are web-only with
  executor-specific target kinds *and tool names* (re-keying recording to
  the grammar is part of the inversion); cross-agent replay is best-effort
  via the target union, strongest within an agent's own history.
- CI defaults read-only; committed caches are untrusted input.
- **Consolidation — one wheel, not two.** The public repo already ships
  `cache-1`, a locate cache (instruction → semantic locator, one entry per
  located action) with the store, key identity, fingerprint, and fail-closed
  validity machinery built. The v2 action-trace cache is the same discipline
  at step granularity, and a locate entry is the one-action degenerate case
  of a trace entry. So the trace cache **extends** `cache-1`'s store and
  rules — a second schema-versioned entry kind in the same `.e2e/cache/`
  store, same CI/read-only posture — and the located verbs converge on
  writing one-action traces, leaving exactly one mechanism before the
  adaptive replay flow lands. v0 item 4's "local cache store" means this
  extension, never a parallel implementation.

## Layer 4 — the brain socket

Golden path — AI SDK native:

```ts
export default createAgent({
  model: anthropic('claude-sonnet-5'),     // any AI SDK LanguageModel
  system: myPrompt,                        // your sauce
  tools: { seedCart },                     // merged with the default toolset
  prepareCall: ({ step, callIndex }) => ({ /* gating, prompt control */ }),
});
```

Raw socket — the contract `createAgent` compiles to:

```ts
const myBrain: StepExecutor = {
  name: 'my-brain', version: '1',
  async runStep(ctx) {
    // ctx.step      { index, type, instruction, params }
    // ctx.observe() a11y tree (+ screenshot); refs are revision-bound
    // ctx.actions   THE GRAMMAR: policed, budgeted, recorded
    // ctx.tools     a toolset over ctx.actions (replaceable wholesale)
    // ctx.ledger / ctx.budgets / ctx.secrets / ctx.signal
    await ctx.actions.click({ role: 'button', name: 'Upgrade' });
    return { status: 'passed', summary: '...' };
    // status: 'passed' | 'failed' | 'blocked' — blocked carries a
    // structured blockedReason (category + summary + error codes)
  },
};
```

Rules:

- **The brain never touches the backend.** Everything bottoms out in
  `ctx.actions` — except declared extensions, which run the same
  policy/recording pipeline under their annotations — and the harness
  enforces policy, budgets, recording, secrets there. Swapping brains changes
  only the thinking — never safety, cache, or receipts.
- **AI SDK native at the edges, e2e-owned at the seam.** The executor type is
  e2e's (engine pins `ai@7.0.2` exact today; public contracts can't inherit
  that churn, and closed-agent-vs-builder `ai` version skew is a hazard the
  `e2e/agent` adapter must own — AI SDK is a peerDependency with a tested
  range). A hand-rolled executor with no AI SDK is valid.
- **No backchannel.** If `@testerarmy/agent` needs to reach around the
  socket, fix the interface.
- **Mid-step resumption is part of the contract — and it is lean.** A
  diverged cache replay hands the step to the executor *mid-step*. The shape
  is taken from main's shipping hand-off (`pendingReplayedPrefix` on the
  qa-agent StepController), not designed fresh: one nullable, step-keyed
  slot — `{ stepIndex, replayedActions: string[] (prose summaries of
  actions 1..k), skippedActions, totalActions, stopReason (one closed
  union: cache-miss | divergence | prefix-stop reasons), startTMs }` —
  set before delegation, cleared in a `finally`. Prose in, not structs in:
  the executor sees action *summaries* and a reason token, never
  descriptors, outputs, or error objects; continuity is live app state plus
  one notice (which *replaces* the ordinary prior-run hint, not appends).
  Recapture is a stitch: `trace[0..consumed) ++ agent-recorded suffix`,
  original startPath, truncation flagged — `consumed` (skips + executions)
  and `replayedActions.length` (executions) are different counters and
  both must survive into the public types, or the stitched trace silently
  corrupts. Cancellation/session-loss/retryable errors rethrow; they never
  enter the resume state. Escalation granularity is the **step** — main has
  no single-action hand-off. This reconciles `intent:` cleanly: a
  grammar-direct action is its own step (Layer 1), so its hand-off *is* the
  step-level hand-off with a one-action trace; anything finer is new
  design, out of v0.

**Multiple agents — the roster.** `agent: x` is sugar for
`agents: { default: x }`; tests/suites route to specialists via the same
`agent` key (naming decided: config and tests both say *agent(s)*;
`StepExecutor` stays the type name, "executor" the spec term):

```ts
agents: { default: testerarmy, checkout: paymentsAgent, canvas: visionAgent }
// ...
test('buy flow', { agent: 'checkout' }, async () => { /* … */ });
```

One agent per step, selected statically — **a roster, not a committee** (no
multi-agent collaboration inside a step). All roster members sit behind the
same socket and grammar, so policy, receipts, and cache stay uniform; the
receipt records which agent ran each step. The platform's fast/deep execution
modes are the primitive form of this, and the dashboard's mode picker
generalizes to an agent picker. Consequences: TesterArmy can sell
*specialists* (a11y, canvas/vision, mobile) alongside the generalist, and the
public benchmark becomes per-category. Cache × roster keying: OQ10.

## How a step runs

```
 next step ── grammar-direct? dispatch directly: fail loud, or `intent:`
        │      hands off like a diverged entry
        └──▶ cache key (test + step + instruction digest + platform
               + grammar/policy version ± executor identity — OQ10)
        ┌───────────┴────────────┐
   CACHE HIT                CACHE MISS
   replay recorded          executor.runStep(ctx)
   actions zero-model,      every grammar action:
   verifying each target      policy → budget → backend dispatch
        │                     → ledger → RECORD
   diverged? ──yes──▶ hand to executor MID-STEP (adaptive)
        │no                   │
        ▼                 passed? → write trace (read-write only)
   step result ──▶ ledger ──▶ report.json (receipt) ──▶ exit code / cloud
```

## Public/private line

| Public (e2e) | Private (TesterArmy) |
|---|---|
| Test API, config, CLI, `e2e mcp` | Prompt corpus, step policy, judges |
| Action grammar + backend SPI (web, mobile) | Production toolset (`qa-tools`, unpublished) |
| Harness, budgets, ledger/report format | `@testerarmy/agent` (closed npm) |
| Cache mechanism + conservative ReplayPolicy | Tuned ReplayPolicy, vision arsenal |
| Default toolset, example agent, scaffold | Cloud: runs, receipts, devices, shared cache, PR verdicts |

- Leak rules: prompts/judges/heuristics never in a public package; public =
  interfaces, formats, shells; the license, not obfuscation, is the wall.
- **Two clocks:** framework ticks in weeks (semver, community); agent ticks
  in minutes (customer hotfixes, flag-ramped). The socket decouples them.
  Agent channels (stable/canary); behavior version stamped in every receipt.
  Note (review M4): the published grammar/snapshot formats must also declare
  a cadence — OQ8.

## Business model

1. **The agent** — `@testerarmy/agent` for everyone who skips the struggle.
   One line to adopt, one to leave; the recurring maintenance tax converts
   DIYers over time.
2. **The devices** — leased remote browsers/simulators for local runners,
   metered, agent-agnostic.
3. **The infra** — hosted third-party executors ("Vercel for testing
   agents"): their bundle, our devices/cache/receipts/PR verdicts. We win
   whenever tests run, whoever's brain runs them. Prereq: sandboxing
   untrusted executors. Not v0.

Requirement: a public benchmark (web-benchmark bug-book) where our agent
credibly leads — per-category once the roster exists, with governance as part
of OQ7. The quality flywheel is the pricing power, not prompt secrecy.

## Why anyone pays (the cannibalization objection)

The objection: "the free framework locks us out of our own business." The
answer: what's free is the *ability to try*; what's paid is reliability,
speed, scale, and workflow — each structural, none artificially withheld.

1. **Reliability you don't maintain.** A DIY agent is a recurring tax —
   models drift, sites change, edge cases accumulate. The paid agent is the
   output of the eval flywheel: benchmark CI, verdict accuracy from thousands
   of customer runs, hotfixes on the fast clock no DIY team staffs for.
   You're not buying prompts; you're buying the pace of the kitchen.
2. **Speed and cost.** The public `ReplayPolicy` is conservative by design —
   fail-closed defaults anyone may tune, not a withheld feature; the paid one
   is eval-corpus-tuned judgment. It turns suites from model-priced into
   replay-priced, and hit-rate is a public benchmark number — paid is
   *visibly* faster and cheaper.
3. **Devices.** Simulator and browser fleets, leased or hosted. Nobody DIYs
   a device farm; this revenue is agent-agnostic.
4. **The workflow.** Receipts, PR verdicts, schedules, dashboards, the
   shared cloud cache — where QA budgets actually live, and it sells to
   DIY-agent users too: via OQ6's receipt path today, hosted executors
   (revenue line 3) later.
5. **The roster.** Specialists as line items.

Why the free path doesn't eat this:

- Builders who make their own agent mostly were never agent customers — the
  exception is the mid-market band named in failure mode 5, which the
  falsifiable test below exists to watch. Without e2e they build on
  Stagehand — we lose them *and* the substrate. On e2e they're ecosystem,
  benchmark participants, and device/infra prospects.
- Gravity points paid-ward: DIY cost recurs, the swap is one config line,
  and ejection-freedom is what lets enterprises buy without lock-in fear.
  Portability closes deals; it doesn't leak them.
- Precedents, honestly both ways: Next.js/Vercel, GitLab, Grafana, and
  Sentry monetized above a free core because the paid layer was **thick**
  (workflow + scale + reliability). Docker's paid layer was thin and it went
  badly. Ours is thick by construction — the flywheel, the fleet, and the
  workflow are products, not license walls.
- The real lock-out risk runs the other way: if Stagehand/Midscene define
  the category's grammar and formats, TesterArmy becomes an app on someone
  else's substrate.
- What a fork cannot take: the eval corpus and benchmark authority, the scar
  tissue in the private agent and ReplayPolicy, the shared-cache network
  effect, device economics, receipt/PR integrations, the two-clock
  operational muscle.

**Falsifiable test (feeds OQ9 kill criteria):** track free-project → paid
conversion (agent or cloud) and paid-churn reasons. If free usage compounds
while conversion stays near zero and churn says "we built our own," the
objection was right — revisit the line, not the mission.

## Failure modes (the honest downside)

Ranked by probability × damage. Arming honestly: 1–2 fully at quiet v0; 8
partially at quiet v0 (`defineTool` code, committed caches, and `e2e mcp`
ship to customers); 3 and 4 start their clocks at the first npm publish,
whatever the dist-tag; 3–7 arm fully at the public moment.

1. **Two-front bleed (most probable).** Three people, two products; e2e
   already froze once when the platform called. Both get 60%. Watch: repo
   cadence after the first platform fire. Hedge: OQ9's named owner.
2. **The inversion regresses the money-maker.** The B2 workstream touches
   the highest-regression-risk package serving paying customers, for a
   product earning nothing yet. Hedge: the bench gates are non-negotiable.
3. **A competitor executor harvests the commons.** Stagehand-on-our-socket:
   their agent + their devices, one config line away. The license can block
   hosting the framework, not implementing the socket — the pitch requires
   that door stay open. Hedge: roster + per-category benchmark, mobile
   depth, the workflow; write OQ7's response scenario before launch.
4. **Velocity tax.** Public semver lands on our fastest-moving internals
   (grammar, snapshot format): community churn or platform slowdown — pick
   one. Hedge: the deliberately tiny public surface, plus OQ8's cadence.
5. **Mid-market leak — the true part of the objection.** Teams that would
   have paid, for whom scaffold-agent-in-CI is good enough. Invisible until
   the falsifiable test fires; watch small-team conversion early.
6. **Benchmark backfire.** The first published loss on our own yardstick
   inverts the pricing-power story. Softened by per-category rosters; not
   removed.
7. **Commoditization on a shorter fuse.** Model progress makes scaffold
   agents good enough; e2e builds the rails that deploy that progress
   against our own premium. This is a named bet: when brains commoditize,
   the rails and the workflow win.
8. **Brand-billed security incidents.** Malicious committed caches,
   arbitrary `defineTool` code, dev-loop MCP in misconfigured repos —
   headlines carry our name either way. Hedge: the security review is not
   an optional line item.

## Keep / retire from v1

Keep: npm name `e2e` + `@e2edev`, release plumbing, fern docs site, the lean
v1 agent (seed of the default toolset + example agent), spec security/cache
/budget chapters as requirements + conformance fixtures. Retire: v1 runner
and agent internals, PR #83 (close as superseded — production `qa-agent` is
the planning tier), the "open standard" framing until conformance is
verifiable by third parties.

**Decision (2026-09-01, supersedes the earlier "locator/`expect` shelved"
line and resolves OQ4):** the deterministic tier ships and stays — it is
what makes agent verdicts falsifiable ("agents act, determinism verifies"),
and its engine powers the located verbs and the cache regardless. But it is
**frozen**: fixes yes, expansion no, until agent-tier work concretely
demands a specific addition. New investment goes exclusively to the agent
tier. Backends are not taxed by the breadth: the driver SPI is
capability-gated, so an agent-first driver ships observation + queries +
core actions and legitimately reports `UNSUPPORTED_CAPABILITY` for the rest.

**Decision (2026-09-01, act-first — supersedes the located-verb clauses of
the note above and the Layer 3 "Consolidation" note):** the located verb
tier (`agent.tap`/`click`/`type`/…, `agent.login`, `InstantActionOptions`)
is removed; `agent.act` is the single action API, and sign-in is an ordinary
`act` flow over `Secret` params through the host-authorized `type_secret`
tool. The locator cache (`cache-1`) — key identity, locate replay, path
guidance, `agent.cache`, `--no-agent-cache`, `maxCacheBytes`,
`CACHE_REPLAY_DIVERGED` — goes with it, which resolves the "one wheel, not
two" consolidation as **zero caches in v0**: every agent decision is made
fresh per run, and runs are comparable through the report, not through
replay. The adaptive action-trace cache stays future direction and would
land as its own mechanism rather than an extension of `cache-1`. The
deterministic tier (`screen`, `expect`, `web`, `app`) stays frozen exactly
as decided above — but where that note froze the located verbs alongside
it, this one removes them: determinism stays, the located verbs are gone.
suiteVersion 0.2.0 → 0.3.0.

**Decision (2026-09-01, cache-in — amends the act-first note's timing, not
its design):** the adaptive action-trace cache moves from future direction to
the active build, landing exactly as act-first prescribed — **its own
mechanism (`trace-1`)**, never an extension of `cache-1`, though `cache-1`'s
reviewed store and key machinery is resurrected and re-typed rather than
re-derived. Phasing is dark-first so spec 10's "no caching" clause is never
amended by an implementation shortcut: (1) mechanism modules + tests, zero
behavior change; (2) recording + `cache` config mode + the cache chapter,
suiteVersion 0.3.0 → 0.4.0; (3) adaptive replay — zero-turn, divergence,
the Layer 4 mid-step hand-off (`replayedPrefix` on `StepExecutorContext`),
recapture; (4) `ReplayPolicy` + bench parity gates. OQ10's conservative
default applies until cross-agent divergence data exists: executor identity
is recorded **on the entry, never in the key**. This reactivates v0 item 4's
cache half. Invariants carried verbatim from the shipping private cache:
fail-to-miss, divergence never fails a step, unconditional write-on-pass,
full replay self-finalizes but an all-skipped replay escalates, recorded
verifications must pass live, non-replayable mutations are gap markers.

**Migration goal (2026-09-01, recorded with cache-in):** the platform adopts
e2e from the inside, not alongside. `@testerarmy/agent` implements the public
`StepExecutor`; the private cache executor re-lands as the tuned
`ReplayPolicy` over the public `trace-1` mechanism; the cloud shared cache
implements the public store interface. Once the action-cache bench shows
parity on the e2e harness, TesterArmy's own suites run through e2e and the
private runner's duplicated lifecycle retires — one engine, publicly built,
privately tuned.

## v0 plan

Quiet release to existing customers first (they have keys; they asked for
tests-in-code — closed-package distribution mechanics: OQ2). Build list —
packaging **plus one real inversion** (review B2):

1. Monorepo hygiene: `qa-tools`, `snapshot`, CLI into root test/typecheck.
2. **The inversion (hard part):** move tool construction, budgets, per-turn
   policy, and cache recording from `qa-agent` into the harness so the
   contract is step-in/verdict-out (today the brain owns all four; verdicts
   flow through a shared StepController). Highest-regression-risk item;
   gated by the action-cache bench + web-benchmark suite.
3. Publish the shrunken public set (harness, grammar + backend SPI —
   including target relocation and identity verification extracted from
   qa-tools' automation layer — snapshot format, default toolset) from the
   monorepo; one source of truth, `qa-agent` and `qa-tools` stay private.
   License: OQ1 is resolved — the public set publishes under **MIT**.
4. Local cache store + local report output — report and exit codes carry the
   ternary verdict (passed/failed/blocked + `blockedReason`) from day one; it
   is not a later refinement.
5. `e2e` package: API + config + CLI shell; `create-e2e-agent`.
6. `e2e mcp` (web now; mobile = local simulator or leased device) — driver +
   project tools free, agentic tools with a TesterArmy key.

Public moment (separate decision): example agent green on v1 testbeds with a
BYO key; license finalized (lean: fair-source → open later); benchmark
published; a named owner.
