# RFC0003 — Agent tool replay tiers

Status: draft. Builds on RFC0001 (layer 2 `defineTool`) and RFC0002 (the
backend contract). Motivated by the TesterArmy vocabulary port: most of its ~53
live tools already carry a replay classification, and two tiers e2e does not yet
express are load-bearing for replaying full-vocabulary runs at zero or near-zero
model cost.

## Problem

Today the trace cache replays exactly one thing: the **grammar** — the backend
`perform` verbs (tap/type/press/select/scroll/navigate) recorded per act step
and re-found against a fresh observation by the relocator. Model-facing tools
declared with `defineTool` never participate. `ToolAnnotations.replay` is a
two-value flag (`'deterministic' | 'none'`, `packages/e2e/src/agent/tool.ts:22`)
that today only gates trust and reporting; a `deterministic` tool is still
re-executed live on every run, and the tool loop records nothing
(`packages/e2e/src/agent/tool-loop.ts` records turns for accounting, not replay).

That is fine while the vocabulary is act/assert over the grammar. It is not
enough for a host that ports a large tool set. Two real tool shapes cannot
replay:

1. **Located tools.** A custom tool whose input carries a node the agent chose
   from an observation — a vision-assisted click, a "extract the value under
   this row" tool. On replay the recorded node id is stale; the tool must be
   re-pointed at the equivalent node in a fresh observation before it re-fires,
   exactly as the grammar relocator does for verbs. e2e has no way to say
   "these input paths are located nodes."

2. **Fixed-model tools.** A tool whose effect is one model call by design — a
   vision assertion ("does this screen show a welcome?"), a vision click that
   resolves a point from a screenshot. Re-running it live spends a model call
   every replay. The recorded outcome is reusable, but only under a single
   fresh model call bounded to that tool, never the full agent loop. e2e has no
   tier between `deterministic` (no model) and `none` (full live loop).

TesterArmy already encodes exactly these: `REPLAY_TOOL_SPECS`
(`packages/qa-agent/src/core/replay/tiers.ts`) classifies tools as `pure`
(deterministic), `pure + targeted` (located), and `fixed_model`, plus read-only
`skippable`. Porting that vocabulary onto e2e needs the middle two tiers.

## Non-goals

- Changing how the grammar replays. Verb replay (trace-1, relocation, staged
  writes, eviction, end anchors) is unchanged; this RFC extends replay to
  `defineTool` calls beside it, reusing the same relocation and settlement.
- A general record/replay of arbitrary model output. Only the two declared
  shapes below are replayable; everything else stays `none`.

## Design

### The annotation

`ToolAnnotations.replay` widens from a string to a discriminated value:

```ts
type ToolReplay =
  | { readonly mode: 'deterministic' }
  | { readonly mode: 'located'; readonly locate: readonly string[] }
  | { readonly mode: 'fixed-model' }
  | { readonly mode: 'none' };
```

- `deterministic` — same input, same effect; replays with no model call and no
  relocation. (Today's `'deterministic'`.)
- `located` — replays with no model call, but the input paths in `locate` are
  node references (ids from the observation the agent acted on). Each path is
  relocated against a fresh observation before the tool re-fires; an ambiguous
  or missing relocation hands off, exactly like a verb.
- `fixed-model` — replays with one fresh model call bounded to this tool, not
  the agent loop; the recorded prompt shape is re-issued and the tool re-fires
  with the new result. Cheaper than a live turn, honest under UI drift.
- `none` — never replayed. (Today's `'none'`.)

A string `'deterministic'`/`'none'` stays accepted as sugar for
`{ mode }`, so existing tools do not churn.

Validation at `defineTool` time (not at replay): every `locate` path must be a
non-empty string that resolves to a property of the tool's `inputSchema`;
`fixed-model` requires the tool to be marked `mutates: false` (a mutating
fixed-model tool cannot be safely re-issued); `locate` is rejected on a tool
with no object input. Validating against the schema at definition time is the
same fail-loud rule `defineBackend` follows (RFC0002).

### Recording

The trace gains a third recorded-action variant beside verbs and the tool gap:
a **tool call**. When a `defineTool` tool with a replayable tier commits inside
a recorded act step, the recorder captures `{ name, tier, input }` where, for a
`located` tool, each `locate` path's value is replaced by the node's durable
descriptor (the same `describeTarget` projection verbs use,
`packages/e2e/src/agent/actions.ts`), and every other value goes through the
existing `verbatim`/redaction poisoning. A `fixed-model` tool records the
sanitized prompt inputs, never the model's raw output. Inputs that cannot be
kept whole poison the trace exactly as verb inputs do.

### Replay

The replay engine (`packages/e2e/src/agent/replay.ts`) gains a tool step beside
its action step:

- `deterministic` — re-invoke `tool.execute(input)` directly.
- `located` — relocate each `locate` path's descriptor against a settled fresh
  observation (reusing `relocate`), substitute the fresh ids into the input,
  then re-invoke `execute`. A failed relocation is an `end-mismatch`-style
  hand-off, not a guess.
- `fixed-model` — issue one bounded model call for this tool with the recorded
  prompt shape, then re-invoke `execute` with the result. Counts one model call
  against the step budget; still zero agent-loop turns.

The step self-finalizes only under the existing postconditions (end path, end
anchors, `conservative/3`); a replayed tool call is subject to the same
settlement and eviction as a replayed verb. This keeps the incident guarantees
(TesterArmy cache rollout, 2026-09): no self-finalize without a verification
step, unique-match relocation, staged writes, eviction of implicated entries.

### Reporting and spec

- `report-v1` records the tool call's tier and redacted `detail`, beside verbs.
- Spec 10 (determinism) and 16 (executors) document the tiers and the
  located/fixed-model replay contract; conformance gains
  `TOOL-REPLAY-LOCATED-001` and `TOOL-REPLAY-FIXED-MODEL-001`. `suiteVersion`
  bumps (schema change).

## Phasing

1. **Annotation + validation.** Widen `ToolReplay`, accept the string sugar,
   validate `locate` paths against the input schema and `fixed-model` against
   `mutates`. No replay behavior yet; a `located`/`fixed-model` tool runs live
   (as `none` does) until phase 2. Self-contained, shippable, unblocks hosts
   declaring the real tiers.
2. **Located replay.** Record tool calls with descriptor substitution; relocate
   and re-fire on replay. Reuses the verb relocator and settlement.
3. **Fixed-model replay.** The bounded single-call tier.

Slice A of the TesterArmy port (act/assert) needs none of this. Slice B needs
phases 1–2 for the located vision-click and the located custom tools; phase 3
for the vision assertion. Each phase is independently shippable.

## Alternatives considered

- **Leave tools at `deterministic | none`.** Full-vocabulary replay then always
  spends live model calls for vision tools and cannot re-point located tools;
  the trace cache's value drops sharply for any suite beyond the grammar.
- **A host-side tool cache** (what TesterArmy has today, `cache-step-executor`).
  The incident showed why the harness must own replay: a host cache
  self-finalized without verification and replayed ordinals onto the wrong row.
  These tiers move that classification into the harness where the settlement,
  relocation, and eviction guarantees already live.
