A test file registers tests when it is imported. Everything runs in declaration
order, and nothing needs to be exported.

```ts title="tests/todos.e2e.ts"
import { test, expect } from 'e2e';

test.describe('todos', { tags: ['todos'] }, () => {
  test.beforeEach(async ({ app }) => {
    await app.open('/todos');
  });

  test('adds a todo', async ({ screen }) => {
    await screen.getByLabel('New todo').fill('Write docs');
    await screen.getByRole('button', { name: 'Add' }).tap();

    await expect(screen.getByTestId('todo')).toHaveCount(1);
  });
});
```

## Finding things

Queries are semantic. Prefer the one a user would recognize: a role and its
accessible name first, a label second, a test ID when nothing else is stable.

```ts
screen.getByRole('button', { name: 'Sign in' });
screen.getByLabel('Email');
screen.getByPlaceholder('Tell us about yourself');
screen.getByText('Design review', { exact: true });
screen.getByDisplayValue('prefilled-value');
screen.getByTestId('todo');
```

A query is a value, not an action. Building one touches nothing; every action and
read resolves it again from scratch.

```ts
const save = screen.getByRole('button', { name: 'Save' }); // no work yet
await save.tap();                                          // resolves now
```

### Exactly one match

An action or read requires exactly one match. Two matches is an error, because a
silent first-match is how a test starts passing for the wrong reason. Narrow it
explicitly:

```ts
await screen.getByTestId('todo').first().tap();
await screen.getByTestId('todo').nth(2).tap();
await screen.getByRole('listitem').filter({ hasText: 'Design review' }).tap();
```

A locator can also scope further queries, which is the cleanest way to say "the
button inside this row":

```ts
const row = screen.getByRole('listitem').filter({ hasText: 'Design review' });
await row.getByRole('button', { name: 'Archive' }).tap();
```

## Acting

```ts
await screen.getByLabel('Full name').fill('Ada Lovelace');
await screen.getByLabel('Team').selectOption('Web');
await screen.getByLabel('Email notifications').check();
await screen.getByRole('button', { name: 'Save profile' }).tap();
await screen.getByLabel('Attachment').setInputFiles('fixtures/attachment.txt');
await screen.getByText('Design review').dragTo(screen.getByLabel('Done column'));
```

Actions wait for the target to be actionable before they run. File paths resolve
from your project root.

Gestures work the same way everywhere:

```ts
await screen.getByTestId('card').longPress({ durationMs: 800 });
await screen.swipe({ direction: 'up', momentum: 'fast' });
await screen.scrollUntilVisible(screen.getByRole('button', { name: 'Accept' }));
```

The full list of actions and reads is in the
[screen and Locator reference](/reference/screen).

## Asserting

`expect` behaves differently depending on what you give it, and the difference
matters.

<CodeBlocks>
```ts title="Locator - polls"
await expect(screen.getByRole('status')).toHaveText('2 remaining');
await expect(screen.getByTestId('todo')).toHaveCount(3);
await expect(screen.getByLabel('Two')).toBeChecked();
await expect(screen.getByText('Two')).toBeHidden();
```
```ts title="web - polls"
await expect(web).toHaveURL('/dashboard');
await expect(web).toHaveTitle(/Playground/);
```
```ts title="Value - immediate"
const value = await screen.getByLabel('Full name').inputValue();
expect(value).toBe('Grace');
expect(names).toEqual(['Ada', 'Grace']);
```
</CodeBlocks>

Locator and `web` assertions retry until they pass or the assertion timeout
expires (5 seconds by default, or `{ timeout }` per call). Value assertions are a
single comparison.

<Callout intent="warning" title="Reads do not retry">
`locator.textContent()` and friends take one reading of the current state. If you
find yourself asserting on a read, use the matcher instead - it is the version
that waits.

```ts
await expect(screen.getByRole('status')).toHaveText('loaded 3'); // waits
expect(await screen.getByRole('status').textContent()).toBe('loaded 3'); // races
```
</Callout>

Negate anything with `.not`:

```ts
await expect(screen.getByLabel('Weekly digest')).not.toBeChecked();
```

## Hooks

```ts
test.beforeAll(async ({ platform }) => { /* once per group */ });
test.beforeEach(async ({ app }) => { await app.open('/todos'); });
test.afterEach(async ({ web }) => { /* after every test */ });
test.afterAll(async () => { /* once per group */ });
```

`beforeEach` runs outside-in, `afterEach` inside-out. `afterEach` still runs when
the test failed, so cleanup is reliable.

`beforeAll` and `afterAll` only receive `{ platform }`. They run once for a whole
group, so they must not touch a browser that belongs to a single test.

## Grouping and options

```ts
test('checks out', { tags: ['billing'], retries: 2, timeout: 60_000 }, async ({ app }) => {
  // ...
});

test.describe('billing', { tags: ['billing'] }, () => { /* ... */ });
test.skip('not ready yet', async () => {});
test.only('just this one while I work', async () => {});
```

| Option | Meaning |
| --- | --- |
| `timeout` | test deadline in ms, default 120000 |
| `retries` | extra attempts after a failure |
| `tags` | filter with `--tag`; unions with group tags |
| `skip` | `true` or a reason string |
| `only` | run just this test locally; rejected in CI |
| `session` | reuse state from a setup test, see [Authentication](/authentication) |
| `platforms` | limit which targets run this test |
| `requires` | required capabilities, e.g. `['web']` |
| `agentContext` | extra context for `agent.*` calls in this test |

Options on a group apply to its tests. `timeout`, `retries`, `platforms`,
`requires`, and `session` are replaced by the inner value; `tags` are unioned;
`agentContext` is concatenated; a `skip` anywhere wins.

### Serial groups

By default each test is independent and gets clean state. When a flow genuinely
must span several tests, make the group serial:

```ts title="tests/wizard.e2e.ts"
test.describe('workspace wizard', { serial: true }, () => {
  let chosenPlan = '';

  test('step 1: name the workspace', async ({ app, screen }) => {
    await app.open('/wizard');
    await screen.getByLabel('Workspace name').fill('Rocketry');
    await screen.getByRole('button', { name: 'Next' }).tap();
  });

  test('step 2: pick a plan', async ({ screen }) => {
    await screen.getByLabel('Plan').selectOption('Pro');
    chosenPlan = 'Pro';
    await screen.getByRole('button', { name: 'Next' }).tap();
  });

  test('step 3: confirm', async ({ screen }) => {
    await screen.getByRole('button', { name: 'Create workspace' }).tap();
    await expect(screen.getByRole('status')).toHaveText(
      `Created "Rocketry" on the ${chosenPlan} plan`,
    );
  });
});
```

Members share one app state, run on one worker in order, and retry as a whole
from the first member. Because they are one unit, per-test `retries`, `session`,
`skip`, and `only` are not allowed inside a serial group.
