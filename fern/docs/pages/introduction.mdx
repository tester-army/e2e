Write a test as goals and checks. An agent drives the app; your code stays in
charge of what counts as passing.

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  // Pin the check that must never drift:
  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

That is the whole framework. `agent.act` plans and executes a flow.
`agent.assert` answers one question about the screen. `expect` and
`screen.getBy*` are the escape hatch when a step is too important to leave to
a model — same test, same file, your choice per line.

## Why this shape

**Resilient by default, exact where you say so.** A scripted suite breaks when
the UI moves; an autonomous one passes for reasons you can't review. Here every
line picks its own point on that dial: draft with `agent.act` while the feature
changes shape, then pin the steps and assertions that matter to `screen` and
`expect` — free, deterministic, and model-independent.

**Bounded and honest.** Every `agent.*` call has a deadline and a model-call
budget; nothing loops forever. Each planned step ends in a ternary verdict —
**passed**, **failed**, or **blocked**. Blocked means credentials, seed data,
or the environment prevented a product verdict: it exits as an
infrastructure signal, not a red test, so trust in red survives.

**Secrets never meet the model.** A password is an opaque handle. Hand it to
`agent.act` and the model sees only its name; the runner fills the field
itself, under the same policy as a deterministic `fill`.

**Yours to extend.** The brain behind `agent.act` is a socket. Add project
tools to the built-in agent, keep its loop with your own tool vocabulary — a
device toolkit, an internal API — or replace it with anything that takes a step
and returns a verdict. Budgets, redaction, and the report don't change.

**Local first.** No account, no hosted service. `npx e2e run` is the same code
path on your laptop and in CI, the report is a JSON file, and a suite with no
`agent.*` calls needs no model at all.
