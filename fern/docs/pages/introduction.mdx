You write tests in simple TypeScript, and you define the agent that executes
them. e2e ships no intelligence of its own: the runner owns safety, budgets,
secrets, and the report. The thinking is yours to control.

```ts title="e2e.config.ts"
import { defineConfig } from '@e2edev/e2e';
import { createAgent } from '@e2edev/e2e/agent';
import { playwright } from '@e2edev/playwright';

export default defineConfig({
  app: { url: 'http://localhost:3000' },
  targets: [{ name: 'web', platform: 'web', backend: playwright() }],
  agent: createAgent({
    system: 'You are a thorough QA agent. Verify every outcome on screen.',
  }),
});
```

```ts title="tests/checkout.e2e.ts"
import { test, expect } from '@e2edev/e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  // A deterministic check for the part that must not drift:
  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

`agent.act` executes a goal. `agent.assert` answers a question about the
screen. When a step or a check is too important to leave to a model, `screen`
and `expect` do exactly what they say, for free.

## What you get

**You control the agent.** `createAgent()` is the built-in one. Give it your
own tools, keep its loop with a different tool vocabulary (a device toolkit, an
internal API), or replace it with anything that takes a step and returns a
verdict. None of that changes the runner's side of the contract: observations
stay redacted, harness actions stay policed, and model budgets and the step
deadline stay enforced.

**Every call is bounded.** An `agent.*` call has a deadline and a model-call
budget. A planned step ends in one of three verdicts: **passed**, **failed**,
or **blocked**, meaning something prevented a verdict about your app. A credential,
environment, or seed-data block exits as configuration or infrastructure
rather than as a failing test, so red keeps meaning "the product misbehaved".

**Secrets never reach a model.** A password is an opaque handle. Pass it to
`agent.act` and the model sees its name only; the runner fills the field
itself.

<Callout intent="note" title="Three backends">
This release ships `@e2edev/playwright` for browsers,
[`@e2edev/agent-device`](/reference/device) for iOS simulators and Android
emulators, and [`@e2edev/tmux`](/reference/terminal) for CLIs and TUIs in a
terminal. The API and the runner are platform-neutral: the same test runs on
both, and a surface neither covers plugs in as a
[backend](/writing-a-backend) of its own.
</Callout>
