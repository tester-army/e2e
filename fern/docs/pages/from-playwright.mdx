---
title: Coming from Playwright
subtitle: What maps over, and what changed on purpose.
---

e2e uses Playwright as its backend, not as its API. The concepts you already know
transfer; the object model does not. A Playwright object never appears in an e2e
test, because a test that touches `page` is no longer portable.

## The shape of a test

<CodeBlocks>
```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('member signs in', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('ada@example.test');
  await page.getByRole('button', { name: 'Sign in' }).click();
  await expect(page).toHaveURL('/dashboard');
});
```
```ts title="e2e"
import { test, expect } from 'e2e';

test('member signs in', async ({ app, screen, web }) => {
  await app.open('/login');
  await screen.getByLabel('Email').fill('ada@example.test');
  await screen.getByRole('button', { name: 'Sign in' }).tap();
  await expect(web).toHaveURL('/dashboard');
});
```
</CodeBlocks>

One `page` becomes three fixtures, split by portability:

| Fixture | Scope |
| --- | --- |
| `screen` | Queries and actions - portable to any platform |
| `app` | Lifecycle: `open`, `restart`, `clearState`, `back`, `deepLink`, `screenshot` |
| `web` | The browser capability: URLs, routes, cookies, dialogs, frames, `evaluate` |

Anything under `web` is web-only by construction, so you can see at a glance
which parts of a test could ever run on a phone.

## Queries and actions

| Playwright | e2e |
| --- | --- |
| `page.getByRole/getByLabel/getByPlaceholder/getByText/getByTestId` | `screen.getBy*`, same semantics |
| `page.getByAltText`, `getByTitle` | no direct API - use role plus name, or text |
| `page.locator('css')`, `page.locator('xpath=…')` | `web.locator(selector)` |
| `locator.filter({ hasText, has })`, `.first()`, `.last()`, `.nth(i)` | identical |
| `click()` | `tap()`, with `click()` as an alias |
| `dblclick()` | `doubleTap()` |
| `fill`, `clear`, `press`, `check`, `uncheck`, `focus`, `hover`, `dragTo`, `selectOption`, `setInputFiles` | same names |
| `scrollIntoViewIfNeeded()` | `scrollIntoView()` |
| `locator.textContent/inputValue/getAttribute/isVisible/isEnabled/isChecked/boundingBox/count` | identical |
| `page.frameLocator(sel)` | `web.frameLocator(sel)`, returns a `Screen` |
| `page.keyboard`, `page.mouse` | `web.keyboard`, `web.mouse` |

## Assertions

`expect` has three overloads instead of one universal matcher set:

```ts
await expect(screen.getByRole('status')).toContainText('Pro');  // locator, polls
await expect(web).toHaveURL('/dashboard');                     // web, polls
expect(await locator.count()).toBe(2);                         // value, immediate
```

Deliberately absent: `toHaveClass`, `toHaveAttribute`, `toHaveCSS`. Those assert
on implementation details rather than on what a user can perceive, and they do not
survive a platform change. Use roles, names, states, and text.

Polling assertions use `assertionTimeout`, 5 seconds by default, not the action
timeout.

## Configuration

| Playwright | e2e |
| --- | --- |
| `playwright.config.ts` `projects` | `targets` |
| `webServer` | `app.command` |
| `baseURL` | `app.url` |
| `storageState` files | `test.setup` plus `session.save(name)` plus `{ session: name }` |
| `test.describe.serial` | `test.describe(title, { serial: true }, …)` |
| `test.beforeEach/afterEach/beforeAll/afterAll` | identical names |
| `test.step` | no direct API - steps are derived from what you call |
| `test.extend` custom fixtures | not available |
| `--grep` | `--tag` and `--tag-mode`, plus positional file paths |
| `retries`, `workers`, `--headed` | identical names |
| trace viewer | `artifacts: ['trace']`, then `npx playwright show-trace` |
| HTML report | `.e2e/report.json` or `--reporter json` |

Sessions are per-run and encrypted, not committed files on disk. See
[Authentication](/authentication).

## Behavioral differences to expect

<AccordionGroup>
  <Accordion title="Strictness was never optional">
    A query that matches two nodes fails. There is no `strict: false`. Be
    explicit with `.filter()`, `.first()`, or `.nth()`.
  </Accordion>
  <Accordion title="Reads do not retry; assertions do">
    `await locator.textContent()` takes one reading.
    `await expect(locator).toHaveText(...)` polls. If you find yourself asserting
    on a read, you wanted the matcher.
  </Accordion>
  <Accordion title="The runner owns waiting">
    Timeouts, polling, actionability, and retry policy come from e2e config. A
    Playwright default cannot change your suite's behavior.
  </Accordion>
  <Accordion title="Locators are immutable values">
    Building one performs no I/O. Every action or read re-resolves it, and no
    element handle crosses a step boundary.
  </Accordion>
  <Accordion title="evaluate is constrained">
    `web.evaluate(fn, arg?)` takes at most one JSON-safe argument and must return
    a JSON-safe value. It is trusted test code, not a general escape hatch.
  </Accordion>
  <Accordion title="Navigation is confined to allowed origins">
    Navigation outside `app.url` plus `app.allowedOrigins` is denied with
    `POLICY_DENIED`, and production needs `allowProduction: true`. See
    [Web capabilities](/web).
  </Accordion>
</AccordionGroup>

## Not available yet

- multi-page contexts and popups
- custom fixtures and custom reporters
- `test.each`, sharding, watch mode, UI mode, codegen
- element screenshots, visual diffing, clock control, HAR replay
- component testing
- video artifacts
- API-request testing without a browser

If a flow needs one of these, keep it in your existing suite. Porting is meant to
be incremental: convert your auth bootstrap first, then read-only smoke tests,
then the flows that keep breaking on selectors.
