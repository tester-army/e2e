title: Testing iOS and Android
description: Set up a simulator or emulator target, write a device test, and know what differs from the web.

`@e2edev/agent-device` runs tests on iOS simulators and Android emulators.
Tests use the same `agent`, `screen`, and `expect` APIs as browser tests.
Each attempt starts in the configured app.

## Set up

Install Xcode with an iOS simulator runtime, or the Android SDK with an
emulator. Check your setup with:

```bash
npx agent-device doctor
```

Follow the [Quickstart](/quickstart) and choose **Mobile (iOS/Android)**.
The wizard selects iOS on macOS and Android elsewhere. It starts with the
Settings app and one worker:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { agentDevice } from '@e2edev/agent-device';

export default {
  // Replace Settings with your app's bundle id.
  targets: [{ name: 'ios', engine: agentDevice({ platform: 'ios', app: 'Settings' }) }],
  workers: 1,
} satisfies E2EConfig;
```

The runner boots the device before test timing starts. Boot time does not
count toward `launchTimeout`.

## Point at your app

Replace `Settings` with your app's bundle id or package name. Setting `app`
opens it at the start of each attempt and enables `app.restart()` and
`app.clearState()`. Add `appPath` to install a build first:

```ts
agentDevice({
  platform: 'ios',
  app: 'com.example.app',
  appPath: process.env.E2E_APP_PATH, // path to the iOS .app bundle
})
```

The build is installed once per worker. Use an `.app` bundle for iOS or an
`.apk` for Android. Optional values accept `undefined`, so environment
variables can be passed directly.

Without `app`, the engine uses whichever app is in the foreground. Set it
when possible so attempts start consistently and cached steps can replay.

## Several devices

Add a target for each platform:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { agentDevice } from '@e2edev/agent-device';

const iphone = agentDevice({ platform: 'ios', app: 'com.example.app' });
const pixel = agentDevice({ platform: 'android', app: 'com.example.app' });

export default {
  targets: [
    { name: 'iphone', engine: iphone },
    { name: 'pixel', engine: pixel },
  ],
  workers: 1,
} satisfies E2EConfig;
```

Tests run on both targets. Use `platforms: ['ios']` or
`platforms: ['android']` for tests with platform-specific labels or behavior.

To run files in parallel, provide a device pool and set `workers` to at
least the pool's size. Each device gets one worker:

```ts
agentDevice({ platform: 'ios', app: 'com.example.app', device: ['iPhone 17', 'iPhone 17 Pro'] })
```

Without `device`, the engine uses booted devices up to the worker limit.
If none are booted, it boots one. Two workers never drive the same device.

## Hosted simulators

A `device` can also be a `DeviceProvider`: an object that leases one hosted
device per worker slot when the run starts and releases it when the run
ends. The engine drives each lease through the agent-device daemon the lease
names instead of the local one, so any service that exposes an agent-device
daemon works: Expo's EAS Simulator, a device farm, or a Mac in your own rack.
Nothing in the framework knows a vendor; a provider is a few dozen lines in
your config.

```ts
export interface DeviceProvider {
  /** Label in progress lines and the report. */
  readonly name: string;
  /** Called once per worker slot, for every slot at once, in the runner process. */
  acquire(request: DeviceRequest): Promise<DeviceLease>;
  /** Called once per lease when the run ends, on every exit path. */
  release(lease: DeviceLease, context: DeviceReleaseContext): Promise<void>;
}

export interface DeviceLease {
  /** The provider's handle (a session id), handed back to `release`. */
  readonly id: string;
  /** The agent-device daemon the worker connects to. */
  readonly daemon: { readonly baseUrl: string; readonly authToken?: string };
  /** Device to select inside that daemon, when it hosts more than one. */
  readonly device?: string;
  /** Bundle id or package the provider installed itself; skips `appPath`. */
  readonly installedApp?: string;
}
```

`acquire` receives the platform, run id, target, slot, the `app` and resolved
`appPath` options, the run's environment, an interrupt signal, and a `log`
that reaches the reporter. Read tokens from `request.env`, not
`process.env`. A slot that fails to lease releases the others and ends the
run before any test runs. Leases are released after the last worker exits,
also on failure and interrupt, within `cleanupTimeout`.

The provider below runs tests on
[EAS Simulator](https://docs.expo.dev/preview/eas-simulator/rest-api/)
sessions. Each session installs an EAS build; set `app` to the build's bundle
id so every attempt opens it.

```ts title="eas-simulator.ts"
import type { DeviceLease, DeviceProvider, DeviceRequest } from '@e2edev/agent-device';

const API = 'https://api.expo.dev/v2/device-run-sessions';

interface Session {
  id: string;
  status: string;
  remoteConfig: {
    agentDeviceRemoteSessionUrl: string;
    agentDeviceRemoteSessionToken?: string;
    webPreviewUrl?: string;
  } | null;
}

async function expo<T>(token: string, path: string, init: RequestInit = {}): Promise<T> {
  const response = await fetch(`${API}${path}`, {
    ...init,
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json', ...init.headers },
  });
  if (!response.ok) throw new Error(`EAS Simulator ${init.method ?? 'GET'} ${path}: HTTP ${response.status}`);
  return ((await response.json()) as { data: T }).data;
}

/** Leases one EAS Simulator session per worker slot, with the given EAS build installed. */
export function easSimulator(options: { appId: string; buildId: string; device?: string }): DeviceProvider {
  const token = (env: DeviceRequest['env']): string => {
    const value = env['EXPO_TOKEN'];
    if (value === undefined || value === '') throw new Error('EXPO_TOKEN is not set');
    return value;
  };
  return {
    name: 'eas-simulator',
    async acquire(request) {
      const created = await expo<Session>(token(request.env), '', {
        method: 'POST',
        body: JSON.stringify({
          appId: options.appId,
          platform: request.platform,
          type: 'agent-device',
          buildId: options.buildId,
          name: `${request.runId} ${request.targetName} ${request.slot + 1}/${request.slots}`,
          ...(options.device === undefined ? {} : { deviceIdentifier: options.device }),
        }),
      });
      let session = created;
      while (session.status === 'new' || session.remoteConfig === null) {
        if (session.status !== 'new' && session.status !== 'in-progress') {
          throw new Error(`EAS Simulator session ${session.id} is ${session.status}`);
        }
        await new Promise((resolve) => setTimeout(resolve, 5_000));
        if (request.signal.aborted) throw new Error('interrupted while the simulator was starting');
        session = await expo<Session>(token(request.env), `/${session.id}`);
      }
      const { agentDeviceRemoteSessionUrl, agentDeviceRemoteSessionToken, webPreviewUrl } = session.remoteConfig;
      if (webPreviewUrl !== undefined) request.log(`watch at ${webPreviewUrl}`);
      return { id: session.id, daemon: { baseUrl: agentDeviceRemoteSessionUrl, authToken: agentDeviceRemoteSessionToken } };
    },
    async release(lease: DeviceLease, context) {
      await expo(token(context.env), `/${lease.id}/stop`, { method: 'POST' });
    },
  };
}
```

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { agentDevice } from '@e2edev/agent-device';
import { easSimulator } from './eas-simulator.ts';

export default {
  targets: [
    {
      name: 'ios',
      engine: agentDevice({
        platform: 'ios',
        app: 'com.example.app',
        device: easSimulator({ appId: process.env.EAS_APP_ID!, buildId: process.env.EAS_BUILD_ID! }),
      }),
    },
  ],
  workers: 2,
} satisfies E2EConfig;
```

Two workers lease two sessions in parallel. Sessions are billed while they
run, so keep `workers` at what the suite can fill. The trace cache keys on
`app`, so traces recorded locally replay on hosted devices.

## Writing a device test

`screen` maps native controls to common roles such as `button`, `textbox`,
`listitem`, and `switch`. Use `getByTestId` for native element identifiers.

```ts
import { test } from '@e2edev/agent-device';
import { expect } from 'e2e';

test('shows the version offline in dark mode', async ({ agent, device, screen }) => {
  await device.setAppearance('dark');
  await device.setNetwork('offline');
  await agent.act('go to General, then About');
  await expect(screen.getByRole('button', { name: /^iOS Version/ })).toBeVisible();
  await expect(device.locator('role=NavigationBar id=About')).toBeVisible();
});
```

`selectOption`, `setInputFiles`, and `scrollIntoView` are unsupported on
devices. Use taps and swipes to interact with native controls.

### The `device` fixture

Use `device` to manage network state, permissions, appearance, app installs,
and other device settings without a model call. Each call appears as a
`device.<method>` step in the report.

`device.locator('...')` accepts an agent-device selector for controls that
`screen` queries cannot identify:

```ts
await expect(device.locator('role=NavigationBar id=About')).toBeVisible();
await device.locator('id=SW_VERSION_SPECIFIER role=Button').tap();
```

Use `device.installApp` within a test to check upgrades or fresh installs:

```ts
const { app } = await device.installApp('./build/MyApp.app', { reinstall: true });
await device.openApp(app);
```

Every method is in the [agent-device reference](/reference/agent-device#device).

### Agent tools

The agent already has basic actions such as `tap`, `type`, and `scroll`.
Add `agentDeviceTools` for app switching, device gestures, and system alerts:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { createAgent } from 'e2e/agent';
import { agentDevice } from '@e2edev/agent-device';
import { agentDeviceTools } from '@e2edev/agent-device/tools';
import { gateway } from 'ai';

const iphone = agentDevice({ platform: 'ios', app: 'com.example.app' });
const pixel = agentDevice({ platform: 'android', app: 'com.example.app' });

export default {
  targets: [
    { name: 'iphone', engine: iphone },
    { name: 'pixel', engine: pixel },
  ],
  workers: 1,
  agents: {
    default: createAgent({
      model: gateway('openai/gpt-5.6-luna'),
      tools: agentDeviceTools(iphone, pixel),
    }),
  },
} satisfies E2EConfig;
```

Pass each configured device engine to `agentDeviceTools`. Calls go to the
engine running the current attempt. Tools that change device state require
the agent to take over during cache replay; the read-only `screenshot` tool
does not interrupt replay.

## What differs from the web

| On the web | On a device |
| --- | --- |
| `app.open('/path')` and the agent's `navigate` verb | No URL. The attempt starts in the pinned `app`; there is no `navigate` |
| `test.setup` saves a session, `session:` restores it | Not available. A simulator has no portable session snapshot; sign in per test or seed the app |
| Secret input | `type_secret` and `screen.getByLabel(...).fill(secret)` fill declared secrets into secure fields |
| Playwright trace per attempt | No Playwright trace; screenshots mask secure fields |
| `--video` writes a WebM screencast | `--video` writes an MP4 of the device screen with taps shown |
| The cache anchors on the page path | The cache anchors on the location `<bundle id> / <screen title>`, the title read off the navigation bar |
