[Lightpanda](https://lightpanda.io) is an open-source headless browser
written from scratch, without Chromium. It starts in milliseconds, holds a
fraction of Chrome's memory, and speaks the Chrome DevTools Protocol, so the
web engine attaches to it with `connect` and nothing else changes: tests,
`e2e run`, and CI stay the same. No extra package is needed.

Lightpanda has no layout engine. It builds the DOM, runs JavaScript, and
exposes the accessibility tree the engine reads, which is what locators,
assertions, and [agent steps](/agent-steps) use. Anything that depends on
where a node is painted behaves differently; see
[What does not work](#what-does-not-work) before moving a suite over.

## Setup

Install the nightly binary:

<CodeGroup>
```bash macOS
brew install lightpanda-io/browser/lightpanda
```

```bash Linux
curl -L -o lightpanda https://github.com/lightpanda-io/browser/releases/download/nightly/lightpanda-x86_64-linux
chmod a+x ./lightpanda
```

```bash Docker
docker run -d --name lightpanda -p 127.0.0.1:9222:9222 lightpanda/browser:nightly
```
</CodeGroup>

Start its CDP server, the `serve` command, before the run; the Docker image
starts it on its own:

```bash
lightpanda serve --host 127.0.0.1 --port 9222
```

Point the target's `connect` at the server:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [
    {
      name: 'lightpanda',
      engine: web({ connect: { cdpEndpoint: () => 'ws://127.0.0.1:9222/' } }),
      app: { url: 'http://localhost:3000' },
    },
  ],
} satisfies E2EConfig;
```

`cdpEndpoint` can also read the address from the environment, so one config
runs against a local binary and a container in CI:

```ts
web({ connect: { cdpEndpoint: () => process.env.LIGHTPANDA_URL ?? 'ws://127.0.0.1:9222/' } })
```

Every worker attaches to the same server and gets its own browser context
there, so `workers` sets how many tests run at once. One `lightpanda serve`
takes 16 connections by default; raise `--cdp-max-connections` above
`workers` when you run more.

## What works

Against the e2e testbed's local suite on a Lightpanda nightly from October
2026, these pass unchanged:

- `app.open`, `app.back`, and `expect(browser).toHaveURL` and `toHaveTitle`.
- Every `screen` query (`getByRole`, `getByLabel`, `getByText`,
  `getByTestId`, filters, `nth`) and the actions on them: `tap`, `fill`,
  `check`, `select`, `press`, and keyboard input.
- Polling assertions on text, value, count, and state.
- `browser.route` mocks and request waits.
- `browser.setCookies` from a test, after a page is open.
- `app.screenshot` and the screenshot of a failure. Lightpanda paints a plain
  render of the DOM, not the page as Chrome would show it.
- Agent steps: `agent.act` and `agent.extract` read the screen tree, which
  Lightpanda provides in full. A judgment on pixels sees the plain render,
  so keep the agent on the tree.

A test that asserts on what the user sees, not where it is drawn, moves
over as is.

## What does not work

Each of these fails the test with the engine's usual error, not a hang. The
reasons are Lightpanda's, and its
[Playwright compatibility issue](https://github.com/lightpanda-io/browser/issues/3076)
tracks most of them.

| Feature | What happens | Why |
| ------- | ------------ | --- |
| [Sessions](/authentication) (`test.setup` with `session.save`, `session:` on a test) | The setup passes and the session is saved, but a test that restores it opens signed out. | Cookies set on a context before its first page exists are dropped. Set them from the test with `browser.setCookies` after `app.open` instead. |
| [Dialogs](/browser#handle-a-dialog) | `browser.onDialog` runs, then fails the test with `ENGINE_FAILURE`: `Page.handleJavaScriptDialog` reports no dialog. | Lightpanda answers `alert`, `confirm` (`false`), and `prompt` (`null`) itself before a client can. |
| [Downloads](/browser#download-a-file) | `browser.waitForDownload` times out. | No download events over CDP. |
| [Iframes](/browser#reach-into-an-iframe) | `frameLocator` finds nothing. | Iframes are not loaded by default. `lightpanda serve --load-resources iframe` loads them; queries and fills then work, but a listener in the host page on an element the frame created does not fire. |
| Drags: `screen.swipe`, `locator.swipeTo`, and `browser.mouse` moves with a button down | `ENGINE_FAILURE` naming `Input.setInterceptDrags`. | Playwright needs that command for a drag and Lightpanda has not implemented it. |
| `browser.setViewport` | The page measures the new size, but a `resize` listener never runs. | No `resize` event is dispatched. |
| Scrolling: `scrollIntoView`, `scrollUntilVisible`, and an action on a node "outside of the viewport" | The scroll is a no-op, and an actionability wait can time out. | Without layout there is no scroll position to move. |
| `browser: 'firefox'` or `'webkit'` | `INVALID_CONFIG`. | `connect` is CDP, and CDP attach is chromium-only. |

A Lightpanda release that closes one of these makes the row above go away
with no change on the e2e side; the engine sends the same CDP commands it
sends Chrome.

## Fetch more of the page

`lightpanda serve` requests no sub-resources by default: no images, no
external stylesheets, no iframes. `--load-resources` opts into each, and
can be passed more than once:

```bash
lightpanda serve --load-resources stylesheet --load-resources iframe
```

Inline styles, `<style>` blocks, and the `hidden` attribute already decide
visibility; `stylesheet` makes an external file's rules count too, so a
node a linked stylesheet hides is hidden to a query. `image` fetches image
headers so `load` and `error` reflect the real status.

## Where it fits

Lightpanda suits a suite that is heavy on the agent's reading of the screen
and light on geometry: smoke flows, forms, navigation, API-backed pages, and
`agent.act` steps whose checks are text and state. It runs that suite in a
fraction of Chrome's time and memory, on a box with no Chrome installed.

Keep a Chromium target for the rest, and select by target when both are in
one config:

```bash
e2e run --target lightpanda
e2e run --target chromium
```
