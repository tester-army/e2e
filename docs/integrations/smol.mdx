`smol()` from `@e2e-dev/smol` is a
[browser provider](/browser#hosted-browsers) that runs Chromium in
[smol machines](https://smolmachines.com) microVMs on your computer. Each
worker slot boots one browser machine, and each test attempt gets a branch
of it or a new browser context on it, depending on the
[scope](#choose-a-scope). State on your computer or in external services
stays shared.

## Set up the provider

<Note>
smol machines run on macOS on Apple Silicon, or on Linux with KVM
(`/dev/kvm`). They need no account or API key. The first boot pulls the
Playwright Ubuntu image, which carries Chromium, so it takes longer.
</Note>

Install the provider and the smol machines SDK:

<CodeGroup>
```bash npm
npm install --save-dev @e2e-dev/smol smolmachines
```

```bash pnpm
pnpm add -D @e2e-dev/smol smolmachines
```

```bash bun
bun add -d @e2e-dev/smol smolmachines
```
</CodeGroup>

Set the target's `browser` to `smol()`:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { smol } from '@e2e-dev/smol';

export default {
  targets: [
    {
      name: 'web',
      engine: web({ browser: smol({ hostPorts: [3000] }) }),
      app: {
        url: 'http://localhost:3000',
        command: { executable: 'npm', args: ['run', 'dev'] },
      },
    },
  ],
  workers: 4,
} satisfies E2EConfig;
```

In the machine, `localhost` is the machine itself. `hostPorts` lists ports
on your computer that the browser reaches as its own `localhost`, so
`app.url` stays `http://localhost:3000`.

<Warning>
`hostPorts` isn't an allowlist. The machine can reach any loopback port on
your computer through `host.smolvm.internal`, and it has unrestricted
outbound network access. Stop sensitive loopback services before you test
an untrusted app with `smol()`.
</Warning>

## Start every test signed in

`prepare` drives each warm browser one time, before any attempt branches
it. Every attempt on that slot starts with the cookies, storage, and pages
it left. It replaces [sessions](/authentication), which `'attempt'` scope
can't use.

`prepare` gets the browser's DevTools endpoint. Work in the default context,
where attempts run. Disconnect before `prepare` resolves, and leave the
browser running.

<Accordion title="Sign in with a session cookie">
Any CDP client works. This example signs in over HTTP and hands the session
cookie to the browser with `Storage.setCookies`, using only Node's `fetch`
and `WebSocket`:

```ts title="Provider options"
smol({
  hostPorts: [3000],
  prepare: async (cdpEndpoint) => {
    const login = await fetch('http://localhost:3000/api/login', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ email: 'qa@example.com', password: process.env.QA_PASSWORD }),
    });
    const [name, value] = login.headers.getSetCookie()[0]!.split(';')[0]!.split('=');
    const version = await (await fetch(`${cdpEndpoint}/json/version`)).json();
    const socket = new WebSocket(version.webSocketDebuggerUrl);
    await new Promise((resolve) => socket.addEventListener('open', resolve, { once: true }));
    const done = new Promise((resolve) => socket.addEventListener('message', resolve, { once: true }));
    socket.send(JSON.stringify({
      id: 1,
      method: 'Storage.setCookies',
      params: { cookies: [{ name, value, domain: 'localhost', path: '/', httpOnly: true }] },
    }));
    await done;
    socket.close();
  },
})
```
</Accordion>

## Run the app in the machine

With `app`, the app under test runs in each browser machine instead of on
your computer, so nothing a test or an agent makes it do runs on the host.
The machine can still reach your loopback ports, as
[Set up the provider](#set-up-the-provider) warns. In `'attempt'` scope,
each attempt gets its own copy of the running app and its files, a local
database included.

```ts title="Provider options"
smol({
  app: {
    source: '.',
    setup: 'npm ci && npm run db:seed',
    start: 'npm start',
    port: 3000,
    env: { DATABASE_URL: 'file:/app/dev.db' },
  },
})
```

Set `app.url` to `http://localhost:<port>` and declare no `app.command`.
`setup` and `start` run on every machine boot, before `prepare`.

| `app` field | Meaning |
| ----------- | ------- |
| `start`     | Required. Shell command that serves the app, run in the background in `/app`. The provider waits up to 180 seconds for the app to answer on `port`. |
| `port`      | Required. Port the app listens on inside the machine. Not 80 or 9229, which the browser uses, and not in `hostPorts`. |
| `source`    | Directory copied to `/app`, without `node_modules`, `.git`, or `.e2e`. Resolved against where the run starts. `.` by default. |
| `setup`     | Shell script run as root in `/app` before `start`. The image includes Node.js and npm, so `npm ci` installs dependencies for the machine's Linux. |
| `env`       | Environment variables for `setup` and `start`. Names must be shell variable names. |

## Choose a scope

`scope: 'attempt'`, the default, gives every attempt its own branch of the
slot's warm machine, so one test's changes to the machine, such as an app's
local database, never reach another. The attempt runs in the branched
browser's own context, with what `prepare` left. `app.clearState()` and
[sessions](/authentication) throw `UNSUPPORTED_CAPABILITY` here. Options
such as `headers` and `locale` work.

`scope: 'worker'` keeps one machine per worker slot for the run. Each
attempt gets a new browser context on it, as in a local run, so sessions
and `app.clearState()` work. Nothing is branched, and `prepare` is an
`INVALID_CONFIG`.

## Options

| Option      | Default     | Meaning |
| ----------- | ----------- | ------- |
| `scope`     | `'attempt'` | See [Choose a scope](#choose-a-scope). |
| `prepare`   | none        | See [Start every test signed in](#start-every-test-signed-in). |
| `hostPorts` | `[]`        | See [Set up the provider](#set-up-the-provider). Not 80 or 9229. |
| `app`       | none        | See [Run the app in the machine](#run-the-app-in-the-machine). |
| `setup`     | none        | Shell script run as root in each machine before Chromium starts, such as `apt-get update && apt-get install -y fonts-noto-cjk` for more fonts. |
| `cpus`      | `2`         | vCPUs per machine. |
| `memoryMb`  | `2048`      | Memory per machine in MiB. |

## What differs from a local browser

The browser's back/forward cache is off, so going back reloads the page.
`browser.waitForDownload` works as it does locally: the provider reads each
file off the machine's disk. `setInputFiles` throws
`UNSUPPORTED_CAPABILITY`.

## Clean up leftover machines

The runner deletes the run's machines when the run ends, including those of
a crashed worker. A killed runner, such as in a cancelled CI job, leaves its
`'worker'`-scope machines behind, stopped, with names that start with
`e2e-`. List and delete them with the [smol CLI](https://smolmachines.com),
for example `smol machine ls`.
