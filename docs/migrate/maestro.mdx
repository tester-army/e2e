e2e replaces Maestro's YAML flows with TypeScript tests. Each command becomes
an awaited locator call, or one agent goal covers several. Both runners can
use the same simulator or emulator while you move one flow at a time.

## Port the config

<Note>Set up a target with the [mobile guide](/mobile) and a model with the [quickstart](/quickstart).</Note>

The reference pages hold the details: [screen](/reference/screen),
[expect](/reference/expect), [test](/reference/test), and the
[mobile engine](/reference/mobile).

| Maestro | e2e | Status |
| --- | --- | --- |
| `appId` at the top of every flow | `app: { bundleId: 'com.example.app' }` on the target, the app `app.open()` launches | renamed |
| a different `appId` per flow | `device.openApp(id)` inside the test, or separate app-specific configs and runs; every test runs on every selected target | renamed |
| `--platform ios` | `mobile({ platform: 'ios' })`, one engine per platform | renamed |
| `--device` | `mobile({ device: 'iPhone 17' })`; a list is a pool, one worker per device | renamed |
| `.maestro/config.yaml` `flows` | `tests`, default `tests/**/*.e2e.ts`; Maestro runs one folder level, e2e recurses | renamed |
| `flows: ['!helper.yaml']` | a `tests` entry with a leading `!`: `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` | renamed |
| `tags` and `--include-tags` | `{ tags: [...] }` on a test or group, `--tag` on the CLI | renamed |
| `--exclude-tags` | `--exclude-tag` | renamed |
| `env` and `${VAR}` | module constants, and `params` in a goal: `agent.act('sign in as {email}', { params: { email } })` | renamed |
| `MAESTRO_*` variables | `process.env` in the config; a password or token goes under `credentials` or `secrets`, which the model never sees, see [Signing in](/authentication) | renamed |
| `--format junit`, `--output` | `--reporter list,junit`, written to `.e2e/junit.xml` | renamed |
| `--format html` | no equivalent; `markdown` writes `.e2e/summary.md`, and each failed test gets a `trace.md` page under `.e2e/results/` | missing |
| `properties` (JUnit `<property>`) | not yet | missing |
| `--shards`, `--shard-split` | `device: [...]` plus `workers` on one machine; `--shard <index/total>` across machines, see [Sharding](/ci#sharding) | renamed |
| `maestro record` | `npx e2e run --video`, one MP4 of the device per attempt, or `video` in the config | renamed |
| `maestro test -c`, Maestro Studio | not yet; `npx e2e mcp` gives a coding agent a live session on the device, see [Coding agents](/coding-agents) | missing |
| `maestro hierarchy` | not yet; `device.locator` takes agent-device selectors for nodes `screen` cannot name | missing |
| Maestro Cloud | your CI, see [Continuous integration](/ci) | by design |

## Rewrite one flow

Start with a flow whose `optional` steps and `runFlow: { when }` branches
often need updating.

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

A flow can also stay fully deterministic, with a `screen.getBy*(...).tap()`
line for every `tapOn`.

## Map each command

`Status` is `renamed`, `device only`, `by design`, or `missing` with what to
do today. Calls on `device` run only on a device, so a test that uses it
declares `requires: ['device']` and other targets skip it. Calls on `screen`,
`app`, `agent`, and `expect(locator)` run on every target.

## Rewrite selectors

Four differences from Maestro's selectors cause most edits.

- Maestro reads text and id as regular expressions, so `tapOn: ".*Save.*"`
  matches any text with Save in it. `getByText` and `getByTestId` match the
  whole string. Write `getByText(/Save/)` or `getByTestId(/^row-/)` for a
  pattern, or `{ exact: false }` for a case-insensitive substring of text.
- Maestro taps the first of several matches. e2e fails with
  `LOCATOR_AMBIGUOUS`, so write `.first()` when the first match is what you
  mean.
- `isVisible()`, the check that replaces `optional` and `runFlow: { when }`,
  is `false` on zero matches and `LOCATOR_AMBIGUOUS` on several. Add
  `{ visible: true }` to the query or `.first()` when a hidden twin may exist.
- `below`, `above`, `leftOf`, `rightOf`, and `containsDescendants` have no
  port. e2e has `filter({ has, hasText })` and chaining for structure, and
  nothing spatial. Use `getByLabel`, a test id, or a goal:
  `agent.act('enter {email} in the email field', { params })` finds the field.

## What differs on purpose

- No agent-device client in tests. `device.locator` covers platform-specific
  selectors. Everything else goes through `screen`, `app`, `device`, and the
  agent, so it is recorded and redacted.
- No `test.setup` or `session:` on a device, see
  [what differs from the web](/mobile#what-differs-from-the-web).
