e2e replaces Maestro's YAML flows with TypeScript tests. Each command becomes
an awaited call, usually on a locator, or one agent goal covers several. Both runners can
use the same simulator or emulator while you move one flow at a time.

## Port the config

<Note>Set up a target with the [mobile guide](/mobile) and a model with the [quickstart](/quickstart).</Note>

| Maestro | e2e |
| --- | --- |
| `appId` at the top of every flow | `app: { bundleId: 'com.example.app' }` on the target, the app `app.open()` launches |
| a different `appId` per flow, or a second one mid-flow | `device.openApp(id)` in the test, or one config per app |
| `--platform`, `--device` | `mobile({ platform: 'ios', device: 'iPhone 17' })`, one target per platform; a `device` list is a pool |
| `.maestro/config.yaml` `flows`, `'!helper.yaml'` | `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` |
| `tags`, `--include-tags`, `--exclude-tags` | `{ tags: [...] }` on a test or group; `--tag`, `--exclude-tag` on the CLI |
| `env` and `${VAR}` | module constants, and `params` in a goal: `agent.act('sign in as {email}', { params: { email } })` |
| `MAESTRO_*` variables | `process.env` in the config; passwords and tokens go under `credentials` or `secrets`, see [Authentication](/authentication) |
| `--format junit` | `--reporter list,junit` writes `.e2e/junit.xml` |
| `--format html` | `htmlReporter()` from `@e2e-dev/html-reporter` writes `.e2e/report.html` |
| `--shards`, `--shard-split` | `device: [...]` plus `workers` on one machine; `--shard <index/total>` across machines, see [Sharding](/ci#sharding) |
| `maestro record` | `npx e2e run --video`, one MP4 of the device per attempt, or a hosted provider's own recording |
| `maestro test -c` | `npx e2e run --watch` |
| `maestro hierarchy` | `await screen.debug()` in a test prints the screen's tree; `screen.tree()` returns it |

## Rewrite one flow

Start with a flow whose `optional` steps and `runFlow: { when }` branches
often need updating.

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

## Map each command

Calls on `device` run only on a device, so a test that uses it declares
`requires: ['device']` and other targets skip it. For signatures, see
[screen](/reference/screen), [expect](/reference/expect),
[test](/reference/test), and the [mobile engine](/reference/mobile).

<AccordionGroup>
<Accordion title="App and device">

| Maestro | e2e |
| --- | --- |
| `launchApp` | `app.open()`, a fresh launch of the target's app; nothing launches on its own |
| `clearState`, `launchApp: { clearState: true }` | `app.clearState()` |
| `launchApp: { stopApp: false }` | `device.openApp(id)` without `relaunch` |
| `launchApp: { arguments }` | `app.launchArguments` on the target, a list of strings, not a map; `device.openApp(app, { relaunch: true, launchArguments })` for one launch |
| `launchApp: { permissions }`, `setPermissions` | `app.permissions` on the target, or `device.openApp(app, { relaunch: true, permissions })` for one launch; `grant`, `deny`, `reset` for `allow`, `deny`, `unset`. `device.setPermission(name, state)` before `app.open()` |
| `stopApp`, `killApp` | `device.closeApp()`, a force stop; `app.restart()` to stop the app and launch it again |
| `clearKeychain`, `openLink`, `setLocation`, `setAirplaneMode`, `setOrientation`, `setClipboard` | the same on `device`, such as `device.openLink(url)`. `clearKeychain` is iOS simulator only, `setAirplaneMode(true)` Android 11 or newer. For `travel`, loop `device.setLocation` |
| `back`, `pressKey: Home`, `hideKeyboard`, `setDarkMode` | `app.back()`, `device.home()`, `device.dismissKeyboard()`, `device.setAppearance('dark')` |

</Accordion>
<Accordion title="Taps, input, and swipes">

| Maestro | e2e |
| --- | --- |
| `tapOn: "Text"`, `tapOn: { id: x }` | `screen.getByText('Text').tap()`, `screen.getByTestId('x').tap()`, see [Rewrite selectors](#rewrite-selectors) |
| `index: 2`, `containsDescendants`, `childOf` | `.nth(2)`, `.filter({ has: other })`, `parent.getByText('Text')` |
| platform-specific selectors | `device.locator('role=text label="..."')`, agent-device's selector terms |
| `tapOn: { point: "x,y" }` | `screen.tapAt({ x, y })`; inside a node, `.tap({ position: { x, y } })` |
| `doubleTapOn`, `longPressOn` | `.doubleTap()`, `.longPress({ duration })` |
| `inputText`, `eraseText`, `pressKey: Enter` after a `tapOn` | `.fill('text')`, `.clear()`, `.press('Enter')` on the field's locator |
| `inputRandomEmail`, `inputRandomText`, `faker` | `unique()` around a value in `act` params, so the cache still replays; any npm faker for the rest |
| `copyTextFrom`, `pasteText` | `await locator.textContent()`, then `.fill(text)` |
| `swipe: { direction: UP }`, `scroll` | `screen.swipe({ direction: 'down' })`; Maestro names the finger's direction, e2e the content's |
| `swipe: { start, end }`, `scrollUntilVisible` | `screen.swipe({ from, to })` in pixels, `screen.scrollUntilVisible(locator, { direction })` |

</Accordion>
<Accordion title="Assertions and flows">

| Maestro | e2e |
| --- | --- |
| `assertVisible`, `assertNotVisible`, `extendedWaitUntil` | `await expect(locator).toBeVisible({ timeout })`, `.toBeHidden()` |
| `assertVisible: { enabled, checked, selected, focused }` | `.toBeVisible()`, then `.toBeEnabled()`, `.toBeChecked()`, `.toBeSelected()`, or `.toBeFocused()` |
| `assertTrue: ${...}` | `expect(value).toBe(true)`, or `expect.poll` for a value that is still changing |
| `assertScreenshot: { path, thresholdPercentage }` | `await expect(screen).toHaveScreenshot(name, { maxDiffPixelRatio })`, see [Visual comparison](/visual-testing) |
| `takeScreenshot`, `startRecording`, `stopRecording` | `app.screenshot('label')`, [`app.startRecording()`, `app.stopRecording()`](/reference/app#startrecording) |
| `assertWithAI`, `assertNoDefectsWithAI`, `extractTextWithAI` | `agent.assert('...', { vision: true })`, `agent.extract('...', { schema })` |
| `runFlow: file.yaml`, `onFlowStart`, `onFlowComplete` | a function or a `test.extend` fixture; `beforeEach`, `afterEach` |
| `runFlow: { when: { visible } }` | `if (await locator.isVisible()) { ... }`, see [Rewrite selectors](#rewrite-selectors) |
| `repeat`, `runScript`, `evalScript`, `${output.x}`, `http.get` | TypeScript in the test: loops, variables, and Node `fetch`, see [API](/api-testing) |

## Rewrite selectors

- Maestro reads text and id as case-insensitive regular expressions.
  `getByText` and `getByTestId` match the whole string, case included. Write
  `getByText(/^mute account$/i)`, or `{ exact: false }` for a substring of text.
- Maestro taps the first of several matches. e2e fails with
  `LOCATOR_AMBIGUOUS`, so add `.first()` when the first match is what you mean.
- `isVisible()` replaces `optional` and `runFlow: { when }`. It reads the
  screen one time and doesn't wait. It fails on several matches, so add
  `{ visible: true }` or `.first()` when a hidden twin may exist.
- `below`, `above`, `leftOf`, and `rightOf` have no port, see
  [Not yet](#not-yet). `filter({ has })` and chaining match nothing on a
  plain React Native `View` on iOS, see [Known device limitations](/mobile#known-device-limitations).

## What e2e doesn't have yet

Planned is on the roadmap, and Not yet has no date. Not planned is left out
on purpose.

### Planned

| Maestro | Use today |
| --- | --- |
| `permissions: { all }`, the grant-all default, names such as `bluetooth` and `storage` | Name each permission in `app.permissions`, or accept the prompt with `device.alert('accept')` |
| `point: "50%,50%"`, percent `start` and `end` on `swipe` | Compute pixels from a full-screen node's `boundingBox()` |
| `inputText` and `pressKey: Enter` with no field, `eraseText: N`, `pressKey: backspace`, `tab` | `fill` or `press` on the field's locator; `fill` a shortened `inputValue()` to erase; tap the next field for Tab |
| `addMedia` | On an iOS simulator, `xcrun simctl addmedia` before `app.open()`; Android is unchecked. See "Photos for a picker test" under [The device fixture](/mobile#the-device-fixture) |
| `label` on a command | `-`. The call names each step |
| `scrollUntilVisible: { centerElement, visibilityPercentage }` | No exact match. After it resolves, read `boundingBox()`, then `screen.swipe({ direction, momentum: 'slow' })` if the node is off center |
| Device logs and crash reports beside a failure | `adb logcat` or `xcrun simctl spawn <udid> log stream`, collected in a fixture |
| `maestro hierarchy` as a terminal command | A one-line test that calls `screen.debug()` |
| `--device-locale` | `app.launchArguments: ['-AppleLanguages', '(de)', '-AppleLocale', 'de_DE']` on iOS, see [Run the app in another language](/mobile#run-the-app-in-another-language); on Android, set the device language before the run |
| Maestro Cloud | Your [CI](/ci) with a [hosted device provider](/mobile#hosted-devices) |
| `pressKey: lock`, `power`, `volume up`, `volume down` | `client.command.hardwareButton` on [`unstable_raw`](/reference/mobile#unstable_raw): power and volume on Android, volume on a physical iPhone |
| JUnit `properties`, a JUnit path with `--output` | Ids in tags or the title; copy `.e2e/junit.xml` after the run |
| `--device` on the command line | `device: process.env.DEVICE` in the config |

### Not yet

| Maestro | Use today |
| --- | --- |
| `optional: true` | `if (await locator.isVisible())` or try/catch; the report shows no warning |
| `executionOrder` | One `describe(..., { serial: true })` that calls each flow as a function |
| `retry: { maxRetries, commands }` | A `for` loop with try/catch; `expect.poll` for a value, `{ retries }` for the whole test |
| Android process death with `killApp` | `device.home()`, then `adb shell am kill <package>`, then `device.openApp(id)` |
| `assertDarkMode`, `assertLightMode` | Assert on a themed control, or `toHaveScreenshot` |
| TV remote keys | `-` |

### Not planned

| Maestro | Use instead |
| --- | --- |
| Text and id as regex, first match wins | A `RegExp` and `.first()`, see [Rewrite selectors](#rewrite-selectors) |
| `retryTapIfNoChange` | Assert the result, then tap again in the test. A blind second tap can fire a control twice |
| `waitToSettleTimeoutMs` | An assertion with its own `timeout` after the action; that assertion is the wait |
| `toggleAirplaneMode`, `toggleDarkMode` | Set the state you want: `device.setAirplaneMode(true)`, `device.setAppearance('dark')` |
| Maestro Studio | A coding agent over [`npx e2e mcp`](/mcp-server), or `screen.debug()` with `npx e2e run --watch` or `--step` |
| `waitForAnimationToEnd` | `await expect(locator).toBeVisible()` on what the animation ends with |
| `below`, `above`, `leftOf`, `rightOf` | `getByLabel`, a test id, `filter({ has })` on a shared container, or an `agent.act` goal |

## What differs on purpose

- Maestro grants every permission when it launches the app. e2e grants none
  unless you name it, so a ported flow meets system prompts Maestro never
  showed. Name each one in [`app.permissions`](/mobile#launch-arguments-and-permissions),
  with `grant`, `deny`, and `reset` for Maestro's `allow`, `deny`, and `unset`.
- Calls through [`device.unstable_raw`](/reference/mobile#unstable_raw)
  aren't steps. The report, the trace, the agent cache, and redaction skip them.
- A device has no `test.setup` or `{ session }`, see
  [what differs from the web](/mobile#what-differs-from-the-web).
