---
title: From Maestro
description: Move Maestro flows to TypeScript with locators, assertions, and agent goals.
---

Translate Maestro commands into awaited TypeScript calls. Keep exact
interactions as locator calls, or give the agent a goal that covers several
interactions. Both runners can use the same simulator or emulator.

Set up a target with the [mobile guide](/mobile) and a model with the
[quickstart](/quickstart), then move one flow at a time.

## Config

| Maestro | e2e |
| --- | --- |
| `appId` at the top of every flow | `mobile({ app: 'com.example.app' })`, opened fresh per attempt |
| `--device` | `mobile({ device: 'iPhone 17' })` |
| `.maestro/config.yaml` `flows` | `tests`, default `tests/**/*.e2e.ts` |
| `tags` and `--include-tags` | `{ tags: [...] }` on a test, `--tag` on the CLI |
| `env` and `${VAR}` | `process.env` in the config, `params` in a goal |
| `--format junit` | `--reporter list,junit` |
| `maestro record` | `npx e2e run --video` |
| Maestro Cloud | Your CI, see [Continuous integration](/ci) |

## A flow, before and after

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2edev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

Here the agent handles onboarding, while locator assertions check the
confirmation and the Resend control.

## Command map

| Maestro | e2e |
| --- | --- |
| `launchApp` | The engine opens the configured app before each attempt |
| `launchApp: { clearState: true }` | `app.clearState()` |
| `stopApp`, then `launchApp` | `app.restart()` |
| `tapOn: "Text"` | `screen.getByText('Text').tap()` |
| `tapOn: { id: x }` | `screen.getByTestId('x').tap()` |
| `tapOn: { point: "x,y" }` | `screen.tapAt({ x, y })`; inside a node, `.tap({ position: { x, y } })` |
| `doubleTapOn`, `longPressOn` | `.doubleTap()`, `.longPress()` |
| `inputText` | `screen.getByTestId('field').fill('text')` |
| `eraseText` | `.clear()` |
| `hideKeyboard` | `device.dismissKeyboard()` |
| `pressKey: Enter` | `.press('Enter')` on the field |
| `pressKey: Home`, `back` | `device.home()`, `device.back()` |
| `swipe: { direction: UP }` | `screen.swipe({ direction: 'up' })` |
| `swipe: { start, end }` | `screen.swipe({ from: { x, y }, to: { x, y } })` |
| `scroll`, `scrollUntilVisible` | `screen.swipe(...)`, `screen.scrollUntilVisible(locator)` |
| `assertVisible`, `assertNotVisible` | `await expect(locator).toBeVisible()`, `.toBeHidden()` |
| `assertVisible: { text, enabled: true }` | `.toBeVisible()` and `.toBeEnabled()` |
| `extendedWaitUntil: { visible, timeout }` | `.toBeVisible({ timeout })` |
| `waitForAnimationToEnd` | Use an assertion on the expected state; the engine also supports settling options |
| `copyTextFrom`, `pasteText` | `await locator.textContent()`, then `.fill(text)` |
| `setLocation` | `device.setLocation({ latitude, longitude })` |
| `setAirplaneMode`, `toggleAirplaneMode` | `device.setAirplaneMode(true)` or `false` to set the desired state |
| `setOrientation` | `device.setOrientation('landscape-left')` |
| `openLink` | No equivalent on a device |
| `takeScreenshot` | `app.screenshot('label')`, subject to the secret policy |
| `assertWithAI`, `assertNoDefectsWithAI` | `agent.assert('...')`, `agent.assert('...', { vision: true })` |
| `extractTextWithAI` | `agent.extract('...', { schema })` |
| `runFlow` | A function, or a fixture from `test.extend` |
| `runFlow: { when: { visible } }` | `if (await locator.isVisible()) { ... }` |
| `optional: true` on a command | The same `isVisible()` check |
| `repeat: { times: n }` | A `for` loop |
| `runScript`, `evalScript` | TypeScript in the test |

Where the behaviour differs from Maestro's:

- `getByText` matches exactly by default. Pass a `RegExp` for pattern matching
  or `{ exact: false }` for substring matching.
- e2e actions require one match. Multiple matches raise `LOCATOR_AMBIGUOUS`.
  Narrow with `.filter()`, `.first()`, or `.nth()`.
- Use `device.openApp(id)` to switch apps. The device tool pack lets the
  agent do this inside a goal; see [Agent tools](/mobile#agent-tools).

## What to migrate first

Start with a flow whose optional steps and branches often need updating.
Give the agent its goal and verify the result with `expect`. For a simple
tap followed by a text check, locator calls may be clearer.
