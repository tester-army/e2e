Translate Maestro commands into awaited TypeScript calls. Keep exact
interactions as locator calls, or give the agent a goal that covers several
of them. Both runners can use the same simulator or emulator.

Set up a target with the [mobile guide](/mobile) and a model with the
[quickstart](/quickstart), then move one flow at a time. This page maps each
Maestro command to its e2e counterpart and says whether it exists. The
reference pages hold the details: [screen](/reference/screen),
[expect](/reference/expect), [test](/reference/test), and the
[mobile engine](/reference/mobile).

## Config

| Maestro | e2e | Status |
| --- | --- | --- |
| `appId` at the top of every flow | `app: { bundleId: 'com.example.app' }` on the target, the app `app.open()` launches | renamed |
| a different `appId` per flow | `device.openApp(id)` inside the test, or separate app-specific configs and runs; every test runs on every selected target | renamed |
| `--platform ios` | `mobile({ platform: 'ios' })`, one engine per platform | renamed |
| `--device` | `mobile({ device: 'iPhone 17' })`; a list is a pool, one worker per device | renamed |
| `.maestro/config.yaml` `flows` | `tests`, default `tests/**/*.e2e.ts`; Maestro runs one folder level, e2e recurses | renamed |
| `flows: ['!helper.yaml']` | a `tests` entry with a leading `!`: `tests: ['tests/**/*.e2e.ts', '!tests/helpers/**']` | renamed |
| `tags` and `--include-tags` | `{ tags: [...] }` on a test or group, `--tag` on the CLI | renamed |
| `--exclude-tags` | `--exclude-tag` | renamed |
| `env` and `${VAR}` | module constants, and `params` in a goal, see [Selectors](#selectors) | renamed |
| `MAESTRO_*` variables | `process.env` in the config; a password or token goes under `credentials` or `secrets` | renamed |
| `--format junit`, `--output` | `--reporter list,junit`, written to `.e2e/junit.xml` | renamed |
| `--format html` | no equivalent; `markdown` writes `.e2e/summary.md`, every run writes `.e2e/report.json` | missing |
| `properties` (JUnit `<property>`) | not yet | missing |
| `--shards`, `--shard-split` | `device: [...]` plus `workers` splits a target's files across devices on one machine; `--shard <index/total>` splits the suite across machines, see [Sharding](/ci#sharding) | renamed |
| `maestro record`, `startRecording` | `npx e2e run --video`, one MP4 of the device per attempt, or `video` in the config | renamed |
| `maestro test -c`, Maestro Studio | not yet; `npx e2e mcp` gives a coding agent a live session on the device, see [Coding agents](/coding-agents) | missing |
| `maestro hierarchy` | not yet; `device.locator` takes agent-device selectors for nodes `screen` cannot name | missing |
| Maestro Cloud | your CI, see [Continuous integration](/ci) | by design |

## A flow, before and after

```yaml title="Maestro"
appId: com.example.app
---
- launchApp:
    clearState: true
- tapOn: "Get started"
- tapOn:
    id: "email"
- inputText: "ada@example.test"
- tapOn: "Continue"
- assertVisible: "Check your inbox"
- scrollUntilVisible:
    element: "Resend"
- assertVisible:
    id: "resend"
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('asks for the email', async ({ app, agent, screen }) => {
  await app.clearState();
  await agent.act('get started with the email {email}', { params: { email: 'ada@example.test' } });
  await expect(screen.getByText('Check your inbox')).toBeVisible();
  await screen.scrollUntilVisible(screen.getByTestId('resend'));
  await expect(screen.getByTestId('resend')).toBeVisible();
});
```

The agent handles onboarding. Locator assertions check the confirmation and
the Resend control. The flow could also stay fully deterministic: every
`tapOn` has a `screen.getBy*(...).tap()` line.

## Command map

Calls on `screen`, `app`, `agent`, and `expect(locator)` run on every
target, a browser included. Calls on `device` run only on a device: a test that uses one
declares `requires: ['device']` so other targets skip it. `Status` is `same`,
`renamed`, `device only`, `by design` (see [Selectors](#selectors) and
[By design](#by-design)), or `missing`, with what to do today.

### App lifecycle

| Maestro | e2e | Status |
| --- | --- | --- |
| `launchApp` | `app.open()`, the fresh launch of the target's `app.bundleId`; nothing launches on its own | renamed |
| `launchApp: { clearState: true }`, `clearState` | `app.clearState()` | renamed |
| `launchApp: { stopApp: false }` | `device.openApp(id)` without `relaunch` | device only |
| `launchApp: { arguments }` | `app.launchArguments` on the target, or `device.openApp(app, { relaunch: true, launchArguments })` for one launch; a list of strings, not a map | renamed |
| `launchApp: { permissions }` | `app.permissions` on the target, set before every fresh launch, or `device.openApp(app, { relaunch: true, permissions })` for one; `grant`, `deny`, `reset` for `allow`, `deny`, `unset`; no `all`, nothing is granted unless named | renamed |
| `stopApp`, `killApp` | `device.closeApp()` | device only |
| `stopApp`, then `launchApp` | `app.restart()` | renamed |
| `clearKeychain` | `device.clearKeychain()`, the whole simulator's keychain; iOS only | renamed |
| `openLink` | `device.openLink(url, { app })`; on iOS the link opens into `app`, default the pinned app | renamed |
| `addMedia` | not yet | missing |
| `back` | `app.back()`, or `device.back()` | renamed |

### Taps and input

| Maestro | e2e | Status |
| --- | --- | --- |
| `tapOn: "Text"` | `screen.getByText('Text').tap()`; exact, see [Selectors](#selectors) | renamed |
| `tapOn: { id: x }` | `screen.getByTestId('x').tap()` | renamed |
| `tapOn: { text, index: 2 }` | `.nth(2)` | renamed |
| `tapOn: { below: "Email" }`, `above`, `leftOf`, `rightOf`, `containsDescendants` | no equivalent, see [Selectors](#selectors) | by design |
| `tapOn: { point: "x,y" }` | `screen.tapAt({ x, y })`; inside a node, `.tap({ position: { x, y } })` | renamed |
| `retryTapIfNoChange`, `waitToSettleTimeoutMs` | `mobile({ settle, transition })`, engine-wide; no per-call knob | renamed |
| `doubleTapOn`, `longPressOn` | `.doubleTap()`, `.longPress({ duration })` | renamed |
| `inputText` | `screen.getByTestId('field').fill('text')` | renamed |
| `inputRandomEmail`, `inputRandomText`, `faker` | `unique()` around a value in `act` params so the cache still replays; any npm faker for the rest | renamed |
| `eraseText` | `.clear()` | renamed |
| `hideKeyboard` | `device.dismissKeyboard()`, the same dismiss key or center drag Maestro uses; fails only when the keyboard outlives both drags | renamed |
| `pressKey: Enter` | `.press('Enter')` on the field | renamed |
| `pressKey: Home`, `back` | `device.home()`, `device.back()` | device only |
| `pressKey: lock`, `power`, `volume up`, TV remote keys | not yet | missing |
| `copyTextFrom`, `pasteText` | `await locator.textContent()`, then `.fill(text)` | renamed |
| `setClipboard` | `device.setClipboard(text)`; `device.clipboard()` reads it | device only |
| `label: "..."` on a command | not yet; every `screen`, `device`, and `agent` call is a report step named by the call | missing |

### Gestures

| Maestro | e2e | Status |
| --- | --- | --- |
| `swipe: { direction: UP }` | `screen.swipe({ direction: 'down' })`, or `locator.swipe(...)` inside one node; Maestro names the finger's direction, e2e the content's | renamed |
| `swipe: { start, end }` | `screen.swipe({ from: { x, y }, to: { x, y } })` | renamed |
| `scroll` | `screen.swipe({ direction: 'down' })` | renamed |
| `scrollUntilVisible: { element }` | `screen.scrollUntilVisible(locator, { direction })` | renamed |
| `waitForAnimationToEnd` | an assertion on the settled state; `mobile({ settle, transition })` for the engine | renamed |

### Assertions and waits

| Maestro | e2e | Status |
| --- | --- | --- |
| `assertVisible`, `assertNotVisible` | `await expect(locator).toBeVisible()`, `.toBeHidden()` | renamed |
| `assertVisible: { text, enabled: true }` | `.toBeVisible()` and `.toBeEnabled()` | renamed |
| `assertVisible: { checked, selected, focused }` | `.toBeChecked()`, `.toBeSelected()`, `.toBeFocused()` | renamed |
| `assertTrue: ${...}` | `expect(value).toBe(true)`, or `expect.poll` for a value that is still changing | renamed |
| `extendedWaitUntil: { visible, timeout }` | `.toBeVisible({ timeout })` | renamed |
| `assertScreenshot: { path, thresholdPercentage }` | not yet; `agent.assert('...', { vision: true })` is a judgment, not a pixel diff | missing |
| `assertDarkMode`, `assertLightMode` | not yet; assert on a themed control | missing |
| `retry: { maxRetries, commands }` | `expect.poll` for a value, `{ retries }` on the test for the flow | renamed |
| `takeScreenshot` | `app.screenshot('label')`, redacted, withheld after a secret fill | renamed |

### Device

| Maestro | e2e | Status |
| --- | --- | --- |
| `setLocation` | `device.setLocation({ latitude, longitude })` | device only |
| `travel: { points }` | `device.setLocation` in a loop | device only |
| `setAirplaneMode`, `toggleAirplaneMode` | `device.setAirplaneMode(true)` or `false`, the state you want | device only |
| `setDarkMode`, `toggleDarkMode` | `device.setAppearance('dark')` or `'light'` | device only |
| `setOrientation` | `device.setOrientation('landscape-left')` | device only |
| `setPermissions` | `device.setPermission(name, 'grant' \| 'deny' \| 'reset')`, one permission per call, on the open app | device only |
| a second `appId` mid-flow | `device.openApp(id)`; the `open_app` tool lets the agent switch inside a goal, see [Agent tools](/mobile#agent-tools) | device only |
| platform-specific selectors | `device.locator('role=StaticText label="..."')`, agent-device's selector terms | device only |

### AI commands and flow control

| Maestro | e2e | Status |
| --- | --- | --- |
| `assertWithAI`, `assertNoDefectsWithAI` | `agent.assert('...')`, `agent.assert('...', { vision: true })` | renamed |
| `extractTextWithAI` | `agent.extract('...', { schema })` | renamed |
| `runFlow: file.yaml` | a function, or a fixture from `test.extend` | renamed |
| `runFlow: { when: { visible } }` | `if (await locator.isVisible()) { ... }`, see [Selectors](#selectors) | renamed |
| `optional: true` on a command | the same `isVisible()` check | renamed |
| `repeat: { times: n }`, `repeat: { while }` | a `for` or `while` loop | renamed |
| `runScript`, `evalScript`, `${output.x}` | TypeScript in the test | renamed |
| `http.get`, `http.post`, `json()` | Node `fetch`, see [Testing APIs](/api-testing) | renamed |
| `onFlowStart`, `onFlowComplete` | `beforeEach`, `afterEach` | renamed |
| `startRecording`, `stopRecording` | `test('x', { video: 'on' }, ...)` records that test's whole attempts, on a device the mobile engine records; no start and stop inside a test | renamed |

## Selectors

Maestro's selector shorthand does not port one to one. Five differences
account for most edits.

- Text and id are regular expressions in Maestro, so `tapOn: ".*Save.*"`
  matches any text with Save in it. `getByText` is exact. Write
  `getByText(/Save/)` for the pattern, or `{ exact: false }` for a
  case-insensitive substring. `getByTestId` matches a string as the whole id;
  write `getByTestId(/^row-/)` for a pattern.
- `index: 2` is `.nth(2)`. When several nodes match and no index is given,
  Maestro taps the first one silently; e2e fails with `LOCATOR_AMBIGUOUS`.
  Write `.first()` when the first match is what you mean.
- `optional: true` and `runFlow: { when: { visible } }` become
  `if (await locator.isVisible())`. `isVisible()` is a read: `false` on zero
  matches, `LOCATOR_AMBIGUOUS` on several. Add `{ visible: true }` to the
  query or `.first()` to the locator when a hidden twin may exist.
- `below`, `above`, `leftOf`, `rightOf`, and `containsDescendants` have no
  port. e2e has `filter({ has, hasText })` and chaining for structure and
  nothing spatial; a selector anchored on layout breaks on the next redesign.
  Anchor an unlabeled input with `getByLabel`, give it a test id, or hand the
  step to a goal: `agent.act('enter {email} in the email field', { params })`
  reads the screen and finds the field.
- `env:` and `${VAR}` become module constants, and `params` inside a goal:
  `agent.act('sign in as {email}', { params: { email } })`. `MAESTRO_*`
  variables become `process.env` in the config. A password or token goes
  under `credentials` or `secrets`, so the model never sees the value.

## By design

These differ from Maestro on purpose and will stay that way.

- One match or `LOCATOR_AMBIGUOUS`, see [Selectors](#selectors).
- A password is a `Secret` the model never sees, see
  [Signing in](/authentication).
- Every `device` call is a step. It lands in the report as `device.<method>`,
  so a failure shows the exact call without a `label`.
- No agent-device client in tests. `device.locator` covers platform-specific
  selectors; everything else goes through `screen`, `app`, `device`, and the
  agent, so it is recorded and redacted.
- No `test.setup` or `session:` on a device, see
  [what differs from the web](/mobile#what-differs-from-the-web).
