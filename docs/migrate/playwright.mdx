`@e2e-dev/web` brings its own pinned `playwright-core`, so your
`@playwright/test` version is yours to keep. Both runners can stay in one
project. e2e reads `e2e.config.ts` and finds `tests/**/*.e2e.ts` by default,
so keep the two file patterns apart.

Follow the [quickstart](/quickstart) to install e2e and configure a model for
agent calls. This page maps each Playwright feature to its e2e counterpart
and says whether it exists. The reference pages hold the details:
[screen](/reference/screen), [expect](/reference/expect),
[test](/reference/test), [config](/reference/config), and the
[web engine](/reference/web).

## Config

Every e2e config key is a top-level key, a target key such as `app`, or an
option of `web(...)`.
A Playwright key the runner recognizes (`testDir`, `baseURL`, `webServer`,
`projects`) is rejected with a message naming where that fact lives here.

### App, targets, and output

| Playwright | e2e | Status |
| --- | --- | --- |
| `use.baseURL` | `app: { url }` on the target | renamed |

## A test, before and after

```ts title="Playwright"
import { test, expect } from '@playwright/test';

test('checkout', async ({ page }) => {
  await page.goto('/cart');
  await page.getByRole('button', { name: 'Checkout' }).click();
  await page.getByLabel('Card number').fill('4242424242424242');
  await page.getByLabel('Expiry').fill('12/30');
  await page.getByLabel('CVC').fill('123');
  await page.getByRole('button', { name: 'Pay' }).click();
  await expect(page.getByRole('heading')).toHaveText('Order confirmed');
});
```

```ts title="e2e"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('checkout', async ({ app, agent, screen }) => {
  await app.open('/cart');
  await agent.act('pay with the test card 4242 4242 4242 4242, expiry 12/30, CVC 123');
  await expect(screen.getByRole('heading')).toHaveText('Order confirmed');
});
```

The navigation and the final assertion stay explicit. The agent handles the
checkout interactions and adapts when the form changes. A test can also stay
fully deterministic: every `page.getBy*` line has a `screen.getBy*` line.

## API map

Calls on `screen`, `app`, `agent`, and `expect(locator)` run on every
target, a device included. Calls on `browser` run only in a browser: a test that uses one declares
`requires: ['browser']` so other targets skip it. `Status` is `same`, `renamed`,
`web only`, `by design` (see [By design](#by-design)), or `missing`, with
what to do today.

### Locators

| Playwright | e2e | Status |
| --- | --- | --- |
| `page.getByRole`, `getByLabel`, `getByText`, `getByTestId`, `getByPlaceholder` | the same on `screen`; `getByRole` also takes the name positionally, `getByRole('button', 'Save')` | same |
| `getByRole(role, { name })`, `getByLabel`, `getByPlaceholder`, `getByText` with a string | matches the whole string, case-sensitive; `{ exact: false }` for Playwright's substring match, see [By design](#by-design) | by design |
| `getByRole('img')` | the same; `img` is an alias of `image`, so engines, the replay cache, and reports see `image` | same |
| `getByAltText(alt)` | `getByRole('image', alt)` | renamed |
| `getByTitle` | not yet; the node carries no title | missing |
| `getByRole(role, { includeHidden })` | a role query never matches a hidden node; `{ visible: true }` on the other queries drops hidden twins | by design |
| `locator.filter({ hasText, has })` | the same | same |
| `filter({ hasNot, hasNotText })` | not yet; a positive filter or `nth`. `INVALID_LOCATOR`, alone or beside `hasText` or `has` | missing |
| `first()`, `last()`, `nth(i)` | the same | same |
| `locator.and(other)`, `locator.or(other)` | not yet | missing |
| `locator.count()` | the same | same |
| `locator.all()`, `allTextContents()` | the same; `allInnerTexts()` is `allTextContents()` | same |
| `page.locator('css')`, `page.locator('xpath=...')` | `browser.locator('css')`: the string is a Playwright selector, so `xpath=` (or a leading `//`) and `>>` chains work too | web only |
| `page.waitForSelector(selector)` | `browser.locator(selector).waitFor()`; a locator is strict, so narrow a selector with several matches with a `>> visible=true` step or `first()` | renamed |
| `locator.locator('css')` | not yet; a semantic query inside the scope (`cell.getByRole('textbox')` for `cell.locator('input')`), `browser.locator('css').getByRole(...)` the other way round, or one `browser.locator` selector for the whole path | missing |
| `page.frameLocator('#frame')` | `browser.frameLocator('#frame')`, then `screen` queries inside it | web only |

| --- | --- | --- |
| `expect(locator).toBeVisible()`, `toBeHidden()`, `toBeEnabled()`, `toBeDisabled()`, `toBeFocused()` | the same | same |

| `toBeChecked({ indeterminate })`, `{ useInnerText }` | not yet; `INVALID_ARGUMENT`, so the matcher never passes on its default | missing |
| `toHaveAttribute('aria-selected', 'true')`, `'aria-expanded'` | `toBeSelected()`, `toBeExpanded()` | renamed |

| `toHaveCSS()`, `toHaveId()`, `toHaveJSProperty()`, `toContainClass()`, `toHaveValues()` | not yet; `browser.evaluate` plus a value matcher | missing |

| `expect(promise).resolves`, `.rejects` | not yet; `await` first, then `expect(value)` | missing |

## Page objects

A page object that wraps `page` takes the fixtures it uses instead: `screen`
for queries and actions, and `browser` for what only a browser has (keyboard,
mouse, CSS selectors, `evaluate`). Type them with `Screen` and `Locator` from
`e2e` and `Browser` from `@e2e-dev/web`, and hand them out as fixtures so every
test gets its page objects without a `beforeEach`:

```ts title="tests/page-models/account-page.ts"
import type { Locator, Screen } from 'e2e';
import type { Browser } from '@e2e-dev/web';

export class AccountPage {
  readonly accountName: Locator;

  constructor(
    readonly screen: Screen,
    readonly browser: Browser,
  ) {
    this.accountName = screen.getByTestId('account-name');
  }

  async filterByNote(note: string) {
    await this.screen.getByRole('button', 'Filter').click();
    await this.screen.getByRole('button', 'Note').click();
    await this.browser.keyboard.type(note);
  }
}
```

```ts title="tests/fixtures.ts"
import { test as base } from '@e2e-dev/web';
import { AccountPage } from './page-models/account-page.ts';

export const test = base.extend<{ accountPage: AccountPage }>({
  accountPage: async ({ screen, browser }, use) => {
    await use(new AccountPage(screen, browser));
  },
});
```

A fixture that reads `browser` makes every test on that `test` web only: on a
device target it fails in `beforeEach` with `UNSUPPORTED_CAPABILITY`. Give
those tests `requires: ['browser']`, or keep portable tests on the base `test`.

A `locator.page()` call has no counterpart: pass `browser` alongside the locator.
Tests that call `browser.newPage()` in `beforeEach` and `page.close()` in
`afterEach` drop both, since every attempt starts in a fresh context.

## By design

These differ from Playwright on purpose and will stay that way.

- A string name is exact. Playwright's `getByRole` names, `getByLabel`,
  `getByPlaceholder`, and `getByText` match a case-insensitive substring; here
  a string matches the whole text, case-sensitive, see
  [queries](/reference/screen#queries). A substring match on `Save` also hits
  `Save as draft`, and a test that passes on the wrong node is worse than one
  that fails. Pass `{ exact: false }` or a `RegExp` when you mean a fragment.
  A query that misses matches nothing, so a negated assertion on it passes:
  check the query with a positive assertion first.

  ```ts
  // <button>Save changes</button>, <label>Email address <input></label>
  screen.getByRole('button', 'Save');                  // no match
  screen.getByRole('button', { name: 'Save', exact: false });    // matches
  screen.getByRole('button', 'save changes');          // no match, case differs
  screen.getByLabel('Email');                                    // no match
  ```
- Text reads are rendered text. On the web, `textContent()` and `toHaveText`
  read what `innerText` returns, see
  [locator reads](/reference/screen#locator-reads). Playwright reads the DOM's
  `textContent` unless `toHaveText` gets `useInnerText`. Queries still match
  the source text, as Playwright's do: `getByText('Draft')` finds the tag
  below, `getByText('DRAFT')` does not. `browser.evaluate` reads the raw DOM text.

  ```ts
  // <span data-testid="tag" style="text-transform: uppercase">Draft</span>
  // <p data-testid="total">Total <span style="display: none">debug</span>42</p>
  // <p data-testid="address">Line one<br>Line two</p>
  await expect(screen.getByTestId('tag')).toHaveText('DRAFT');                 // Playwright: 'Draft'
  await expect(screen.getByTestId('total')).toHaveText('Total 42');            // Playwright: 'Total debug42'
  await expect(screen.getByTestId('address')).toHaveText('Line one Line two'); // Playwright: 'Line oneLine two'
  ```
- A node with no checked state is unchecked. `isChecked()` is `false` and
  `.not.toBeChecked()` passes on a button or a heading, where Playwright
  throws `Not a checkbox or radio button`. A checkbox replaced by a plain
  button still passes an unchecked assertion found by test id, so query a
  checkable control by role: the query fails when the control changes kind.

  ```ts
  await expect(screen.getByRole('checkbox', 'Subscribe')).not.toBeChecked();
  ```
- One match or `LOCATOR_AMBIGUOUS`, `isVisible()` included, where Playwright
  reads the first match silently. See [screen](/reference/screen).
- `browser.evaluate` takes and returns JSON only. The result is recorded in the
  report and redacted; a `JSHandle` or `ElementHandle` cannot be. Pass values
  in through `arg`.
- `goto` returns nothing. `app.open` and `browser.goto` resolve to `void`; the
  response of a navigation comes from `browser.waitForResponse`.
- A password is a `Secret` with no string value, and the model never sees
  it. See [Signing in](/authentication).
- Sessions are per run and encrypted. `test.setup` saves state under a name
  and `{ session }` restores it. The file is AES-256-GCM encrypted with a key
  that lives in memory and is deleted at cleanup, so there is no
  `.auth/user.json` to cache across runs; setup runs once per run and target.
- Every `browser` call is a step. It lands in the report with its arguments
  redacted, so a failure shows the exact call without a `test.step` around
  it.
- No raw `Page` in tests. Nothing on a raw page is recorded, redacted, or
  masked, so `page.screenshot()` after a secret fill would leak pixels.
  `surfaceOf(engine)` exists for [custom executors](/executors#driving-the-page-yourself),
  not for test code.

## Defaults that differ

| Setting | Playwright | e2e |
| --- | --- | --- |
| Test timeout | 30 s | 120 s, `timeout` |
| Action timeout | none | 30 s, `actionTimeout` |
| Expect timeout | 5 s | 5 s, `assertionTimeout` |
| Navigation timeout | none | 120 s, the test budget; `browser.goto(url, { timeout })` overrides one call |
| Retries | 0 | 1 in CI, 0 locally |
| Trace | `off` (`on-first-retry` in the scaffolded config) | `retain-on-failure` |
| `getByRole` name, `getByLabel`, `getByPlaceholder`, `getByText` | case-insensitive substring | exact |
| `isVisible()` on several matches | the first match, no error | `LOCATOR_AMBIGUOUS` |
