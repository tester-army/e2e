A TesterArmy saved test is a list of plain-language steps that a QA agent
runs in TesterArmy's cloud. In e2e, each step becomes a line in a TypeScript
test that runs on your machine or in your CI: an `agent.act` or
`agent.assert` call, or a locator call when the step needs no judgment. A
coding agent reads your projects and tests through the TesterArmy MCP server
and writes the e2e tests.

## Connect the TesterArmy MCP server

The coding agent reads your tests from the hosted server at
`https://tester.army/mcp`. Add it to the coding agents on your machine:

<CodeGroup>
```bash npm
npx add-mcp --global --name testerarmy https://tester.army/mcp
```

```bash pnpm
pnpm dlx add-mcp --global --name testerarmy https://tester.army/mcp
```

```bash bun
bunx add-mcp --global --name testerarmy https://tester.army/mcp
```
</CodeGroup>

`add-mcp` writes Claude Code's entry to `~/.claude.json`. If you set
`CLAUDE_CONFIG_DIR`, run
`claude mcp add --transport http testerarmy https://tester.army/mcp` instead.
Sign in when the client asks. Other ways to add the server are in
[TesterArmy's MCP setup](https://tester.army/docs/cli/mcp).

The migration only reads from TesterArmy. It never edits, deletes, or runs
your tests there.

## Port the project

<Note>Install e2e and configure a model with the [quickstart](/quickstart). Agent calls need a model.</Note>

| TesterArmy | e2e |
| --- | --- |
| web project `url` | `app: { url }` on a `web()` target |
| mobile project and its uploaded builds | a `mobile({ platform })` target with `app: { bundleId, appPath }`. You build the app, and `device.installApp()` installs it, see [Mobile](/mobile) |
| static environments (Staging, QA) | one target per environment, each with its own `app.url`. `--target staging` runs one |
| PR preview environment | a CI job that sets `app.url` to the preview URL, see [Protected previews](/web#protected-previews) |
| `login` credential | a `credentials` entry. TesterArmy never returns the password or TOTP secret, so read it from an environment variable, see [Signing in](/authentication#credentials) |
| credential `totpSecret` | a `secrets` entry whose value is a function that computes the code. e2e ships no TOTP generator, so add a TOTP library |
| credential environment overrides | one `credentials` entry, with `E2E_USER_<NAME>_PASSWORD` set per environment, see [Override a value per run](/authentication#override-a-value-per-run) |
| `inbox` credential | Not yet. Call your own test inbox from a [fixture](/fixtures) |
| `agentInstructions` | `system` on the agent, see [Instructions and vocabulary](/agents#instructions-and-vocabulary) |
| memories | `context` on the agent |
| project files | files in the repository, such as `tests/fixtures/receipt.jpg` |
| test `viewport` setting | `web({ viewport: { width, height } })`, one target per size |
| `browserRegion`, `simulatorRegion` | No equivalent. The browser runs where `e2e run` runs, or on a [hosted provider](/integrations) |
| `webSearchEnabled` | No equivalent |
| `accessibilityAuditEnabled` | Not yet |
| PR testing | an e2e job on each pull request, with the [GitHub reporter](/github) for the comment |
| group schedule | a scheduled CI workflow |

## Rewrite one test

Each step becomes one awaited call. A `login` step becomes a setup test that
signs in one time and saves a session:

```json title="TesterArmy (get_test)"
{
  "title": "Creates a project",
  "steps": [
    { "type": "login", "title": "Log in as the admin" },
    { "type": "act", "title": "Open Projects from the sidebar and click New Project" },
    { "type": "act", "title": "Name the project Apollo and save" },
    { "type": "assert", "title": "Apollo appears in the project list" }
  ]
}
```

<Tabs>
  <Tab title="tests/projects.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('creates a project', { session: 'admin' }, async ({ app, agent, screen }) => {
  await app.open('/');
  await agent.act('open Projects from the sidebar and click New Project');
  await agent.act('name the project {name} and save', { params: { name: 'Apollo' } });
  await agent.assert('Apollo appears in the project list');
  await expect(screen.getByText('Apollo')).toBeVisible();
});
```

  </Tab>
  <Tab title="tests/auth.setup.e2e.ts">

```ts
import { test } from '@e2e-dev/web';
import { credentials } from 'e2e';

test.setup('log in as the admin', { sessions: ['admin'] }, async ({ app, agent, session }) => {
  const admin = credentials.user('admin');

  await app.open('/login');
  await agent.act('log in', { params: { username: admin.username, password: admin.password } });
  await agent.assert('the dashboard is shown');
  await session.save('admin');
});
```

  </Tab>
</Tabs>

TesterArmy opens the project URL before the first step. In e2e, nothing
opens on its own, so each test starts with `app.open()`.

## Map each step

| TesterArmy | e2e |
| --- | --- |
| `act` step | `agent.act('...')`, or a locator call when the step opens a known route or acts on one named control |
| `assert` step | `agent.assert('...')`, then a locator assertion when a label or test id names the end state |
| `login` step | a `test.setup` that signs in and calls `session.save()`, and `{ session }` on each test, see [Signing in](/authentication) |
| `login` with `temporaryEmail` | Not yet |
| `files` step, `@receipt.jpg` in a step, on web | the file's repository path in the goal: `agent.act('attach tests/fixtures/receipt.jpg')`, or `locator.setInputFiles()` |
| `files` step on mobile (photo library) | Not yet |
| `screenshot` step | `app.screenshot('label')` |
| `javascript` step | `browser.evaluate()`. It fails only when the code throws, so check a `{ success: false }` return with `expect` |
| `microphone` step | Not yet |
| step with `disabled: true` | leave it out |
| disabled test | `test.skip` |
| group | `describe` with `tags`, run with `npx e2e run --tag <tag>` |
| group `runMode: sequential` | `{ serial: true }` on the group |
| group `maxConcurrentRuns` | `workers` in the config. It limits the whole run, not one group |
| group `prepTestId` | a `test.setup` that saves a session, and `{ session }` on the group |
| `run_test`, `run_group` | `npx e2e run <file>`, `npx e2e run --tag <tag>` |

Keep the agent for a step that reads the screen to decide, spans several
screens, or names no stable control. Before you swap a step for a locator,
find the control's exact name, and check the same end state.

## What differs on purpose

- Tests run on your machine or in your CI, not in TesterArmy's cloud. You
  choose the app URL and the device.
- The model never sees a password. The runner types it from a handle, see
  [Signing in](/authentication#the-password-is-a-handle).
- An `agent.act` step replays its recorded actions without a model call.
  When the screen no longer matches, the agent takes over, see
  [Replay cache](/cache).
