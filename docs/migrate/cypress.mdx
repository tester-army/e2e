e2e tests run in Node. Use `await` for UI actions and call Node functions
directly for work previously handled by `cy.task`. Both suites can stay in
the project while you migrate one spec at a time.

Start with the [quickstart](/quickstart) to install e2e and configure a model
for the agent calls shown below.

## Config

| Cypress | e2e |
| --- | --- |
| `baseUrl` | `app: { url }` on the target |
| `start-server-and-test` | `app: { url, command }`, see [Starting your app](/starting-your-app) |
| `viewportWidth`, `viewportHeight` | `web({ viewport })` |
| `data-cy` selectors | `web({ testIdAttribute: 'data-cy' })`, then `screen.getByTestId` |
| `retries` | `retries` |
| `env`, `Cypress.env()` | `process.env` |
| `cypress.env.json` secrets | `credentials` and `secrets`, see [Signing in](/authentication) |
| `cypress run --browser firefox` | A second target with `browser: 'firefox'` |
| Component testing | No equivalent |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{
    engine: web({ testIdAttribute: 'data-cy' }),
    app: { url: 'http://localhost:3000' },
  }],
} satisfies E2EConfig;
```

## A test, before and after

```js title="Cypress"
describe('todos', () => {
  it('completes one', () => {
    cy.visit('/todos');
    cy.get('[data-cy=new-todo]').type('Buy milk{enter}');
    cy.get('[data-cy=new-todo]').type('Walk the dog{enter}');
    cy.contains('li', 'Buy milk').find('[data-cy=toggle]').click();
    cy.get('[data-cy=todo]').should('have.length', 2);
    cy.contains('1 item left').should('be.visible');
  });
});
```

```ts title="e2e"
import { describe, test } from '@e2e-dev/web';
import { expect } from 'e2e';

describe('todos', () => {
  test('completes one', async ({ app, agent, screen }) => {
    await app.open('/todos');
    await agent.act('add todos "Buy milk" and "Walk the dog", then complete "Buy milk"');
    await expect(screen.getByTestId('todo')).toHaveCount(2);
    await expect(screen.getByText('1 item left')).toBeVisible();
  });
});
```

## API map

| Cypress | e2e |
| --- | --- |
| `cy.visit(path)` | `app.open(path)` |
| `cy.get('[data-cy=x]')` | `screen.getByTestId('x')` |
| `cy.get('css')` | `browser.locator('css')`, not portable; prefer a role or label |
| `cy.contains('text')` | `screen.getByText('text', { exact: false })` |
| `cy.contains('li', 'text')` | `screen.getByRole('listitem').filter({ hasText: 'text' })` |
| `.find()`, `.within()` | Chain a query off the locator: `row.getByRole(...)` |
| `.first()`, `.eq(n)` | `.first()`, `.nth(n)` |
| `.click()`, `.dblclick()`, `.rightclick()` | `.tap()`, `.doubleTap()`, `.secondaryTap()` |
| `.type('text')` | `.fill('text')` replaces the content |
| `.type('{enter}')` | `.press('Enter')` |
| `.clear()`, `.check()`, `.select()` | `.clear()`, `.check()`, `.selectOption()` |
| `.selectFile()` | `.setInputFiles()` |
| `.should('be.visible')` | `await expect(locator).toBeVisible()` |
| `.should('have.text', t)`, `.should('contain', t)` | `.toHaveText(t)`, `.toContainText(t)` |
| `.should('have.length', n)` | `.toHaveCount(n)` |
| `.should('have.value', v)` | `.toHaveValue(v)` |
| `.should('not.exist')` | `.toHaveCount(0)`; `toBeHidden()` also accepts a node that is still in the DOM |
| `cy.url().should('include', p)` | `expect(browser).toHaveURL(/p/)` |
| `cy.title()` | `expect(browser).toHaveTitle()` |
| `cy.intercept(url, body)` | `browser.route(url, route => route.fulfill({ json: body }))` |
| `cy.wait('@alias')` | `browser.waitForResponse(url)` |
| `cy.on('window:confirm')` | `browser.onDialog('accept')` |
| `cy.window()`, `cy.document()` | `browser.evaluate(() => ...)` |
| `cy.setCookie` | `browser.setCookies` |
| `cy.viewport` | `browser.setViewport` |
| `cy.session` | `test.setup` and `{ session }` |
| `cy.task`, `cy.exec`, `cy.request` | Node code: `fetch`, `fs`, your database client |
| `cy.fixture` | `import data from './fixture.json'` |
| `Cypress.Commands.add` | A function, or a fixture from `test.extend` |
| `cy.wait(ms)` | Use a locator assertion for the condition you need |
| `cypress open` | `npx e2e run --headed`, plus `--debug` for the step table |

Where the behavior differs from Cypress's:

- There is no chain. Each command is awaited on its own line and returns a
  value, so `const text = await locator.textContent()` works.
- Actions and single-node reads or assertions need one match; several fail
  with `LOCATOR_AMBIGUOUS`. Narrow with `.filter()`, `.first()`, or `.nth()`,
  see [screen](/reference/screen).

## What to migrate first

Start with a spec that often breaks and whose fixed `cy.wait` calls can
become assertions on the condition the test needs.
