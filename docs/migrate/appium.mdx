e2e replaces the Appium server, its drivers, and the client library with
one Node package. `@e2e-dev/mobile` drives iOS simulators, Android
emulators, and connected phones through
[agent-device](https://github.com/callstack/agent-device), which it
includes. Capabilities become a target in `e2e.config.ts`, and `driver`
commands become the `app` and `device` fixtures. Your app build and its
accessibility ids stay as they are.

The examples use WebdriverIO. A Java or Python client maps the same way.

## Port the capabilities

<Note>Set up a target with the [mobile guide](/mobile) and a model with the [quickstart](/quickstart). Only agent steps need a model.</Note>

| Appium | e2e |
| --- | --- |
| `platformName`, `appium:automationName` | `mobile({ platform: 'ios' })` or `'android'` |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`: a name, a simulator UDID, or an `emulator-5554` serial. A phone goes by its name |
| `appium:app` | `app: { appPath }`. Install the build yourself, see [Point at your app](/mobile#point-at-your-app) |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`, the app `app.open()` launches |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`, a list of strings |
| `appium:permissions` | `app.permissions: { camera: 'grant' }`. Each [`DevicePermission`](/reference/mobile#device-fixture) name takes `grant`, `deny`, or `reset` |
| `appium:noReset` | `true` is the default, so nothing clears the app's data. For `false`, call `app.clearState()` at the start of the test |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, WebDriverAgent timeouts | Not needed. Actions use `actionTimeout`, assertions `assertionTimeout`, and tests `timeout` |
| `bstack:options`, `lt:options` | A device provider: [`browserstack()`](/integrations/browserstack) or [`testmu()`](/integrations/testmu) |
| `appium:platformVersion`, `appium:language`, `appium:locale` on a hosted device | `osVersion`, `language`, and `locale` on `browserstack()` and `testmu()`; `android.osVersion` on [`limrun()`](/integrations/limrun) |
| Several capabilities, `maxInstances` | One target per platform, `workers`, and a `device` list with one worker per device |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

## Rewrite one test

Start with a test whose XPath selectors or explicit waits often break.

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- Nothing launches on its own, so the test starts with `app.open()`.
- Actions wait for their element and assertions retry, so the explicit
  wait goes away.

Where a run of scripted taps breaks often, one `agent.act` goal can replace
it. The [replay cache](/cache) records its actions once a later check
passes, and the next run replays them without a model call. A password
belongs in [configured credentials](/authentication), which the model never
sees:

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## Rewrite selectors

| Appium | e2e |
| --- | --- |
| `$('~login')` on iOS, an accessibility identifier or React Native `testID` | `screen.getByTestId('login')` |
| `$('~Log in')` on Android, a content description or React Native `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`; the `com.example:id/` prefix is optional |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` or `getByLabel('Sign in')` |
| `-ios class chain`, class names (`XCUIElementTypeButton`, `android.widget.Button`) | `screen.getByRole('button', 'Sign in')` |
| `$$(selector)[2]` | `.nth(2)`; `.all()` returns every match |
| A selector the queries can't express | `device.locator('role=text label="Total"')`, agent-device's selector syntax |

- `getByText`, `getByLabel`, and `getByTestId` match the whole string, case
  included. Pass a `RegExp`, or `{ exact: false }` for a case-insensitive
  substring of text or label.
- Appium's `$()` returns the first match. An e2e action needs exactly one
  and fails with `LOCATOR_AMBIGUOUS` on several. Narrow it with `.filter()`,
  `.first()`, or `.nth()`.
- Roles such as `button`, `textbox`, and `switch` are the same on iOS and
  Android, so one test runs on both. See [Roles](/reference/mobile#roles).

## Map each command

Calls on `device` run only on a device. A suite that also runs on the web
declares `requires: ['device']` on those tests.

| `mobile: longClickGesture`, `mobile: touchAndHold` on an element | `.longPress({ duration })` |
| `.setValue(t)`, `.clearValue()` | `.fill(t)`, which replaces the content, and `.clear()` |

## Permissions and deep links

Set a permission before `app.open()`, since a change stops a running app on
iOS. Permissions every test needs go in `app.permissions`.

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

## Run in CI

With no server to start, an e2e job installs the build and runs the suite.
Each platform needs its own job, see [Mobile jobs](/ci#mobile-jobs).

```bash npm
npx e2e run --target ios --reporter list,junit
```

```bash pnpm
xcrun simctl install booted ios/build/MyApp.app
pnpm exec e2e run --target ios --reporter list,junit
```

```bash bun
xcrun simctl install booted ios/build/MyApp.app
bunx e2e run --target ios --reporter list,junit
```

## What e2e doesn't have yet

Planned rows are on the roadmap, and Not yet rows have no date. Not planned
rows are left out on purpose. A call through [`unstable_raw`](/reference/mobile#unstable_raw)
is not a step, so it skips the report and secret redaction.

### Planned

<AccordionGroup>
<Accordion title="Capabilities and devices">

| Appium | Use today |
| --- | --- |
| `appium:autoGrantPermissions`, Android permissions off the list, iOS location `always` | List each permission in `app.permissions`, or run `adb shell pm grant` before the run. For iOS location `always`, tap the prompt's button |
| Device settings and alerts on a `browserstack()` or `testmu()` device | Tap the prompt as UI. Run those tests on a local device |

### Not yet

| Appium | Use today |
| --- | --- |
| `appium:autoAcceptAlerts`, `appium:autoDismissAlerts` | Set `app.permissions`, or call `device.alert('accept')` |
| Webview contexts: `getContexts()`, `switchContext()`, CSS selectors, `execute(js)` | Query the webview's accessibility nodes with `getByText` and `getByRole` |
| Mobile web: `browserName: 'Safari'` or `'Chrome'` | A `web()` target at a [phone viewport](/web#viewports), layout only |
| `appium:unlockType`, `unlockKey` | Keep the device unlocked |
| `driver.getPageSource()` as XML | No XML export. `screen.tree()` returns the tree as text, and `client.capture.snapshot()` through [`unstable_raw`](/reference/mobile#unstable_raw) returns its nodes. Keep XML consumers in Appium |
| `performActions()` with several fingers or waypoints | Single gestures, or `client.interactions.gesture` through [`unstable_raw`](/reference/mobile#unstable_raw) |
| `mobile: shell`, `getPerformanceData()` | Run `adb` or `simctl` from Node with `device.unstable_raw.deviceId`; local devices only |
| `mobile: setSimulatedLocation`, `mobile: setAppearance`, `mobile: setPasteboard` on an iPhone | Run those tests on a simulator, see [Physical devices](/mobile#physical-devices) |
| Other `bstack:options` keys, such as `gpsLocation` and `uploadMedia` | - |
| `appium:platformVersion` on a local device, a phone's `appium:udid` | Name a simulator or emulator that runs the version. Put the phone's name in `device` |
| `appium:avd`, `avdArgs`, `isHeadless` | Boot the emulator before the run and name its serial |
| Tests in Java, Python, Ruby, or C# | e2e tests run in Node. Rewrite them in TypeScript in an `e2e/` folder beside the app |

### Not planned

| Appium | Use instead |
| --- | --- |
| XPath | Chain queries (`screen.getByTestId('row').getByText('Delete')`) or use `filter({ has, hasText })`. XPath ties a test to one platform's tree |
| `-image` selectors, `findImage` | `screen.tapAt({ x, y })`, or an `agent.act` goal |
| `$(selector)` acting on the first of several matches | `.first()`, see [Rewrite selectors](#rewrite-selectors) |
| WebDriverAgent capabilities such as `usePrebuiltWDA` | Nothing to set. agent-device builds and signs its own runner |
| Compound `-ios predicate string` logic, `UiSelector` flags and `fromParent()` | A `getBy*` query with `filter({ has })` or a `RegExp` |
| Gherkin feature files | One test per scenario. A step can be an `agent.act` goal |
| Saved sessions, `test.setup` and `{ session }` | Sign in per test or seed the app. A device has no session to save, see [What differs from the web](/mobile#what-differs-from-the-web) |
| A device grid or hub, other device clouds | A hosted provider, or a `DeviceProvider` you write |
| `sauce:options` | Write a [`DeviceProvider`](/mobile#hosted-devices) |
| Appium Inspector | `screen.debug()`, or [`npx e2e mcp`](/mcp-server) for a coding agent's live session |
| `driver.updateSettings()`, `appium:settings[...]` | `snapshot`, `settle`, and `transition` on [`mobile()`](/reference/mobile#engine) |
| `.getAttribute('clickable')`, `.isClickable()` | Act on the element. The action waits until it is actionable |
| A remote Appium server (`hostname`, `port`) | Run e2e on the machine that has the devices |
| Allure | Feed it `.e2e/junit.xml`, or use `htmlReporter()` |
