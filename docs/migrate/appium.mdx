e2e replaces the Appium server, its drivers, and the client library with
one Node package. `@e2e-dev/mobile` drives iOS simulators, Android
emulators, and connected phones through
[agent-device](https://github.com/callstack/agent-device), which it
includes. Your app build and its accessibility ids stay as they are.

This guide is for suites that test a mobile app through Appium's XCUITest or
UiAutomator2 driver, from WebdriverIO or another client. The examples use
WebdriverIO. A Java or Python client maps the same way.

## What replaces each Appium part

| Appium | e2e |
| --- | --- |
| The Appium server, started before the run | No server. The engine starts agent-device's daemon |
| Drivers (`appium driver install xcuitest`) | `mobile({ platform: 'ios' })` or `'android'`, one engine per platform; nothing else to install |
| Capabilities | A target in `e2e.config.ts`: engine options plus `app` |
| A session (`remote()`, `deleteSession()`) | One device session per worker, which the runner opens and closes |
| Selector strategies (accessibility id, id, XPath) | `screen.getByTestId`, `getByLabel`, `getByText`, `getByRole` |
| Element commands (`click`, `setValue`) | Locator actions (`tap`, `fill`), which wait for one actionable match |
| `driver` and `mobile:` commands | The `device` and `app` fixtures |
| expect-webdriverio, implicit and explicit waits | `expect(locator)` matchers, which retry until their timeout |
| The WebdriverIO testrunner, Mocha, TestNG, pytest | `test`, `describe`, hooks, and `npx e2e run` |
| Nothing in Appium | Agent steps: `agent.act`, `agent.assert`, and `agent.extract` take a goal in plain words |

## Port the capabilities

<Note>Set up a target with the [mobile guide](/mobile) and a model with the [quickstart](/quickstart). Only agent steps need a model.</Note>

On this page, "Not yet" marks a capability or command e2e doesn't have
today, and "No equivalent" one it leaves out on purpose.

| Capability | e2e |
| --- | --- |
| `platformName` | `mobile({ platform: 'ios' })` or `'android'` |
| `appium:automationName` | Nothing to set |
| `appium:deviceName`, `appium:udid` | `mobile({ device: 'iPhone 17' })`: a name, a simulator UDID, or an `emulator-5554` serial; a list is a pool, one worker per device |
| `appium:platformVersion` | Not yet. Name a simulator or emulator that runs that version |
| `appium:app` | `app: { appPath }` on the target, installed by the suite, see the note after the config |
| `appium:bundleId`, `appium:appPackage` | `app: { bundleId }`, the app `app.open()` launches |
| `appium:appActivity`, `appium:appWaitActivity` | Not yet. e2e opens the app by its package |
| `appium:processArguments`, `appium:optionalIntentArguments` | `app.launchArguments`, a list of strings: process arguments on iOS, `am start` arguments on Android. `processArguments.env` is not yet supported |
| `appium:autoGrantPermissions`, `appium:permissions` | `app.permissions: { camera: 'grant' }`, set before every fresh launch; nothing is granted unless named |
| `appium:autoAcceptAlerts`, `appium:autoDismissAlerts` | Not yet. Set `app.permissions` so the prompt never shows, or call `device.alert('accept')` |
| `appium:noReset: true` | The default. Nothing clears the app's data unless a test asks |
| `appium:noReset: false` | `app.clearState()` at the start of the test |
| `appium:fullReset` | `device.installApp(path, { reinstall: true })` |
| `appium:newCommandTimeout`, WebDriverAgent timeouts | Not needed. Actions use `actionTimeout`, assertions `assertionTimeout`, and tests `timeout` |
| `appium:language`, `appium:locale` | On iOS, `app.launchArguments: ['-AppleLanguages', '(fr)', '-AppleLocale', 'fr_FR']`; see [Run the app in another language](/mobile#run-the-app-in-another-language). Not yet on Android: set the emulator's language before the run |
| `bstack:options`, `lt:options` | A device provider: [`browserstack()`](/integrations/browserstack) or [`testmu()`](/integrations/testmu) |
| Several capabilities, `maxInstances` | One target per platform, `workers`, and a `device` pool |

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    {
      name: 'ios',
      engine: mobile({ platform: 'ios', device: 'iPhone 17' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'ios/build/MyApp.app',
        launchArguments: ['-e2e', 'YES'],
        permissions: { notifications: 'grant' },
      },
    },
    {
      name: 'android',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        appPath: 'android/app/build/outputs/apk/release/app-release.apk',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { notifications: 'grant' },
      },
    },
  ],
  workers: 1,
} satisfies E2EConfig;
```

`appPath` names the build, but the suite installs it. Install it in CI
before the run, or call `device.installApp()` in a fixture. See
[Point at your app](/mobile#point-at-your-app).

## Rewrite one test

Start with a test whose XPath selectors or explicit waits often break.

```js title="Appium (WebdriverIO)"
describe('login', () => {
  it('signs in', async () => {
    await $('~email').setValue('ada@example.test');
    await $('~password').setValue('hunter2');
    await $('//XCUIElementTypeButton[@name="Sign in"]').click();
    await $('~welcome').waitForDisplayed({ timeout: 10000 });
    await expect($('~welcome')).toHaveText('Welcome, Ada');
  });
});
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('signs in', async ({ app, screen }) => {
  await app.open();
  await screen.getByTestId('email').fill('ada@example.test');
  await screen.getByTestId('password').fill('hunter2');
  await screen.getByRole('button', 'Sign in').tap();
  await expect(screen.getByText('Welcome, Ada')).toBeVisible({ timeout: 10_000 });
});
```

- Nothing launches on its own, so the test starts with `app.open()`.
- Actions wait for their element and assertions retry, so the explicit
  wait goes away.

Where a run of scripted taps breaks often, one goal can replace it. The
agent reads the screen and finds the fields. The [replay cache](/cache)
records its actions once a later check passes, and the next run replays them
without a model call. A password belongs in
[configured credentials](/authentication), which the model never sees:

```ts
import { credentials } from 'e2e';

const ada = credentials.user('ada');
await agent.act('sign in as {username}', { params: { username: ada.username, password: ada.password } });
```

## Rewrite selectors

| Appium | e2e |
| --- | --- |
| `$('~login')` on iOS, an accessibility identifier or React Native `testID` | `screen.getByTestId('login')` |
| `$('~Log in')` on Android, a content description or React Native `accessibilityLabel` | `screen.getByLabel('Log in')` |
| `$('id=com.example:id/email')`, `resourceId` | `screen.getByTestId('email')`; the `com.example:id/` prefix is optional |
| `-ios predicate string:label == "Sign in"`, `android=new UiSelector().text("Sign in")` | `screen.getByText('Sign in')` or `getByLabel('Sign in')` |
| `-ios class chain`, class names (`XCUIElementTypeButton`, `android.widget.Button`) | `screen.getByRole('button', 'Sign in')` |
| XPath | No equivalent. Chain queries (`screen.getByTestId('row').getByText('Delete')`), or use `filter({ has, hasText })` |
| `$$(selector)[2]` | `.nth(2)`; `.all()` returns every match |
| `-image` selectors | No equivalent. Use a goal, or `screen.tapAt({ x, y })` |
| A selector the queries can't express | `device.locator('role=text label="Total"')`, agent-device's selector syntax |

Three differences from Appium cause most edits:

- `getByText`, `getByLabel`, and `getByTestId` match the whole string, case
  included. Pass a `RegExp`, or `{ exact: false }` for a case-insensitive
  substring of text or label.
- Appium's `$()` returns the first match. An e2e action or single-element
  read needs exactly one, and fails with `LOCATOR_AMBIGUOUS` on several.
  Narrow it with `.filter()`, `.first()`, or `.nth()`.
- Appium reads the tree in each platform's own terms, as the iOS class in
  the XPath above shows. e2e maps native controls to shared roles such as
  `button`, `textbox`, and `switch`, so one test runs on both platforms. The
  [capabilities table](/reference/mobile#capabilities) lists the mapping.

Calls on `device` run only on a device. A suite that also runs on the web
declares `requires: ['device']` on those tests.

## Permissions and deep links

Appium grants permissions through capabilities or `mobile:` commands, and
opens links through `driver.url()`:

```js title="Appium (WebdriverIO)"
await driver.execute('mobile: setPermission', {
  bundleId: 'com.example.app',
  access: { location: 'yes' },
});
await driver.activateApp('com.example.app');
await driver.url('myapp://orders/42');
await expect($('~order-title')).toHaveText('Order #42');
```

```ts title="e2e"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('opens an order from a link', async ({ app, device, screen }) => {
  await device.setPermission('location', 'grant');
  await app.open();
  await device.openLink('myapp://orders/42');
  await expect(screen.getByText('Order #42')).toBeVisible();
});
```

Set a permission before `app.open()`: a change terminates a running app on
iOS. Permissions every test needs go in `app.permissions`, see
[Launch arguments and permissions](/mobile#launch-arguments-and-permissions).

## Run in CI

An Appium job starts the server with `appium &`, then the client with
`npx wdio run wdio.conf.ts`. An e2e job has no server. It installs the build
and runs the suite:

<CodeGroup>
```bash npm
xcrun simctl install booted ios/build/MyApp.app
npx e2e run --target ios --reporter list,junit
```

```bash pnpm
xcrun simctl install booted ios/build/MyApp.app
pnpm exec e2e run --target ios --reporter list,junit
```

```bash bun
xcrun simctl install booted ios/build/MyApp.app
bunx e2e run --target ios --reporter list,junit
```
</CodeGroup>

Each platform needs its own job: iOS on macOS, Android on Linux with KVM.
[Mobile jobs](/ci#mobile-jobs) has the full setup.

## Migration checklist

1. Install e2e beside the app, or in an `e2e/` folder for a Java or Python
   suite. Run `npx e2e doctor`.
2. Port the capabilities to one target per platform.
3. Rewrite one flaky test. Replace XPath with test ids, labels, and roles,
   and add an id where the app has none.
4. Run it with `npx e2e run <file>` on each target until it passes.
5. Add the e2e job to CI beside the Appium job.
6. Delete the Appium test, and repeat. After the last one, remove the Appium
   server and drivers from CI.

## What has no direct equivalent

The tables above mark single commands. These gaps cut across a whole suite:

- **Webview contexts.** Not yet. There is no `getContexts` or
  `switchContext`, and no script runs in a webview.
- **Device shell and files.** Not yet. No `mobile: shell`, `pushFile`,
  `pullFile`, `startActivity`, or performance data. For what
  agent-device supports, `device.unstable_raw` exposes its client. Its calls
  aren't steps, so they skip the report and secret redaction.
- **Sauce Labs and other Appium grids.** Not yet. BrowserStack, TestMu AI,
  Limrun, and [Expo Simulators](/integrations/eas) have providers.
- **Session reuse.** No equivalent. A device has no `test.setup` or
  `{ session }`, see [what differs from the web](/mobile#what-differs-from-the-web).
