A migration guide maps one test runner's config, API, and commands to e2e.
It also marks what e2e doesn't have yet, with a workaround. Keep the old
suite installed while you move one test at a time, so both suites stay green.

## Move one test at a time

<Note>Install e2e and configure a model with the [quickstart](/quickstart) first.</Note>

Each guide follows the same steps:

1. Port the config. The old runner's base URL, app command, and devices
   become a target in `e2e.config.ts`.
2. Rewrite one test as a `.e2e.ts` file under `tests/`. Keep the file
   patterns of the two runners apart, so neither runs the other's tests.
3. Run the new test with `npx e2e run <file>` until it passes.
4. Delete the old test when you trust the new one.

e2e tests are TypeScript. For a Java, Python, or native suite, put the e2e
project in an `e2e/` folder with its own `package.json`.

## Let an agent migrate the suite

The `migrate-to-e2e` skill ports one slice of the suite per session and
keeps the old suite running. A `MIGRATION.md` file records progress for the
next session.

<CodeGroup>
```bash npm
npx skills add tester-army/e2e --skill migrate-to-e2e
```

```bash pnpm
pnpm dlx skills add tester-army/e2e --skill migrate-to-e2e
```

```bash bun
bunx skills add tester-army/e2e --skill migrate-to-e2e
```
</CodeGroup>

Then ask the agent for `/migrate-to-e2e`. See
[Migrate an existing suite](/coding-agents#migrate-an-existing-suite). For a
port in one session, copy the agent prompt at the top of your runner's guide.

## Migrate from a runner with no guide

WebdriverIO and Appium have no guide. Map WebDriver calls with the
[Selenium](/migrate/selenium) guide. Map Appium device commands with the
[Detox](/migrate/detox) and [Maestro](/migrate/maestro) guides, on the
[mobile engine](/mobile).
