A bug bash runs many `e2e explore` sessions at the same time. Each session
examines one area of the app. A coding agent then writes a test for each
finding. The agent reports a finding as a bug only when its test fails.

## Before you start

- Make sure that the app can serve many explorers at the same time. Start
  the app one time and set `reuseExisting: true` on the target's
  `app.command`, or set port `0` in the app URL so each run starts its own
  copy. See [Starting your app](/web#starting-your-app).
- On mobile, declare one target for each simulator or emulator. Each
  explorer needs its own device.
- Each explore session uses model calls. The last lines of each run show
  the tokens, cost, and duration.
- On a deployed site that other people use, do not change data.

The agent does the rest of the setup, such as seeded accounts and sign-in,
from the skill.

## Install the skill

The coding agent runs the bug bash from the `e2e` skill. Install the skill
in your project:

<CodeGroup>
```bash npm
npx skills add tester-army/e2e
```

```bash pnpm
pnpm dlx skills add tester-army/e2e
```

```bash bun
bunx skills add tester-army/e2e
```
</CodeGroup>

`e2e init` also installs the skill. See [Coding agents](/coding-agents).

## Start a bug bash

Give a prompt to your coding agent:

```text
Bug bash the checkout and account settings on this branch.
```

## What the agent does

<ShowMore id="bug-bash-steps">

1. Reads the routes of the app. On a branch, it also reads the diff.
2. Writes 5 to 10 charters. A charter is a one-sentence goal for one area,
   with one posture: first-time user, numbers and copy, edge input, state
   after reload, or error paths.
3. Runs one `e2e explore` for each charter, 4 at the same time. Each
   charter has its own persona (`--agent`) and its own output directory
   (`--output`).
4. Merges the findings of all charters.
5. Rejects findings that have a known cause: a limit of the explorer (for
   example, a link that opens a new tab), the local environment, the
   intended design, or the seed data.
6. Writes a repro test for each remaining finding. The test asserts the
   expected behavior. The agent can start one subagent for each area. Each
   subagent opens its own [`e2e mcp` session](/reference/mcp#several-sessions)
   to check locators on the live app.
7. Runs each repro test. The finding is a bug only when the test fails with
   `ASSERTION_FAILED`.
8. Reports, in this order: confirmed bugs, production risks that it cannot
   verify locally, rejected findings by reason, and warnings.

</ShowMore>

Each confirmed bug has its repro test and steps. It also has the
explorer's screenshot and video when the engine records them.

To read the full procedure, run `npx e2e guide bug-bash`.

## Repro tests

A repro test fails until the bug is fixed. The agent tags each repro test
`bugbash`. Keep these tests out of the test run that gates merges:

<CodeGroup>
```bash npm
npx e2e run --exclude-tag bugbash
```

```bash pnpm
pnpm exec e2e run --exclude-tag bugbash
```

```bash bun
bunx e2e run --exclude-tag bugbash
```
</CodeGroup>

After the fix, the test passes. Remove the tag and keep the test as a
regression test.
