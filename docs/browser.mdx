Use `screen`, `app`, and `expect` for navigation, interactions, and checks.
For browser-specific operations such as request mocking, dialogs, and
downloads, use `web`. Import `test` from `@e2edev/web` to access it:

```ts
import { test } from '@e2edev/web';
import { expect } from 'e2e';

test('the dashboard loads', async ({ app, screen, web }) => {
  await app.open('/dashboard');
  await expect(web).toHaveURL('/dashboard');
  await expect(web).toHaveTitle(/Dashboard/);
  await expect(screen.getByRole('heading', { name: 'Overview' })).toBeVisible();
});
```

In a suite with device targets, add `{ requires: ['web'] }` to tests that
use `web` so the runner skips them on devices.

## Mock an API

`web.route` intercepts requests for the attempt. Register it before the page
opens; it stays in force across `app.restart()` and a session restore.

```ts
await web.route('**/api/quote', async (route) => {
  await route.fulfill({ json: { cents: 4200 } });
});

await app.open('/checkout');
await expect(screen.getByText('$42.00')).toBeVisible();
```

Each handler must call exactly one of `fulfill`, `continue`, or `abort`.
To inspect a real response, start waiting before the action that sends it:

```ts
const [response] = await Promise.all([
  web.waitForResponse('**/api/orders'),
  screen.getByRole('button', { name: 'Place order' }).tap(),
]);
expect(response.status).toBe(201);
```

## Handle a dialog

An unhandled `alert`, `confirm`, or `prompt` fails the next step. Register a
handler first:

```ts
const off = await web.onDialog('accept');
await screen.getByRole('button', { name: 'Delete' }).tap();
await off();
```

A function handler gets the dialog and must call `accept(text?)` or
`dismiss()`.

## Download a file

```ts
const file = await web.waitForDownload(() =>
  screen.getByRole('link', { name: 'Export CSV' }).tap(),
);
```

The download is registered as a `download` artifact. `file.path` is relative to
the attempt's artifact directory, not an absolute or project-relative file
path.

## Reach into an iframe

`web.frameLocator` scopes queries to a frame:

```ts
const payment = web.frameLocator('#payment-frame');
await payment.getByLabel('Card number').fill('4242424242424242');
```

Use role and label queries when possible. Within a frame, `locator` accepts
CSS or XPath selectors and `frameLocator` enters a nested frame:

```ts
const editor = web.frameLocator('#result');
await editor.locator('#upload').setInputFiles('fixtures/photo.png');
await expect(editor.frameLocator('#preview').getByRole('heading', { name: 'Uploaded' })).toBeVisible();
```

## Read from the page

`web.evaluate` runs a function in the page. It is serialized, so it cannot
close over test variables; pass data as the second argument.

```ts
const count = await web.evaluate(() => document.querySelectorAll('li').length);
const flag = await web.evaluate((name: string) => window.localStorage.getItem(name), 'featureFlags');
```

Use `evaluate` for state that `screen` cannot read. Prefer locators and
assertions for visible UI so tests depend less on the DOM structure.

## Cookies and viewport

```ts
await web.setCookies([{ url: 'http://localhost:3000', name: 'tz', value: 'UTC' }]);
await web.setViewport({ width: 390, height: 844 });
```

Cookie URLs must use HTTP or HTTPS. If any entry is invalid, no cookies
are set.

## Pick a browser and viewport

The browser and the initial viewport are options of the engine. Two browsers
on one app are two targets:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2edev/web';

const app = { url: 'http://localhost:3000' };

export default {
  targets: [
    { name: 'chromium', engine: web(app) },
    { name: 'webkit-mobile', engine: web({ ...app, browser: 'webkit', viewport: { width: 390, height: 844 } }) },
  ],
} satisfies E2EConfig;
```

`npx playwright install webkit --with-deps` provisions the extra browser in
CI. `connect` attaches to a remote Chromium over CDP instead of launching
one; a [browser provider](#hosted-browsers) does the same and also leases
and releases the browser. [Testing viewports](/viewports) covers a suite
that runs at several sizes and what the agent sees at each.

## Hosted browsers

`browser` can also be a `BrowserProvider`: an object that leases a browser
from a service and hands back the CDP endpoint to attach to. The engine
attaches over CDP the way `connect` does, and adds the lifecycle `connect`
lacks: it asks for a browser when one is needed and gives it back when its
scope ends, on every exit path, so a session billed by the minute stops
when the run no longer uses it. Nothing in the framework knows a vendor; a
provider is a few dozen lines in your project.

```ts
export interface BrowserProvider {
  /** Label in progress lines and error messages. */
  readonly name: string;
  /** `worker` (default): one browser per worker slot for the run. `attempt`: a fresh browser per attempt. */
  readonly scope?: 'worker' | 'attempt';
  acquire(request: BrowserRequest): Promise<BrowserLease>;
  release(lease: BrowserLease, context: BrowserReleaseContext): Promise<void>;
}

export interface BrowserLease {
  /** The provider's handle (a session id), handed back to `release`. */
  readonly id: string;
  /** `ws://`, `wss://`, or `http://` DevTools endpoint to attach to over CDP. */
  readonly cdpEndpoint: string;
  /** Endpoint to reattach to the same browser after a transport drop; per-attempt leases only. */
  readonly reconnectEndpoint?: string;
}
```

`acquire` receives the run id, target, worker slot and slot count, the
attempt id for a per-attempt lease, the run's environment, an abort signal,
and a `log` that reaches the reporter. Read tokens from `request.env`, not
`process.env`. A lease is JSON data: only `id`, `cdpEndpoint`, and
`reconnectEndpoint` travel to the worker, and `release` gets back the object
`acquire` returned, so a provider can keep its own fields on it. A target
with nothing to run leases nothing. A provider implies chromium (CDP attach
is chromium-only) and cannot be combined with `connect`.

`scope: 'worker'`, the default, leases one browser per worker slot when the
run starts, all slots in parallel, and each worker attaches to its own for
every attempt it runs. Every lease granted is held by the engine: a slot
that fails to lease ends the run before any test, and the leases that
succeeded are still released. Release happens after the last worker exits,
on every exit path including failure, interrupt, and a `prepare` that
threw, within `cleanupTimeout`. When a worker's browser drops, the worker
leases a replacement itself at the next attempt start and releases it when
the worker exits; the dead lease stays with the runner, which releases it
at the end. `acquire` therefore runs in a worker process too, so a provider
must not depend on state it built in the runner process, and `log` is
discarded there. Each lease is released exactly once, by the side that
acquired it.

`scope: 'attempt'` leases a fresh browser in every `startAttempt`, retries
included, and releases it in `endAttempt`, also after a start that failed.
The attempt runs in the browser's persistent default context, so the
remote must contain only that context, and the limits of
[`connect.reconnectEndpoint`](/reference/web#recovering-a-cdp-transport)
apply: no `headers` or `basicAuth` (both are `INVALID_CONFIG`), no
`app.clearState()`, no session state capture or restore. After a transport
drop the next operation reattaches through the lease's `reconnectEndpoint`,
or `cdpEndpoint` when the lease has none, and the engine checks it is the
same browser.

A provider against a typical session API has three requests: create a
session, poll it until it exposes a DevTools endpoint, stop it.

```ts title="browser-provider.ts"
import type { BrowserProvider } from '@e2edev/web';

/**
 * Leases browsers from a service that starts a Chromium per session and
 * exposes its DevTools endpoint. Replace the three requests with your
 * service's API.
 */
export function hostedBrowsers(options: { serviceUrl: string; scope?: 'worker' | 'attempt' }): BrowserProvider {
  return {
    name: 'hosted-browsers',
    scope: options.scope ?? 'worker',
    async acquire(request) {
      const token = request.env['BROWSER_SERVICE_TOKEN'];
      if (token === undefined || token === '') throw new Error('BROWSER_SERVICE_TOKEN is not set');
      const headers = { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' };
      // 1. Ask for a browser; name the session after the run so it can be found later.
      const created = await fetch(`${options.serviceUrl}/sessions`, {
        method: 'POST',
        headers,
        body: JSON.stringify({
          name: `e2e ${request.runId} ${request.targetName} ${request.attemptId ?? `slot ${request.slot + 1} of ${request.slots}`}`,
        }),
        signal: request.signal,
      });
      if (!created.ok) throw new Error(`browser service: HTTP ${created.status}`);
      const { id } = (await created.json()) as { id: string };
      // 2. Wait until the session exposes its DevTools endpoint.
      for (;;) {
        const response = await fetch(`${options.serviceUrl}/sessions/${id}`, { headers, signal: request.signal });
        const session = (await response.json()) as { status: string; cdpUrl?: string; viewerUrl?: string };
        if (session.status === 'ready' && session.cdpUrl !== undefined) {
          if (session.viewerUrl !== undefined) request.log(`watch at ${session.viewerUrl}`);
          return { id, cdpEndpoint: session.cdpUrl };
        }
        if (session.status !== 'starting') throw new Error(`browser service: session ${id} is ${session.status}`);
        await new Promise((resolve) => setTimeout(resolve, 2_000));
      }
    },
    async release(lease, context) {
      // 3. Stop the session; the run waits for this within cleanupTimeout.
      const token = context.env['BROWSER_SERVICE_TOKEN'] ?? '';
      await fetch(`${options.serviceUrl}/sessions/${lease.id}/stop`, {
        method: 'POST',
        headers: { Authorization: `Bearer ${token}` },
        signal: context.signal,
      });
    },
  };
}
```

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2edev/web';
import { hostedBrowsers } from './browser-provider.ts';

export default {
  targets: [
    {
      name: 'hosted',
      engine: web({
        url: 'https://staging.example.com',
        browser: hostedBrowsers({ serviceUrl: 'https://browsers.example.com' }),
      }),
    },
  ],
  workers: 2,
} satisfies E2EConfig;
```

Two workers lease two sessions in parallel and keep them for the run. Hosted
sessions are billed while they run, so keep `workers` at what the suite can
fill; `scope: 'attempt'` trades a session start per test for a browser no
earlier test has touched.

## Raw selectors

Use `web.locator('css or xpath')` when role, label, and test-id queries
cannot identify an element. If a hidden duplicate causes an ambiguous
match, try `{ visible: true }` on the query first.
