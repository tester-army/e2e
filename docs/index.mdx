**e2e lets an agent test your app like a real user.** You write a goal
or a question in natural language, and a model interacts with the app to
reach it. Exact values and exact checks go in the same test as regular locator calls and assertions.

**e2e tests applications through their user interface**: web, mobile,
desktop, and anything else with a UI. It is not an agent-eval harness and not
an API-only tool; what it drives is what a user sees and touches.

**The runner is platform agnostic.** Browsers, iOS simulators, and Android
emulators ship as engines, and the same test runs on each.

The engine contract carries no platform noun, so a desktop shell or a TV app
fits it as well as a browser does. You can write [your own engine](/writing-an-engine)
for any surface with a user interface.

**The agent thinks once.** With the [cache](/cache) on, a passing `agent.act`
records its actions, and later runs **replay them with no model call** until
the app changes. A suite costs tokens when the UI moves, not on every run. This substantially reduces the maintenance of tests.

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('a member upgrades to Pro', async ({ app, agent, screen }) => {
  await app.open('/settings/billing');

  await agent.act('upgrade the workspace to the Pro plan');
  await agent.assert('the invoice preview shows a prorated amount');

  await expect(screen.getByRole('status')).toContainText('Pro');
});
```

Agent steps stay under your control. The runner decides what the model
sees, what it may do, how many calls it gets, and what ends up in the
report. You choose the model and can replace the agent outright.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { createAgent } from 'e2e/agent';
import { playwright } from '@e2edev/playwright';
import { gateway } from 'ai';

export default {
  targets: [{ engine: playwright({ url: 'http://localhost:3000' }) }],
  agents: { default: createAgent({ model: gateway('openai/gpt-5.6-luna') }) },
} satisfies E2EConfig;
```

## What you get

- **Tests that survive UI changes.** An agent step names the outcome, not the
  selector. Renamed buttons and rearranged forms do not break it.
- **Replay instead of re-thinking.** In read-write cache mode, an `agent.act`
  followed by a recorded verification can save its actions. Later runs replay
  them with no model call until the app diverges.
- **Bounded agent steps.** Every `agent.*` call has a deadline and a model-call
  budget, and ends in a verdict: passed, failed, or blocked.
- **Secrets the model never sees.** A password, an API key, any value from the
  environment is an opaque handle. The model gets its name; the runner fills
  the field and redacts the value everywhere.
- **One contract, any surface.** Tests share the agent and locator APIs
  across engines; only setup follows the platform. Engines today:
  - `@e2edev/playwright` drives Chromium, Firefox, and WebKit.
  - `@e2edev/agent-device` drives iOS simulators and Android emulators.
  - [Your own](/writing-an-engine), for anything else.
- **Every run is on the record.** Each agent step is written down: what it
  saw, what it did, what it cost, and why it stopped. A person or a coding
  agent reads one [report](/debugging) to find out what went wrong, with
  screenshots, traces, and video beside it.
