`E2EConfig` is the type of the object `e2e.config.ts` default-exports. Write the
object literal and end it with `satisfies E2EConfig`: the editor completes every
key, unknown keys are flagged, and the export keeps its literal type. Every rule
below is enforced when the runner resolves the config, not by the type.

```ts title="e2e.config.ts"
import type { E2EConfig } from '@e2edev/e2e';
import { playwright } from '@e2edev/playwright';

export default {
  targets: [
    {
      name: 'web',
      platform: 'web',
      engine: playwright({ browser: 'chromium', url: process.env.APP_URL ?? 'http://localhost:3000' }),
    },
  ],
} satisfies E2EConfig;
```

Unknown keys are rejected with `INVALID_CONFIG` at every level: top level,
`agent`, `agent.model`, and `limits`. There is no top-level `app` key: the
engine declares the app it drives (see [the app under test](#the-app-under-test)).

## Loading

`--config <path>` selects an explicit file. Otherwise the runner searches the
working directory and each parent for `e2e.config.ts` or `e2e.config.mts`,
stopping at the repository root. Both names in one directory is
`CONFIG_AMBIGUOUS`. The selected file's directory is the project root; with no
config file, the working directory is.

A config file is required. Targets that drive an app name an engine;
HTTP tests and agents using their own tools can use a target without one.
`npx --no-install e2e init` offers optional engine and AI setup.

Config and test modules run as ESM. For `.ts` files, the nearest `package.json`
must set `"type": "module"`. In a directory without a package manifest, `init`
creates one with this setting. Existing module types are preserved, and `init`
prints the command to opt into ESM when needed. Loading a `.ts` config or
collecting a `.ts` test outside an ESM package reports this requirement with
instructions to fix it.

An `.mts` config is always ESM, but renaming the config alone does not change
the module type of `.ts` test files or helpers.

## Top level

| Key | Type | Default | Valid range |
| --- | --- | --- | --- |
| `projectId` | `string` | nearest `package.json` name, else a generated ID | 1-256 characters |
| `targets` | `readonly Target[]` | required | non-empty; each engine declares [the app under test](#the-app-under-test) |
| `tests` | `string \| readonly string[]` | `'tests/**/*.e2e.ts'` | non-empty, `/` separators, duplicates removed |
| `timeout` | `number` | `120000` | positive safe integer |
| `launchTimeout` | `number` | `60000` | positive safe integer |
| `actionTimeout` | `number` | `30000` | positive safe integer; bounds every engine operation, including each observation and action inside an agent step |
| `assertionTimeout` | `number` | `5000` | positive safe integer |
| `cleanupTimeout` | `number` | `30000` | positive safe integer |
| `retries` | `number` | `1` in CI, else `0` | integer 0-10 |
| `workers` | `number` | `1` in CI, else `max(1, floor(availableParallelism() / 2))` | integer 1-1024 |
| `artifacts` | kinds array or `{ kinds?, store? }` | `['screenshot', 'trace']` | those two kinds; `store` is an [`ArtifactStore`](#artifacts) |
| `reporters` | `readonly ('list' \| 'json' \| 'junit')[]` | `['list']` | those three IDs; `json` cannot be combined with `list`; `junit` also writes `.e2e/junit.xml` |
| `screen` | object | see [screen](#screen) | - |
| `agent` | object | see [agent](#agent) | - |
| `cache` | string or object | `'read-write'` (`'read-only'` in CI when unset) | see [cache](#cache) |
| `limits` | object | see [limits](#limits) | - |
| `credentials` | record | `{}` | see [credentials](#credentials) |

Every numeric value must be a safe integer.

`artifacts` accepts `screenshot` and `trace` only; `video` is not a
configurable artifact kind. A configured kind the target's engine cannot
produce fails before collection with `UNSUPPORTED_ARTIFACT`.

### artifacts

The object form adds a **store**, the cloud seam for evidence the way
`cache.store` is for traces:

```ts
artifacts: {
  kinds: ['screenshot', 'trace'],
  store: {
    async put(artifact) {
      // artifact.bytes, .sha256, .mediaType, .path, .runId, .testId, .attemptId, .stepId?
      const key = await bucket.upload(artifact.path, artifact.bytes);
      return { ref: key };
    },
  },
},
```

A host store receives every artifact the moment it is complete on disk — as
produced, not after the run — and returns its own reference, which the report
records as the artifact's `ref` beside the local path. A failed `put` never
fails the run; the record simply carries no `ref`. Like every live value, a
store never crosses a process boundary, so it runs in-process
(`rawConfig`).
Every run writes `.e2e/report.json` regardless of the selected reporters; the
`junit` reporter adds `.e2e/junit.xml` beside it (see [CLI](/reference/cli#output)).

## The app under test

The app is declared by the engine that drives it, never by a config key. The
browser engine takes the declaration as options of `playwright(...)`; the
device engine derives it from the app it pins
(`agentDevice({ platform, app })`). The runner resolves each target's
declaration at config load and owns what is built on it: navigation and
origin policy, cache and session identity, the report's target record, and
the app process.

```ts
export interface EngineAppDeclaration {
  url?: string;
  command?: CommandConfig;
  readyUrl?: string;
  services?: readonly ServiceConfig[];
  allowedOrigins?: readonly string[];
  environment?: 'test' | 'staging' | 'production';
  identity?: string;
}
```

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `url` | `string` | unset | Required once a test calls `app.open()` or navigates relatively, else `APP_URL_REQUIRED` at that call. A missing scheme becomes `https://`, or `http://` for a loopback host. No userinfo, query, or fragment; HTTP only for loopback. |
| `command` | `CommandConfig` | unset | Structured app process, never shell-interpreted. Targets declaring the same command share one process, probed at the first declaring target's `readyUrl`. |
| `readyUrl` | `string` | the resolved `url` | Absolute http(s) readiness probe; a status of 200-499 counts as ready. A `command` with neither is `APP_URL_REQUIRED` at config load. |
| `services` | `readonly ServiceConfig[]` | `[]` | Dependency processes started in order before any app command and torn down in reverse; see [services](#services) |
| `allowedOrigins` | `readonly string[]` | the origin of `url`, else none | Each entry must be a serialized origin |
| `environment` | `'test' \| 'staging' \| 'production'` | `'test'` for loopback, `.localhost`, and `.test` hosts and without a URL, otherwise `'production'` | A label for the report and the cache/session identity digest; it never gates a run |
| `identity` | `string` | the URL's origin and base path, else none | Stable logical app identity for cache/session keying. Set it when the origin is ephemeral (a per-PR preview URL) so entries survive redeploys, or on a surface without a URL; never share one identity across genuinely different apps. The environment always joins the derived identity. |

A target without an engine, or whose engine declares nothing, resolves to the
empty app: no URL, no allowed origins, environment `test`, no identity. Unknown
declaration keys fail at `defineEngine`; invalid values fail at config load
naming the target.

```ts title="e2e.config.ts"
export default {
  targets: [
    {
      name: 'web',
      platform: 'web',
      engine: playwright({
        url: 'http://127.0.0.1:3000',
        command: { executable: 'pnpm', args: ['dev'], startupTimeout: 120_000 },
      }),
    },
  ],
} satisfies E2EConfig;
```

### command

```ts
export interface CommandConfig {
  executable: string;
  args?: readonly string[];
  cwd?: string;
  env?: Readonly<Record<string, string>>;
  startupTimeout?: number;
  shutdownTimeout?: number;
  log?: string;
  reuseExisting?: boolean;
}
```

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `executable` | `string` | - | Required, non-empty, resolved with the process `PATH` |
| `args` | `readonly string[]` | `[]` | Passed verbatim |
| `cwd` | `string` | project root | Resolved from the project root |
| `env` | `Record<string, string>` | `{}` | Adds to the inherited set |
| `startupTimeout` | `number` | `60000` | Ready-probe budget; expiry is `APP_UNREACHABLE` |
| `shutdownTimeout` | `number` | `10000` | Grace period before force-kill |
| `log` | `string` | unset (output discarded) | File that receives the process's stdout and stderr, appended; resolved from the project root and must stay inside it. Missing directories are created |
| `reuseExisting` | `boolean` | `false` | If `readyUrl` already answers before the spawn, attach to that process: nothing is started or stopped. Without it, an already-answering URL is `APP_ALREADY_RUNNING`. Ignored in CI |

Without `log` the runner discards everything the process prints, so a dev
server that crashes on boot or a migration that fails leaves no trace beyond
`APP_UNREACHABLE`. Point `log` at a file such as `.e2e/logs/app.log` to keep
the output; it appends, so one file can collect several commands and several
runs. Every `ServiceConfig` and every service `teardown` is a `CommandConfig`
and accepts `log` too. The file is the raw, unredacted output of the process:
whatever the app prints, including secrets from its own `env`, ends up there,
so keep it in an ignored directory. `e2e init` adds `.e2e/logs/` to
`.gitignore` for this purpose.

The child inherits only `PATH`, `HOME`, `TMPDIR`, `TMP`, `TEMP`, `SystemRoot`,
and `COMSPEC` when present, plus `command.env`. Model credentials,
`E2E_USER_*` values, and CI tokens are never inherited. The runner never
terminates a process it did not start.

The runner probes `readyUrl` once before spawning, within the `startupTimeout`
budget. If something already answers, a process this run did not start is
serving the URL, and HTTP readiness could never tell it apart from the new
command later, so the runner decides up front. Without `reuseExisting` the
launch fails with `APP_ALREADY_RUNNING` before anything is spawned, so tests
never run against stale code by accident. `reuseExisting: true` is for local
development, where the dev server is usually already up on that port: the
runner reports `<label>: reusing the process already serving <url>` and leaves
the process alone on teardown. When nothing answers, the command starts and is
owned as usual either way. CI ignores the flag with a notice, so a leftover
server on a shared runner is `APP_ALREADY_RUNNING` there and never silently
tested.

### services

```ts
export interface ServiceConfig extends CommandConfig {
  name?: string;
  readyUrl?: string;
  waitForExit?: boolean;
  teardown?: CommandConfig;
}
```

Real apps need dependencies before they can boot: a database container, a
cache, an auth emulator, a migration step. `services` declares them as ordered
processes so no wrapper launcher is needed. Each service is a `CommandConfig`
with the same spawning, `cwd`, `log`, and environment rules as `command`,
plus:

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | `string` | executable base name | Label used in errors, reporter output, and the report (`service "postgres" exited with code 1`). Set it when the executable is a wrapper such as `sh`. Non-empty, at most 64 characters, unique across named services |
| `readyUrl` | `string` | unset | HTTP readiness probe, polled like the app's; a status of 200-499 counts as ready |
| `waitForExit` | `boolean` | `false` | The process is the step: ready when it exits 0. A non-zero exit is `APP_UNREACHABLE` |
| `teardown` | `CommandConfig` | unset | Run during teardown after the service is stopped, waited on until exit within its own `startupTimeout` |

Exactly one of `readyUrl` or `waitForExit` is required per service, otherwise
`INVALID_CONFIG`. `reuseExisting` works on a `readyUrl` service like on
`command` (a reused service also skips its `teardown`); on a `waitForExit`
service or a `teardown` command there is nothing to reuse and it is
`INVALID_CONFIG`. Services start sequentially in declaration order before any
app command, each ready before the next starts, and `startupTimeout` bounds
every readiness wait. Each service is one setup step of the run: the list
reporter shows the one starting with a ticking clock, prints its wait once it
is ready, and splits the whole startup out of the summary's `Duration`; the
programmatic runner streams the same as `setup` events. `services` works
without `command` when the app is already running or is itself one of the
services. Services declared
identically by several targets start once; two targets that order shared
services differently, or put one explicit `name` on two different services,
are `INVALID_CONFIG`.

On every exit path (success, failure, interrupt) the runner stops every app
command, then stops the started services in reverse order, then runs their
`teardown` commands in reverse order. A `waitForExit` service that has
already exited still gets its teardown. A failing teardown is recorded as a
`cleanup`-phase run error and never skips the teardowns after it. Service and
teardown `env` values enter the config digest as names only, like
`command.env`.

```ts title="e2e.config.ts"
export default {
  targets: [
    {
      name: 'web',
      platform: 'web',
      engine: playwright({
        url: 'http://localhost:3000',
        services: [
          {
            name: 'postgres',
            executable: 'docker',
            args: ['compose', 'up', '--wait', 'postgres'],
            waitForExit: true,
            teardown: { executable: 'docker', args: ['compose', 'down'] },
          },
          {
            name: 'migrate',
            executable: 'pnpm',
            args: ['db:migrate'],
            waitForExit: true,
            log: '.e2e/logs/services.log',
          },
          {
            name: 'auth-emulator',
            executable: 'pnpm',
            args: ['auth:emulator'],
            readyUrl: 'http://127.0.0.1:7000/health',
            log: '.e2e/logs/services.log',
          },
        ],
        command: { executable: 'pnpm', args: ['dev'], log: '.e2e/logs/app.log' },
      }),
    },
  ],
} satisfies E2EConfig;
```

## targets

A target's `name` defaults to its `platform`, so one target per platform needs
none; two targets on the same platform name themselves. Names are unique and
limited to ASCII letters, digits, `_`, `-`, and `.`. An empty `targets` array
is an error.

```ts
export interface Target {
  name?: string; // defaults to platform
  platform: Platform;
  engine?: EngineHandle; // defineEngine(...) from '@e2edev/e2e/engine'
}
```

Every target is served by an engine, and the runner knows only the engine
contract: the engine's declared capabilities (observation, actions, location,
state, artifacts, contributed fixtures) grade what the target serves, and
anything undeclared fails loud with `UNSUPPORTED_CAPABILITY`. A target without
an `engine` is agent-tools-only and runs everything opaque. The engine
declares [the app under test](#the-app-under-test); a URL is needed only once
a test calls `app.open()`. With an `executor` in the `agent`
block, a custom brain composes with the model, budget, and context options
instead of replacing them.

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `name` | `string` | `platform` | Stable ID used by `--target`, reports, sessions, and artifact paths; unique across targets |
| `platform` | `Platform` | - | Any label; `platforms: [...]` on a test filters against it |
| `engine` | `EngineHandle` | none | `playwright({ url?, command?, browser?, viewport?, connect? })` from `@e2edev/playwright` for a browser (`connect` attaches to a remote browser over CDP); `agentDevice({ platform, app?, appPath? })` from `@e2edev/agent-device` for an [iOS or Android device](/reference/device); any [`defineEngine`](/writing-an-engine) handle otherwise |

The app URL, browser choice, and viewport are options of the playwright
engine, not of the runner. Two browsers on one app each name it:

```ts
const app = { url: 'http://localhost:3000' };
targets: [
  { name: 'chromium', platform: 'web', engine: playwright(app) },
  { name: 'webkit-mobile', platform: 'web', engine: playwright({ ...app, browser: 'webkit', viewport: { width: 390, height: 844 } }) },
],
```

## agent

```ts
agent?: {
  model?: string | ModelConfig | ModelInstance;
  visionModel?: string | ModelConfig | ModelInstance;
  maxSteps?: number;
  maxModelCalls?: number;
  maxObservationBytes?: number;
  context?: string;
  vision?: boolean | 'fallback' | 'only';
  providerOptions?: Record<string, Record<string, unknown>>;
};
```

| Key | Type | Default | Valid range | Notes |
| --- | --- | --- | --- | --- |
| `model` | `string \| ModelConfig \| ModelInstance` | unset | - | No implicit default. Unset means acquiring `agent` fails with `MODEL_UNAVAILABLE`. Naming a model that differs from the one passed to `createAgent({ model })` is `INVALID_CONFIG`. |
| `visionModel` | `string \| ModelConfig \| ModelInstance` | `agent.model` | - | Model used by calls with `vision`. Same three forms as `model`. Built on first vision call. |
| `maxSteps` | `number` | `25` | integer 1-100 | Committed actions per agent call |
| `maxModelCalls` | `number` | `25` | integer 1-100 | Model requests per agent call |
| `maxObservationBytes` | `number` | `1048576` | integer 1024-16777216 | Observation payload ceiling. Not a `limits` key. |
| `context` | `string` | unset | at most `limits.maxAgentContextBytes` UTF-8 bytes | Trusted project context prepended to agent prompts. Exceeding the budget is `INVALID_CONFIG`. |
| `vision` | `boolean \| 'fallback' \| 'only'` | `false` | - | Project-wide default for the per-call `vision` option. `'fallback'` behaves like `false` for `assert`, `waitFor`, and `extract`; `'only'` sends pixels instead of the tree. A per-call value wins. |
| `providerOptions` | `Record<string, Record<string, unknown>>` | unset | object keyed by provider name | AI SDK provider options sent with every model call of both `act` and the judgments, e.g. `{ openai: { reasoningEffort: 'low' } }`. Values pass through unchecked; a non-object provider entry is `INVALID_CONFIG`. `createAgent({ providerOptions })` overrides it for `act`. |

Judgments (`assert`, `waitFor`, `extract`) allow 8192 output tokens per call
and set no temperature, so a reasoning model keeps its default sampling and
has room to think before the answer.

### agent.model

```ts
export interface ModelConfig {
  provider: string;
  id: string;
  endpoint?: string;
  /** Environment variable containing the provider credential. */
  apiKeyEnv?: string;
}

export interface ModelInstance {
  readonly specificationVersion: string;
  readonly provider: string;
  readonly modelId: string;
}
```

| Form | Example | Behavior |
| --- | --- | --- |
| String | `'openai/gpt-4o'` | Split at the first `/` and routed through the AI Gateway. A leading or trailing `/` is `INVALID_CONFIG`. |
| `ModelConfig` | `{ provider: 'openai', id: 'gpt-4o' }` | `provider` and `id` are required and non-empty |
| `ModelInstance` | `openai('gpt-4o')` | Any AI SDK model instance. Detected structurally; owns its own transport and credentials. |

| `ModelConfig` key | Default | Rules |
| --- | --- | --- |
| `endpoint` | `E2E_MODEL_ENDPOINT`, else the gateway default | Absolute URL of any OpenAI-compatible endpoint. Must be HTTPS unless the host is loopback. The config value wins over the variable. |
| `apiKeyEnv` | `'E2E_MODEL_API_KEY'` | Must match `/^[A-Za-z_][A-Za-z0-9_]*$/` |

Each worker re-resolves the config module and constructs its own model instance,
so an instance never crosses a process boundary. A config whose digest differs
between the runner and a worker fails with `CONFIG_NOT_DETERMINISTIC`.

## credentials

```ts
credentials?: Readonly<
  Record<
    string,
    {
      username: string;
      password: string | SecretProvider;
      allowedOrigins?: readonly string[];
    }
  >
>;

type SecretProvider = () => string | Promise<string>;
```

| Key | Type | Required | Notes |
| --- | --- | --- | --- |
| `username` | `string` | yes | Default username |
| `password` | `string \| SecretProvider` | yes | A static value, or a provider called on every authorized fill — a vault lookup, a freshly computed TOTP. Recorded in the config digest by name only; a resolved value joins redaction the moment it exists and never reaches a model. An `E2E_USER_*` env override wins over a provider. |
| `allowedOrigins` | `readonly string[]` | no | Narrows this credential relative to the target's allowed origins (the engine's `allowedOrigins` declaration). It can only narrow. |

`credentials.user(name)` resolves a configured entry into a `Credential`. The
username is a plain string; the password is an opaque `Secret` that test code
cannot read, accepted only by `locator.fill` and `agent.act` params.

```ts
export interface Secret {
  readonly name: string;
  readonly purpose: 'password' | 'one-time-code' | 'generic-secret';
  readonly [secretBrand]: true;
}

export interface Credential {
  readonly name: string;
  readonly username: string;
  readonly password: Secret;
  readonly [credentialBrand]: true;
}
```

An unconfigured name, or a call outside an active runner, throws
`AUTH_CREDENTIAL_UNAVAILABLE` with exit code 2.

```ts title="e2e.config.ts"
export default {
  targets: [{ name: 'web', platform: 'web', engine: playwright({ url: 'http://localhost:3000' }) }],
  credentials: {
    member: { username: 'member@example.test', password: 'local-dev-only' },
    admin: {
      username: 'admin@example.test',
      password: 'local-dev-only',
      allowedOrigins: ['http://localhost:3000'],
    },
  },
} satisfies E2EConfig;
```

## cache

The adaptive trace cache: each passing `agent.act()` step records the grammar
actions it performed, and the next run replays them zero-turn — diverging to
the live agent mid-step whenever the app no longer matches the recording.
Judgments (`assert`, `waitFor`, `extract`) are never cached.
A step that records no actions creates no entry and skips the cache's
end-state observation.

The cache is **on by default** (`read-write`; an unset mode becomes `read-only` in CI).
Opt out per project with `cache: 'off'`, or per run with `e2e run --no-cache`
— the quickest way to check whether a failure is cache-related.

| Key | Type | Default | Description |
| --- | --- | ---: | --- |
| `mode` | `'off' \| 'read-only' \| 'read-write'` | `'read-write'` | A bare string is shorthand for `{ mode }`. In CI an unset mode is demoted to `read-only` because a committed cache is untrusted input; set `'read-write'` explicitly when CI restores the cache from its own cache service instead of git. `--no-cache` wins over both. |
| `store` | `TraceCacheStore` | file store | Custom entry store (for example a shared remote cache). Exempt from the CI demotion — it is not a committed file cache, and states its own trust through `writable`. Never crosses a process boundary; workers re-resolve the config module. |
| `dir` | `string` | `.e2e/cache` | File store directory, resolved against the project root. |

A replay never passes on mechanics alone. Each entry records the state the
step passed in — the page path and the **end anchors**, the elements that
appeared between the step's first look at the screen and its last — and a
replay self-finalizes only when that state is on screen again. If every
recorded action ran but the effect is missing (a save that never committed,
a record created under the wrong name), the step hands off to the live agent
with an `end-mismatch` notice, which tells it to check whether the step took
effect before doing anything. If the agent then has to act to finish the step,
the entry is evicted and the next passing run records a clean flow, so a
broken recording never accumulates its own repairs.

Anchors skip text that cannot read the same on the next run, such as a minted
key prefix, a countdown, a date, or a clock time, as long as something stable
appeared; a step whose only visible effect is volatile keeps those anchors and
hands off every time rather than passing on mechanics alone. A target whose
recorded fields match several controls on the recording screen (one unlabeled
"Set up" button per card) is recorded with its `position` among them, and a
replay honors that position only when the live screen shows exactly as many.
A distinct accessible name (`aria-label="Set up Coolify"`) makes the position
unnecessary and is the better fix. A step that ends on another page records
that page's first stable anchors too, and its end path is matched up to the
ids the app mints per record (a uuid, a hex or digit run, a long short id), so
a flow that creates a project and lands on it replays even though the next
project has a new id.

An entry is written only once a **verification step** after it passes: an
`expect(...)` assertion, a locator `waitFor`, or an `agent.assert` /
`agent.waitFor` judgment. A later `agent.act` passing does not count, and
neither does the test passing on its own — a trailing act nothing ever checks
is never replayed blind, so pair every `agent.act()` with an assertion of its
outcome to make it cacheable. A failed run writes nothing the failure could
have implicated and evicts the entries it did; the flow re-records on the
next passing run.

Cache-friendly tests also create their own data under names unique to the
run and clean up in `afterEach`, not in their last steps: a replay that finds
two rows with the recorded name hands off rather than guessing, and a run
that fails before its cleanup should not leave duplicates for the next one
to trip over.

Entries are disposable: deleting `.e2e/cache/` slows the next run and changes
nothing else. Every agent step's report records how the cache participated
(`step.cache`: `self-finalized`, `agent-concluded`, or `missed`, with a
reason; a retry attempt records but never replays, so its steps read `missed`
with the reason `retry`).

### Commit your traces

Committing cache entries is opt-in. `e2e init` adds `.e2e/cache/` to
`.gitignore`, so out of the box every machine records its own entries and CI
starts with none: an unset mode is `read-only` there, and with nothing to read
every `agent.act()` runs live.

To share replays, remove the `.e2e/cache/` line from `.gitignore` and commit
the directory. Entries a passing local run wrote then replay in CI and on every
teammate's machine. CI stays `read-only` unless you set `cache: 'read-write'`
explicitly, which is the right call only when CI restores the directory from
its own cache service rather than from git.

Treat committed entries as test data: review them in the same pull request as
the test change that re-recorded them, and delete the directory when a flow
changes so much that the next passing run should record it from scratch.

## limits

Resolved limits are immutable for a run. Per-call options may only lower them.

Every limit is enforced: a key exists here exactly when the runner has an
enforcement site for it, so a configured limit is never a silent no-op.

| Key | Type | Default | Range | Description |
| --- | --- | ---: | --- | --- |
| `maxAgentContextBytes` | `number` | `16384` | 1024-65536 | Trusted agent context |
| `maxLedgerBytes` | `number` | `8192` | 1024-65536 | Prior-step ledger |
| `maxEventsPerStep` | `number` | `1000` | 1-10000 | Events recorded per step |
| `maxModelTokensPerCall` | `number` | `64000` | 1-1000000 | Tokens per model request |

## Environment variables

The runner reads a closed set. Diagnostics are `e2e run --debug` and
`e2e run --ai-trace`.

| Variable | Effect |
| --- | --- |
| `E2E_MODEL` | `provider/model-id` fallback when `agent.model` is unset |
| `E2E_VISION_MODEL` | `provider/model-id` fallback when `agent.visionModel` is unset |
| `E2E_MODEL_API_KEY` | Default provider credential |
| `AI_GATEWAY_API_KEY` | Gateway credential, used when the named key variable holds no value |
| `E2E_USER_<NAME>_USERNAME` | Overrides `credentials.<name>.username` |
| `E2E_USER_<NAME>_PASSWORD` | Overrides `credentials.<name>.password` |
| `CI` | Switches CI defaults and rejects focused tests |
| `E2E_TELEMETRY_DISABLED` | Turns anonymous usage telemetry off, as does `DO_NOT_TRACK`; `e2e telemetry disable` saves the same choice. See [Telemetry](/telemetry) |
| `E2E_TELEMETRY_DEBUG` | Prints every telemetry event to stderr instead of sending it |

### Resolution order

| Setting | Order |
| --- | --- |
| Base URL | the engine's declared `url`, else `APP_URL_REQUIRED` at the first navigation. The runner reads no `APP_URL`; the scaffolded config reads it itself (`url: process.env.APP_URL ?? ...`) |
| Model | the model passed to `createAgent({ model })`, then `agent.model`, then `E2E_MODEL` parsed as `provider/model-id`, then `MODEL_UNAVAILABLE` at `agent` acquisition. One model serves `act` and the judgment calls |
| Vision model | `agent.visionModel`, then `E2E_VISION_MODEL`, then `agent.model` |
| Model credential | the variable named by `agent.model.apiKeyEnv`, else `E2E_MODEL_API_KEY`, then `AI_GATEWAY_API_KEY` |
| Credential username and password | the `E2E_USER_*` variable, then the config value |

"First non-empty" ignores values that are undefined or whitespace only. Naming
`apiKeyEnv` replaces the default variable name rather than adding to it. A
missing model credential is not a config error; it surfaces as
`MODEL_UNAVAILABLE` when the `agent` fixture is first acquired. That check runs
once per run and stops it (exit 2), so a suite without a model reports one
run-level error rather than one blocked step per test. A custom executor with no
model skips the check.

An `E2E_USER_*` pair for a name that is not in the `credentials` block is
ignored. The variable name is the credential name uppercased with every character
outside `A-Z0-9` replaced by `_`, so `power-user` becomes
`E2E_USER_POWER_USER_USERNAME` and `E2E_USER_POWER_USER_PASSWORD`.

### CI

CI mode is on unless `CI` is unset, empty, whitespace only, `0`, or `false`. The
value is trimmed and lowercased first, so `FALSE` is also falsy. Every other
value, including `no` and `off`, turns CI mode on.

| Setting | Local | CI |
| --- | --- | --- |
| `retries` | `0` | `1` |
| `workers` | `max(1, floor(availableParallelism() / 2))` | `1` |
| `test.only` | allowed | `ONLY_IN_CI`, exit code 2 |
