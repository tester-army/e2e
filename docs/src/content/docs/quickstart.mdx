The first run needs no model key. Start your app's dev server, run three
commands in the app's directory, and a browser test goes green against it.
Adding an agent step comes after.

<Aside type="note">
Node.js 22.12 or newer. On Windows, run everything inside WSL.
</Aside>

## Three commands

<Steps>

1. **Scaffold**

   With your dev server up on `http://localhost:3000`:

   <Tabs syncKey="pkg">

   <TabItem label="npm">

   ```bash
   npx @e2edev/e2e@beta init
   ```

   </TabItem>

   <TabItem label="pnpm">

   ```bash
   pnpm dlx @e2edev/e2e@beta init
   ```

   </TabItem>

   </Tabs>

   Accept the defaults: Playwright, AI testing on, and the coding-agent
   skill. `init` adds `@e2edev/e2e`, `@e2edev/playwright`, and `ai` to
   `devDependencies`, a `test:e2e` script, `.e2e/` entries in `.gitignore`,
   and writes two files. It never overwrites a file that exists.

   <Code code={config} lang="ts" title="e2e.config.ts" />

   <Code code={example} lang="ts" title="tests/example.e2e.ts" />

   Every target names the engine that drives it, and the engine declares the
   app: here a URL, on a device a bundle id. `APP_URL` overrides the default
   when you run. A scheme is optional; `localhost:3000` becomes
   `http://localhost:3000` and `app.example.com` becomes
   `https://app.example.com`.

2. **Install**

   ```bash
   npm install
   ```

   Or whatever `init` printed as its `next:` line; it names the package
   manager your lockfile or `packageManager` field points at.

3. **Run**

   ```bash
   APP_URL=http://localhost:3000 npx --no-install e2e run
   ```

   The first run downloads a browser, once. Then:

   ```text
    RUN  e2e v0.7.0 /home/ada/my-app
         run 01a08550-4cfd-780e-a5f6-98980fc63fed · targets: web

    ✓ playwright engine for target "web" prepared 8.85s
    ✓ |web| tests/example.e2e.ts (1 test) 135ms
      ✓ app opens 135ms

    Test Files  1 passed (1)
         Tests  1 passed (1)
      Start at  08:36:59
      Duration  523ms
        Report  .e2e/report.json
   ```

   No model was called. `agent` is configured but nothing asked for it, and
   the runner only checks the model when a test acquires the `agent` fixture.

</Steps>

`npx --no-install e2e list` is the dry run: it collects and selects tests the
way `run` does and prints one line per test and target without opening a
browser.

```text
tests/example.e2e.ts › app opens [web]
```

Every run writes `.e2e/report.json` with the results, attempts, steps,
artifacts, and model usage. Exit codes separate test failures (1) from
configuration (2) and infrastructure (3). A step that runs out of its own
budget or time is a test failure; a missing model is configuration and an
unreachable app is infrastructure. The [CLI reference](/reference/cli) has every flag and the
report shape.

## Add an agent step

The scaffold's `tests/example.e2e.ts` ends with a commented-out agent test.
Give it a goal your app can actually satisfy, or write a new file next to it:

<Code code={agentExample} lang="ts" title="tests/signup.e2e.ts" />

Import `test` from `@e2edev/playwright` when a test touches the `web` fixture:
it is the same runtime `test` as `e2e`'s, typed with the fixture the browser
engine contributes. One goal per `act`. Real values go through `params`, not
through the instruction. The final `expect` is deterministic: it costs no
model calls and cannot vary. There are no waits or sleeps anywhere: queries
poll, actions wait, assertions retry.

Now the run needs a model. There is one, and it comes from the environment:

```bash
E2E_MODEL=openai/gpt-5.4-mini \
E2E_MODEL_API_KEY=... \
APP_URL=http://localhost:3000 npx --no-install e2e run
```

`E2E_MODEL` is a `provider/model-id` string routed through the Vercel AI
Gateway, so one `E2E_MODEL_API_KEY` reaches any provider. Set
`E2E_MODEL_ENDPOINT` to point the same string at another OpenAI-compatible
endpoint instead. To call a provider directly, pass an AI SDK model instance
to `createAgent({ model: openai('gpt-5.4-mini') })`; then the variables are
not read. Either way there is exactly one model: it drives `agent.act` and
judges `agent.assert`, `agent.waitFor`, and `agent.extract`. The runner
checks it once, when the first test acquires the `agent` fixture, and stops
the run with `MODEL_UNAVAILABLE` (exit 2) if it is missing or has no
credential.

`system` shapes how the agent works. Later you can hand it your own tools, or
replace it with a custom executor; [Your own agent](/agents) covers both.

```bash
npx --no-install e2e run tests/signup.e2e.ts   # one file
npx --no-install e2e run --tag smoke           # by tag
npx --no-install e2e run --headed              # watch it happen
npx --no-install e2e run --debug               # save full agent transcripts
npx --no-install e2e run --ai-trace            # record every model call for a trace viewer
```

## Let the runner start your app

Uncomment the `command` line the scaffold left in `playwright(...)` and the
runner spawns your dev server, waits until `url` answers, and stops it when
the run ends, fails, or is interrupted:

<Code code={commandConfig} lang="ts" title="e2e.config.ts" />

```text
 ✓ target "web" command ready 1.20s
```

`reuseExisting: true` attaches to the dev server you already have running
instead of failing with `APP_ALREADY_RUNNING`; CI ignores it, so a leftover
server there is still an error. `log` keeps what the server printed, since
the runner otherwise discards it. The child sees only `PATH`, `HOME`, and the
temp-directory variables plus `command.env`; model credentials and CI tokens
are never inherited, so anything the app needs must be passed explicitly.
Databases and migrations go in `services`, started in order before the
command. Every option is in the [config reference](/reference/config#command).

## Run it in CI

With `command` in place the job is install, browser, run:

```yaml title=".github/workflows/e2e.yml"
name: e2e
on: [pull_request]
jobs:
  e2e:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
      - uses: actions/setup-node@820762786026740c76f36085b0efc47a31fe5020 # v7.0.0
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npx playwright install chromium --with-deps
      - run: npx --no-install e2e run --reporter list,junit
        env:
          E2E_MODEL: openai/gpt-5.4-mini
          E2E_MODEL_API_KEY: ${{ secrets.E2E_MODEL_API_KEY }}
```

`CI` switches the defaults to one worker and one retry and rejects
`test.only`. The full workflow, with artifact uploads and pinned actions, is
on the [CI page](/ci).

## Project notes

Config and test files are ES modules. In an empty directory, `init` creates a
private `package.json` with `"type": "module"`. An existing `package.json`
keeps its module type; `init` prints `npm pkg set type=module` so you can opt
in, which also changes how the package's existing `.js` files run. There is
no `tsconfig.json` requirement; add one for editor completions on
`e2e.config.ts` and `tests/`.

For mobile tests, choose **agent-device** in `init` instead. It defaults to
iOS on macOS and Android elsewhere, and writes a Settings example; see
[Device](/reference/device) for simulator and emulator setup.
