title: How agent steps work
description: What the model sees, what it may do, how a step ends, and what it costs.

An agent step is one `agent.act`, `agent.assert`, `agent.waitFor`, or
`agent.extract` call. The model reads the screen, asks for actions, and ends
the step with a verdict. Every step has a deadline and a model-call budget.

## Who does what

The executor chooses the actions and returns the verdict. The runner
redacts the screen, authorizes and performs each action, enforces budgets,
fills secrets, and writes the report. The built-in agent is the executor
unless the agents entry sets `executor`. [Custom executors](/executors) get
the same redacted screen and the same checked actions.

## What the model sees

For `act`, the first prompt holds the instruction, the params, the completed
steps, and a redacted text snapshot of the screen: roles, names, text, and
states. It holds no raw HTML, cookies, headers, or environment values.
Password fields are masked, and a configured secret value on screen becomes
`<secret:name>`.

After an action, the model gets the changes to the screen, or a new full
snapshot when most of it changed. Node ids stay the same while their
elements exist. A failed action also returns the current screen, so the
model can choose its next action.

Judgments from `assert`, `waitFor`, and `extract` see only the instruction
and the current screen. They don't see completed steps or the acting
agent's summaries. You can set a separate
[judge model](/models#a-judge-of-its-own).

`vision: true` adds a masked screenshot, and `vision: 'only'` judges the
screenshot alone. See the [agent reference](/reference/agent#vision) for
the modes. After a secret fill, no screenshot reaches the model
([why](/reference/security#screenshots-after-a-secret-fill)).

## What the model may do

The agent gets the tools the target's engine supports, such as `tap`,
`type`, `press`, `select`, `scroll`, and `navigate`. A step that declares
credentials also gets `type_secret`. On engines with a keyboard, the agent
can type and press keys in the focused control. When the text snapshot
can't describe a control, pixel tools let the agent take a screenshot and
act at a point. See the
[tool reference](/reference/agent#pixel-tools-screenshot-and-the-point-verbs).

The runner checks each built-in action and counts it against the budget. A
targeted action times out after at most 15 seconds. [Project tools](/tools)
add your own operations, with declared budgets and platforms.

The loop detects repeated calls and cycles. After three failed actions in a
row, it tells the model to change its approach. After five, it asks for a
verdict. It also asks for a verdict when the budget or the deadline is
near.

## How a step ends

A step ends with one of three verdicts:

- `passed`: the screen shows that the step succeeded.
- `failed`: the required condition is false or can't be shown. Too little
  evidence is `ASSERTION_INCONCLUSIVE`.
- `blocked`: a prerequisite, the environment, or a limit stopped the step
  before a product verdict. The error code sets the exit code.

Only `failed` and `blocked` carry an error code. When the built-in agent's
model passes a step with a code, e2e drops the code, the step passes, and
the turn's outcome says so. A [custom executor](/executors) that does this
gets `MODEL_OUTPUT_INVALID`.

| Blocked by | Codes | Exit |
| --- | --- | ---: |
| A credential the app rejected, or one that is not configured | `AUTH_CREDENTIAL_INVALID`, `AUTH_CREDENTIAL_UNAVAILABLE` | 2 |
| An environment that is down | `ENVIRONMENT_UNAVAILABLE` | 3 |
| Seed data or a prerequisite outside the product that is not there | `SEED_DATA_MISSING`, `TEST_SETUP_FAILED` | 2 |
| A budget or the clock | `STEP_BUDGET_EXHAUSTED`, `STEP_TIMEOUT` | 1 |
| An interaction the toolset cannot perform | `AUTOMATION_UNSUPPORTED` | 1 |

The [errors reference](/reference/errors#agenterror) lists every code a
verdict can carry.

## What a step costs

Each call has a model-call budget and a default timeout. See
[budgets](/reference/agent#budgets). Past the budget, the step is
`STEP_BUDGET_EXHAUSTED`. At the deadline, it is `STEP_TIMEOUT`.

- `assert` and `extract` make one judgment, plus one repair call if the
  answer is malformed. When the data is not on screen, `extract` fails with
  `ASSERTION_INCONCLUSIVE` and returns no placeholder.
- `waitFor` makes no model call while the screen stays the same.
- A screenshot adds input tokens to every call that carries it. `act` asks
  for one only when the text snapshot is not enough.
- The [replay cache](/cache) reruns passing `act` steps with no model calls.
- Under a [custom executor](/executors#what-the-executor-handles), `assert`
  uses the `act` budgets.

Use `expect` for exact checks, and give each `act` one goal. When the
provider caches prompts, `--debug` shows the cached share of input tokens
per step.

## Where secrets go

For a `Secret` param, the model gets only its name and purpose. The runner
checks the field the model picked, then fills the value itself. The value
never enters prompts, transcripts, reports, or AI traces.
