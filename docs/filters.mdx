Test filters shorten pull request runs by leaving out tests before they start.
The built-in decision filter sends your diff and test files to a small
[decision model](/decision-models), such as Jev. It asks whether the change
can affect each test, then [starts the likeliest files first](#start-the-likeliest-first).

Filters run only with `--changed-since <ref>`. Without it, every selected test runs.

## Add the decision filter

Install the filter with `ai` 7.0.134 or later.

<CodeGroup>
```bash npm
npm install -D @e2e-dev/decision ai
```

```bash pnpm
pnpm add -D @e2e-dev/decision ai
```

```bash bun
bun add -d @e2e-dev/decision ai
```
</CodeGroup>

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';
import { decisionFilter } from '@e2e-dev/decision';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  filters: [decisionFilter({ model: gateway.decisionModel('typesafe-ai/jev') })],
} satisfies E2EConfig;
```

Set `AI_GATEWAY_API_KEY` before running e2e.

<Accordion title="Use another decision model or provider options">
Any decision model that answers `boolean` questions works. For TypeSafe
directly, use `typeSafeAi.decisionModel('jev-latest')` from
`@ai-sdk/typesafe-ai` and set `TYPESAFE_AI_API_KEY`.

Pass `providerOptions` to `decisionFilter` to include them in every call,
such as `{ gateway: { zeroDataRetention: true } }`.
</Accordion>

## Preview locally

`e2e list` shows exclusions and reasons without starting an app.
It makes the same model calls as a run.

<CodeGroup>
```bash npm
npx e2e list --changed-since origin/main
```

```bash pnpm
pnpm exec e2e list --changed-since origin/main
```

```bash bun
bunx e2e list --changed-since origin/main
```
</CodeGroup>

Commit first so the model can [read your diff](#what-the-model-reads).

## Run on pull requests

Pass `--changed-since` only on pull requests. Pushes, merge queues, and
scheduled runs then keep every test:

```yaml title=".github/workflows/e2e.yml"
steps:
  - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
    with:
      fetch-depth: 0
  # ...
  - run: npx e2e run ${{ github.event_name == 'pull_request' && format('--changed-since origin/{0}', github.base_ref) || '' }}
    env:
      AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
```

`fetch-depth: 0` fetches the base branch and merge base. Missing git,
a non-repository directory, an unknown ref, or unrelated history fails
the run with `INVALID_CHANGED_SINCE`.

<Warning>
Never use this on `pull_request_target`. That event has access to secrets,
and a fork's diff could persuade the model to leave tests out.
</Warning>

On other CI services, fetch the merge base and pass `--changed-since origin/main`
only on pull request builds. See [GitLab](/ci/gitlab#run-only-affected-tests).
With `--shard`, each machine filters only its slice.

<Accordion title="Run every test with an all-tests label">
Omit the flag when a pull request has the `all-tests` label.
Include `labeled` in the events so adding the label starts a run:

```yaml title=".github/workflows/e2e.yml"
on:
  pull_request:
    types: [opened, synchronize, reopened, labeled]
# ...
      - run: npx e2e run ${{ github.event_name == 'pull_request' && !contains(github.event.pull_request.labels.*.name, 'all-tests') && format('--changed-since origin/{0}', github.base_ref) || '' }}
```
</Accordion>

## What always runs

Filters leave the selection unchanged when no files changed, on
`--last-failed` reruns, and on `--watch` reruns after the first.
The command `e2e run || e2e run --last-failed` keeps all failed tests.

The decision filter also keeps tests whose test file, session setup file,
or stored screenshots changed. A change to the loaded config, under any
name, keeps every test.

<Accordion title="Config files and lockfiles that keep every test">
These files keep every test when changed in the project directory,
its descendants, or its parents, including the workspace root:

- `e2e.config.ts`, `.mts`, `.js`, or `.mjs`.
- Gradle's `libs.versions.toml`.
- Known lockfiles, including `pnpm-lock.yaml`, `Podfile.lock`,
  `gradle.lockfile`, `Gemfile.lock`, `go.sum`, and `Cargo.lock`.

The model judges other files and files in sibling projects.
</Accordion>

## What the model reads

The decision filter reads the committed diff since the merge base of `<ref>`
and `HEAD`, test files, and session setup files. Uncommitted and untracked changes reach
it by file name only, including files written by CI steps.

It [redacts secrets](/custom-test-filters#handle-secrets-and-cancellation)
before sending text, except values returned by secret providers.

A test is left out only when both it and its setup rate below 20% likely affected.
Tests the model cannot judge stay in the run.

<Accordion title="Large diffs and failed calls">
A diff over 60 kB keeps every test. A test or setup file too large to
send with the diff keeps its tests. Failed calls keep their tests.
The filter's note explains each case.

If every call fails, such as a fork pull request without an API key,
the filter throws. A filter that throws, returns an invalid result, or
exceeds 5 minutes leaves nothing out and produces a warning.
Later filters still receive its input tests.

If the decision filter fails, it still prioritizes tests whose test file,
setup file, or stored screenshots changed. Custom filters can also
[return scores on failure](/custom-test-filters#score-tests-by-relevance).
A timed-out filter is abandoned; later results or errors do not count.
</Accordion>

## Start the likeliest first

The decision filter scores each test it keeps. Each target starts the files
with the highest scores first, helping failures surface earlier with
`--max-failures` or one worker, the CI default.

| Test | Score |
| --- | --- |
| Its test file, setup file, or stored screenshots changed | 100% |
| Every other test | The higher of its rating and its setup's; a missing rating counts as 50%. |

<Accordion title="How scores order files and targets">
Files start in four bands: 75% and up, 50% up to 75%, 25% up to 50%,
and under 25%. A file takes the band of its highest-scoring test.

With multiple workers, the longest file by [timings history](/ci#cache-the-timings-history)
starts first within a band. Files without timings start before timed files.

Targets start by their highest file band, with ties in config order.
Each target orders its own files; setup tests finish before its first test file starts.

A short likely file can start before a long unlikely one, so a full run
with multiple workers can finish later. Reports keep their order;
`e2e list` does not show the scheduling order.
</Accordion>

To set scores in your own filter, return
[`relevance`](/custom-test-filters#score-tests-by-relevance).

## Read the results

The terminal prints each filter's decision. The decision filter also reports model spend:

```text
decision kept 7 of 77 tests, left out 70 (1 call, 17.6k tokens, $0.0007)
```

Spend includes model calls, tokens, and cost when the provider reports it.
The summary has a `Left out` row. If filters leave no tests, the run passes
without starting an app.

When scores span multiple bands, the terminal also prints a line such as
`ranked 7 of 7 tests by relevance, likeliest first`.

| Output | Excluded tests |
| --- | --- |
| `summary.md` and [pull request comment](/github#when-nothing-is-posted) (read-only fork tokens cannot post) | A headline such as `7 passed, 70 left out by filters`, then a folded table with reasons. |
| `junit.xml` and `report.json` | Skipped cases. JSON includes `skip.filter`, `run.filters`, and `run.changes`. See [Reporters](/reference/reporters#test-filters). |
