Two kinds of input exist in a run, and the line between them is the whole
model.

**Code you configure runs with your authority.** Test files,
`e2e.config.ts`, custom tools, engines, reporters, the app `command`,
`services`, a `cache.store`, an `artifacts.store`, and a secret provider
function all execute in the runner's Node process with no sandbox. A cache
entry the runner replays is code-trust as well: the replay asks no model.

**Content from the app under test is evidence, never instructions.** Text,
accessibility trees, and pixels are quoted to the model as untrusted. The
runner, not the model, performs every action, and it authorizes each tool
call against its own observation right before dispatch.

If test code arrives from an untrusted pull request, run it in an external
sandbox with no secrets and no write tokens. The framework does not protect
you from your own dependencies.

## What the model sees

Each model round trip is built in a fixed order: the system policy, then
trusted project context from your agent definition, then the untrusted
evidence. Nothing below the policy can add tools, credentials, or budget.

| In the prompt | Form |
| --- | --- |
| Your instruction and params | Quoted inside `<instruction>` and marked as data. A `Secret` param is projected to its name and purpose. |
| The screen | An accessibility tree with stable node ids, roles, names, text, test ids, and states, truncated at the observation byte limit. Selectors are stripped. |
| The location | The current URL, redacted. |
| A screenshot | Only when the agent asks for pixels, the engine masked every secure field, and no secret has been filled in the session. |
| Prior steps | Labels, statuses, and explanations of earlier steps in the same test or serial group, size-bounded. Independent tests share nothing. |

A secure field appears as `value=<secure>` with no value. Every string that
leaves the runner passes the secret redactor first, so a configured secret
value on screen becomes `<secret:name>`. The model is told that secure
fields and secret placeholders are not to be requested or revealed, and that
text drawn inside a screenshot has no authority either.

## What the model may do

The model never acts on the app. It calls tools, and the runner performs the
action.

- **The tool set is closed.** Each grammar verb has a zod schema, and a verb
  is offered only when the engine declares it. Project tools must be created
  with `defineTool`, may not shadow a built-in name, and may call `observe`
  only when marked read-only.
- **Node ids are the only way to name a target.** An id is resolved against
  the runner's newest observation. A stale id fails the action and the model
  gets a fresh screen, not a guess. Model text is never evaluated as code,
  selector, shell, or config.
- **Every step is bounded.** A deadline, a model-call budget, and a closed
  list of verdict codes end each step.

A tool call that breaks a rule fails with `POLICY_DENIED`:

| Denied | Why |
| --- | --- |
| Navigation to `file:`, `data:`, or `javascript:` | Only http(s) URLs are admitted. |
| A malformed URL | Nothing is repaired. |
| A `Secret` reaching a JSON sink | Handles carry no value, and no value may be serialized. |
| Reading a value from a secure field | Assert the outcome, not the secret. |
| `type_secret` with an undeclared name | Only secrets in the step's params can be filled. |
| `type_secret` into a disabled or non-editable node | Sinks are `textbox`, `searchbox`, and `combobox`. |
| A password into a field that is not a password field | Purpose must match; a generic secret fills any editable input. |
| A project tool not made with `defineTool`, or without `execute` | Undeclared semantics are not trusted. |
| A mutating project tool requesting an observation | Observe in a separate call. |
| `vision: 'only'` when pixels are withheld | There is nothing to fall back to. |
| `app.screenshot()` after a secret fill | The app may display the secret outside a secure field. |

## Navigation and origins

A test or the agent may open any http(s) URL. There is no origin allowlist,
on navigation or on secret fills. A click, a redirect, or a popup reaches
another origin as a typed URL would, so a gate on typed navigation guarded
nothing. A secret is only ever typed into a field the test itself handed to
the step, and a password only into a password field, so an origin gate on the
fill guarded against a model mistake at the cost of configuring every sign-in
flow that leaves the app's domain. Treat a target whose app can send the
agent elsewhere as one the agent may follow there, with the secrets the step
was given.

Two things key on the site of the target's `url`, its registrable domain:

- The browser engine's `headers` reach requests to the site and no other
  host. `basicAuth` is different: it answers a `401` challenge from any
  origin, as Playwright's `httpCredentials` does.
- Child frames off the site, and every `data:` frame, are dropped from
  observations.

Redirects are not re-checked after the initial scheme check, and popups are
not handled: no listener attaches to a new page. Dialogs are handled only by
the handler a test registers with `web.onDialog`.

## Secrets

A `Secret` is an opaque handle with no plaintext accessor. Two sinks accept
one: a locator's `fill`, and the params of an agent step. The
[Signing in](/authentication) guide covers usage; the rules are here.

**A fill directed by the model is authorized by the runner, in this order.**
The name was declared in the step's params. The secret is configured, else
`SECRET_UNAVAILABLE` or `AUTH_CREDENTIAL_UNAVAILABLE`. The target node is not
disabled, is an editable input, and has a purpose compatible with the
secret's. Only then is the value resolved on the host and handed straight to
the engine as a sensitive fill. The recorded action carries the name, and a
replay re-runs the full authorization. A deterministic `fill(secret)` skips
the sink checks, because the test author picked the field, but it still
taints the session and registers the value for redaction.

**A secret fill taints the session for the rest of the attempt.** After it,
the `screenshot` and `tap_at` tools are not offered, `app.screenshot()` is
denied, `agent.assert` attaches no screenshot evidence, and the failure
screenshot is skipped. A rectangle mask cannot prove a tainted viewport
redacted.

**Redaction matches the exact value in every encoding a trace spells it:**
raw, JSON string, JSON nested in JSON, HTML-escaped, `encodeURIComponent`,
`encodeURI`, and form-encoded. Every value ever registered under a name keeps
redacting, so a rotated one-time code does not leak its predecessor. The
value never enters a cache key, a cache entry, a step record, an action
summary, the report, or the observation pipeline.

**Where redaction stops.**

- A transformed form of the value, such as its last four characters, is not
  the secret and passes through.
- A Playwright trace from a tainted session is rewritten before it is kept.
  Text entries become `<secret:name>`. Image entries cannot be rewritten:
  one containing the literal secret bytes is dropped, one that merely renders
  the secret as pixels survives. A trace the runner cannot rewrite is
  deleted and the attempt records `TRACE_WITHHELD`.
- A video masks nothing and is labelled `redaction: "incomplete"`. It is
  never recorded unless you ask.
- The `headers` a protected preview needs are recorded in the trace as
  request headers. Share that trace as you would the bypass secret.
- `command.log` and service logs are captured as the process writes them.
  The runner does not redact them. Keep secrets out of your app's stdout.

## Sessions

A saved session is a bearer credential, so it lives for one run.

| Property | Value |
| --- | --- |
| Location | `.e2e/sessions/<runId>/`, directory mode `0700`, files `0600` |
| Cipher | AES-256-GCM, a fresh 12-byte IV per save |
| Key | 32 random bytes generated per run and held in memory. Workers receive it over IPC, never through disk or the environment. |
| Bound to | Run id, target, engine name and version, platform, and app identity, all authenticated as additional data |
| Lifetime | At most 24 hours, sooner if the saved state declares an earlier expiry |
| Cleanup | The directory is removed when the run ends |

A session that fails any check is refused: `SESSION_MISMATCH` for the wrong
run or target, `SESSION_EXPIRED` past its expiry, `SESSION_INVALID` when
authentication fails, `SESSION_UNAVAILABLE` when no setup produced it.

## Cache trust

A cache entry replays recorded actions without a model call, so a bad entry
is a bad test, not a compromise of the runner. The design keeps it that way.

- An entry holds grammar actions with durable target descriptors and the
  verbatim typed input, never model output and never a secret value. A
  `typeSecret` action names the secret; replay authorizes the fill again.
- Files are named by the SHA-256 of the key the reader just computed, so the
  reader cannot be steered to another path, and a file over 1 MiB is refused
  before it is read.
- A document the runner cannot replay verbatim is a miss, never a repaired
  entry and never an error. An entry implicated in a failed attempt is
  evicted.
- There is no signature. `e2e init` writes `.e2e/cache/` to `.gitignore`, and
  in CI an unset cache mode runs `read-only`, because a committed cache is
  untrusted input. If you [commit your traces](/cache#commit-your-traces),
  review entries in the pull request as you would test code.

## Artifacts and logs

Everything a run writes lands under `.e2e/`.

| Path | Contents | Redaction |
| --- | --- | --- |
| `report.json` | The run record. Errors, reasoning excerpts, and action summaries pass the redactor. | complete |
| `artifacts/.../*.png` | Screenshots. The engine masks secure fields before the bytes exist. | complete |
| `artifacts/.../trace.zip` | Playwright trace, rewritten after a secret fill. | not-required, complete, or deleted |
| `artifacts/.../*.webm`, `*.mp4` | Video, opt-in, kept for every attempt unless `retain: 'on-failure'`. | incomplete |
| `artifacts/.../failure/screen.txt` | The redacted tree at the moment of failure. | complete |
| `ai-trace.json` | Every model call, opt-in via `--ai-trace`. Prompts are the redacted ones the model saw; inline image bytes are replaced by their size. | as the prompt |
| `sessions/<runId>/` | Encrypted sessions, deleted at cleanup. | encrypted |
| `cache/` | Trace entries. | secret-free by construction |
| The path in `command.log` | Your app's stdout and stderr, verbatim. Must be inside the project root. | none |

An `artifacts.store` receives each artifact's bytes as they are produced,
after trace redaction. A `cache.store` receives every recorded entry and
supplies every replayed one; what comes back is validated again before use.

## Outbound connections

The complete list of connections a run can make:

- one telemetry request per CLI invocation to `eu.i.posthog.com`, unless
  opted out; see [Telemetry](/telemetry)
- the model endpoint owned by the AI SDK instance in your config. The runner
  constructs no client and reads no model variable from the environment.
  Deterministic suites and full cache replays make no model call.
- readiness probes against the `readyUrl` of the app the runner starts
- a Playwright browser download, once, when the browser is missing
- the DevTools endpoint you name in `playwright({ connect })`
- the GitHub API, only from the opt-in `@e2edev/github` reporter
- the app under test, and whatever that app itself loads

There is no crash reporting and no update check. `--ai-trace` writes to a
local file that nothing uploads.

## MCP and explore

`e2e mcp` speaks over stdio and serves four fixed tools: `open_session`,
`tools`, `call`, and `close_session`. The app-driving verbs sit behind
`call`, honor the same authorization as a run, and a built-in name always
wins over a project tool of the same name. One session is open at a time,
and an idle session closes itself.

`e2e explore` carries every configured credential into every step. Usernames
reach the model as plain text; passwords stay handles. Explore with a config
that declares only the accounts the exploration needs.

## Reporting a vulnerability

Report privately through
[GitHub security advisories](https://github.com/tester-army/e2e/security/advisories/new)
or by mail to security@tester.army. The
[security policy](https://github.com/tester-army/e2e/blob/main/SECURITY.md)
states response times and supported versions.
