title: Security model

Test code and configuration run with your operating-system permissions.
This includes engines, tools, reporters, stores, secret providers, and app
commands. e2e does not sandbox them. Run untrusted pull request code in an
external sandbox without secrets or write tokens.

The model receives app content as untrusted evidence. It requests actions
through tools; the runner validates and performs those actions. Cached
actions also run with your permission, so review shared cache entries as
you would test code.

## What the model sees

Model requests separate runner policy and trusted project context from app
content. App content cannot grant tools, credentials, or a larger budget.

| In the prompt | Form |
| --- | --- |
| Your instruction and params | Quoted inside `<instruction>` and marked as data. A `Secret` param is projected to its name and purpose. |
| The screen | An accessibility tree with stable node ids, roles, names, text, test ids, and states, truncated at the observation byte limit. Selectors are stripped. |
| The location | The current URL, redacted. |
| A screenshot | When needed or requested, only if the engine proves secure fields are masked and no secret has been filled in the attempt. |
| Prior steps | `agent.act` receives bounded records from the same test or serial group, each step's label and handoff redacted. Judgments use the current screen and instruction, without prior-step records. |

Secure fields appear as `value=<secure>`. Known secret values in model input
and reports become `<secret:name>`. This redaction has limits for transformed
values, images, and app logs, described below.

## What the model may do

Built-in tools have closed schemas and are offered only when the engine
supports them. Project tools must use `defineTool` and cannot replace a
built-in name. Only read-only project tools may request an observation.

A call outside that vocabulary never runs. A tool name the step does not
offer is refused with the names it may use; an argument a schema does not
declare fails the closed schema, and the refusal names the field. Either
refusal is the call's result: the model's next turn is its repair, and
refusals count toward the failure streak that forces a verdict. Neither is
`POLICY_DENIED`.

Element actions resolve node ids against the current observation. A node id
that is not on the current screen fails the action with `LOCATOR_NOT_FOUND`,
and the result carries the screen again so the model can re-aim; that is an
action failure, not a policy denial. Pixel tools can act on coordinates when
screenshots are permitted. The runner does not evaluate model text as code,
selectors, shell commands, or config. Each step has a deadline and a
model-call budget.

A tool call that breaks a rule fails with `POLICY_DENIED`:

| Denied | Why |
| --- | --- |
| Navigation to `file:`, `data:`, or `javascript:` | These URL schemes are forbidden. |
| A malformed URL | Nothing is repaired. |
| A `Secret` reaching a JSON sink | Handles carry no value, and no value may be serialized. |
| Reading a value from a secure field | Assert the outcome, not the secret. |
| `type_secret` with an undeclared name | Only secrets in the step's params can be filled. |
| `type_secret` into a disabled or non-editable node | Sinks are `textbox`, `searchbox`, and `combobox`. |
| A password into a field that is not a password field | Purpose must match; a generic secret fills any editable input. |
| A project tool not made with `defineTool`, or without `execute` | Undeclared semantics are not trusted. |
| A mutating project tool requesting an observation | Observe in a separate call. |
| `vision: 'only'` when pixels are withheld | There is nothing to fall back to. |
| `app.screenshot()` after a secret fill | The app may display the secret outside a secure field. |
| `attachScreenshot(pixels, label)` from an executor or tool after a secret fill | The same rule. The runner cannot tell when the pixels were captured. |

## Navigation and origins

Navigation and secret fills have no origin allowlist. The agent can follow
the app to other sites and use the secrets supplied to the current step
there. Password fills still require a password field.

The browser engine uses a hostname-based site check for two purposes:

- Configured `headers` are added to requests on the target's site.
- Child frames outside that site, and `data:` frames, are omitted from
  observations.

The site check approximates the registrable domain without a public suffix
list, and reads one label deeper under a shared hosting suffix such as
`vercel.app`, `netlify.app`, `pages.dev`, or `github.io`: `myapp.vercel.app`
and `other.vercel.app` are two sites, and headers never cross between them.
The suffixes are listed in `siteOf`'s source
(`packages/e2e/src/internal/urls.ts`); under a shared host the list misses,
headers reach every deployment of that host. `basicAuth` is broader:
it answers a `401` challenge from any origin.

The runner checks forbidden schemes on explicit navigation: `app.open`, the
agent's `navigate` verb, and `device.openLink`. `device.openApp` and the
`open_app` tool take an app id and refuse a link, since the device would
open one as a URL. The runner does not re-check redirects or attach to popup
pages. Register `web.onDialog` to handle browser dialogs.

## Secrets

A `Secret` is an opaque handle with no plaintext accessor. Two sinks accept
one: a locator's `fill`, and the params of an agent step. The
[Signing in](/authentication) guide covers usage; the rules are here.

Before a model-directed fill, the runner checks that the step declared the
secret, the secret is configured, and the target is an enabled editable
input. Passwords require a password field. It then resolves the value on the
host and passes it to the engine. Replay repeats these checks.

A deterministic `fill(secret)` uses the field chosen by test code without
those model-directed field checks. It still registers the value for
redaction and disables pixels for the rest of the attempt.

After any secret fill, screenshot and pixel tools are unavailable,
`app.screenshot()` and an executor's `attachScreenshot` are denied, and the
runner omits assertion and failure screenshots. The app could display the
value anywhere, beyond the field's masked rectangle.

The redactor matches registered values in raw, JSON, HTML, and URL-encoded
forms. It retains old values after a secret rotates, and never rewrites a
marker it wrote, so text that passes it twice reads as text that passed once.
Secret values are excluded from cache entries, model input, and reports. A
step label that spells a value out, such as `app.open('/reset?token=...')` or
``agent.act(`use key ${key}`)``, is recorded, reported, and handed to later
steps as `<secret:name>`. The instruction of that same step still reaches
its own model call as written. `report.json` and `ai-trace.json` pass the
ledger once more as they are written, with every value known by then, so a
value a provider resolved after a step was recorded or a model call closed
is covered too.

### Where redaction stops


- A transformed form of the value, such as its last four characters, is not
  the secret and passes through.
- A Playwright trace from a tainted session is rewritten before it is kept.
  Text entries become `<secret:name>`. Image entries cannot be rewritten:
  one containing the literal secret bytes is dropped, one that merely renders
  the secret as pixels survives. A trace the runner cannot rewrite is
  deleted and the attempt records `TRACE_WITHHELD`.
- A video masks nothing and is labelled `redaction: "incomplete"`. It is
  never recorded unless you ask.
- The `headers` a protected preview needs are recorded in the trace as
  request headers. Share that trace as you would the bypass secret.
- `command.log` and service logs are captured as the process writes them.
  The runner does not redact them. Keep secrets out of your app's stdout.

## Sessions

Saved sessions contain authentication state. They are encrypted and last
for one run.

| Property | Value |
| --- | --- |
| Location | `.e2e/sessions/<runId>/`, directory mode `0700`, files `0600` |
| Cipher | AES-256-GCM, a fresh 12-byte IV per save |
| Key | 32 random bytes generated per run and held in memory. Workers receive it over IPC, never through disk or the environment. |
| Bound to | Run id, target, engine name and version, platform, and app identity, all authenticated as additional data |
| Lifetime | At most 24 hours, sooner if the saved state declares an earlier expiry |
| Cleanup | The directory is removed when the run ends. It carries an `owner.json` naming the runner's pid: a run killed before cleanup (a third Ctrl-C, `SIGKILL`, a crash) leaves its directory behind with its key gone, and the next run removes any sibling older than 24 hours whose pid is no longer running |

Invalid, expired, missing, or mismatched sessions are refused. See the
[session errors](/reference/errors) for the corresponding codes.

## Cache trust

Shared cache entries deserve the same review as test code. They can replay
actions without consulting a model and are not signed.

The runner validates entries before use. Invalid entries become misses.
Files are named by a hash of the expected key and refused if larger than
1 MiB. Entries store actions and a redacted summary; replay executes only
the actions. Secret fills store a name and authorize the fill again.

`e2e init` ignores `.e2e/cache/` in Git. If you choose to
[commit recordings](/cache#commit-your-traces), review their actions and typed
values. CI defaults to read-only when no cache mode is configured.

## Artifacts and logs

By default everything a run writes lands under `.e2e/`. The `--artifacts`
flag moves the artifact root, and `command.log` is whatever project-relative
path you configure.

| Path | Contents | Redaction |
| --- | --- | --- |
| `report.json` | The run record. Step labels, errors, model turns, reasoning excerpts, and action summaries pass the redactor. | complete |
| `artifacts/.../*.png` | Screenshots. Secure fields are masked before screenshots are returned or saved as artifacts. | complete |
| `artifacts/.../trace.zip` | Playwright trace, rewritten after a secret fill. | not-required, complete, or deleted |
| `artifacts/.../*.webm`, `*.mp4` | Video, opt-in, kept for every attempt unless `retain: 'on-failure'`. | incomplete |
| `artifacts/.../failure/screen.txt` | The redacted tree at the moment of failure. | complete |
| `ai-trace.json` | Every model call, opt-in via `--ai-trace`. Run names, prompts, model output, tool-call arguments, errors, and provider metadata pass the redactor, once as recorded and once as written; inline image bytes are replaced by their size. Written readable by its owner only. | complete |
| `sessions/<runId>/` | Encrypted sessions and the run's `owner.json` (pid, start time), deleted at cleanup; a killed run's directory goes once it is a day old and its runner has exited. | encrypted |
| `cache/` | Trace entries. | secret-free by construction |
| The path in `command.log` | Your app's stdout and stderr, verbatim. Must be inside the project root. | none |

An `artifacts.store` receives each artifact's bytes as they are produced,
after trace redaction. A `cache.store` receives every recorded entry and
supplies every replayed one; what comes back is validated again before use.

## Outbound connections

Built-in features may connect to:

- one telemetry request per CLI invocation to `eu.i.posthog.com`, unless
  opted out; see [Telemetry](/telemetry)
- the provider endpoint used by your configured model. Deterministic tests
  and fully replayed action steps make no model call.
- readiness probes against the `readyUrl` of the app the runner starts
- a Playwright browser download, once, when the browser is missing
- the DevTools endpoint you name in `web({ connect })`
- the GitHub API, only from the opt-in `@e2edev/github` reporter
- the app under test, and whatever that app itself loads

There is no crash reporting or update check. `--ai-trace` writes a local
file without uploading it. Your test code, plugins, and app can make
additional connections.

## MCP and explore

`e2e mcp` uses stdio and the same action authorization as a test run. It
allows one open session at a time and closes idle sessions.

`e2e explore` carries every configured credential into every step. Usernames
reach the model as plain text; passwords stay handles. Explore with a config
that declares only the accounts the exploration needs.

## Reporting a vulnerability

Report privately through
[GitHub security advisories](https://github.com/tester-army/e2e/security/advisories/new)
or by mail to security@tester.army. The
[security policy](https://github.com/tester-army/e2e/blob/main/SECURITY.md)
states response times and supported versions.
