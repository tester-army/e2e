title: Project tools
description: Add tools for test APIs, data setup, and device operations.
---

Pass tools to `createAgent` so the agent can call your test API or perform
other project-specific operations during a goal. Wrap each AI SDK tool with
`defineTool` to declare whether it changes state and which platforms support it.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { createAgent, defineTool } from 'e2e/agent';
import { playwright } from '@e2edev/playwright';
import { gateway, tool } from 'ai';
import { z } from 'zod';

const seedCart = defineTool(
  tool({
    description: 'Seed the cart with a SKU via the store test API',
    inputSchema: z.object({ sku: z.string() }),
    execute: async ({ sku }) => {
      const baseUrl = new URL(process.env.APP_URL ?? 'http://localhost:3000');
      baseUrl.pathname = `${baseUrl.pathname.replace(/\/+$/, '')}/`;
      const url = new URL('api/test/cart', baseUrl);
      url.searchParams.set('sku', sku);
      const response = await fetch(url);
      if (!response.ok) throw new Error(`Cart seeding failed: HTTP ${response.status}`);
      return response.text();
    },
  }),
  { mutates: true },
);

export default {
  targets: [{ engine: playwright({ url: process.env.APP_URL ?? 'http://localhost:3000' }) }],
  agents: { default: createAgent({ model: gateway('openai/gpt-5.6-luna'), tools: { seedCart } }) },
} satisfies E2EConfig;
```

The agent can now seed a cart before checking out:

```ts
await agent.act('seed the cart with SKU {sku}, then check out', {
  params: { sku: 'SHIRT-BLUE-M' },
});
```

Built-in tool names are reserved. `createAgent` rejects a project tool with
a name such as `tap`, `screenshot`, or `complete_step`.

## Declare what a tool does

`defineTool` takes the AI SDK tool and these annotations:

| Annotation | Meaning |
| --- | --- |
| `mutates: true` | Changes state. The runner reserves an action slot and runs the tool in the action queue. The call creates a replay gap in the [trace cache](/cache). |
| `mutates: false` | Read-only. Runs without an action slot and may observe the screen. |
| `platforms: ['ios', 'android']` | Offers the tool only on those platforms. Omit this to offer it on every target. |

A failed call still consumes its action slot. The runner checks the budget
before dispatch, including when the model requests several calls at once.

## Observe from a tool

A read-only tool can observe the redacted screen. This example saves a
masked screenshot as report evidence when pixels are available:

```ts
import { randomUUID } from 'node:crypto';
import { defineTool, getToolContext } from 'e2e/agent';
import { tool } from 'ai';
import { z } from 'zod';

const captureEvidence = defineTool(
  tool({
    description: 'Save a screenshot as evidence in the report',
    inputSchema: z.object({}),
    execute: async (_input, executionOptions) => {
      const context = getToolContext(executionOptions);
      const observation = await context.observe({ pixels: true });
      const pixels = observation.pixels;
      if (pixels === undefined) {
        return { withheld: observation.pixelsWithheld ?? 'UNSUPPORTED_CAPABILITY' };
      }
      const id = await context.attachScreenshot(pixels, `evidence-${randomUUID()}`);
      return { evidence: id };
    },
  }),
  { mutates: false },
);
```

`observe()` returns a redacted text snapshot. Request `tree: true` for the
node tree or `pixels: true` for a masked screenshot. The same restrictions
apply as for the built-in agent, including withholding pixels after a secret fill.

Observe in a separate read-only tool. A mutating tool already occupies the
action queue, so observing from inside it would wait on its own operation.

`attachScreenshot(pixels, label)` adds the image to the step's artifacts and
returns its artifact id. Use a unique label for each capture to avoid
overwriting an earlier image.

## Device toolkits

`@e2edev/agent-device` ships a ready tool pack for its engine:

```ts
import type { E2EConfig } from 'e2e';
import { createAgent } from 'e2e/agent';
import { agentDevice } from '@e2edev/agent-device';
import { agentDeviceTools } from '@e2edev/agent-device/tools';
import { gateway } from 'ai';

const iphone = agentDevice({ platform: 'ios', app: 'Settings' });

export default {
  targets: [{ engine: iphone }],
  agents: {
    default: createAgent({
      model: gateway('openai/gpt-5.6-luna'),
      tools: agentDeviceTools(iphone),
    }),
  },
} satisfies E2EConfig;
```

It adds `open_app`, `swipe`, and `alert` on device targets.
Screenshots and point actions come from the engine's built-in tools.
See the [agent-device reference](/reference/agent-device#agent-tools).
