Agent steps use the model you set in `e2e.config.ts`. The model comes from
an [AI SDK](https://ai-sdk.dev/providers) provider: a gateway, a direct API
key, a local server, or your [subscription](/subscriptions). `e2e init`
offers these choices and writes the config. For a first setup, follow the
[quickstart](/quickstart#use-a-subscription-or-api-key).

Tests without agent steps need no model. The built-in agent needs a model
that supports tool calls and images. [Decision models](/decision-models)
such as Clef or Jev run through a custom executor instead.

## Pick a gateway or a provider

The built-in agent needs the `ai` package, whatever the provider:

<CodeGroup>
```bash npm
npm install -D ai
```

```bash pnpm
pnpm add -D ai
```

```bash bun
bun add -d ai
```
</CodeGroup>

There is no default model. The config picks the model, and the provider
reads its own key from the environment. A gateway reaches many providers
with one key. To change a config, replace its model import and `model`
value:

<Tabs>
  <Tab title="Vercel AI Gateway">

`gateway` comes with the `ai` package. Set `AI_GATEWAY_API_KEY`, or use a
[Vercel OIDC token](#vercel-oidc-instead-of-a-key) with no key.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="OpenRouter">

Install `@openrouter/ai-sdk-provider` and set `OPENROUTER_API_KEY`. Use
`agent` as `agents.default`:

```ts title="Model setup"
import { openrouter } from '@openrouter/ai-sdk-provider';

const agent = { model: openrouter('openai/gpt-6-luna-fast') };
```
  </Tab>
  <Tab title="Provider API key">

Install the provider's AI SDK package and set its API key. For OpenAI,
install `@ai-sdk/openai` and set `OPENAI_API_KEY`. Use `agent` as
`agents.default`:

```ts title="Model setup"
import { openai } from '@ai-sdk/openai';

const agent = { model: openai('gpt-6-luna') };
```

Other providers work the same way, with their own package, model IDs, and
credentials. See [AI SDK providers](#ai-sdk-providers).
  </Tab>
  <Tab title="Local or self-hosted">

Install `@ai-sdk/openai-compatible`. Set the endpoint URL and a model ID the
endpoint serves. Add `apiKey` if the server needs one. Use `agent` as
`agents.default`:

```ts title="Model setup"
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

const local = createOpenAICompatible({
  name: 'local',
  baseURL: 'http://127.0.0.1:11434/v1',
  // apiKey: process.env.LLM_API_KEY,
});

const agent = { model: local.chatModel('your-model-id') };
```
  </Tab>
</Tabs>

Model IDs depend on the provider. Gateways usually use `provider/model`.
Direct providers use their own IDs.

### Vercel OIDC instead of a key

Without `AI_GATEWAY_API_KEY`, `gateway()` signs in with a Vercel OIDC token.
Sign in to the Vercel CLI and link the project one time. The gateway then
gets a short-lived token for that project and refreshes it:

<CodeGroup>
```bash npm
npx vercel login
npx vercel link
npx e2e run
```

```bash pnpm
pnpm dlx vercel login
pnpm dlx vercel link
pnpm exec e2e run
```

```bash bun
bunx vercel login
bunx vercel link
bunx e2e run
```
</CodeGroup>

The gateway uses a valid `VERCEL_OIDC_TOKEN`. Else it gets a token for the
project in `.vercel/project.json`, found from the working directory upward.
e2e loads no `.env` file. A token from `npx vercel env pull` works when your
shell exports it, or when the config loads the file with
[`process.loadEnvFile()`](/reference/config#loading).

An OIDC failure is `MODEL_PROVIDER_FAILED`, and the message names only
`AI_GATEWAY_API_KEY`. Make sure the Vercel CLI is signed in and
`.vercel/project.json` exists.

## AI SDK providers

Every AI SDK provider that supports tool calls works. Select yours:

<ModelProvider show="select" />

A provider that is not in the list also works if it implements the AI SDK
language model specification v2 or later. Its model must support tool calls
and images.

<Steps>
  <Step title="Install the provider package">
  Install `ai` and the provider package:

  <ModelProvider show="install" />
  </Step>
  <Step title="Set the credentials">
  The provider reads its credentials from the environment. e2e loads no
  `.env` file. Export the variables in your shell or CI, or load the file in
  the config with [`process.loadEnvFile()`](/reference/config#loading).

  <ModelProvider show="env" />

  If a key is missing or wrong, the first agent step fails with
  `MODEL_PROVIDER_FAILED`. Some providers read the key when the config
  loads. For those, a missing key stops the run with `CONFIG_LOAD_FAILED`.
  </Step>
  <Step title="Add the model to the config">
  Set the model in `agents.default`. The model ID is an example. Use a model
  that supports tool calls and images.

  <ModelProvider show="config" />
  </Step>
</Steps>

<Accordion title="DeepSeek V4 and Meta Muse Spark">
These models refuse the forced tool choice that agent steps ask for.
DeepSeek's V4 models (`@ai-sdk/deepseek`) refuse it because they think by
default. Muse Spark models accept only `auto`. e2e sends the step again with
`auto` and an instruction to reply with tool calls only. Later steps on that
model start that way, so thinking can stay on.
</Accordion>

## Several models in one config

Give each model its own agent name:

```ts title="e2e.config.ts"
export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: { model: gateway('openai/gpt-6-luna-fast') },
    careful: { model: gateway('anthropic/claude-sonnet-5') },
  },
} satisfies E2EConfig;
```

Run with `npx e2e run --agent careful`, or
[choose an agent in a test](/agents). Agents don't inherit from each other,
so an entry without a `model` doesn't use the one from `default`.

To switch a model without editing the config, read an environment variable:

```ts title="Agent setup"
const agent = {
  model: gateway(process.env.MODEL ?? 'openai/gpt-6-luna-fast'),
};
```

### A judge of its own

By default, one model drives `agent.act` and answers `agent.assert`,
`agent.waitFor`, and `agent.extract`. Set `judge` to use another model for
those checks:

```ts title="Agent setup"
const agent = {
  model: gateway('openai/gpt-6-luna-fast'),
  judge: gateway('anthropic/claude-sonnet-5'),
};
```

A judgment sees the current screen and the question, not the acting agent's
transcript or summaries. Reports name the model of each judgment. `judge`
takes an AI SDK language model. Clef and Jev use a different API: use the
[decision executor](/decision-models) for `agent.act` and `agent.assert`.

## Data retention and compliance

Model input is the redacted screen, the step instruction, and the
screenshots the agent asks for. e2e reads nothing back from the provider
after a response, so a run needs no state stored by the provider.

Every model request names e2e. The `User-Agent` starts with
`e2e/<version> (<platform>; <arch>)`, and `HTTP-Referer:
https://tester.army/e2e` and `X-Title: e2e` credit the traffic on Vercel AI
Gateway and OpenRouter. They replace the same headers on the provider
instance.

<AccordionGroup>
<Accordion title="OpenAI and Azure OpenAI: zero data retention">
Every request to a Responses model (`openai(...)`, `azure(...)`, or
`openai/*` on the gateway) carries `store: false` and a prompt cache key.
Chat Completions models and OpenAI-compatible providers get neither. The
provider keeps no copy of the conversation. A reasoning model's earlier
turns travel inline as encrypted content, and the prompt cache still serves
the repeated prefix.

Organizations with zero data retention need no configuration. To keep
stored responses, set `store` in `providerOptions`. For Azure OpenAI, the
key is `azure`:

```ts title="Agent setup"
const agent = {
  model: openai('gpt-6-luna'),
  providerOptions: { openai: { store: true } },
};
```
</Accordion>
<Accordion title="Anthropic under a BAA">
Agent steps use the Messages API with tool use, prompt caching, images, and
structured outputs. All are eligible under Anthropic's HIPAA readiness.

The agreement covers `api.anthropic.com` only. Call it with
`@ai-sdk/anthropic`, not through a gateway or OpenRouter. Leave `judge`
unset, so one agreement covers every request. Anthropic's Covered Models
need 30-day retention, so organizations with zero data retention can't use
them.
</Accordion>
</AccordionGroup>

## What fails, and where

| Problem | Code | Fix |
| --- | --- | --- |
| A model is a string instead of an AI SDK instance | `INVALID_CONFIG` | Construct it, for example `gateway('openai/gpt-6-luna-fast')`. |
| The built-in agent has no model | `MODEL_UNAVAILABLE` | Set `agents.<name>.model`. |
| Authentication fails on the first model call | `MODEL_PROVIDER_FAILED` | Check the provider's API key or the linked Vercel project, or run `npx e2e login` for a subscription. |
| The `ai` package is missing | `MODEL_UNAVAILABLE` | Install `ai`. See [Pick a gateway or a provider](#pick-a-gateway-or-a-provider). |
| A step's second turn fails with `Item with id 'rs_…' not found` | `MODEL_PROVIDER_FAILED` | Leave `store` off in `providerOptions`, the default, or call OpenAI directly instead of through a gateway. |
| A custom executor's own `model` or `judge` differs from the agents entry's | `INVALID_CONFIG` | See [Custom executors](/executors#keep-the-loop-change-the-vocabulary). |
