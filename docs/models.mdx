Agent steps use the model configured in `e2e.config.ts`. You can use an
[existing subscription](/subscriptions), an API key, or a local server.
e2e uses the [AI SDK](https://ai-sdk.dev/providers). You can use
[all AI SDK providers that support tool calls](#ai-sdk-providers).
`e2e init` offers these choices and writes the config for you. For the first
setup, follow the [quickstart](/quickstart#use-a-subscription-or-api-key).

Tests without agent steps do not need a model. For the built-in agent,
choose a model that supports tool calls and images. Agent steps need the `ai`
package installed, whichever provider you use:

<CodeGroup>
```bash npm
npm install -D ai
```

```bash pnpm
pnpm add -D ai
```

```bash bun
bun add -d ai
```
</CodeGroup>

There is no default model or shared API-key variable. The config selects the
model, and the provider reads its own key from the environment, such as
`AI_GATEWAY_API_KEY`. For a subscription, run `npx e2e login` instead.

## Pick a gateway or a provider

A gateway gives you access to several providers with one API key. A provider
package connects to one provider directly. To change an existing config,
replace its model import and `model` value:

<Tabs>
  <Tab title="Vercel AI Gateway">

`gateway` is included in the `ai` package. Set `AI_GATEWAY_API_KEY`, or use
a [Vercel OIDC token](#vercel-oidc-instead-of-a-key) without a key.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
} satisfies E2EConfig;
```
  </Tab>
  <Tab title="OpenRouter">

Install `@openrouter/ai-sdk-provider` and set `OPENROUTER_API_KEY`.

```ts title="Model setup"
import { openrouter } from '@openrouter/ai-sdk-provider';

const agent = { model: openrouter('openai/gpt-6-luna-fast') };
```

Use `agent` as `agents.default` in your config.
  </Tab>
  <Tab title="Provider API key">

Install the provider's AI SDK package and set its API key. For OpenAI,
install `@ai-sdk/openai` and set `OPENAI_API_KEY`:

```ts title="Model setup"
import { openai } from '@ai-sdk/openai';

const agent = { model: openai('gpt-6-luna') };
```

Use `agent` as `agents.default`. Other AI SDK providers work the same way,
with their own package, model IDs, and authentication settings. See
[AI SDK providers](#ai-sdk-providers).
  </Tab>
  <Tab title="Local or self-hosted">

Install `@ai-sdk/openai-compatible`. Set the endpoint URL and a model ID
served by that endpoint:

```ts title="Model setup"
import { createOpenAICompatible } from '@ai-sdk/openai-compatible';

const local = createOpenAICompatible({
  name: 'local',
  baseURL: 'http://127.0.0.1:11434/v1',
  // apiKey: process.env.LLM_API_KEY,
});

const agent = { model: local.chatModel('your-model-id') };
```

Use `agent` as `agents.default`. Add `apiKey` if the server requires one.
  </Tab>
</Tabs>

Model IDs depend on the provider. Gateways usually use `provider/model`;
direct providers use their own model IDs.

### Vercel OIDC instead of a key

Without `AI_GATEWAY_API_KEY`, `gateway()` authenticates with a Vercel OIDC
token. Sign in to the Vercel CLI and link the project once; the gateway then
mints a short-lived token for that project and refreshes it when it expires:

<CodeGroup>
```bash npm
npx vercel login
npx vercel link
npx e2e run
```

```bash pnpm
pnpm dlx vercel login
pnpm dlx vercel link
pnpm exec e2e run
```

```bash bun
bunx vercel login
bunx vercel link
bunx e2e run
```
</CodeGroup>

The token is a valid `VERCEL_OIDC_TOKEN`, otherwise one minted for the
project in `.vercel/project.json`, found by walking up from the working
directory. e2e loads no `.env` files, so a token pulled with
`npx vercel env pull` reaches the gateway only when your shell exports it or
the config loads the file with
[`process.loadEnvFile()`](/reference/config#loading).

An OIDC failure is the same `MODEL_PROVIDER_FAILED` as a bad key, and the AI
SDK's message names only `AI_GATEWAY_API_KEY`. With no key set, check that the
Vercel CLI is signed in and that `.vercel/project.json` exists.

## AI SDK providers

Select a provider. The three steps below show the setup for that provider.

<ModelProvider show="select" />

The list shows the AI SDK providers that support tool calls. A provider that
is not in the list also works if it uses the AI SDK language model
specification v2 or later. Its model must support tool calls and images.

### Install the provider package

Install `ai` and the provider package.

<ModelProvider show="install" />

### Set the credentials

The provider reads its credentials from the environment. e2e does not load
`.env` files. Export the variables in your shell or CI, or load the file in
the config with [`process.loadEnvFile()`](/reference/config#loading).

<ModelProvider show="env" />

If a key is missing or wrong, the first agent step fails with
`MODEL_PROVIDER_FAILED`. Some providers read the key when the config loads.
For these providers, a missing key stops all runs with `CONFIG_LOAD_FAILED`.

### Add the model to the config

Set the model in `agents.default`. The model ID is an example. Use a model
that supports tool calls and images.

<ModelProvider show="config" />

DeepSeek's V4 models (`@ai-sdk/deepseek`) think by default, and in that mode
they refuse the forced tool choice agent steps ask for. The step is sent again
with `auto` and an instruction to reply with tool calls only, and later steps
on that model start that way, so thinking can stay on.

## Several models in one config

Give agents different names to use different models:

```ts title="e2e.config.ts"
export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: { model: gateway('openai/gpt-6-luna-fast') },
    careful: { model: gateway('anthropic/claude-sonnet-5') },
  },
} satisfies E2EConfig;
```

Run with `npx e2e run --agent careful`, or
[choose an agent in a test](/agents). Each model can use a different provider.
Agents do not inherit from each other: an entry without a `model` does not
use `default`'s, see [Agents and personas](/agents).

### Switch a model with an env var

To switch a model without editing the config, read your own environment
variable:

```ts title="Agent setup"
const agent = {
  model: gateway(process.env.MODEL ?? 'openai/gpt-6-luna-fast'),
};
```

### A judge of its own

By default, the same model drives `agent.act` and answers `agent.assert`,
`agent.waitFor`, and `agent.extract`. Set `judge` to use a separate model
for those checks:

```ts title="Agent setup"
const agent = {
  model: gateway('openai/gpt-6-luna-fast'),
  judge: gateway('anthropic/claude-sonnet-5'),
};
```

Judgments use the current screen and the question, without the acting
agent's transcript or summaries. Reports include the model used for each
judgment. See [Custom executors](/executors) if you replace the built-in agent.

## Data retention and compliance

Model input is the redacted screen, the step instruction, and the
screenshots the agent asks for. e2e reads nothing back from the provider
after a response, so a run needs no state kept on the provider's side.

**OpenAI and Azure OpenAI.** Every request carries `store: false` and a
prompt cache key. The provider keeps no copy of the conversation, a
reasoning model's earlier turns travel inline as encrypted content, and the
prompt cache still serves the repeated prefix. Organizations with zero data
retention need no configuration. To keep stored responses, set `store` in
`providerOptions`; the key is `azure` for Azure OpenAI:

```ts title="Agent setup"
const agent = {
  model: openai('gpt-6-luna'),
  providerOptions: { openai: { store: true } },
};
```

**Anthropic under a BAA.** Agent steps use the Messages API with tool use,
prompt caching, images, and structured outputs, all eligible under
Anthropic's HIPAA readiness. The agreement covers `api.anthropic.com` only:
call it directly with `@ai-sdk/anthropic` rather than through a gateway or
OpenRouter, and leave `judge` unset so one agreement covers every request.
Anthropic's Covered Models require 30-day retention and are not offered to
organizations with zero data retention.

## What fails, and where

| Problem | Code | Fix |
| --- | --- | --- |
| A model is a string instead of an AI SDK instance | `INVALID_CONFIG` | Construct it, for example `gateway('openai/gpt-6-luna-fast')`. |
| The built-in agent has no model | `MODEL_UNAVAILABLE` | Set `agents.<name>.model`. |
| Authentication fails on the first model call | `MODEL_PROVIDER_FAILED` | Check the provider's API key or the linked Vercel project, or run `npx e2e login` for a subscription. |
| The `ai` package is missing | `MODEL_UNAVAILABLE` | Run `npm install -D ai`. |
| A step's second turn fails with `Item with id 'rs_…' not found` | `MODEL_PROVIDER_FAILED` | Leave `store` off in `providerOptions`, the default, or call OpenAI directly instead of through a gateway. |
| A custom executor's own `model` or `judge` differs from the agents entry's | `INVALID_CONFIG` | See [Custom executors](/executors#keep-the-loop-change-the-vocabulary). |
