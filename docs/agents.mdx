description: Configure several agents in one suite, pin tests to them, and run one flow as each persona.
---

Define named agents in `agents` to give tests different models, instructions,
or tools. Tests use `default` unless you select another agent.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2edev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web({ url: 'http://localhost:3000' }) }],
  agents: {
    default: { model: gateway('openai/gpt-5.6-luna') },
    thorough: { model: gateway('anthropic/claude-opus-5'), context: 'Verify every claim on screen before concluding.' },
    buyer: { model: gateway('openai/gpt-5.6-luna'), context: 'You are a first-time buyer.' },
    admin: { model: gateway('openai/gpt-5.6-luna'), context: 'You manage orders and approve refunds.' },
  },
} satisfies E2EConfig;
```

An entry takes one of three shapes:

- An options object to configure the built-in agent's model, context, and budgets.
- `createAgent(...)` to add a `system` prompt or [tools](/tools).
- A [custom executor](/executors), directly or in an options object with `executor`.

Use `context` for project vocabulary and `system` on `createAgent` for
instructions about how the acting agent should work. `model` handles acting
and judgments unless you set a separate `judge`. Models that receive
screenshots must accept images. See [Models](/models) and the
[config reference](/reference/config#agents).

## Make the agent yours

When a step fails or takes too many calls, inspect its report or run with
`--debug` to see the transcript. Start with the instruction, then adjust the
agent if the problem affects several tests:

1. Use the labels on screen in the goal.
2. Put shared vocabulary in `context`, or use `agentContext` for one test.
3. Add a `system` prompt through `createAgent` for instructions such as
   verifying a visible confirmation before completing a step.
4. Add [tools](/tools) for operations such as seeding a cart through a test API.
5. Compare models or `providerOptions` by running the same tests with
   `--agent <name>`.

Named agents can use the [trace cache](/cache). Custom tools and executors
have their own replay constraints, described on their pages.

## Pick an agent per run

Use `--agent` to choose the agent for tests that do not specify one:

```bash
npx e2e run --agent thorough tests/checkout.e2e.ts
```

Several names run each unpinned test once per agent:

```bash
npx e2e run --agent buyer,admin
```

## Pin an agent in the suite

A test, describe block, or individual call can select an agent. The closest
setting wins, in this order: call, test, enclosing groups, run.

The abbreviated tests below show how to select an agent at each level.

```ts title="tests/checkout.e2e.ts"
import { test } from 'e2e';

test.describe('checkout as a first-time buyer', { agent: 'buyer' }, () => {
  test('pays for one item', async ({ app, agent }) => { /* ... */ });

  test.describe('refunds', { agent: 'admin' }, () => {
    test('refunds the order', async ({ agent }) => { /* ... */ });
  });

  test('reorders, and the admin approves', async ({ app, agent }) => {
    await app.open('/orders');
    await agent.act('reorder the most recent order');
    // The admin's act call receives the earlier steps in the ledger.
    await agent.act('approve the pending reorder', { agent: 'admin' });
    await agent.assert('the reorder shows as approved');
  });
});
```

`--agent` does not replace an explicitly selected agent. An unknown agent
on a test or group fails during collection. An unknown agent on a call raises
`INVALID_ARGUMENT`. Reports record the agent for each step.

## One flow, several personas

Select several agents to run the same test once with each:

```ts title="tests/checkout.e2e.ts"
import { test } from 'e2e';

test.describe('checkout', { agent: ['buyer', 'admin'] }, () => {
  test('pays for one item', async ({ app, agent }) => { /* runs once per persona */ });
  test('applies a promo code', async ({ app, agent }) => { /* ... */ });
});
```

Each agent gets a separate result and artifact directory. Terminal and JUnit
test names include the agent, such as `[admin]`.

For the list above, `--agent admin` selects only `admin`. A flag with no
matching name, such as `--agent thorough`, leaves both selected agents in place.

A serial group runs as one unit per agent, so its members share the group's
pin. A setup test pins at most one agent.

Selecting an agent does not switch the signed-in user. For signed-in personas,
pair each agent with a `session` in a separate describe block.
[Signing in](/authentication#several-signed-in-users) shows how to create the
sessions and run the tests.
