title: Quickstart
description: Scaffold a project, run the example test in a browser or on a device, then add an agent step.

Scaffold a project and run the example test. No model key is needed for
that. Once it passes, add an agent step and give it a key. The steps are the
same for web and mobile; the wizard's first question picks the engine.

<Note>
Node.js 22.12 or newer. On Windows, run everything inside WSL. A mobile
target also needs Xcode with an iOS simulator runtime, or the Android SDK
with an emulator.
</Note>

## Run your first test

<Steps>
  <Step title="Scaffold">
  In your app's directory:

  <CodeGroup>
  ```bash npm
  npx @e2edev/e2e@canary init
  ```

  ```bash pnpm
  pnpm dlx @e2edev/e2e@canary init
  ```

  ```bash bun
  bunx @e2edev/e2e@canary init
  ```
  </CodeGroup>

  The wizard asks which platform to test, then offers defaults for the rest:
  the Vercel AI Gateway for the model and the coding-agent skill. `init` adds
  `@e2edev/e2e`, the engine packages, and `ai` to `devDependencies`, a
  `test:e2e` script, and `.gitignore` entries, and writes the config, an
  example test, and the skill files. It never overwrites a file that exists.

  <Tabs>
    <Tab title="Web">
    Choose **Web (Playwright)**, with your dev server on `http://localhost:3000`.

  ```ts title="e2e.config.ts"
  import type { E2EConfig } from '@e2edev/e2e';
  import { createAgent } from '@e2edev/e2e/agent';
  import { playwright } from '@e2edev/playwright';
  import { gateway } from 'ai';

  export default {
    // The Vercel AI Gateway serves the model id and reads AI_GATEWAY_API_KEY.
    agents: {
      default: createAgent({
        model: gateway('openai/gpt-5.6-luna'),
        system: 'You are a thorough QA agent. Verify every outcome.',
      }),
    },
    targets: [{
      engine: playwright({
        url: process.env.APP_URL ?? 'http://localhost:3000',
        // Or let the runner start the dev server:
        // command: { executable: 'npm', args: ['run', 'dev'] },
      }),
    }],
  } satisfies E2EConfig;
  ```

  ```ts title="tests/example.e2e.ts"
  import { test } from '@e2edev/playwright';
  import { expect } from '@e2edev/e2e';

  test('app opens', async ({ app, web }) => {
    await app.open('/');
    await expect(web.locator('body')).toBeVisible();
  });
  
  // With the model key in the environment, uncomment:
  // test('the agent drives a flow', async ({ app, agent }) => {
  //   await app.open('/');
  //   await agent.act('one goal in natural language');
  //   await agent.assert('one question about the screen');
  // });
  ```
    </Tab>
    <Tab title="Mobile">
    Choose **Mobile (iOS/Android)**. Check the toolchain first with
    `npx agent-device doctor`. `init` picks iOS on macOS and Android
    elsewhere, points the target at the Settings app so the first run works
    before your own build exists, and sets one worker. On Android the target
    is `platform: 'android'` with `app: 'com.android.settings'`.

  ```ts title="e2e.config.ts"
  import type { E2EConfig } from '@e2edev/e2e';
  import { createAgent } from '@e2edev/e2e/agent';
  import { agentDevice } from '@e2edev/agent-device';
  import { gateway } from 'ai';

  export default {
    // The Vercel AI Gateway serves the model id and reads AI_GATEWAY_API_KEY.
    agents: {
      default: createAgent({
        model: gateway('openai/gpt-5.6-luna'),
        system: 'You are a thorough QA agent. Verify every outcome.',
      }),
    },
    // Replace Settings with your app's bundle id.
    targets: [{ name: 'ios', engine: agentDevice({ platform: 'ios', app: 'Settings' }) }],
    workers: 1,
  } satisfies E2EConfig;
  ```

  ```ts title="tests/example.e2e.ts"
  import { test } from '@e2edev/agent-device';
  import { expect } from '@e2edev/e2e';

  test('Settings opens', async ({ screen }) => {
    await expect(screen.getByRole('button', { name: 'General' })).toBeVisible();
  });

  // With the model key in the environment, uncomment:
  // test('the agent opens General', async ({ agent, device }) => {
  //   await agent.act('open General settings');
  //   await expect(device.locator('role=NavigationBar id=General')).toBeVisible();
  // });
  ```
    </Tab>
  </Tabs>

  A target names the engine that drives it, and the engine declares the app:
  a URL for a browser, a bundle id on a device.
  </Step>
  <Step title="Install">
  <CodeGroup>
  ```bash npm
  npm install
  ```

  ```bash pnpm
  pnpm install
  ```

  ```bash bun
  bun install
  ```
  </CodeGroup>
  </Step>
  <Step title="Run">
  ```bash
  npx e2e run
  ```

  A web target downloads a browser on the first run, once. A device target
  boots the simulator or emulator first; that time is not charged to the run.
  Then:

  ```text
   RUN  e2e v0.12.0 /home/ada/my-app
        run 01a09565-2be0-733b-821e-47801132399b · targets: web

   ✓ |web| tests/example.e2e.ts (1 test) 416ms
     ✓ app opens 416ms

   Test Files  1 passed (1)
        Tests  1 passed (1)
     Start at  13:33:50
     Duration  720ms
       Report  .e2e/report.json
  ```

  No model was called. The runner only checks the model when a test asks for
  the `agent` fixture.
  </Step>
</Steps>

Every run writes `.e2e/report.json`. The exit code says what went wrong: 1 is
a test failure, 2 is configuration, 3 is infrastructure.

## Add an agent step

The scaffold's example file ends with a commented-out agent test. Give it a
goal your app can satisfy, or write a new file next to it:

<Tabs>
  <Tab title="Web">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2edev/playwright';
import { expect } from '@e2edev/e2e';

test('a visitor signs up for a trial', async ({ app, agent, screen }) => {
  await app.open('/');

  await agent.act('sign up for a free trial as {name} with email {email}', {
    params: { name: 'Ada Lovelace', email: 'ada@example.test' },
  });

  await agent.assert('the welcome screen greets Ada by name');
  await expect(screen.getByRole('status')).toContainText('trial');
});
```
  </Tab>
  <Tab title="Mobile">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2edev/agent-device';
import { expect } from '@e2edev/e2e';

test('the agent opens General', async ({ agent, device }) => {
  await agent.act('open {section} settings', { params: { section: 'General' } });

  await agent.assert('the General settings screen is showing');
  await expect(device.locator('role=NavigationBar id=General')).toBeVisible();
});
```

  A device attempt starts inside the configured app, so there is no
  `app.open`. `device.locator` takes the engine's own selector syntax; see
  [Testing iOS and Android](/mobile#the-device-fixture).
  </Tab>
</Tabs>

One goal per `act`. Real values travel through `params`, not through the
instruction. The final `expect` pins the outcome; it never varies, and it is
what the [cache](/cache) verifies a replay against. There are no sleeps
anywhere: queries poll, actions wait, assertions retry.

This run needs a key. The scaffold's model is `gateway('openai/gpt-5.6-luna')`
from the Vercel AI Gateway, which reads `AI_GATEWAY_API_KEY`:

```bash
AI_GATEWAY_API_KEY=... npx e2e run tests/agent.e2e.ts
```

Any AI SDK model instance works in that slot. [Choosing a model](/models)
covers OpenRouter, local servers, and calling a provider directly.

Useful flags while you iterate:

```bash
npx e2e run tests/agent.e2e.ts   # one file, or just agent.e2e.ts
npx e2e run --headed             # watch the browser
npx e2e run --no-cache           # skip replay, run the agent live
npx e2e list                     # what would run, without running it
```
