1. Run \`npx e2e init --yes\` (or the pnpm or bun equivalent for this project). It writes a web config using Vercel AI Gateway, an example test, the e2e skill, and MCP config. It installs nothing yet.
2. Read the e2e skill (\`npx e2e guide\` prints it, \`npx e2e guide <topic>\` prints a topic) and follow it for every step below.
3. Point the target at this app. For a web app, set its URL and the command that starts its dev server. For an iOS or Android app, replace @e2e-dev/web with @e2e-dev/mobile and rewrite the example test for the mobile engine.

5. Install dependencies, run the example test, and fix setup errors until it passes.
6. Write one test for the most important user flow in this app, run it, and iterate until it passes.`;

## Set up with your coding agent

Paste this prompt into Claude Code, Codex, Cursor, or another coding agent
in your app's directory:

<SetupPrompt>

<Prompt description={setupPrompt} children={setupPrompt} actions={["copy", "cursor"]} />

</SetupPrompt>

The agent installs the [e2e skill](/coding-agents), so later prompts such as
"add a test for checkout" need no more setup.

<Note>
Use Node.js 24.8 or newer (22.22.3 or newer on Node.js 22). On Windows, run inside WSL. Mobile tests also
need Xcode with an iOS simulator runtime, or the Android SDK with an emulator.
</Note>

## Set up manually

### Run your first test

<Steps>
  <Step title="Create the test project">
  In your app's directory:

  <CodeGroup>
  ```bash npm
  npx e2e init
  ```

  ```bash pnpm
  pnpm dlx e2e init
  ```

  ```bash bun
  bunx e2e init
  ```
  </CodeGroup>

  Choose **Web (Playwright)** or **Mobile (iOS/Android)**, then a
  subscription, a model provider, or **None** for tests without AI. The
  wizard writes a config and an example test, adds dependencies, and offers
  to set up your coding agent. It keeps existing files.

  <Tabs>
    <Tab title="Web">
    Start your app's dev server at `http://localhost:3000`, or set its address
    in `e2e.config.ts`. You can also [let e2e start it](/web#starting-your-app).

    <Accordion title="Example web config and test">
    This config uses Vercel AI Gateway. The wizard configures the provider you chose.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('app opens', async ({ app, browser }) => {
  await app.open('/');
  await expect(browser.locator('body')).toBeVisible();
});
```
    </Accordion>
    </Tab>
    <Tab title="Mobile">
    Run `npx agent-device doctor` to check your setup. The wizard picks iOS
    on macOS and Android elsewhere. The example opens the Settings app.

    <Accordion title="Example iOS config and test">
    This config uses Vercel AI Gateway. For Android, the wizard sets
    `platform: 'android'` and `app: { bundleId: 'com.android.settings' }`.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { gateway } from 'ai';

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [{ name: 'ios', engine: mobile({ platform: 'ios' }), app: { bundleId: 'Settings' } }],
  workers: 1,
} satisfies E2EConfig;
```

```ts title="tests/example.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('Settings opens', async ({ app, screen }) => {
  await app.open();
  await expect(screen.getByRole('button', 'General')).toBeVisible();
});
```
    </Accordion>

    See [Mobile](/mobile) to use your own app.
    </Tab>
  </Tabs>

  <Accordion title="Use JavaScript instead of TypeScript">
  Rename `e2e.config.ts` to `e2e.config.js` and `tests/example.e2e.ts` to
  `tests/example.e2e.js`. In the config, delete the
  `import type { E2EConfig } from 'e2e';` line and `satisfies E2EConfig`.
  Then add a JSDoc type and set `tests`:

```js title="e2e.config.js"
/** @type {import('e2e').E2EConfig} */
export default {
  tests: 'tests/**/*.e2e.js',
  // ...the rest of the config, unchanged
};
```

  The example test has no types to remove. Name later tests `*.e2e.js`. See
  [JavaScript](/reference/config#javascript) for type checks and mixing
  JavaScript with TypeScript.
  </Accordion>
  </Step>
  <Step title="Run the example">
  <CodeGroup>
  ```bash npm
  npx e2e run
  ```

  ```bash pnpm
  pnpm exec e2e run
  ```

  ```bash bun
  bunx e2e run
  ```
  </CodeGroup>

  e2e downloads a browser or boots the simulator or emulator, checks that
  the app opens, and prints the result. The example makes no model calls,
  so it needs no sign-in or API key.
  </Step>
</Steps>

### Add an agent step

Give `agent.act` one [atomic goal](/core-concepts#goals) per call, then
check the result. Adapt the example to a flow in your app:

<Tabs>
  <Tab title="Web">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-dev/web';
import { expect } from 'e2e';

test('a visitor signs up for a trial', async ({ app, agent, screen }) => {
  await app.open('/');

  await agent.act('sign up for a free trial as {name} with email {email}', {
    params: { name: 'Ada Lovelace', email: 'ada@example.test' },
  });

  await agent.assert('the welcome screen greets Ada by name');
  await expect(screen.getByRole('status')).toContainText('trial');
});
```
  </Tab>
  <Tab title="Mobile (iOS)">
```ts title="tests/agent.e2e.ts"
import { test } from '@e2e-dev/mobile';
import { expect } from 'e2e';

test('the agent opens General', async ({ agent, app, device }) => {
  await app.open();
  await agent.act('open {section} settings', { params: { section: 'General' } });

  await agent.assert('the General settings screen is showing');
  await expect(device.locator('role=navigation-bar id=General')).toBeVisible();
});
```

  `app.open()` launches the app fresh. Without it, a test starts where the
  previous one left the device. `device.locator` takes
  [agent-device selectors](/mobile#the-device-fixture).
  </Tab>
</Tabs>

`params` fill the goal's placeholders. `agent.assert` judges the screen.
`expect` checks an exact value.

<CodeGroup>
```bash npm
npx e2e run tests/agent.e2e.ts
```

```bash pnpm
pnpm exec e2e run tests/agent.e2e.ts
```

```bash bun
bunx e2e run tests/agent.e2e.ts
```
</CodeGroup>

If you chose **None** in the wizard, [add a model](/models) first. Add
`--headed` to watch a web test. Add `--no-cache` to skip cached actions.

### Configure the project

`e2e.config.ts` holds the options. These are the ones most projects change
after `init`:

| To | Set | See |
| --- | --- | --- |
| point at your app | `app.url`, or `app.bundleId` on mobile | [The app under test](/reference/config#the-app-under-test) |
| start the app with the run | `app.command` | [Starting your app](/web#starting-your-app) |
| use a model | `agents.default.model` | [Models](/models) |
| test several browsers or devices | one `targets` entry each, with a `name` | [targets](/reference/config#targets) |
| give tests more time | `timeout`, `actionTimeout`, `assertionTimeout` | [timeout](/reference/config#timeout) |
| retry failed tests | `retries`, `1` in CI | [retries](/reference/config#retries) |
| run tests in parallel | `workers`, `1` in CI | [workers](/reference/config#workers) |
| pick the test files | `tests` | [tests](/reference/config#tests) |
| keep traces and videos | `trace`, `video` | [Recording](/reference/config#recording) |
| write a JUnit report | `reporters: ['list', 'junit']` | [reporters](/reference/config#reporters) |
| sign in and pass API keys | `credentials`, `secrets` | [Signing in](/authentication) |
| write the replay cache in CI | `cache: 'read-write'` | [Caching](/cache) |

<Accordion title="Example config with common options">
```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

const app = {
  url: process.env.APP_URL ?? 'http://localhost:3000',
  command: { executable: 'npm', args: ['run', 'dev'], reuseExisting: true },
};

export default {
  agents: { default: { model: gateway('openai/gpt-6-luna-fast') } },
  targets: [
    { name: 'chromium', engine: web({ viewport: { width: 1440, height: 900 } }), app },
    { name: 'firefox', engine: web({ browser: 'firefox' }), app },
  ],
  timeout: 180_000,
  workers: 4,
  reporters: ['list', 'junit'],
  video: 'retain-on-failure',
} satisfies E2EConfig;
```

`--target firefox` runs one target. Targets that share one `command` share
one server process.
</Accordion>
