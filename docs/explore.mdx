`e2e explore` runs the agent against your app with a goal instead of a test
file. The agent plans a step, does it, and records findings until the goal
is covered or a budget ends, then writes an assessment. It uses the same
model, tools, and action rules as `agent.act()`.

  `e2e explore --headed` drives the app and reports findings as it goes.
</Video>

## Start an exploration

Name the flow and the user goal, and add limits if necessary:

<CodeGroup>
```bash npm
npx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash pnpm
pnpm exec e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash bun
bunx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```
</CodeGroup>

A limit can be "stop before placing the order." With no goal, explore uses
`Explore the app and find bugs`. A failed step does not stop the run.

With no `e2e.config.ts`, explore runs the
[`e2e init`](/reference/cli#e2e-init) wizard first. The exploration starts
right after when nothing is left to do by hand. Otherwise init lists the
steps left, such as `npm install` or setting the model key.
Without a terminal, as in CI, explore fails with `CONFIG_NOT_FOUND`.

## Read the results

The terminal shows each finding and each finished step as they happen:

```text
 ❯  web  Exploring  Explore this bookshop like a careful first-time buyer: browse the catalog, ...
   ⚑ medium issue  Home greeting exposes an unresolved userName template (/)
   ⚑ high issue  Neuromancer shows an impossible negative stock availability (/catalog)
   ✓ 1  Catalog browsing 31.46s · 7 actions · 4 findings
   ⚑ high issue  Cart total does not update when Hyperion quantity increases (/cart)
   ⚑ trivial warning  Checkout newsletter label misspells Receive (/checkout)
   ✓ 2  Cart quantities and removal 19.47s · 4 actions · 3 findings
   ended: the agent covered the goal
```

An `issue` fails the run with exit code 1. A `warning` does not. The final
report puts the most severe issues first. Each finding has the steps to
reproduce it and, when possible, a screenshot. Compare each finding with
its evidence before you act on it. For the other exit codes, the JSON
report, and artifact paths, see the [CLI reference](/reference/cli#e2e-explore).

## Start signed in

Add `--session <name>`, the name of a session that a
[setup test](/authentication) saves:

<CodeGroup>
```bash npm
npx e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash pnpm
pnpm exec e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash bun
bunx e2e explore --session admin 'Explore the admin settings and find bugs'
```
</CodeGroup>

Explore runs only that setup test and restores the session. The explorer
knows the app starts signed in and plans no sign-in step.

Screenshots mask the password field. A value the app shows anywhere else
reaches the model. See
[screenshots after a secret fill](/reference/security#screenshots-after-a-secret-fill).

## Explore a pull request's change

Add `--changed-since <ref>` to explore what the branch changed. The planner
reads the commit messages and their diff since the merge base with the ref,
and spends its steps on the screens that the change can affect. A file no
commit changed is listed by name only. With no
goal, the goal is `Explore what this change affects and find bugs in it`.
When the planner sees every changed file in full and none can change what a
user sees, such as a change to docs or tests only, it can skip the run
before the first step. It says why, the run ends `skipped` in the report,
and it passes. The branch's own commit messages and code can sway that call,
so to tell a skip from a clean exploration, read `run.explore.ended`.

<CodeGroup>
```bash npm
npx e2e explore --changed-since origin/main
```

```bash pnpm
pnpm exec e2e explore --changed-since origin/main
```

```bash bun
bunx e2e explore --changed-since origin/main
```
</CodeGroup>

On GitHub Actions, run it in its own job on `pull_request`. With the
[GitHub reporter](/github) in the config, the findings go to their own pull
request comment. A fork's run can't post; see
[when nothing is posted](/github#when-nothing-is-posted).

```yaml title=".github/workflows/explore.yml"
on: pull_request

jobs:
  explore:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      pull-requests: write
    # An issue exits 1. Keep the findings as a review aid, not a merge gate.
    continue-on-error: true
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          fetch-depth: 0
      # ...install, browsers
      - run: npx e2e explore --changed-since origin/${{ github.base_ref }}
        env:
          AI_GATEWAY_API_KEY: ${{ secrets.AI_GATEWAY_API_KEY }}
          GITHUB_TOKEN: ${{ github.token }}
```

`fetch-depth: 0` puts the base branch in the checkout. Without it, the run
fails with `INVALID_CHANGED_SINCE`.

<Warning>
Never run it on `pull_request_target`. That run holds your secrets, and the
model reads the diff and commit messages a fork wrote.
</Warning>

## If the run stops too early

A run stops after 8 steps or 10 minutes. To reach further into the flow,
raise `--max-steps <n>` (up to 12) or `--timeout <ms>` (up to `900000`, 15
minutes).

## Choose the target and agent

Explore uses the targets, app command, models, and agents from
`e2e.config.ts`. Select them with `--target <name>` and `--agent <name>`.
Without `--target`, explore uses the first target.

## Explore from code

To start an exploration from your own code, with a config value,
cancellation, and progress events, call
[`explore` from `e2e/runner`](/reference/runner#explore).
