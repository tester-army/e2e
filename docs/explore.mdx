Use `e2e explore` to examine a flow without a test file. You give the agent
a goal:

<CodeGroup>
```bash npm
npx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash pnpm
pnpm exec e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```

```bash bun
bunx e2e explore 'Explore the checkout flow like a first-time buyer and report anything off'
```
</CodeGroup>

The agent plans a step, does it, and records findings. It repeats until the
goal is covered or a budget ends, then writes an assessment. A failed step
does not stop the run. The agent uses the same model, tools, and action rules
as `agent.act()`.

## Write a good goal

Name the flow and the user goal. For example: "Explore checkout as a
first-time buyer and check that totals match the cart." Add limits if
necessary, for example "stop before placing the order." With no goal,
explore uses `Explore the app and find bugs`.

## Read the results

The terminal shows each finding when the agent reports it, and each step
when it ends:

```text
 ❯  web  Exploring  Explore this bookshop like a careful first-time buyer: browse the catalog, ...
   ⚑ medium issue  Home greeting exposes an unresolved userName template (/)
   ⚑ high issue  Neuromancer shows an impossible negative stock availability (/catalog)
   ✓ 1  Catalog browsing 31.46s · 7 actions · 4 findings
   ⚑ high issue  Cart total does not update when Hyperion quantity increases (/cart)
   ⚑ trivial warning  Checkout newsletter label misspells Receive (/checkout)
   ✓ 2  Cart quantities and removal 19.47s · 4 actions · 3 findings
   ended: the agent covered the goal
```

An `issue` fails the run with exit code 1. A `warning` does not. The final
report puts the most severe issues first. Each finding has the steps to
reproduce and, when possible, a screenshot. Compare each finding with its
evidence before you act on it.

For the other exit codes, the JSON report, and artifact paths, see the
[CLI reference](/reference/cli#e2e-explore).

## Start signed in

To explore as a signed-in user, use `--session <name>`. The name is a session
that a [setup test](/authentication) saves:

<CodeGroup>
```bash npm
npx e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash pnpm
pnpm exec e2e explore --session admin 'Explore the admin settings and find bugs'
```

```bash bun
bunx e2e explore --session admin 'Explore the admin settings and find bugs'
```
</CodeGroup>

Explore runs only that setup test, then restores the session. The explorer
knows that the app starts signed in, so it does not plan a sign-in step.

If the setup fills a password, the exploration has no screenshots. See
[screenshots after a secret fill](/security#screenshots-after-a-secret-fill).

## If the run stops too early

A run stops after 8 steps or 10 minutes. If it stops before the part of the
flow you need, increase `--max-steps <n>` (up to 12) or `--timeout <ms>` (up
to `900000`, 15 minutes).

## Choose the target and agent

Explore uses the targets, app command, models, and agents from
`e2e.config.ts`. Use `--target <name>` and `--agent <name>` to select them.
Without `--target`, explore uses the first target.

## Explore a whole app

To test a full app or branch, run many explorations at the same time and
verify their findings. See [Bug bashes](/bug-bash).
