## Web

This pipeline runs deterministic and agent tests in one job, for each merge
request and each push to the default branch. It assumes a config
[command](/web#starting-your-app) that starts the app:

```yaml title=".gitlab-ci.yml" expandable
workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

e2e:
  image: node:26
  interruptible: true
  variables:
    APP_URL: http://127.0.0.1:3000
    PLAYWRIGHT_BROWSERS_PATH: $CI_PROJECT_DIR/.cache/ms-playwright
  cache:
    key:
      files:
        - package-lock.json
    paths:
      - .npm/
      - .cache/ms-playwright/
  script:
    - npm ci --cache .npm --prefer-offline
    - npx @e2e-dev/web install chromium --with-deps
    - npx e2e run --reporter list,junit
  artifacts:
    when: always
    expire_in: 7 days
    paths:
      - .e2e/
    reports:
      junit: .e2e/junit.xml
```

GitLab caches only paths inside the project, so `PLAYWRIGHT_BROWSERS_PATH`
moves the [browsers](/reference/web#installing-browsers) there. The cache
keeps them until the lockfile changes.

Make the app's command listen on `127.0.0.1`, the host `APP_URL` names. In
the container, a dev server that listens on `localhost`, such as Vite's,
can bind only `::1`. Then e2e can't reach it and the run fails with
`APP_UNREACHABLE`.

`reports: junit` shows the results in the merge request widget and on the
pipeline's **Tests** tab. `when: always` uploads `.e2e/` when a test fails
too.

## Model key

Add the model key, such as `AI_GATEWAY_API_KEY`, under **Settings > CI/CD >
Variables**, with the visibility **Masked and hidden**. Add user
credentials, such as `E2E_USER_ADMIN_PASSWORD`, the same way. Each job gets
them as environment variables.

- Clear **Expand variable reference**. Otherwise GitLab rejects a masked
  value with `$` and some other characters.
- GitLab masks only values of 8 or more characters, on one line, with no
  spaces. Use **Visible** for a value it can't mask, such as a short
  username.
- Clear **Protect variable** unless the tests run only on protected
  branches. GitLab gives a protected variable only to pipelines on
  protected branches and tags.
- A merge request from a fork runs in the fork's project, with none of
  your variables. When a member runs it in your project, its code can read
  the key. Do that only for code you trust.

## Run only affected tests

To let a [test filter](/filters) leave out the tests a merge request can't
affect, pass the merge request's base to `--changed-since`. Add
`GIT_DEPTH: 0` to the job's `variables` to fetch the full history. Then
replace the `npx e2e run` line with this one, which skips the flag in merge
trains:

```yaml
  script:
    # ...
    - |
      if [ -n "$CI_MERGE_REQUEST_IID" ] && [ "$CI_MERGE_REQUEST_EVENT_TYPE" != merge_train ]; then
        set -- --changed-since "${CI_MERGE_REQUEST_TARGET_BRANCH_SHA:-$CI_MERGE_REQUEST_DIFF_BASE_SHA}"
      fi
      npx e2e run --reporter list,junit "$@"
```

`CI_MERGE_REQUEST_TARGET_BRANCH_SHA` is set in merged results pipelines,
and `CI_MERGE_REQUEST_DIFF_BASE_SHA` in the others. On the default branch
the whole suite runs. See
[Add the decision filter](/filters#add-the-decision-filter).

## Sharding

`parallel` runs one job for each [shard](/ci#sharding). GitLab merges the
JUnit reports of all shards in the merge request widget:

```yaml
e2e:
  parallel: 3
  script:
    # ...
    - npx e2e run --shard $CI_NODE_INDEX/$CI_NODE_TOTAL --reporter list,junit
```

## iOS and Android

Run the mobile jobs on self-managed runners with the shell executor: a Mac
with Xcode for iOS, and Linux with KVM and the Android SDK for Android.
GitLab's hosted macOS runners are headless and don't support `testmanagerd`,
which XCUITest needs. Its hosted Linux runners don't list KVM.

These jobs follow the rules in [Mobile jobs](/ci#mobile-jobs). Replace the
`tags` with your runners' tags. The Android job boots an AVD named `e2e`
that you create on the runner.

```yaml title=".gitlab-ci.yml" expandable
.e2e-mobile:
  timeout: 60m
  interruptible: true
  artifacts:
    when: always
    expire_in: 7 days
    paths:
      - .e2e/
    reports:
      junit: .e2e/junit.xml

e2e-ios:
  extends: .e2e-mobile
  tags: [macos]
  script:
    - npm ci
    - (cd ios && pod install)
    - |
      xcodebuild -workspace ios/MyApp.xcworkspace -scheme MyApp \
        -configuration Release -sdk iphonesimulator \
        -destination 'generic/platform=iOS Simulator' \
        -derivedDataPath build
    - export E2E_DEVICE=$(xcrun simctl create e2e "iPhone 17" com.apple.CoreSimulator.SimRuntime.iOS-26-5)
    - echo "$E2E_DEVICE" > .simulator-udid
    - xcrun simctl bootstatus "$E2E_DEVICE" -b
    - xcrun simctl install "$E2E_DEVICE" build/Build/Products/Release-iphonesimulator/MyApp.app
    - npx e2e run --target ios --reporter list,junit
  after_script:
    - xcrun simctl delete "$(cat .simulator-udid)"

e2e-android:
  extends: .e2e-mobile
  tags: [linux-kvm]
  variables:
    E2E_DEVICE: emulator-5580
  script:
    - npm ci
    - (cd android && ./gradlew :app:assembleRelease)
    - mkdir -p .e2e
    - $ANDROID_HOME/emulator/emulator -avd e2e -port 5580 -no-window -no-audio -no-boot-anim -no-snapshot -gpu swiftshader_indirect > .e2e/emulator.log 2>&1 &
    - timeout 300 adb -s $E2E_DEVICE wait-for-device
    - timeout 300 sh -c 'until [ "$(adb -s $E2E_DEVICE shell getprop sys.boot_completed | tr -d "\r")" = 1 ]; do sleep 2; done'
    - adb -s $E2E_DEVICE install -r android/app/build/outputs/apk/release/app-release.apk
    - npx e2e run --target android --reporter list,junit
  after_script:
    - adb -s $E2E_DEVICE emu kill
```

Each target names its device with `device: process.env.E2E_DEVICE` in
`mobile()`. Then the run drives the device this job booted, never a device
left over from another job on the same machine.

GitLab runs all `script` lines in one shell, so the emulator and
`E2E_DEVICE` stay available to the next lines. `after_script` runs in a new
shell after a failed `script` too, but not after a timeout, so a timed-out
job can leave its device running. The Android job writes the emulator's log
to `.e2e/emulator.log`, so a failed boot shows in the artifacts. A
self-managed runner keeps `~/.agent-device` between jobs, so the XCUITest
runner is built only on the first run.

To run without a simulator or emulator on the runner, lease devices from
a [hosted device service](/mobile#hosted-devices).
