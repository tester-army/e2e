The `screen` fixture builds locators. A `Locator` stores a query and resolves
it when an action, read, or assertion runs. `Locator` extends `Screen`, so
every query also runs on a locator, scoped to its subtree.

```ts title="tests/invoices.e2e.ts"
import { expect, test } from 'e2e';

test('void an invoice', async ({ app, screen }) => {
  await app.open('/invoices');
  const row = screen.getByRole('listitem').filter({ hasText: 'Invoice 42' });
  await row.getByRole('button', 'Void').tap();
  await expect(row.getByText('Voided')).toBeVisible();
});
```

## Match rules

Most operations require exactly one match. A read polls for its one match
until the action timeout, as an action does, then returns the current value
without waiting for it to change. A node the engine reports stale (a resolve
that raced a navigation, or a match the app replaced while it was read) is
re-resolved within the same timeout. Use [`expect`](/reference/expect) to
wait for a value.

| Operation | Zero matches | Multiple matches |
| --- | --- | --- |
| Actions | Poll until the timeout, then `LOCATOR_NOT_FOUND` | `LOCATOR_AMBIGUOUS` |
| Reads | Poll until the timeout, then `LOCATOR_NOT_FOUND` | `LOCATOR_AMBIGUOUS` |
| `count()`, `all()`, `allTextContents()` | `0`, `[]`, `[]` | The count, one locator per match, one text per match |
| `isVisible()`, `isHidden()` | `false`, `true` | `LOCATOR_AMBIGUOUS` |
| Assertions | Poll until the timeout | `LOCATOR_AMBIGUOUS` |
| Any of these under a frame that is not in the document | As zero matches for `count()`, `all()`, `allTextContents()`, `isVisible()`, and `isHidden()`; actions, reads, and assertions poll for the frame until the timeout, then `LOCATOR_NOT_FOUND` | `LOCATOR_AMBIGUOUS` when several frames match |

## Queries

| Method | Example | Returns |
| --- | --- | --- |
| [`getByRole`](#getbyrole) | `screen.getByRole('button', 'Save')` | `Locator` |
| [`getByLabel`](#getbylabel) | `screen.getByLabel('Email')` | `Locator` |
| [`getByPlaceholder`](#getbyplaceholder) | `screen.getByPlaceholder('Search memory...')` | `Locator` |
| [`getByText`](#getbytext) | `screen.getByText('Welcome back')` | `Locator` |
| [`getByDisplayValue`](#getbydisplayvalue) | `screen.getByDisplayValue('ada@example.test')` | `Locator` |
| [`getByTestId`](#getbytestid) | `screen.getByTestId('todo-3')` | `Locator` |

Every query returns a `Locator` synchronously and performs no work. An
option key the query does not take (`{ nam: 'Save' }`) throws
`INVALID_LOCATOR` naming the keys it does.

A string passed to `getByRole` as the name, `getByLabel`, `getByPlaceholder`,
`getByText`, or `getByDisplayValue` matches the whole text, case-sensitive,
after whitespace normalization: `getByRole('button', 'Save')` does not match
`Save changes`. `{ exact: false }` makes it a case-insensitive substring
match, and a `RegExp` matches as written.

Every query accepts `visible: true`, which drops nodes the platform reports
as hidden before the exactly-one rule runs. See
[Hidden duplicates](#hidden-duplicates).

### `getByRole`

Matches nodes by [role](#types), optionally narrowed to an accessible name
and to states.

```ts
/** Creates a lazy role query. An alias such as `img` is rewritten to its role. */
getByRole(role: Role | RoleAlias, options?: RoleOptions): Locator;
/** Creates a lazy role query narrowed to an accessible name: `getByRole('button', 'Sign in')`. */
getByRole(role: Role | RoleAlias, name: TextMatch, options?: Omit<RoleOptions, 'name'>): Locator;
```

```ts
screen.getByRole('button', 'Save');
screen.getByRole('button', 'Save', { exact: false });
screen.getByRole('button', { name: 'Save', disabled: true }); // the object form
screen.getByRole('heading', /welcome/i, { level: 1 });
```

The accessible name goes second, a string or a `RegExp`, with the other
options after it. The object form, `getByRole('button', { name: 'Save' })`,
is the same query. Options ([`RoleOptions`](#types)):

- `name`: the accessible name.
- `checked`, `disabled`, `selected`, `expanded`: require that state.
- `pressed`: requires the pressed state of a toggle button.
- `level`: requires a heading level, 1 through 6.
- `exact`, `visible`: as in [`TextMatchOptions`](#types).

<Note>
A role query never matches a node hidden from the accessibility tree: one
that does not render, or one under `aria-hidden`. `visible` narrows the
other query kinds to the nodes that render, the check `toBeVisible()` makes,
so an `aria-hidden` node that still paints counts as visible there. See
[Hidden duplicates](#hidden-duplicates).
</Note>

#### `img` alias

`img` is an alias, not a role: `getByRole('img', { name })` builds the same
query as `getByRole('image', { name })`, so a test ported from Playwright keeps
its spelling while engines, the replay cache, and reports see `image`. On the
web, `image` covers `<img>` with alt text and any element with `role="img"`;
an `<img alt="">` is decoration and matches nothing.

#### Roles on the web

The web engine derives the roles from HTML the way HTML-AAM does:

- `<progress>` is `progressbar`, `<meter>` is `meter`, `<hr>` is `separator`.
- `<fieldset>` and `<details>` are `group`.
- `<input type="number">` is `spinbutton`. `<input type="file">` is `button`,
  as Chrome and Playwright read it.
- `<select size="3">` is a `listbox`, like a `multiple` one. An
  `<input list>` naming a `<datalist>` is a `combobox`.
- A `<td>` of a `role="grid"` table is a `gridcell`.
- `<thead>` and `<tbody>` are `rowgroup`.
- `<th scope="row">` is `rowheader`. A scope-less `<th>` beside a data cell
  with text or children is also a `rowheader`; header-only rows keep
  `columnheader`. A lone scope-less header in a one-row table has no header
  role, while `scope="col"` and `scope="colgroup"` explicitly keep
  `columnheader`.
- `<figure>` is `figure`, `<article>` is `article`.
- `<header>` and `<footer>` are `banner` and `contentinfo` only outside
  sectioning content or an element with a sectioning role (`article`,
  `complementary`, `main`, `navigation`, `region`).
- `<form>` and `<section>` are `form` and `region` only when they carry an
  `aria-label`, `aria-labelledby`, or `title`.
- `<menu>` is a `list`; only `role="menu"` is a `menu`.

Names follow the same rules:

- A `<legend>`, `<figcaption>`, or `<caption>` names its fieldset, figure, or
  table, so `toHaveAccessibleName` reads what `getByRole('group', { name })`
  matched.
- A role accname names from content (a button, link, heading, tab, menu item,
  option, checkbox, radio, switch, cell, row or column header, row, tree
  item, tooltip) is named by its descendants, a custom element's shadow tree
  included, so `getByRole('checkbox', { name })` and
  `toHaveAccessibleName(name)` agree on a `<div role="checkbox">`.
- An `<input type="submit">` or `type="reset"` with no `value` reads `Submit`
  or `Reset`.

#### Roles on a device

A device engine maps the platform types it has (a tab bar or segmented
control is a `tablist`, a progress indicator a `progressbar`, a stepper a
`spinbutton`) and keeps any other type verbatim, so a role with no native
widget, such as `tooltip` or `figure`, matches nothing on a phone.

#### Editing hosts

A `contenteditable` editing host, the root a TipTap, ProseMirror, Lexical, or
Slate editor renders into, is a `textbox`.

- Its value is its text as rendered (and, while it has focus, its `selection`
  is the text selected inside it). The value keeps spaces and newlines, so
  `toHaveValue` and `inputValue()` read a `white-space: pre-wrap` editor like
  a textarea.
- An empty editor, holding only the `<p><br></p>` or the zero-width no-break
  space its editor pads an empty line with, reads as `''`, and that padding
  is never part of a value.
- It is named by its `aria-label`, `aria-placeholder`, or the
  `data-placeholder` its editor paints; the blocks inside it are content, not
  textboxes.
- The tag does not matter (an `<article contenteditable>` is the editor, not
  an article), while a native control or a drawn surface made editable keeps
  its own role.
- A name taken from a block's `data-placeholder` (TipTap, ProseMirror) goes
  once the editor has content, as the painted hint does, so the host reads as
  an unnamed `textbox` from then on. A name from the host's own `aria-label`,
  `aria-labelledby`, `aria-placeholder`, or `data-placeholder` (Quill) stays.

`getByRole` resolves through Playwright's role selector, which has no such
rule, so a test addresses an editor by role only when the host carries
`role="textbox"`; `getByLabel` and `getByTestId` reach it either way. Anchor
a test on a label or a test id, not on the placeholder.


### `getByPlaceholder`

Matches nodes by placeholder.

```ts
/** Creates a lazy placeholder query. */
getByPlaceholder(text: TextMatch, options?: TextMatchOptions): Locator;
```

```ts
await screen.getByPlaceholder('Search memory...').fill('launch');
```

### `getByText`

Matches nodes by visible text.

```ts
/** Creates a lazy visible-text query. */
getByText(text: TextMatch, options?: TextMatchOptions): Locator;
```

```ts
screen.getByText('Welcome back', { exact: false });
```

#### Echoed text

`getByText` answers with the innermost matching node, so a container that
echoes its child's text counts once. Browsers do this natively; on a device
the engine applies the same rule, since iOS reports a React Native `Text` as
a host view plus a `StaticText` child with the same label. Two matches that
do not contain each other remain `LOCATOR_AMBIGUOUS`.

### `getByDisplayValue`

Matches controls by their displayed value.

```ts
/** Creates a lazy displayed-value query. */
getByDisplayValue(value: TextMatch, options?: TextMatchOptions): Locator;
```

```ts
await screen.getByDisplayValue('ada@example.test').clear();
```

<Note>
In the web engine a `getByDisplayValue` locator cannot be the scope of a
child query or a `has` filter; both fail with `UNSUPPORTED_CAPABILITY`.
Playwright has no selector for a control's current value, so the engine
filters candidates after the fact.
</Note>

### `getByTestId`

Matches the node's `testId`.

```ts
/** Creates a lazy test-id query: a string matches the whole id, case-sensitive; a RegExp tests it. An engine may also match an id without its platform's namespacing. */
getByTestId(id: TextMatch, options?: { visible?: boolean }): Locator;
```

```ts
screen.getByTestId('todo-3');
screen.getByTestId(/total-budgeted$/);
```

- On the web, `testId` is the value of the engine's test-id attribute
  (`web({ testIdAttribute })`, default `data-testid`).
- On a device, it is the accessibility identifier or resource id.
- A string matches the whole id, case-sensitive; a `RegExp` matches as
  written. `visible` is the only option.
- An engine may also match an id without its platform's namespacing, such
  as the mobile engine's [Android resource ids](/reference/mobile#capabilities).

### Hidden duplicates

Every query accepts `visible: true`, which drops nodes the platform reports
as hidden before the exactly-one rule runs. Frameworks often keep a hidden
copy of content in the document, such as a closed drawer or an inactive tab
panel, and without `visible` both copies match.

```ts
await browser.reload();
// Two "No memories yet" nodes exist for a moment; one is display:none.
await expect(screen.getByText('No memories yet', { visible: true })).toBeVisible();
await screen.getByPlaceholder('Search memory...', { visible: true }).fill('launch');
await screen.getByTestId('memory-list', { visible: true }).getByRole('listitem').first().tap();
```

`visible` uses the same visibility check as `toBeVisible()`, `isVisible()`,
and `waitFor()`: what renders, as Playwright reads it.

- Hidden: `display: none`, `visibility: hidden`, a box with no size, a closed
  `<details>` body, and content under `content-visibility: hidden`.
- Not hidden: `aria-hidden`, since a decorative spinner marked with it still
  paints, so `toBeHidden()` on one waits until it leaves.
- A child that sets `visibility: visible` under a hidden parent is visible.
- On the web, text directly under a `display: contents` element with
  `visibility: hidden` is hidden, where Playwright calls it visible.
- It works with scopes, `filter`, `first`, `last`, and `nth`:
  `getByText('Save', { visible: true }).first()` is the first visible match.

Prefer it over `browser.locator('p:visible')`, which ties the test to CSS.

### `filter`

Keeps the matches that pass deterministic filters.

```ts
/** Adds deterministic locator filters. */
filter(options: { hasText?: TextMatch; has?: Locator }): Locator;
```

```ts
const row = screen.getByRole('listitem').filter({ hasText: 'Invoice 42' });
await row.getByRole('button', 'Void').tap();
```

- `hasText` with a string is a case-insensitive substring match over the
  match and its descendants, unlike a query text, which matches exactly. Pass
  a `RegExp` for anything stricter.
- `has` keeps a match whose subtree resolves the inner locator.

| Throws | When |
| --- | --- |
| `INVALID_LOCATOR` | Neither `hasText` nor `has` is given. |
| `INVALID_LOCATOR` | Any other key, even beside them: `hasNot`, `hasNotText`, and `visible` are not filters here. |
| `INVALID_LOCATOR` | `has` is not a runner locator, or was made by another target's screen. |

## Screen actions

| Method | Example | Returns |
| --- | --- | --- |
| [`screen.tapAt`](#screen-tapat) | `screen.tapAt({ x: 120, y: 48 })` | `Promise<void>` |
| [`screen.swipe`](#screen-swipe) | `screen.swipe({ direction: 'up' })` | `Promise<void>` |
| [`screen.scrollUntilVisible`](#screen-scrolluntilvisible) | `screen.scrollUntilVisible(button)` | `Promise<void>` |

`tapAt` and `swipe` act on the viewport. `scrollUntilVisible` scrolls the
viewport, or a node when called on a locator.

### `screen.tapAt`

Taps a viewport point with no node behind it: a pin on a canvas, a control
the tree does not list.

```ts
/** Taps a viewport point, with no node behind it. */
tapAt(point: Point, options?: ActionOptions): Promise<void>;
```

```ts
const map = (await screen.getByRole('image', 'Map').boundingBox())!;
await screen.tapAt({ x: map.x + 360, y: map.y + 70 });
```

- The point is in CSS pixels, the space `boundingBox()` reports in.
- Nothing is resolved or waited for; the page decides what the tap lands on.
- Uses `config.actionTimeout`.
- Prefer a locator when the tree lists the control; a point moves with the
  layout. For a point inside a node, `tap({ position })` reads the node's box
  for you.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | A negative or non-finite coordinate. |
| `UNSUPPORTED_CAPABILITY` | The engine does not list `tap` in its pointer actions. |

<Note>
`tapAt` is not scoped: on a locator it still taps a viewport point.
</Note>

### `screen.swipe`

A viewport-level gesture, in one of two shapes.

```ts
/** Performs a viewport-level swipe: in a direction, or along a path from one point to another. */
swipe(options: SwipeOptions | SwipePathOptions): Promise<void>;
```

```ts
await screen.swipe({ direction: 'up', momentum: 'fast' });

const row = (await screen.getByText('Design review').boundingBox())!;
await screen.swipe({
  from: { x: row.x + row.width - 10, y: row.y + row.height / 2 },
  to: { x: row.x + 10, y: row.y + row.height / 2 },
  duration: 300,
});
```

`{ direction, momentum? }` is a scroll gesture on the screen:

- `direction` is the way the content scrolls, not the finger: `'down'`
  reveals what is below.
- `momentum` is its fling strength, `'none'` by default. `'none'` is a
  plain drag of half the surface, `'slow'` a short fling, `'fast'` a long
  one. How far each carries is the engine's.

`{ from, to, duration? }` is a swipe along a path between two viewport
points: a touch swipe on a device, a pointer drag on a document platform.
That is what reveals a row action, dismisses a sheet, or drags a card between
columns.

- `duration` sets how long the gesture takes, an integer from 16 through
  10000 ms. Omitted, it is the engine's default.

Uses `config.actionTimeout` and takes no `timeout` option.

| Throws | When |
| --- | --- |
| `ACTION_FAILED` | The gesture is rejected. |
| `INVALID_ARGUMENT` | A mix of the two shapes, an out-of-range duration, a coordinate off the plane, or a `timeout` key. |
| `UNSUPPORTED_CAPABILITY` | The engine does not list `swipe` in its actions (a direction) or `swipeTo` in its pointer actions (a path). |

### `screen.scrollUntilVisible`

Scrolls until a locator resolves visibly or times out.

```ts
/**
 * Scrolls until a locator resolves visibly or times out: the viewport on
 * `screen`, the node itself on a locator. `momentum` is the stride of each
 * step, `slow` unless told otherwise.
 */
scrollUntilVisible(
  target: Locator,
  options?: { direction?: ScrollDirection; momentum?: Momentum; timeout?: number },
): Promise<void>;
```

```ts
await screen.scrollUntilVisible(screen.getByRole('button', 'Accept'));
await screen.getByTestId('feed').scrollUntilVisible(row);
```

| Option | Type | Default |
| --- | --- | --- |
| `target` | `Locator` | - |
| `options.direction` | `ScrollDirection` | `'down'` |
| `options.momentum` | `Momentum` | `'slow'` |
| `options.timeout` | `number` | `30000` |

- `momentum` is the gesture of each step, as [`screen.swipe`](#screen-swipe)
  defines it. A longer step is faster but must not carry the target past the
  surface unseen, which is what a virtualized list does.
- `timeout` is its own default, not `config.actionTimeout`. It bounds the
  whole scroll, each swipe included.
- On `screen` each step is a viewport swipe. On a locator the step is a swipe
  of that node, so a feed or a table that is its own scroll container pages
  without the pointer having to hover it first.

| Throws | When |
| --- | --- |
| `INVALID_LOCATOR` | `target` is not a runner locator, or was made by another target's screen. |
| `INVALID_ARGUMENT` | An option it does not take. |
| `LOCATOR_NOT_FOUND` | The deadline expires first, a swipe it cut short included. |

`INVALID_ARGUMENT` before the node is resolved, so the control is never
touched.

| Throws | When |

| `INVALID_ARGUMENT` | An option key the action does not take. |
| `LOCATOR_NOT_FOUND` | No match before the timeout. |
| `LOCATOR_AMBIGUOUS` | More than one match. |
| `ACTION_FAILED` | The action may already have committed; it is never repeated. |

### `tap`

Taps exactly one matching actionable node. `click` is an alias.

```ts
/** Taps exactly one matching actionable node; with `position`, taps that point of its box once it is in view, with no other actionability check. */
tap(options?: TapOptions): Promise<void>;
/** Alias of tap. */
click(options?: TapOptions): Promise<void>;
```

```ts
await screen.getByRole('button', 'Save').tap({ timeout: 10_000 });
await screen.getByRole('image', 'Seat map').tap({ position: { x: 120, y: 48 } });
await row.click({ modifiers: ['Shift'] });
```

Options ([`TapOptions`](#types)):

- `timeout`: the action deadline.
- `modifiers`: the keys held for the click, as a Shift-click extends a
  selection: `Shift`, `Control`, `Alt`, `Meta`, `ControlOrMeta`.
  `ControlOrMeta` is Control on Windows and Linux, Meta on macOS. The
  browser engine holds them.
- `position`: taps at an offset of the node's top-left corner, in CSS
  pixels. The node is scrolled into view when the engine lists
  `scrollIntoView`, then its box is read and the pointer dispatched at the
  point, with no node behind the gesture, so the platform's other
  actionability checks (enabled, not covered) do not run.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | An unknown or repeated modifier, or `modifiers` beside `position`. |
| `UNSUPPORTED_CAPABILITY` | `modifiers` on an engine that does not declare `tapModifiers`, the mobile engine among them; thrown before it acts. |
| `UNSUPPORTED_CAPABILITY` | `position` on an engine without the `tap` pointer action. |
| `ACTION_FAILED` | `position` on a node the browser engine cannot bring into view; its scroll waits for visibility. Other engines fail as they report it. |
| `LOCATOR_NOT_FOUND` | `position` on a node that resolves but never shows a visible box within the timeout. |

### `longPress`

Long-presses exactly one matching actionable node.

```ts
/** Long-presses exactly one matching actionable node. */
longPress(options?: LongPressOptions): Promise<void>;
```

```ts
await screen.getByText('Design review').longPress({ duration: 800 });
```

- `duration` is the hold time in milliseconds, an integer from 100 through

  `delayLongPress`.

### `fill`

Fills exactly one input, replacing its current content.

```ts
/** Fills exactly one input. Secret values are never logged. */
fill(value: string | Secret, options?: ActionOptions): Promise<void>;
```

```ts
await screen.getByLabel('Email').fill('ada@example.test');
await screen.getByLabel('Password').fill(credentials.user('member').password);
```

A `Secret` is resolved on the host right before the call and never logged,
reported, or sent to a model.

<Note>
`fill` sets the value directly and fires no key events. For an input wired
to `keydown` or `keyup`, use [`pressSequentially`](#presssequentially).
</Note>

### `pressSequentially`

Focuses exactly one input and types text through the engine's keyboard, one
character at a time, appending to the current content.

```ts
/**
 * Focuses exactly one input and types `text` through the keyboard, one
 * character at a time, so the app receives key events. A `Secret` is
 * refused; it goes through `fill`.
 */
pressSequentially(text: string, options?: PressSequentiallyOptions): Promise<void>;
```

```ts
await screen.getByLabel('City').pressSequentially('War', { delay: 50 });
```

- An autocomplete, a search-as-you-type box, or a masked input wired to
  `keydown` or `keyup` never reacts to `fill`; this is the action for those.
- `delay` waits that many milliseconds between characters, each sent in its
  own keyboard call. Without it the whole text goes in one call.
- Focus, pauses, and keystrokes share the one action deadline: a pause is cut
  short at it and no character is sent past it.
- It relies on the [keyboard contract](/reference/engine#engine): `type` must
  deliver text as a person typing would, so key events reach the app where
  the platform has them.
- The step records the locator, not the text, like `fill`.

| Throws | When |
| --- | --- |
| `ACTION_FAILED` | The deadline passed mid-text; the error names how many characters landed. |
| `UNSUPPORTED_CAPABILITY` | The engine lacks the `focus` action or the `keyboard` capability; thrown before any node resolves. |
| `INVALID_ARGUMENT` | A `Secret` at runtime (a type error at compile time): a secret is filled, never typed as keystrokes. |

## Locator reads

| Method | Example | Returns |
| --- | --- | --- |
| [`textContent`](#textcontent) | `alert.textContent()` | `Promise<string \| null>` |
| [`inputValue`](#inputvalue) | `input.inputValue()` | `Promise<string>` |
| [`getAttribute`](#getattribute) | `link.getAttribute('href')` | `Promise<string \| null>` |
| [`isVisible`](#isvisible) | `alert.isVisible()` | `Promise<boolean>` |
| [`isHidden`](#ishidden) | `spinner.isHidden()` | `Promise<boolean>` |
| [`isEnabled`](#isenabled) | `button.isEnabled()` | `Promise<boolean>` |
| [`isDisabled`](#isdisabled) | `button.isDisabled()` | `Promise<boolean>` |
| [`isChecked`](#ischecked) | `checkbox.isChecked()` | `Promise<boolean>` |
| [`boundingBox`](#boundingbox) | `map.boundingBox()` | `Promise<{ x, y, width, height } \| null>` |
| [`count`](#count) | `rows.count()` | `Promise<number>` |
| [`all`](#all) | `rows.all()` | `Promise<Locator[]>` |
| [`allTextContents`](#alltextcontents) | `items.allTextContents()` | `Promise<string[]>` |
| [`waitFor`](#waitfor) | `spinner.waitFor({ state: 'hidden' })` | `Promise<void>` |

A read polls for its one match until `config.actionTimeout`, then returns the
current value without waiting for it to change ([Match rules](#match-rules)).
`count`, `all`, and `allTextContents` take a snapshot and do not wait. Use
[`expect`](/reference/expect) to wait for a value.

```ts
if (await screen.getByRole('alert').isVisible()) {
  const message = await screen.getByRole('alert').textContent();
}
await screen.getByTestId('spinner').waitFor({ state: 'hidden' });
```

On a secure field, `textContent`, `inputValue`, `getAttribute`, and
`allTextContents` throw `POLICY_DENIED`, and so do
`expect(locator).toHaveValue`, `toHaveText`, `toContainText`, and
`toHaveAttribute`. `isEnabled`, `isDisabled`, `isChecked`, and `boundingBox`
are allowed there.

### `textContent`

Reads the node's rendered text with whitespace collapsed to single spaces.

```ts
/** Reads normalized text once a match exists, without retrying for a particular value. */

```

```ts

```

- On the web that is what `innerText` reads, not the DOM's `textContent`:
  CSS `text-transform` applies, `display: none` descendants are left out, and
  a `<br>` reads as a space.
- A node that is not rendered itself, such as a `display: none` one, reads
  its DOM text, as `innerText` does.

| Throws | When |
| --- | --- |
| `POLICY_DENIED` | A secure field. |

### `all`

Resolves the query once and returns one `nth(i)` locator per match, so a loop
can act on each row.

```ts
/** One `nth(i)` locator per current match, without auto-waiting; empty when nothing matches. */
all(): Promise<Locator[]>;
```

```ts
for (const row of await screen.getByRole('row').all()) {
  await row.getByRole('checkbox').check();
}
```

- It neither waits nor enforces exactly-one: zero matches is an empty array,
  the same snapshot rule as `count()`. A `frameLocator` whose frame is not in
  the document counts as zero matches here, where an action or assertion
  polls for it.
- Each locator `all()` returns re-resolves when used, so a list that changes
  under the loop can make a later `nth(i)` point at a different row, or at
  nothing. Follow the loop with an assertion on the list.

### `allTextContents`

Reads every match's normalized text in one call.

```ts
/** Reads the normalized text of every current match, without auto-waiting; empty when nothing matches. */
allTextContents(): Promise<string[]>;
```

```ts
expect(await screen.getByRole('listitem').allTextContents()).toEqual(['Alpha', 'Beta']);
```

- Text reads as in [`textContent`](#textcontent).
- It neither waits nor enforces exactly-one: zero matches is an empty array,
  as for [`all`](#all).
- Use [`toHaveText([...])`](/reference/expect#locator-matchers) instead of a
  loop when the point is to check the texts.

| Throws | When |
| --- | --- |
| `POLICY_DENIED` | A secure field. |

### `waitFor`

Waits for the requested locator state.

```ts
/**
 * Waits for the requested locator state, `visible` by default: `attached`
 * for one match, visible or not; `detached` for none; `hidden` for none or
 * a hidden one.
 */
waitFor(options?: { state?: 'attached' | 'detached' | 'visible' | 'hidden'; timeout?: number }): Promise<void>;
```

```ts
await screen.getByTestId('spinner').waitFor({ state: 'hidden' }); // default state: 'visible'
```

| State | Waits for |
| --- | --- |
| `'visible'` (default) | One visible match. |
| `'attached'` | One match, hidden or shown. |
| `'detached'` | No match. |
| `'hidden'` | A hidden match, or none. |

`timeout` defaults to `config.actionTimeout`.

| Throws | When |
| --- | --- |
| `LOCATOR_NOT_FOUND` | The timeout expires. |
| `LOCATOR_AMBIGUOUS` | Several matches, in every state. |
| `INVALID_ARGUMENT` | Any other state, or an option key besides `state` and `timeout`; thrown before anything is resolved. |

## Types

```ts
/**
 * The closed role vocabulary; an unsupported role is a type error. Every
 * engine maps its platform's element types onto these names, so a role query
 * reads the same against a browser and a device. A role the platform has no
 * widget for matches nothing there; it is never a type error.
 */
export type Role =
  | 'button'
  | 'link'
  | 'textbox'
  | 'searchbox'
  | 'combobox'
  | 'listbox'
  | 'option'
  | 'checkbox'
  | 'radio'
  | 'radiogroup'
  | 'switch'
  | 'slider'
  | 'spinbutton'
  | 'progressbar'
  | 'meter'
  | 'image'
  | 'heading'
  | 'tab'
  | 'tablist'
  | 'tabpanel'
  | 'menu'
  | 'menubar'
  | 'menuitem'
  | 'menuitemcheckbox'
  | 'menuitemradio'
  | 'toolbar'
  | 'tooltip'
  | 'tree'
  | 'treeitem'
  | 'list'
  | 'listitem'
  | 'table'
  | 'grid'
  | 'row'
  | 'rowgroup'
  | 'rowheader'
  | 'cell'
  | 'gridcell'
  | 'columnheader'
  | 'separator'
  | 'group'
  | 'article'
  | 'figure'
  | 'form'
  | 'status'
  | 'alert'
  | 'dialog'
  | 'alertdialog'
  | 'main'
  | 'navigation'
  | 'banner'
  | 'contentinfo'
  | 'complementary'
  | 'region';

/**
 * Spellings `getByRole` accepts beside the vocabulary and rewrites to a `Role`
 * before the query is built: `img` is the ARIA name of `image`. An alias never
 * reaches an engine, the replay cache, or a report; a `Role` is what they see.
 */
export type RoleAlias = 'img';

/** A string matches exactly; a RegExp uses its own source and flags. */
export type TextMatch = string | RegExp;

export interface TextMatchOptions {
  /** Exact match, the default. `false` is case-insensitive substring matching; a RegExp ignores it. */
  exact?: boolean;
  /**
   * When true, nodes the platform reports as hidden are excluded before the
   * exactly-one rule is applied, so a visible node with a hidden twin (a
   * prerendered copy kept after navigation, a closed drawer) still resolves.
   * Omitted or false keeps every match, hidden ones included.
   */
  visible?: boolean;
}

/**
 * Role query options. A role query never matches a node hidden from the
 * accessibility tree, on every engine; `visible` (inherited) is the one knob
 * that narrows the other query kinds, to the nodes `toBeVisible()` accepts.
 */
export interface RoleOptions extends TextMatchOptions {
  /** Accessible name filter. */
  name?: TextMatch;
  /** Requires the checked state. */
  checked?: boolean;
  /** Requires the disabled state. */
  disabled?: boolean;
  /** Requires the selected state. */
  selected?: boolean;
  /** Requires the expanded state. */
  expanded?: boolean;
  /** Requires the pressed state of a toggle button. */
  pressed?: boolean;
  /** Requires a heading level, 1 through 6. */
  level?: number;
}

export interface ActionOptions {
  /** Deadline in milliseconds; defaults to `config.actionTimeout`. */
  timeout?: number;
}

/** `longPress` options: the hold time in milliseconds, 100 through 10000, default the engine's own. */
export interface LongPressOptions extends ActionOptions {
  /** Hold time in milliseconds, 100 through 10000; unset, the engine's default. */
  duration?: number;
}

/** `pressSequentially` options: an optional pause between characters. */
export interface PressSequentiallyOptions extends ActionOptions {
  /** Milliseconds to wait between characters; omitted types the whole text in one call. */
  delay?: number;
}

export interface SwipeOptions {
  /** Swipe direction. */
  direction: ScrollDirection;
  /** Fling strength; default `none`. The three values are defined under screen.swipe. */
  momentum?: Momentum;
  from?: never;
  to?: never;
  duration?: never;
}

/** A swipe along a path between two viewport points: a touch swipe on a device, a pointer drag on a document platform. */
export interface SwipePathOptions {
  /** Where the finger goes down. */
  from: Point;
  /** Where it lifts. */
  to: Point;
  /** Gesture duration, an integer from 16 through 10000 ms; omitted = the engine's default. */
  duration?: number;
  direction?: never;
  momentum?: never;
}

/**
 * A point in CSS pixels. For `screen.tapAt` and `screen.swipe` the origin is
 * the viewport's top-left corner, the space `boundingBox()` reports in; for
 * `tap({ position })` it is the node's own top-left corner.
 */
export type Point = ViewportPoint; // { x: number; y: number }

/** `tap`, `click`, `doubleTap`, `dblclick`, and `secondaryTap` options: the action timeout and the keys held for the click. */
export interface ClickOptions extends ActionOptions {
  /**
   * Keys held while the pointer clicks, as a Shift-click extends a selection:
   * `Shift`, `Control`, `Alt`, `Meta`, or `ControlOrMeta` (Control on Windows
   * and Linux, Meta on macOS). Needs an engine that declares `tapModifiers`,
   * `UNSUPPORTED_CAPABILITY` otherwise.
   */
  modifiers?: readonly KeyModifier[];
}

/** A modifier key, for `modifiers` and the `press` key grammar. */
export type KeyModifier = 'Shift' | 'Control' | 'Alt' | 'Meta' | 'ControlOrMeta';

/** `tap` and `click` options. */
export interface TapOptions extends ClickOptions {
  /**
   * Where to tap, relative to the node's top-left corner. Without it the
   * platform picks a point of the node, usually its center, behind its own
   * actionability checks; with it the pointer is dispatched at that point
   * once the node is in view and has a box, which needs the engine's `tap`
   * pointer action.
   */
  position?: Point;
}

/** One option of a select: its label (a bare string too), its `value` attribute, or its zero-based index. */
export type SelectOption =
  | string
  | { label: string; value?: never; index?: never }
  | { value: string; label?: never; index?: never }
  | { index: number; label?: never; value?: never };

/** A swipe or scroll direction. */
export type ScrollDirection = 'up' | 'down' | 'left' | 'right';

/** Fling strength of a swipe; defined under screen.swipe. */
export type Momentum = 'none' | 'slow' | 'fast';
```
