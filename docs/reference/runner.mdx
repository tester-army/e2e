`e2e/runner` runs e2e in process without `e2e run`. `list` returns a selection. `openHost` prepares a target for your test runner, and `host.openSession` opens a fresh attempt for each test. Importing `e2e` from a test file does not load the runner.

## list

`list` collects and selects the way [`e2e list`](/reference/cli#e2e-list) does, and stops there. No app process, engine, or worker starts, and nothing is written.

```ts
import { isE2EError, list } from 'e2e/runner';

const { pairs, unmatched, targets } = await list({
  files: ['tests/signup.e2e.ts'],
  grep: [/checkout/],
});

for (const pair of pairs) {
  console.log(`${pair.id} ${pair.disposition} ${pair.titlePath.join(' › ')}`);
}
```

### Options

`list` takes one object. Omit `config` to discover `e2e.config.ts` from `cwd`, the same walk `e2e list` does.

| Option | Meaning |
| --- | --- |
| `config` | A config file path, or an `E2EConfig` value in place of a file. |
| `targets` | Target names (`--target`). An unknown name is `UNKNOWN_TARGET`. |
| `cwd` | Project directory. Defaults to the current working directory. |
| `files` | Positional file selection: paths, globs, bare names, and `file:line`. |
| `tags`, `tagMode`, `excludeTags` | The `--tag`, `--tag-mode`, and `--exclude-tag` filters. |
| `grep`, `grepInvert` | `RegExp` arrays. A test's describe titles and title, joined by spaces, must match one `grep` pattern and no `grepInvert` pattern. |
| `lastFailed` | Only tests the previous run did not pass, read from `report.json` under `output`. |
| `shard` | `{ index, total }`, the `--shard index/total` slice. |
| `passWithNoTests` | Resolve with no runnable test instead of throwing `NO_TESTS`. |
| `output` | Results directory, over the config's `output`. `lastFailed` reads `report.json` there. |
| `env` | Environment the config resolves against. Defaults to `process.env`. |

### Result

`ListResult` is `{ pairs, unmatched, targets }`.

`pairs` is one `ListedPair` per test, target, and agent, in selection order, including pairs a filter removed. Repeats are not expanded. `unmatched` is the positional arguments, as written, that selected no discovered file. `targets` is the selected target names, in config order.

| Field | Meaning |
| --- | --- |
| `id` | The result id `report.json` stores for repeat 0. |
| `file`, `title`, `titlePath`, `kind`, `tags` | The collected test. `kind` is `test` or `setup`. `tags` is `[]` when the test declares none. |
| `source` | The declaration, project-relative: `{ file, line, column }`. `undefined` when the test recorded none. |
| `session` | The session the test consumes, from the test or its describe chain. `undefined` when it consumes none. |
| `sessions` | Session names a setup produces. `[]` on an ordinary test. |
| `serialId` | Set when the test belongs to a serial group, otherwise `undefined`. |
| `target`, `agent` | The target name and the configured agent this pair runs as. |
| `disposition` | `run`, `skip`, or `filtered`. |
| `reason` | Why the pair is skipped or filtered. Omitted when it runs. |

`e2e list` prints only `run` and `skip`. `list` returns `filtered` pairs too, each with `reason` (for example `title does not match --grep`).

### Errors

A failure is the same classified error `e2e list` exits with. `instanceof` can miss it across copies of the package. Recognize one with `isE2EError` and branch on `error.code`. `ConfigurationError` and `isE2EError` are both exported from `e2e/runner`.

An empty selection throws `ConfigurationError` `NO_TESTS` unless `passWithNoTests`. An unknown target is `UNKNOWN_TARGET`. A missing config, a config the loader refused, and a collection failure throw the same codes `run` records.

```ts
import { isE2EError, list } from 'e2e/runner';

try {
  await list({ targets: ['missing'] });
} catch (error) {
  if (isE2EError(error) && error.code === 'UNKNOWN_TARGET') {
    console.error(error.message);
  }
}
```

Each call imports the test files again, so a later `list()` in the same process sees an edit.

## openHost

`openHost` prepares e2e for Playwright Test, Vitest, Jest, or your own harness.
Your runner owns collection, retries, and reporting. The host prepares the
target's engine, starts app processes, and initializes the engine once per
worker lifetime. Each `host.openSession` creates a test-lifetime attempt with
fresh fixtures, a deadline, steps, and artifacts.

Use a worker-scoped host and a test-scoped session:

```ts
import { test as base } from '@playwright/test';
import { openHost, type E2EHost, type E2ESession } from 'e2e/runner';
import type { Device } from '@e2e-dev/mobile';

type Fixtures = { device: Device };

const test = base.extend<
  { e2e: E2ESession<Fixtures> },
  { e2eHost: E2EHost<Fixtures> }
>({
  e2eHost: [async ({}, use) => {
    const host = await openHost<Fixtures>({ target: 'android' });
    try {
      await use(host);
    } finally {
      const failures = await host.close();
      if (failures.length > 0) throw new AggregateError(failures, 'e2e host close failed');
    }
  }, { scope: 'worker' }],
  e2e: async ({ e2eHost }, use, testInfo) => {
    const session = await e2eHost.openSession({
      name: testInfo.titlePath.join(' › '),
      // Playwright's 0 disables its timeout; e2e then falls back to the config's.
      timeout: testInfo.timeout || undefined,
      onStep: (step) => {
        if (step.phase === 'end') console.log(`${step.api} ${step.label}: ${step.status}`);
      },
    });
    try {
      await use(session);
    } finally {
      const failures = await session.close();
      await testInfo.attach('e2e trace', { path: session.tracePath, contentType: 'text/markdown' });
      if (failures.length > 0) throw new AggregateError(failures, 'e2e session close failed');
    }
  },
});

test('turns on dark mode', async ({ e2e }) => {
  const { agent, app } = e2e.fixtures;
  await agent.act('open settings and turn on dark mode');
  await app.screenshot();
});
```

### Host options

`openHost<Fixtures>(options?: OpenHostOptions)` returns
`Promise<E2EHost<Fixtures>>`. Omit `config` to discover the config from `cwd`,
the same walk `list` does. If opening fails, e2e tears down what started
before throwing the error.

| Option | Default | Meaning |
| --- | --- | --- |
| `config` | nearest `e2e.config.ts` or `e2e.config.mts` | Config file path relative to `cwd`, or an `E2EConfig` value |
| `cwd` | `process.cwd()` | Directory for config discovery, and the project root of a config value |
| `target` | the only target | Target name; required when the config declares several |
| `env` | `process.env` | Environment the config, engines, and providers read |
| `signal` | none | Cancels host provisioning, a pending session open, or live fixture calls |
| `headed` | `false` | Runs a browser engine headed |
| `onNotice` | none | Progress outside a step, such as provisioning or an app process |

A config file and its project-file imports are loaded fresh for each host.
Package imports remain shared; their singleton state is not recreated per host.
A config value uses the engine instances in that value. Neither form allows
overlapping hosted attempts in one process. A config value's engine instance
belongs to one host until it closes; a second host must use another instance.

### Host

| Member | Meaning |
| --- | --- |
| `runId`, `target` | Identity shared by the host's sessions |
| `openSession(options)` | Opens a fresh `E2ESession<Fixtures>` on this host's target |
| `close()` | Cancels any active or pending session, waits for it to close, then disposes the engine, stops app processes, and releases provisioning. Returns `Promise<readonly SerializedError[]>` |

Only one hosted attempt may be opening, live, or closing per process, even
across different hosts. An overlapping open is rejected before engine
attempt state starts. Await `session.close()` before opening the next
session on the same host. A launch that fails or is cancelled ends what it
opened and leaves the host usable, as a run keeps its worker for the retry.
A session whose engine cleanup failed closes the host permanently, since
its isolation is uncertain; open a new host. Overlap and closed-host errors
use `WORKER_PROTOCOL`.

`host.close()` is idempotent and disposes and releases resources only once.
A host is `AsyncDisposable`; `await using host = await openHost()` closes it
at scope exit and throws an `AggregateError` when closing reports failures.

## host.openSession

`host.openSession(options: OpenSessionOptions)` returns
`Promise<E2ESession<Fixtures>>`. A session is one test attempt with no retry
loop. A retry opens a new session on the same worker host.

### Session options

| Option | Default | Meaning |
| --- | --- | --- |
| `name` | required | Test name for step and trace reporting; a string |
| `timeout` | config `timeout` | Deadline for the session's operations in milliseconds, positive and finite, counted from when it opens. Does not bound provisioning or opening, and does not close the session |
| `signal` | none | Cancels opening or live fixture calls; the host signal also applies |
| `agent` | the first configured agent | Agent the `agent` fixture uses when a call names none |
| `onStep` | none | Live `StepProgress`, the same feed reporters receive |

`timeout`, `agent`, and `onStep` belong to the session, not `openHost`.
Use `signal` to cancel provisioning or launch. `onStep` must not block or
throw. Its `phase` is `start`, `event`, `activity`, `replay`, or `end`.
An `end` event includes `status`, `durationMs`, `modelCalls`, and a redacted
`error` when the step failed.

### Session

| Member | Meaning |
| --- | --- |
| `fixtures` | `agent`, `app`, `screen`, `platform`, and the engine's fixtures, typed as `TestFixtures & Fixtures` |
| `runId`, `attemptId`, `target` | Host run and target, plus a unique attempt id |
| `steps()` | Read-only `StepRecord`s for steps run so far, as the [report](/reference/reporters) records them |
| `artifactsDir` | Absolute directory for this attempt's screenshots, recordings, and trace |
| `tracePath` | Absolute string path to `trace.md`; attach or read it after `close()` settles |
| `exportDebugBundle()` | Deeply frozen `SessionDebugBundle` after close settles, including failed close; `undefined` while live or closing |
| `close()` | Cancels remaining operations, ends the attempt, and writes its trace. Returns soft expectation and cleanup failures as `Promise<readonly SerializedError[]>` instead of throwing them |

`session.close()` is idempotent and returns the same failures on later calls.
The host stays open for the next test. A session is `AsyncDisposable`:
`await using session = await host.openSession({ name: 'checkout' })` closes
it at scope exit and throws an `AggregateError` of the returned failures.

`expect.soft` collects failures for the session's whole lifetime. Check
`close()`'s result to fail the host runner's test. `expect.poll` uses the
session's remaining budget, even when its own timeout is longer. Contributed
fixture operations also honor that budget, including operations that disable
their own timeout. When the deadline passes, a poll or operation that was
watching it reports its own cut; everything else still running, including an
operation an engine or a model never answered, fails with `TEST_TIMEOUT`.
Either way the session's outcome is timed out and `close()` returns the
timeout. Later operations fail with `TEST_TIMEOUT`; close the session.

Artifacts live under `<output>/results/host/<resultSegment>/`, with
`trace.md` written at close through the existing redacted report-formatting
pipeline. e2e generates the safe `resultSegment` from the name and unique
attempt identity; the name never becomes a raw path component. Repeated
names and retries get separate directories. With provider-backed secrets,
the directory uses an identity-only segment because unresolved values cannot
be redacted from a title slug. The trace still displays the redacted name.

### Closed-session debug export

After `close()` settles, `exportDebugBundle()` returns the same deeply
read-only, frozen JSON snapshot on every call. It remains available after
soft failures, deadline expiry, engine cleanup failures, and trace-write
failure. Export itself writes or uploads nothing.

Reports and traces are finalized only after attempt cleanup and any worker
retirement have settled. Teardown returning does not prove that a pending
secret provider finished. The runner tracks actual resolution calls, including
engine-derived values, and drains them using only the time left in the
attempt's cleanup window. It never invokes unused providers. If a resolution
is still pending or failed, potentially secret-bearing prose becomes
`[text withheld: secret resolution unproven]` and content artifacts are withheld
as `incomplete-redaction`. An empty resolution queue is not proof against
a new provider call during publication failure recovery or later disposal.
With any configured opaque provider, freeform prose is conservatively withheld
before the first trace bytes are written, even when an earlier call settled.
Providers compute fresh values. Hosted path selection and finalization classify
effective private definitions through own data descriptors, never by reading a
lazy value. Accessors and missing definitions remain opaque; only a requested,
tracked resolution may evaluate a getter. The exporter adds no calls or waits
to learn unused values. Effective environment overrides that replace a provider
with a literal retain ordinary known-value redaction. SDK outcomes, declared
enum tokens, validated generated identities, timings, and counters remain
structural facts. Optional unknown
URLs are omitted. If known-value redaction changes a target origin, that optional
URI is also omitted. A changed model endpoint withholds the optional model
record because its endpoint is required; no replacement address is invented.
Declared `local` and `provider-default` endpoint tokens are preserved.
Schema-unique arrays are deduplicated after redaction, including known-value
collisions; ordered steps, events, and turns retain repetitions.
Later provider completion cannot change the frozen bundle
or rewrite the trace.

With provider-valued
secrets, previously truncated prose is withheld when its redaction cannot be
proven, including cut app logs, model turns, and byte-capped error text. It is
replaced by `[text withheld: truncated before final redaction]`. This may also
withhold literal ellipses or cut notices. Uncut text is redacted before the
report's field-specific length bounds are applied. No raw text is retained
to recover a cut. Verdict summaries redact known values before their
2,000-character producer bound and mark cuts explicitly; the report's
8,192-character explanation bound is not a substitute for that producer proof.

The report projection preserves closed enum tokens only at their declared
paths. The same words in labels, names, explanations, or external identity
text still undergo prose redaction. Forwarded accepted-image byte totals
must be nonnegative safe integers and stay separate from peak image bytes.
Absent totals are not synthesized; these guards introduce no public report fields.

UUID or digest shape alone grants no redaction exemption. Target names, external
test IDs, carried declarations, and error details remain user text, and masked
target IDs still join result target references. SDK run and attempt UUIDs,
result digests, and attempt-owned step/artifact IDs retain their exact protocol
locations and validated references. Unknown fields get no identity exemption.

The SDK-minted `run.runner.name` remains the public literal `e2e`, including
with opaque providers. Only that exact declared path and value are exempt.
A target, session, fixture, agent, or external runner name spelled `e2e`
still undergoes prose redaction. The shipped report schema pins the same literal.

Prospective accounting reads own data descriptors, not getters. Every effective
session or resolution layer seeds all of its literal values before a handoff.
An accessor or provider permanently marks the ledger opaque, even after a
successful resolution or a later literal replacement. Missing accounting denies
publication proof. No definition maps are retained for proof-time inspection.

Media types are facts only for original, sink-bound SDK capture tickets whose
registered bytes match the producer format. PNG signature, UTF-8 text, and
parseable checkpoint JSON checks accompany size and hash measurement; filenames
and caller-declared media types grant no permission. PNG signature validation
is not full image decoding or masking proof. These media facts survive a
coinciding configured secret only in report artifact and manifest media fields.
The same text in labels, logs, names, or external IDs is still masked or withheld.
An unsafe, unproven required media type removes that optional artifact row and
its references rather than publishing a redaction marker as a MIME type.


Only the private SDK missing-checkpoint protocol can retain fixed unavailable
facts when opaque secrets deny content publication. It requires the original
sink-bound, unconsumed ticket, expected byte length and SHA-256, actual owning
attempt/step joins, original boundary timestamp, and a null capture association.
The timestamp must match the private association snapshot, not mutable public
registration fields. Before the first write and again after asynchronous reads,
the sink checks exactly nine boundary fields,
closed missing reasons, and canonical compact JSON with zero or one trailing LF.
Duplicate keys, discarded prose, extra fields, capture data and trailing bytes
are denied even with a matching receipt. This permission never covers generic
JSON, text, pixels, engine metadata or caller names. Registered checkpoint
recordedness is independent of retained-file availability. Consumers still own
hosting and later file rechecks. This exporter does not enable checkpoint capture.


<Note>
With configured literal secrets, complete prose such as `Waiting… done.` can
be withheld as a possible earlier cut. Default-agent tool output, loop/overflow
formatters, decision-executor request/answer serialization, unmarked element
clips, and custom executor strings do not share trusted completeness provenance.
Removing one marker check would also expose bare secret prefixes. This export
keeps the conservative gate; it does not promise complete transcript availability.
</Note>


For an existing session, close and publish before propagating the same body,
SDK/cleanup, or publisher errors to the enclosing test runner:

```ts
import type { E2ESession, SessionDebugBundle } from 'e2e/runner';

async function withPublishedDebug(
  session: E2ESession,
  body: () => Promise<void>,
  publish: (bundle: SessionDebugBundle, paths: readonly string[]) => Promise<void>,
): Promise<void> {
  const errors: unknown[] = [];
  try { await body(); } catch (cause) { errors.push(cause); }
  try { errors.push(...await session.close()); } catch (cause) { errors.push(cause); }
  const bundle = session.exportDebugBundle();
  if (bundle !== undefined) {
    const paths = bundle.artifacts.flatMap((artifact) =>
      artifact.evidence.status === 'available' ? [artifact.evidence.path] : [],
    );
    try { await publish(bundle, paths); } catch (cause) { errors.push(cause); }
  }
  if (errors.length === 1) throw errors[0];
  if (errors.length > 1) throw new AggregateError(errors, 'Test or debug finalization failed');
}
```

The publisher owns upload and use-time file verification. The caller owns retries
and runner reporting; publication must not convert a failed test into a pass.

`SessionDebugBundle`, `DebugArtifact`, and `ImmutableReport` are public types
from `e2e/runner`. The shipped `schema/session-debug-v1.schema.json` validates
`session-debug-1` and references the shipped `report-v1.schema.json`.

| Field | Meaning |
| --- | --- |
| `schemaVersion` | `session-debug-1` |
| `report` | The existing `report-1` shape, with one session result and attempt. Includes run, target and attempt identity, SDK outcome, errors, timings, events, bounded reasoning and tool turns when recorded. No stacks, external error objects, raw native trees, or pixel buffers |
| `artifacts` | SDK registration manifest, in registration order. Each entry has `id`, `kind`, `mediaType`, `stepIds`, `observationRevision`, optional `checkpoint`, and `evidence` |
| `evidence` | Per-step availability of semantic summaries, reasoning excerpts, turns, and checkpoints |
| `trace` | `written` or `failed`. A failed write is also recorded as a finalization error in the report |

Only `artifact.evidence.status === 'available'` has a `path`, `size`, and
`sha256`. Its path is relative to `session.artifactsDir`, not cwd. Nested
report artifact paths retain their report-relative meaning, but only manifest
paths are the publication allowlist. Missing or withheld entries have a
closed `reason` and no file path. `not-retained` covers registrations without
a retained path and actual ENOENT; no other filesystem-access error maps to
this reason. `read-failed` means I/O prevented verification. It does not assert absent or
changed bytes. `changed-file` means original file/root custody could not be
verified, not necessarily that the content changed. Report artifact locations, store references,
and external URLs are removed when evidence is not exportable.

The manifest admits runner-created, policy-checked evidence only. Pixels and
observed semantic text keep a private capture-start ledger proof before any
asynchronous engine call. Executor screenshots carry the original observation
ticket and byte identity through model-image sizing and persistence, without
a new capture. A private, one-use receipt binds the expected SHA-256 and byte
length before writing. The sink compares those expectations with the actual
persisted bytes before any store handoff or export admission; a mismatch
publishes neither bytes nor a file reference. Executor attachment filenames
use SDK-generated nonces and exclusive creation, not sanitized labels. For
path-returning engine captures, the SDK holds the original descriptor on return,
before the first yield, then hashes it asynchronously in bounded chunks.
Only receipt binding has bounded chunk memory; an ArtifactStore still receives
a complete buffer. Binding abandons its wait at the existing capture deadline or
caller cancellation; its ticket cannot regain authority from late bytes. An issued
read may keep its stream-owned descriptor until safe cleanup. This is not an
end-to-end memory cap or an atomic I/O abort.
It registers the original engine path, never copies or restores a file to defeat engine retention. Ordinary
contained engine filenames may include spaces or Unicode; hosted export still
requires portable ASCII names. A root may have symlink ancestors, but its own
entry must be a directory, not a link; reads anchor to its stable physical identity.
Both binding and hosted reads reject traversal,
component symlinks, hard links and non-files. The engine
remains responsible for returning its actual capture; a filename is not
pixel-masking authority. SDK transcripts get a text ticket after final known-value
redaction and before writing. Opaque or pending content is withheld before the
first transcript or failure-summary write. With known secrets, already-cut
transcripts are withheld because short prefixes cannot be repaired. Transcript
files are bounded to 262,144 UTF-8 bytes after masking, with an explicit cut notice.
Checkpoint JSON gets its ticket only after final field redaction. Original tickets are single-use and sink-bound;
a bare marker, copy, or cross-sink registration is not SDK evidence. Evidence captured
while resolution was pending, before later values joined the ledger, or
without a capture proof is
withheld even if cleanup eventually resolved the provider. Filename checks,
pixel masking, and prose redaction against an older ledger do not prove
final redaction. The runner cannot repair opaque pixels or recover clipped
prose. This evidence policy is applied before the trace renderer can read a
log or publish a file link. ArtifactStore redaction metadata is separate from private export eligibility.
Genuine redacted transcripts remain `complete` for ordinary CLI, MCP and serial
stores. Unsupported custom pictures retain legacy store metadata only when live
secrecy is proven and the viewport is untainted. The sink rechecks live secrecy,
ledger growth and pixel taint after asynchronous measurement, before any store
handoff, including local-only metadata. Failed proof marks the record incomplete
and prevents a store handoff; it never grants custom pictures SDK export evidence.
A bare marker never grants capture or pixel-masking permission.
Locally retained incomplete recordings and
non-SDK attachments remain on disk, but are no longer links in a hosted trace. Arbitrary
files in the directory, contributed-fixture attachments, downloads, and
incompletely redacted recordings are not export paths. It rejects traversal,
symlinks, hard links, and files changed since registration. Retention still
decides which files exist; exporting never restores discarded evidence.
Before later copying files, recheck containment, symlinks, size, and SHA-256.
The snapshot cannot prevent trusted code from changing the filesystem.

Today's semantic evidence is the bounded screen summary or diff in
`report.run.results[0].attempts[0].steps[].screen`, not a full observation
timeline. Reasoning and turns are present only when recorded; provider-private
reasoning is never promised. `checkpoints` is `recorded` only for an SDK-registered checkpoint belonging to
that step, even if its file is missing or withheld. Consult each artifact's
`evidence` before copying. Ordinary captures still omit `checkpoint` and keep
`observationRevision: null`.

An optional `checkpoint` contains the registered `id`, `phase` of `before` or
`after`, and `observationId: string | null`. The row's `observationRevision`
is the actual capture revision, not parsed from an ID or taken from the
step's last observation. Opaque identities are nonempty, control-free, and
at most 1,024 UTF-8 bytes. The schema also caps them at 1,024 characters;
the producer enforces the byte limit. Missing or unproven observation identity
and revision are both `null`. Known-secret identity is never clipped or
rewritten into a new association: it withholds the file and omits or nulls
that metadata. This manifest extension does not enable checkpoint capture.

The report uses the trace's finalized SDK outcome. Trace-write errors remain
visible even when no trace can be written. External test-body outcomes are
not accepted by this API.

Opening failures are classified, redacted errors; raw engine causes are not
exposed. Match them with `isE2EError` and
`error.code`, as for `list`. `openHost` reports `UNKNOWN_TARGET` for an
unknown target and `TARGET_REQUIRED` when several targets exist and none
was named.

<Note>
A hosted session writes its trace, not a run report file. Your runner owns retries
and reporting; use `exportDebugBundle()` for structured results and check `close()`'s failures. Video follows
the target's mode for a first attempt, including retaining failure-only video
for soft failures and failed, blocked, timed-out, or cancelled steps. Your
runner's test-body failures are not
passed to e2e.

The one-shot attempt used by `e2e mcp` remains internal. There is no
top-level `openSession` export.
</Note>
