`@e2e-dev/mobile` is the engine for iOS simulators, Android emulators, and
connected phones, driven through
[agent-device](https://github.com/callstack/agent-device). It contributes the
`device` fixture. `agent`, `app`, `screen`, and `expect` work as they do
everywhere; this page covers what is specific to a device target.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

export default {
  targets: [
    { name: 'iphone', engine: mobile({ platform: 'ios' }), app: { bundleId: 'com.apple.Preferences' } },
  ],
} satisfies E2EConfig;
```

```ts title="tests/settings.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/mobile';

test('General opens in dark mode', async ({ app, device, screen }) => {
  await device.setAppearance('dark');
  await app.open();
  await screen.getByText('General').tap();
  await expect(screen.getByText('About')).toBeVisible();
});
```

- Import `test` from `@e2e-dev/mobile` to have `device` typed. Declare
  `requires: ['device']` in a suite that also runs on the web.
- Choose **Mobile (iOS/Android)** in `e2e init` to add the package with a
  Settings example. iOS needs Xcode and a simulator; Android needs the Android
  SDK and an emulator.
- The package includes a compatible version of `agent-device`; no separate
  installation is needed.

## Reference

### Engine

`mobile(options)` creates an engine for one platform. Create one for each
platform you test, and use `platforms: ['ios']` or `platforms: ['android']`
on tests with platform-specific labels or operations.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';
import { mobileTools } from '@e2e-dev/mobile/tools';
import { gateway } from 'ai';

const iphone = mobile({ platform: 'ios' });
const pixel = mobile({ platform: 'android' });

export default {
  targets: [
    { name: 'iphone', engine: iphone, app: { bundleId: 'Settings' } },
    { name: 'pixel', engine: pixel, app: { bundleId: 'com.android.settings' } },
  ],
  workers: 1,
  agents: {
    default: {
      model: gateway('openai/gpt-6-luna-fast'),
      tools: mobileTools(iphone, pixel),
    },
  },
} satisfies E2EConfig;
```

`mobile()` takes `MobileOptions`: which devices the engine drives and how.
The app under test is the target's `app`, not an engine option; see
[The app under test](#the-app-under-test).

| Option | Type | Default |
| --- | --- | --- |
| [`platform`](#platform) | `'ios' \| 'android'` | required |
| [`device`](#device-option) | `string \| readonly string[] \| DeviceProvider` | every booted device |
| [`session`](#session) | `string` | `e2e-<target name>` |
| [`snapshot`](#snapshot) | `'full' \| 'interactive'` | `'full'` |
| [`settle`](#settle) | `number \| false` | `150` |
| [`transition`](#transition) | `number` | `500` |
| [`videoTouches`](#videotouches) | `boolean` | `true` |

Every optional value also accepts `undefined`, so values read straight from
`process.env` need no conditional spread. Each entry below shows its member's
declaration.

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | An empty `device` list, a blank `device` name, or a blank or non-string list entry. |
| `INVALID_CONFIG` | A `device` value that is neither a string, a list, nor a valid provider: a provider without a non-empty `name`, without `acquire()` or `release()`, or with a `record` that is not a function. |
| `INVALID_CONFIG` | `platform` is missing or not `'ios'` or `'android'`; the match is case-sensitive. |
| `INVALID_CONFIG` | A provided `snapshot` value is not `'full'` or `'interactive'`, or a provided `videoTouches` value is not a boolean. |
| `INVALID_CONFIG` | An option `mobile()` does not take, such as `mobile({ app })` and the other old app options. The message names the nearest known option for a likely typo, else every option. |
| `INVALID_CONFIG` | `settle` or `transition` is not a non-negative integer of milliseconds (`settle` may also be `false`). |

#### `platform`

```ts
/** Platform the target's device runs. */
readonly platform: MobilePlatform;
```

```ts
mobile({ platform: 'android' });
```

- `'ios'` or `'android'`. Required.

#### `device` option

```ts
/**
 * Device to use: a simulator or emulator by name, simulator UDID, or
 * emulator serial (`emulator-5554`), or a connected phone by name. A list
 * is a pool: the engine declares one worker per entry and worker slot `n`
 * drives the `n`th, so `workers` at or above the pool size runs the target's
 * files across every device at once. Omitted, the pool is every booted device
 * of the platform at `prepare` that no other agent-device session holds, as
 * many as the run has slots. A paired iPhone or iPad that is reachable (USB or network) counts as booted and
 * joins the pool. With none booted, agent-device boots a shut-down one: on
 * iOS an iPhone over an iPad over an Apple TV, on Android a phone or tablet
 * over a TV, then the newest OS, then name order (a stopped Android emulator
 * reports no OS version, so the name decides). With every booted one held,
 * `prepare` fails. A `DeviceProvider` leases hosted devices
 * instead: one per worker slot at `prepare`, each driven through the daemon
 * and client configuration the lease names. A replacement worker resumes a
 * healthy agent-device session on the same lease. Forced worker shutdown
 * can close the session. `device.closeApp()` ends the agent-device session,
 * allowing another session to take the device. If agent-device has not
 * confirmed a recording stop, the engine resets the recording before the
 * next attempt. This reset also ends the session. The provider lease stays
 * held until run end. At run end, the engine closes its sessions and the
 * provider releases its leases.
 */
readonly device?: string | readonly string[] | DeviceProvider | undefined;
```

```ts
mobile({ platform: 'ios' }); // default: every booted iOS device no other agent-device session holds
mobile({ platform: 'ios', device: 'iPhone 17' });
mobile({ platform: 'android', device: 'emulator-5554' });
mobile({ platform: 'ios', device: ['iPhone 17', 'iPhone 17 Pro'] });
```

- Two workers never drive the same device, as long as each `device` entry
  names a different one.
- Without `device`, a booted simulator another tool holds through its own
  agent-device session is skipped. A booted device nothing holds, such as
  one you are using by hand, is still in the pool: name the device to keep
  the run off it.
- [Hosted devices](/mobile#hosted-devices) has the `DeviceProvider` contract
  and an example provider.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { mobile } from '@e2e-dev/mobile';

const iphones = mobile({
  platform: 'ios',
  device: ['iPhone 17', 'iPhone 17 Pro'],
});

export default {
  targets: [{ name: 'ios', engine: iphones, app: { bundleId: 'com.example.app' } }],
  workers: 2,
} satisfies E2EConfig;
```

#### `session`

```ts
/**
 * agent-device session name, before the worker slot: slot `n` drives its
 * device under `<session>-<n>`, `e2e-<target name>-<n>` by default. One run
 * per session at a time: concurrent runs on the same session interleave
 * taps.
 */
readonly session?: string | undefined;
```

```ts
mobile({ platform: 'ios', session: 'checkout' }); // default: e2e-<target name>
```

#### `snapshot`

```ts
/**
 * What an observation captures. `full` (default) includes static text, so
 * judgments can read values; `interactive` keeps only actionable nodes and
 * is cheaper on screens with long lists.
 */
readonly snapshot?: 'full' | 'interactive' | undefined;
```

```ts
mobile({ platform: 'android', snapshot: 'interactive' }); // default: 'full'
```

#### `settle`

```ts
/**
 * How long the UI must hold still after a tap, fill, screen scroll, or
 * back before the agent observes again, in milliseconds; `false` skips the
 * wait. The wait keeps that observation off a transition frame; the runner's
 * own polling (`expect`, actions waiting for their node) covers the rest,
 * so a short window suffices. Default 150.
 * Every frame of a running animation changes the tree, so a 150 ms
 * window still catches a transition in flight; raise it for slow devices
 * or apps that settle in stages, or lower it to 0 to keep only the first
 * re-observation. A test's steps do not settle, except `device.back()`:
 * `expect` verifies their outcome, and `transition` covers a control that is
 * still arriving.
 */
readonly settle?: number | false | undefined;
```

```ts
mobile({ platform: 'ios', settle: 300 }); // default: 150
```

#### `transition`

```ts
/**
 * Wait before acting on a control that just appeared or moved, in
 * milliseconds. Default 500. Accessibility bounds cannot tell a sliding
 * control from a landed one (iOS reports the final frame at once, Android
 * the frame in flight), so the control is found again in a fresh snapshot
 * once the wait is over and acted on where it landed. Unmoved controls are
 * acted on immediately only when keyboard visibility is unchanged. Opening
 * or closing the keyboard also uses the remaining budget. Screen swipes in
 * tests wait out the remaining budget before scrolling. Raise it for slower
 * transitions.
 */
readonly transition?: number | undefined;
```

```ts
mobile({ platform: 'ios', transition: 800 }); // default: 500
```

If the control changes during the wait, the action finds it again within its timeout before acting.

`back`, `home`, `alert`, `dismissKeyboard`, `setOrientation`, and `fold` on
[`device`](#device) change the screen, so they count as actions for this
budget the way a tap does. A control that arrives with the screen they reveal
waits out the budget before the next action lands on it.

`fill` and `clear` re-read the field before typing. Missing fields, changed
security state, or incomplete captures return `NODE_STALE` before mutation,
then retry after a fresh observation. Non-input targets return
`UNSUPPORTED_CAPABILITY`. An iOS `other`, the type of an element the platform
did not classify, is typed into when it holds a value or only text, since a
custom-drawn field (Compose Multiplatform, Flutter) can read that way.

#### `videoTouches`

```ts
/**
 * Whether a video recording draws agent-device's touch indicator where a
 * test tapped. Default `true`. `false` records the plain screen, and skips
 * the pass that draws the indicator once the recording stops: on a hosted
 * daemon such as Expo Simulators' that pass can outlast the attempt's
 * `cleanupTimeout`.
 */
readonly videoTouches?: boolean | undefined;
```

```ts
mobile({ platform: 'ios', videoTouches: false }); // default: true
```

#### The app under test

The app is the target's `app`: `bundleId`, `appPath`, `launchArguments`,
`permissions`, `identity`, and `environment` are documented under
[the app under test](/reference/config#the-app-under-test).

```ts title="e2e.config.ts"
export default {
  targets: [{ name: 'ios', engine: mobile({ platform: 'ios' }), app: { appPath: './build/MyApp.app' } }],
} satisfies E2EConfig;
```

- A device target needs `app.bundleId` or `app.appPath`.
- `app.open()` launches the target's app fresh. An attempt launches nothing
  on its own, so a test starts where the previous one left the app.
- `app.open` takes no path on a device: a link goes through
  [`device.openLink`](#openlink).
- `app.appPath` is the build the suite runs against. The engine installs
  nothing on its own: [`device.installApp()`](#installapp) installs it where
  the suite says so. A device provider installs it on the device it leases.
- Without `bundleId`, the installed bundle id or package becomes the app
  `app.open()` launches.
- Declare an `identity` when the build path changes per run (a version in
  it), so recordings survive the rename.

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | At config load: no `app.bundleId` and no `app.appPath`; an `app.url` (not supported yet); a link in `bundleId` (a test opens one with `device.openLink`); an unknown permission name. |
| `UNSUPPORTED_CAPABILITY` | `app.open()`, `app.restart()`, or `app.clearState()` on a target with no `app.bundleId` before its build is installed. |

#### Launch arguments and permissions

`app.launchArguments` and `app.permissions` ride every fresh launch of the
pinned app: `app.open()`, `app.restart()`, and `app.clearState()`, which
resets the permissions with the data.

```ts title="e2e.config.ts"
export default {
  targets: [
    {
      name: 'pixel',
      engine: mobile({ platform: 'android' }),
      app: {
        bundleId: 'com.example.app',
        launchArguments: ['--ez', 'e2e', 'true'],
        permissions: { camera: 'grant', notifications: 'deny' },
      },
    },
  ],
} satisfies E2EConfig;
```

- iOS hands the arguments to the app process
  (`ProcessInfo.processInfo.arguments`). Android appends them to `am start`,
  so `['--ez', 'e2e', 'true']` is a boolean intent extra.
- Each permission is `grant`, `deny`, or `reset`. `deny` is a recorded
  refusal on iOS, where the app is told no without a prompt, and a revocation
  on Android, where the OS asks again when the app requests the permission.
- The permissions are set on the app by name before it starts, with no open
  first, since iOS terminates a running app whose permission changed and
  Android one whose permission was revoked.
- The warm-up passes no launch argument and touches no permission.
- [`device.openApp(app, { relaunch: true, launchArguments, permissions })`](#openapp)
  does the same for one launch of any app.

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | In `app.permissions`: a permission name outside `DevicePermission` (naming the nearest one when it is a likely typo), or a state other than `grant`, `deny`, or `reset`. Fails before any device command. |
| `INVALID_ARGUMENT` | The same, in `device.openApp`. |

#### Boot and prepare

Devices boot in `prepare`, once per run and before the run's clock starts,
so a cold boot on CI is never charged against `launchTimeout`.

- [`device`](#device-option) says which devices `prepare` uses and how many
  workers the engine declares.
- On iOS, `prepare` starts the automation runner on every device with
  agent-device's `prepare ios-runner`, so its first launch is paid before the
  first test.
- Then, on both platforms, it opens the target's `app.bundleId` once per
  device. A build the
  suite installs itself comes up with the first `app.open()`, which
  relaunches it fresh whenever a test asks.
- A device that cannot boot, or a runner that is busy, wedged, or past its
  watchdog, ends the run in `prepare`.
- A runner that does not start for another reason is logged and left to the
  first attempt, and that device's app is not opened there.

Each device logs one line of how long its prepare steps took, a failed step
included. A cold iOS simulator:

```text
ℹ booting E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5 (1 of 1)
ℹ E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5: boot 36.3s, iOS runner 61.6s, open dev.e2e.benchmark 9.2s
```

- `boot` is the device boot, a few seconds on a device that is already up.
- `iOS runner` is the automation runner's start, on iOS only.
- `open <app>` brings the app to the foreground, launching it on a cold
  device. It is missing on a device where the open is skipped as described
  above.

An ordinary app-open failure is logged on a line of its own, and the run goes
on. That line prints before the device's timing line, which still lists the
failed `open <app>` step:

```text
ℹ E93FA5E5-1592-43C7-9149-F1B5FE0AD5F5: dev.e2e.not.installed did not open (open dev.e2e.not.installed failed: Simulator device failed to launch dev.e2e.not.installed. Hint: The app bundle is not installed on this simulator. Run install before open.); the first attempt opens it
```

<Note>
A pending tap, double tap, focus, check or uncheck is cancelled when the step
stops waiting for it or the run is interrupted. This also covers the tap that
dismisses a keyboard tip.

Input already sent to the device may still finish.
Other commands can outlive their caller's timeout; the next attempt waits for
them to finish.
</Note>

#### Capabilities

| Contract member | On a device |
| --- | --- |
| `observe` | The accessibility tree with rects. Element types map onto roles as listed under [Roles](#roles); a `Switch` or `CheckBox`, and an Android `RadioButton`, carry the `checked` state the device reports, and a `SecureTextField` or an Android field UIAutomator flags as `password` is a secure `textbox`. An iOS field keeps a value equal to its label (an unlabeled field is named by its text); Android's echo of a text view's label as its value is dropped. The accessibility identifier (iOS) or resource id (Android) is the node's `testId`. An Android node is named by the content description its app set (React Native's `accessibilityLabel`), else by its text, and its `text` is what it shows, so a labeled text view or a filled field answers `getByLabel` by its label and `getByText` by its text. A field's hint is its `placeholder` attribute, showing or not. Compose Multiplatform reports no placeholder on iOS: an empty field appends the text it draws to its label (`Name, Ada Lovelace`) over one `StaticText` child, so that text is the field's `placeholder` and the child is left out. An empty field has no value: Android flags a showing hint, and XCTest reports an empty iOS field's placeholder as its value, so an iOS field whose value equals its placeholder (trimmed) reads empty, text typed to match the placeholder exactly included. One Android fact is agent-device's, not the platform's: `rect` and every point are the screen's physical pixels; the display density it reports is not applied yet. Android's status bar and navigation bar, the full-width `com.android.systemui` windows along the screen's edges and the narrow status icons (clock, signal, battery) agent-device reports on their own inside that edge band, are left out; the notification shade, system dialogs, and a heads-up notification or other popup inset from the sides stay. Pixels on request, with every secure node's bounds painted black. |
| `perform` | `tap`, `doubleTap`, `longPress`, `fill`, `clear`, `hover`, `check`, `uncheck`, `press` (`Enter`, `Space`, or one character), `swipe`, `dragTo`, and `focus` on editable fields. A tap on a `switch` or `checkbox` lands on its innermost control, since UIKit reports a settings row as one labelled switch with the real toggle as a child. `check` and `uncheck` need a `checked` state. Switches report one on both platforms, and so does a native Android `CheckBox`; a React Native checkbox or radio reports one only when the app sets `accessibilityState.checked`. A control with no state is `UNSUPPORTED_CAPABILITY`, so tap it instead. `doubleTap` is two presses, 284 to 285 ms apart on iOS (the cadence of agent-device's XCTest tap): agent-device's own double-tap gesture reaches a React Native `Pressable` as one press. A detector with a window of 300 ms or less can read the pair as two single taps. `longPress` holds for one second unless the test passes `duration`, past a React Native `Pressable`'s `delayLongPress` of 500 ms and the longer thresholds apps set; agent-device's own default hold is shorter and registers as a tap on those. `selectOption`, `setInputFiles`, `scrollIntoView`, and `secondaryTap` are not declared, and neither is `tapModifiers`, so `tap` or `doubleTap` with `modifiers` is `UNSUPPORTED_CAPABILITY`. An action on a node that a newer snapshot replaced finds the node again instead of acting on a different element. |
| `performAt` | `tap`, `doubleTap`, `longPress`, and `swipeTo` at a bare screen point, so `screen.tapAt`, `screen.doubleTapAt`, `tap({ position })`, `screen.swipe({ from, to })`, and the agent's `tap_at` reach a control the tree does not list. No `hover`, `secondaryTap`, or `dragTo` at a point: touch has none without a node, so `hover_at` needs a listed control. |
| `keyboard` | `type` and `press` into the focused field, the agent's `type` and `press` without a target and the fallback of `type_at` and `press_at`, and `dismiss`, the agent's `dismiss_keyboard`. |
| `locate` | Every `screen` query. Text and label queries answer with the innermost match, since a device echoes both up the tree (a React Native input is a host view and the field inside it, both labelled). On Android a test id query, a string or a RegExp, also matches a resource id without its `<package>:id/` prefix, for any package but the framework's `android`, when nothing on the screen matches the full id. `screen.locator('id=…')` is agent-device's selector and takes the full id. |
| `validateApp` | Requires `app.bundleId` or `app.appPath` and refuses `app.url` for now, with a note on reaching this machine from the platform's device. A target with either is a `native-app` target, so `requires: ['native-app']` selects device targets. |
| `session` | `back`, `restart`, and `reset`. No `open`: `app.open()` takes no path and the runner serves it with `restart`, the fresh launch of the pinned app; the agent's `navigate` verb is unavailable, and `device.openLink(url)` opens a deep link or web link. |
| `artifacts` | Redacted screenshots under `screenshots/NNN-<label>.png`; a screenshot that cannot be redacted fails instead of being written. Video, when the attempt's [video mode](/reference/config#video) records, as `video/video.mp4`, or a device provider's own recording. |
| `location` | `<bundle id> / <screen title>`, the replay cache's anchor. The title is the navigation bar's on iOS and the toolbar's on Android. |
| `state` | Not declared. `test.setup` and `session:` are unavailable. |

### Device

The `device` fixture is deterministic device management. A test calls it
directly to arrange or assert device state.

```ts
test('offline banner', { platforms: ['android'] }, async ({ app, device, screen }) => {
  await app.open();
  await device.setNetwork('offline');
  await expect(screen.getByText('You are offline')).toBeVisible();
  await device.setNetwork('online');
});
```

| Member | Returns |
| --- | --- |
| [`unstable_raw`](#unstable_raw) | `DeviceSession` |
| [`locator`](#locator) | `Locator` |
| [`setNetwork`](#setnetwork) | `Promise<void>` |
| [`setAirplaneMode`](#setairplanemode) | `Promise<void>` |
| [`setPermission`](#setpermission) | `Promise<void>` |
| [`setLocation`](#setlocation) | `Promise<void>` |
| [`clearLocation`](#clearlocation) | `Promise<void>` |
| [`setAppearance`](#setappearance) | `Promise<void>` |
| [`setOrientation`](#setorientation) | `Promise<void>` |
| [`fold`](#fold) | `Promise<void>` |
| [`setBiometrics`](#setbiometrics) | `Promise<void>` |
| [`enrollBiometrics`](#enrollbiometrics) | `Promise<void>` |
| [`installApp`](#installapp) | `Promise<InstalledApp>` |
| [`openApp`](#openapp) | `Promise<void>` |
| [`openLink`](#openlink) | `Promise<void>` |
| [`closeApp`](#closeapp) | `Promise<void>` |
| [`clearKeychain`](#clearkeychain) | `Promise<void>` |
| [`foregroundApp`](#foregroundapp) | `Promise<ForegroundApp>` |
| [`home`](#home) | `Promise<void>` |
| [`back`](#back) | `Promise<void>` |
| [`alert`](#alert) | `Promise<void>` |
| [`dismissKeyboard`](#dismisskeyboard) | `Promise<void>` |
| [`clipboard`](#clipboard) | `Promise<string>` |
| [`setClipboard`](#setclipboard) | `Promise<void>` |

Every async method is a recorded step named `device.<method>`, bounded by
`config.actionTimeout`. `back`, `home`, `alert`, `dismissKeyboard`,
`setOrientation`, and `fold` count as actions for the
[`transition`](#transition) budget. Each entry below shows its member's
declaration; the types they use are under [Types](#device-fixture).

| Throws | When |
| --- | --- |
| `APP_NOT_OPEN` | The session is lost. |
| `ACTION_FAILED` | `actionTimeout` expires. |
| `UNSUPPORTED_CAPABILITY` | The platform cannot run the command. |
| `ENGINE_FAILURE` | Anything else, with agent-device's message. A timeout the device itself reports (a boot, the runner connecting) keeps its text and hint there. A busy or wedged iOS automation runner names itself and the recovery (see [Troubleshooting](/mobile#troubleshooting)). |

#### `unstable_raw`

```ts
/**
 * The raw driver session this test drives, for what the methods here do
 * not cover. Calls through `client` bypass e2e: they are not steps, so the
 * report and trace leave them out, the agent's cache does not replay them,
 * their arguments reach the driver unredacted, and nothing waits for the
 * screen to settle after one. Unstable: it may change or go away in any
 * release.
 */
readonly unstable_raw: DeviceSession;
```

```ts
const { client, selection } = device.unstable_raw;
await client.apps.list(selection);
```

`client` is typed as `DeviceSessionClient`, exported from `@e2e-dev/mobile`.
Its operations are unstable and can change in any release.
After the worker disposes the session, reading `unstable_raw` or `client`
throws `INVALID_STATE`.

#### `locator`

```ts
/**
 * A locator from an agent-device selector (`'id=SW_VERSION_SPECIFIER'`,
 * `'role=text label="26.2"'`), for nodes the closed `screen` query
 * vocabulary cannot name. Same polling and strictness as any locator.
 */
locator(selector: string): Locator;
```

```ts
await expect(device.locator('role=navigation-bar id=About')).toBeVisible();
await expect(device.locator('role=text label="iOS Version"')).toHaveText('iOS Version');
await device.locator('id=SW_VERSION_SPECIFIER role=button').tap();
```

Selector terms and their rules are agent-device's, the ones `agent-device
find ... list` applies:

- Terms: `id`, `role`, `text`, `label`, `value`, `appname`, `windowtitle`,
  and the flags `visible`, `hidden`, `editable`, `selected`, `focused`,
  `enabled`, `hittable`.
- `role` takes agent-device's kind, the role `agent-device snapshot` prints:
  `button`, `text`, `text-field`, `navigation-bar`, `scroll-area`, `switch`,
  `image`. It is not the `getByRole` role (`textbox`).
- Text terms compare case-insensitively after collapsing whitespace.
- `visible` means the node is hittable or has a non-empty frame; `hidden` is
  its opposite.
- `text` reads the first non-empty label, value, or identifier.

<Note>
An action on a selector that matches several nodes fails, where an
agent-device action skips an ambiguous `||` alternative.
</Note>

#### `setNetwork`

```ts
/**
 * Switches an Android device's Wi-Fi. Cellular data stays on, so an
 * emulator hands the app over to its cellular link; `setAirplaneMode(true)`
 * cuts both. On iOS `offline` is `UNSUPPORTED_CAPABILITY`, since a
 * simulator shares the Mac's network and simctl can only repaint its status
 * bar; `online` sends nothing there, so a cleanup hook shared with Android
 * passes.
 */
setNetwork(state: 'online' | 'offline'): Promise<void>;
```

### Agent tools

`mobileTools(...engines)` from `@e2e-dev/mobile/tools` adds device tools to
an agent's `tools`.

```ts
tools: mobileTools(iphone, pixel),
```

- It takes at least one engine. Pass all device engines in one call; the
  tools use the current attempt's engine.

| Tool | Replay | Purpose |
| --- | --- | --- |
| `open_app` | gap | Bring an app to the foreground by id, optionally relaunched. Without an id it returns to the target's app. A link is refused, as it is for `device.openApp`. |
| `swipe` | gap | Free-form swipe between two points in logical pixels. |
| `alert` | gap | Accept or dismiss a system alert; prefer a listed button, whose tap replays. |

| Throws | When |
| --- | --- |
| `INVALID_STATE` | An engine that `mobile()` did not return. In the config this fails the load as `CONFIG_LOAD_FAILED`, whose message includes this one. |

A tool that fails during a built-in agent step returns
`Tool "<name>" failed: <message>` to the model as the call's result; the step
goes on. `open_app` fails with `INVALID_STATE` when it names no app, the
target has no `app.bundleId`, and nothing has installed its `app.appPath`
build yet (no `device.installApp()`, no device provider install); with
`INVALID_ARGUMENT` when it names an app that is not installed or a link; and
with `POLICY_DENIED` for a link with a forbidden scheme. Any tool fails with
`INVALID_STATE` when no device attempt is running, or when several device
attempts are running in one worker.

The grammar verbs need no tool pack. The engine's declared actions give the
agent:

- `tap`, `double_tap`, `long_press`, `hover`, `type`, `press`, `check`,
  `scroll`, `drag`, `scroll_to` by `text` (paging the list until a row
  reading it is drawn), `back`, and `dismiss_keyboard`.
- The pixel tools `screenshot`, `tap_at`, `hover_at` (on a listed control
  only), `drag_at` (between two different listed controls only), `type_at`, and
  `press_at`. Point actions can tap controls absent from the accessibility
  tree.
- `type_secret`, when the step declares a secret.

There is no `right_click`, `select`, `scroll_to` by node id, `upload`, or
`navigate` on a device, and `select_at` is not offered.

<Note>
Pixels whose masking the engine cannot prove are withheld as `MASKING_UNPROVEN`. An accessibility
capture failure still stops the observation. Device screenshot masks depend
on secure-field bounds from that capture, so without them the engine cannot
prove a fallback screenshot safe.
</Note>

#### `unstable_deviceSession`

`unstable_deviceSession(...engines)` from `@e2e-dev/mobile/tools` gives a custom tool
the running attempt's `DeviceSession`, the same object a test reads from
[`device.unstable_raw`](#unstable_raw). Its `client` is bound to the engine's
daemon, lease, and per-worker session, for capabilities e2e does not wrap
yet. Its `client` is typed as `DeviceSessionClient`.
The following example assumes the current driver supports `settings.update`.

```ts
import { tool } from 'ai';
import { z } from 'zod';
import { defineTool } from 'e2e/agent';
import { unstable_deviceSession } from '@e2e-dev/mobile/tools';

const mobileData = defineTool(
  tool({
    description: 'Turn cellular mobile data on or off. Wi-Fi is not affected.',
    inputSchema: z.object({ on: z.boolean() }),
    execute: async ({ on }) => {
      const { client, selection } = unstable_deviceSession(iphone, pixel);
      await client.settings.update({ ...selection, setting: 'mobile-data', state: on ? 'on' : 'off' });
      return on ? 'mobile data is on' : 'mobile data is off';
    },
  }),
  { mutates: true, platforms: ['android'] },
);

tools: { ...mobileTools(iphone, pixel), mobileData },
```

- Pass every device engine the config declares, as with `mobileTools`.
  Outside an attempt it throws `INVALID_STATE`.
- Spread `selection` into a call so it reaches the worker's device even
  before the session has an app open, as the engine's own calls do.
- Client calls are not steps: the report shows the tool call, not what the
  client did, and a cache replay runs a `mutates: true` tool live.
- Client calls skip e2e's guards, as with `unstable_raw`. A snapshot or
  screenshot a tool returns is not redacted or masked, even after a secret
  fill, nothing waits for the screen to settle after a call, and a tool
  whose calls change the device must declare `mutates: true`.
- Like `unstable_raw`, it can change in any release.

A node the platform reports editable is a `textbox`, unless it already maps
to `combobox`.

| --- | --- | --- |

| `textbox` | `TextField`, `SearchField`, `TextView`, `SecureTextField` | `EditText`, `AutoCompleteTextView`, `TextInputEditText`, `SearchView` |
| `combobox` | | `Spinner` |
| `switch` | `Switch`, `Toggle` | `Switch`, `SwitchCompat`, `SwitchMaterial`, `ToggleButton` |
| `checkbox` | `CheckBox` | `CheckBox`, `MaterialCheckBox` |
| `radio` | `RadioButton` | `RadioButton` |

and `timer` give are not `getByRole` roles.

`checked` and `expanded`; only what follows them is the node's value.

Android `WebView` is `document`. Neither is a `getByRole` role: find text
with `getByText`.

## Visibility

A device node is hidden when the platform reports it off screen, or when the
soft keyboard covers its centre. So `toBeVisible()`, `scrollUntilVisible`,
and `getByRole` treat a field under the keyboard like a field scrolled out
of view. The keyboard's own keys, suggestion bar, and dock stay visible, and
so does the focused field.

- The keyboard's area is the frame agent-device measures. When a capture has
  no frame, the area runs from the top of the keyboard in the tree to the
  bottom of the screen.
- A container whose centre is under the keyboard stays visible while one of
  its children shows above it.
- A node under another view, such as a footer the keyboard lifts, is not
  hidden. A tap on it fails with `ACTION_FAILED` when agent-device finds the
  cover, and the message names the cover. A tap under the keyboard fails the
  same way. Dismiss the cover, or scroll the target clear of it.

## Video recording cleanup

A pending agent-device screen-recording stop is shared with later callers
and attempt cleanup. Cancelling one caller's wait does not repeat the stop
or discard its eventual completion. If the device stop fails, cleanup can
retry it. A cancelled caller still reports cancellation.

A provider recording that fails to stop stays owned by its worker. The
engine retries its stop at attempt end, before another attempt on that
worker, and during worker disposal. A pending stop is shared. Each retry
uses the original attempt's video directory.

The next attempt starts only after the provider confirms the stop. A
failed or cancelled stop wait prevents that attempt from starting.
Confirmed stops are not repeated if the returned artifact is invalid.
A failed provider stop alone does not close a healthy agent-device session
during worker replacement.

A recording recovered by a retry is not added to the report: its file can
stay in the original attempt's video directory, and a returned URL is
dropped. A required video whose first stop failed stays a cleanup failure.

These recording handles do not survive worker exit. At run end, the engine
closes its agent-device sessions and the provider releases its leases.
Providers must clean up any remaining external recordings when releasing a
lease. Closing an agent-device session cannot guarantee that an arbitrary
cloud recording stops. A failed provider stop callback does not confirm that
the recording stopped.

## Replay cache on a device

The replay cache anchors on the [`location`](#capabilities) a device reports,
`<bundle id> / <screen title>`. A step recorded on
`com.apple.Preferences / General` replays only when Settings is on General
again.

```ts
await app.open();
await screen.getByText('General').tap();
await agent.act('Open About and read the iOS version');
```

- A mutating project-tool call such as `open_app` ends a replay.
- Declare `app.bundleId` and call `app.open()` first, so steps start on the
  same screen.
- Switch apps through the `device` fixture between steps rather than inside
  one.
- A step recorded after [`device.openLink`](#openlink) replays when the link
  lands on the same screen again.
