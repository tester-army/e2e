---
title: E2EConfig
description: Every configuration key, its default, its valid range, and the environment variables.
---

Export an object from `e2e.config.ts` and use `satisfies E2EConfig` to check
its shape without widening its inferred types. The runner also validates the
config when it loads, including ranges and rules TypeScript cannot check.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [
    {
      name: 'web',
      engine: web({ browser: 'chromium', url: process.env.APP_URL ?? 'http://localhost:3000' }),
    },
  ],
} satisfies E2EConfig;
```

Unknown keys are rejected with `INVALID_CONFIG` at every level. There is no
top-level `app` key: the engine declares the app it drives (see
[the app under test](#the-app-under-test)).

An optional key takes a value or is left out; `undefined` is not a value, so
`store: process.env.CACHE_URL && createStore(...)` fails to compile. Spread a
key that depends on the environment in only when it has a value:

```ts
export default {
  targets: [{ engine: web({ url: 'http://localhost:3000' }) }],
  ...(process.env.CACHE_URL === undefined ? {} : { cache: { store: createStore(process.env.CACHE_URL) } }),
} satisfies E2EConfig;
```

## Loading

`--config <path>` selects an explicit file. Otherwise the runner searches the
working directory and each parent for `e2e.config.ts` or `e2e.config.mts`,
stopping at the repository root. Both names in one directory is
`CONFIG_AMBIGUOUS`. The selected file's directory is the project root.

The `tests` globs select files relative to the project root. Discovery visits
only directories that could match, skips `node_modules`, and ignores
symlinks. A dot directory is included only when a glob segment explicitly
starts with a dot.

Config and test files run as ESM whatever the nearest `package.json` `type`
says. Packages imported by name keep their own format. A config or test
written with `require` or `module.exports` fails to load.

## Top level

```ts
export interface E2EConfig {
  /** The config format this runner implements: `'0.1'`. */
  specVersion?: '0.1';
  /** Stable project id, 1 through 256 characters; defaults to the root `package.json` name. */
  projectId?: string;
  /** The surfaces tests run on; required, at least one, each naming its engine. */
  targets: readonly Target[];
  /** Test file globs relative to the project root (`*`, `?`, and a whole `**` segment); default every `*.e2e.ts` under `tests/`. */
  tests?: string | readonly string[];
  /** Test attempt deadline in milliseconds; default 120000. */
  timeout?: number;
  /** Engine init and attempt start budget in milliseconds; default 60000. */
  launchTimeout?: number;
  /** Budget of every engine operation in milliseconds; default 30000. */
  actionTimeout?: number;
  /** Default `expect` deadline in milliseconds; default 5000. */
  assertionTimeout?: number;
  /** Budget of each `afterEach` hook, fixture teardown, and engine cleanup in milliseconds; default 30000. */
  cleanupTimeout?: number;
  /** Retries per test, 0 through 10; default 1 in CI, else 0. */
  retries?: number;
  /** Parallel workers, 1 through 1024; default 1 in CI, else half the cores. An engine may cap it lower. */
  workers?: number;
  /** Artifact kinds, or `{ kinds, store, video }` to also hand every artifact to a host store. */
  artifacts?: readonly ConfiguredArtifactKind[] | ArtifactsConfig;
  /**
   * Output renderers and reporter objects. `junit` writes `.e2e/junit.xml`,
   * `markdown` writes `.e2e/summary.md`, `json` prints the report and
   * excludes `list`; a `Reporter` object runs
   * beside them and `--reporter` never removes it.
   */
  reporters?: readonly (BuiltinReporter | Reporter)[];
  /**
   * Named agent configurations, `createAgent(...)` values, or custom
   * `StepExecutor` values. Tests use `default` unless selected otherwise.
   * Each worker constructs its own agents from this config module.
   */
  agents?: Readonly<Record<string, AgentConfig | StepExecutor>>;
  /**
   * Trace cache mode or options. Defaults to `read-write` locally and
   * `read-only` in CI. An explicit mode overrides the default;
   * `--no-cache` disables caching for the run.
   */
  cache?: CacheMode | CacheConfig;
  /**
   * Maximum context size, ledger size, events, and tokens.
   */
  limits?: {
    /** Trusted agent context, 1024 through 65536; default 16384. */
    maxAgentContextBytes?: number;
    /** Prior-step ledger, 1024 through 65536; default 8192. */
    maxLedgerBytes?: number;
    /** Events recorded per step, 1 through 10000; default 1000. */
    maxEventsPerStep?: number;
    /** Tokens per model request, 1 through 1000000; default 64000. */
    maxModelTokensPerCall?: number;
  };
  /**
   * Named accounts. A credential's password is registered as a secret under
   * the credential's name, so the name may not also appear under `secrets`.
   */
  credentials?: Readonly<Record<string, CredentialConfig>>;
  /**
   * Named values the model must never see: API keys, tokens, anything sourced
   * from the environment. `secrets.get(name)` hands a test the opaque handle;
   * the value is filled by the runner, masked in every observation, and
   * redacted from logs, traces, and the report.
   */
  secrets?: Readonly<Record<string, SecretConfig>>;
}
```

Every numeric value must be a safe integer. `projectId` falls back to
`unportable-<sha256 of the project root, 32 hex>` when there is no
`package.json`. `workers` never exceeds what a target's engine declares. A
targeted agent action is bounded by the smaller of `actionTimeout` and 15 s.

## targets

```ts
/**
 * One named test target. The engine declares its app and capabilities.
 * Without an engine, the target supports agent tools only.
 */
export interface Target {
  /** Label in reports and for `--target`; defaults to the platform. */
  name?: string;
  /**
   * Platform label, inherited from the engine when omitted. Required for a
   * target without an engine; when both name one, they must agree.
   */
  platform?: string;
  /** The engine driving the surface: `web(...)`, `mobile(...)`, or any `defineEngine` handle. */
  engine?: EngineHandle;
}
```

`name` is the id `--target`, reports, sessions, and artifact paths use:
ASCII letters, digits, `_`, `-`, `.`, not only dots (`.` and `..` are path
segments), unique across targets.

`{ engine: web({ url }) }` is a complete target. Two targets on one
platform need names. A target without an engine runs through agent tools
only. Tests whose `requires` names a capability the target lacks are skipped
for it; a `test.setup` a selected test depends on must be runnable there or
selection fails with `COLLECTION_ERROR`.

## The app under test

The engine declares the app it drives: the browser engine as options of
`web(...)`, the device engine from the app it pins. The runner
resolves it at config load.

```ts
/**
 * App details declared by an engine and resolved once per target.
 */
export interface EngineAppDeclaration {
  /**
   * Base URL of an addressable app: `app.open()` opens it and relative
   * navigation resolves against it. WHATWG-normalized; no userinfo, query, or
   * fragment; a missing scheme becomes `https://`, or `http://` for a
   * loopback host. Plain HTTP is accepted for loopback hosts only. A URL on
   * `127.0.0.1` or `[::1]` with port 0 asks the run for a free port,
   * substituted wherever the declaration used it and handed to `command` and
   * `services` as `{port}`.
   */
  readonly url?: string;
  /**
   * Labels the target in the report and joins the cache and session identity
   * digest; never gates a run. Defaults to `test` for loopback, `.localhost`,
   * and `.test` hosts and for a surface without a URL, `production` otherwise.
   */
  readonly environment?: 'test' | 'staging' | 'production';
  /**
   * App identity for trace cache and session entries. Defaults to the URL's
   * origin and base path. Set a stable value to reuse entries across preview
   * URLs. Without a URL or identity, entries use the target alone. Different
   * apps must have different identities to prevent replay across them.
   */
  readonly identity?: string;
  /**
   * Process the runner starts before the first test and stops on every exit
   * path (a dev server). Structured, never shell-interpreted; the child
   * inherits only `PATH`, `HOME`, the temp-directory variables, and
   * `command.env`. Targets declaring the same command share one process,
   * probed at the first declaring target's `readyUrl`.
   */
  readonly command?: CommandConfig;
  /** URL polled until `command` is ready (a 200-499 status); defaults to `url`. */
  readonly readyUrl?: string;
  /**
   * Dependency processes the app needs before it can boot (a database
   * container, a migration step), started in declaration order before any
   * app command and torn down in reverse after it. Valid without `command`:
   * the app may already be running, or be one of the services itself.
   * Services declared identically by several targets start once; shared
   * services must be declared in one order, and an explicit `name` must mean
   * one process across the run.
   */
  readonly services?: readonly ServiceConfig[];
}
```

Port `0` on any host other than `127.0.0.1` or `[::1]`, `localhost`
included, is `INVALID_APP_URL`. A `command` with neither `url` nor `readyUrl`
is `APP_URL_REQUIRED` at config load.

### The app's site

A test or the agent may open any http(s) URL; `file:`, `data:`, and
`javascript:` are `POLICY_DENIED`. The site of `url`, its registrable domain
(`app.example.com` and `auth.example.com` are one site), scopes two things:
the browser engine's [`headers`](/reference/web#options) reach the
site and no other host, and child frames off the site stay out of
observations.

### Free ports

A `url` on a literal loopback address with port `0` (`http://127.0.0.1:0`,
`http://[::1]:0`) asks the run for a free TCP port. The runner picks one when
the config loads and substitutes it wherever the declaration used the port:
the base URL, the default `readyUrl`, and the report. The command must take
the port through `{port}` in `args` or `env`.

```ts title="e2e.config.ts"
engine: web({
  url: 'http://127.0.0.1:0',
  command: { executable: 'pnpm', args: ['dev', '--port', '{port}'], env: { PORT: '{port}' } },
}),
```

`localhost:0` is `INVALID_APP_URL`: it may resolve to an address other than
the one the command binds. Write the address the command will bind.

Each target asking for port `0` gets its own port, so two targets meant to
share one dev server should share a fixed port. Services keep the ports their
config gives them and read the app's through `{port}`. The default `identity`
derives from the declared `:0`, so cache and session entries do not churn
with the port. Tests read the allocated URL from
[`app.baseUrl`](/reference/app).

### command

```ts
export interface CommandConfig {
  /** Resolved with `PATH`; never shell-interpreted. */
  executable: string;
  /** Passed verbatim; `{port}` expands to the app's port. */
  args?: readonly string[];
  /** Working directory, resolved from the project root. */
  cwd?: string;
  /** Added to the inherited set; `{port}` expands in values. */
  env?: Readonly<Record<string, string>>;
  /** Ready-probe budget in milliseconds; default 60000. Expiry is `APP_UNREACHABLE`. */
  startupTimeout?: number;
  /** Grace period before force-kill in milliseconds; default 10000. */
  shutdownTimeout?: number;
  /** File that receives the process's stdout and stderr, appended, resolved from the project root. Omitted discards output. */
  log?: string;
  /**
   * When the readiness URL already answers before the command starts, use that
   * process instead of spawning: nothing is started and nothing is stopped.
   * Off by default; CI ignores it and always starts the command.
   */
  reuseExisting?: boolean;
}
```

`log` must stay inside the project root and holds the raw, unredacted
output, so keep it in an ignored directory. A startup failure quotes the last
20 lines appended since the command started, with `command.env` values
replaced by `<secret:NAME>` markers. Without `reuseExisting`, a `readyUrl`
that already answers is `APP_ALREADY_RUNNING`. `{port}` on a target without a
`url` is `INVALID_CONFIG`.

The child inherits only `PATH`, `HOME`, `TMPDIR`, `TMP`, `TEMP`,
`SystemRoot`, and `COMSPEC`, plus everything in `command.env`. The runner
never terminates a process it did not start.

### services

```ts
/**
 * One dependency process of the app under test (a database container, a
 * cache, an auth emulator, a migration step). Services start sequentially in
 * declaration order before `app.command`, and each must be ready before the
 * next starts. Exactly one of `readyUrl` or `waitForExit` declares how a
 * service becomes ready; a service with neither has no readiness contract and
 * is rejected as `INVALID_CONFIG`.
 */
export interface ServiceConfig extends CommandConfig {
  /** Label used in errors, reporter output, and the report; defaults to the executable name. */
  name?: string;
  /** Optional HTTP readiness probe; a status of 200 through 499 counts as ready. */
  readyUrl?: string;
  /**
   * Wait for the process to exit with code 0 instead of probing a URL
   * (migrations, `docker compose up --wait`). A non-zero exit or the
   * `startupTimeout` expiring is `APP_UNREACHABLE`.
   */
  waitForExit?: boolean;
  /**
   * Optional command run during teardown after the service itself has been
   * stopped (`docker compose down`). Runs on every exit path, is waited on
   * until exit within its own `startupTimeout`, and a failure is recorded as a
   * cleanup-phase run error rather than a crash.
   */
  teardown?: CommandConfig;
}
```

`name` is at most 64 characters and unique across named services. `{port}`
in a service's `args`, `env`, `readyUrl`, and `teardown` is the app's port.

Exactly one of `readyUrl` or `waitForExit` is required per service.
`reuseExisting` works on a `readyUrl` service and skips its `teardown`; on a
`waitForExit` service it is `INVALID_CONFIG`. Services start in declaration
order before any app command, each ready before the next. Services declared
identically by several targets start once; two targets that order them
differently are `INVALID_CONFIG`.

On every exit path the runner stops the app commands, then the services in
reverse order, then their `teardown` commands. A failing teardown is a
`cleanup` run error and never skips the ones after it.
[Starting your app](/starting-your-app) shows a full example.

## artifacts

```ts
artifacts: {
  kinds: ['screenshot', 'trace', 'video'],
  store: {
    async put(artifact) {
      const key = await bucket.upload(artifact.path, artifact.bytes);
      return { ref: key };
    },
  },
  video: { retain: 'on-failure' },
},
```

`kinds` accepts `screenshot`, `trace`, and `video`. The default set is
screenshot and trace, captured best-effort. A configured kind the target's
engine cannot produce fails before collection with `UNSUPPORTED_ARTIFACT`.
`video` is never in the default set; `--video` adds it for one run.

`store` receives every artifact once it is complete on disk and returns a
reference the report records as `ref` beside the local path. A failed `put`
never fails the run. Each worker constructs its own store from the config
module. `redaction` is the report's label: a store that exports only what
the runner vouches for keeps back an `incomplete` artifact, a video or a
download the runner did not rewrite.

```ts
/** One produced artifact, handed to `store.put` once it is complete on disk. */
export interface StoredArtifact {
  readonly kind: 'screenshot' | 'trace' | 'video' | 'download' | 'log';
  readonly mediaType: string;
  readonly bytes: Uint8Array;
  readonly size: number;
  readonly sha256: string;
  /** Report-relative path with `/` separators, stable across runs of the same test. */
  readonly path: string;
  /** How much of the file the runner masked, as the report records it. */
  readonly redaction: 'complete' | 'not-required' | 'incomplete';
  readonly runId: string;
  readonly testId: string;
  readonly attemptId: string;
  /** The step that produced it, when one was running. */
  readonly stepId?: string;
  /** When a time-based artifact (a video segment) began recording. */
  readonly startedAt?: string;
}
```

### video

With `video` among the kinds, or `--video`, every selected engine must
support recording; otherwise configuration fails with `UNSUPPORTED_ARTIFACT`.
Playwright writes `video/video.webm` under the attempt's artifact directory,
one segment per page, later ones as `video/video-part<n>.webm`. The
mobile engine writes `video/video.mp4`. Each segment carries
`startedAt`, so `step.startedAt - artifact.startedAt` is a step's offset into
it.

| Key | Type | Default | Notes |
| --- | --- | --- | --- |
| `retain` | `'all' \| 'on-failure'` | `'all'` | `on-failure` deletes the recording of every attempt that passed once its verdict is known |

A recording masks nothing and is recorded with `redaction: 'incomplete'`.
Turning video on or off never invalidates cached replays.

## agents

```ts
/** Agent options for the built-in agent; `agent` also accepts a StepExecutor. */
export interface AgentConfig {
  /**
   * Executor for `agent.act()`. Defaults to the built-in agent.
   */
  executor?: StepExecutor;
  /** An AI SDK model instance; no implicit default. */
  model?: ModelInstance;
  /**
   * Model for `assert`, `waitFor`, and `extract`; defaults to `model`.
   * Must agree with `createAgent({ judge })` when both are set.
   */
  judge?: ModelInstance;
  /** Committed actions per agent call, 1 through 100; default 25. */
  maxSteps?: number;
  /** Model requests per agent call, 1 through 100; default 25. */
  maxModelCalls?: number;
  /** Deadline of one `assert`, `waitFor`, or `extract` call in milliseconds; default 30000. Raise it for a slow judge; engine operations keep `actionTimeout`. */
  timeout?: number;
  /** Observation payload ceiling for act turns and judgments, 1024 through 16777216; default 262144. */
  maxObservationBytes?: number;
  /**
   * What the app calls things, told to every model call this agent makes,
   * act turns and judgments alike. At most `limits.maxAgentContextBytes`.
   * Redundant when the executor was built with `createAgent({ context })`;
   * two different values is `INVALID_CONFIG`.
   */
  context?: string;
  /**
   * Provider options every model call carries, e.g. a reasoning effort.
   * OpenAI and Azure OpenAI calls also carry `store: false` and a prompt
   * cache key unless set here.
   */
  providerOptions?: ProviderOptions;
}
```

Tests use the `default` agent unless you select another with
`e2e run --agent <name>`, a test or group option, or an individual `agent.*`
call. A test with `{ agent: ['buyer', 'admin'] }` runs once for each agent.
`default` exists even when the config declares no agents, but has no model.

Names may contain ASCII letters, numbers, `_`, `-`, or `.`, and are never
only dots: a name is an artifact path segment. An unknown name
is `INVALID_CONFIG` on the CLI flag, `COLLECTION_ERROR` on a test or group,
and `INVALID_ARGUMENT` on a call. See [Agents and personas](/agents).

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { createAgent } from 'e2e/agent';
import { web } from '@e2e-dev/web';
import { gateway } from 'ai';

export default {
  targets: [{ engine: web({ url: 'http://localhost:3000' }) }],
  agents: {
    default: { model: gateway('openai/gpt-6-luna-fast') },
    ux: createAgent({ model: gateway('openai/gpt-6-luna-fast'), system: 'Check labels, contrast, and keyboard access.' }),
    thorough: { model: gateway('anthropic/claude-opus-5'), context: 'Verify every claim on screen.' },
    buyer: {
      executor: createAgent({
        model: gateway('openai/gpt-6-luna-fast'),
        system: 'You are a first-time buyer.',
        context: 'Plans are called tiers. Billing lives under Settings.',
      }),
      maxSteps: 40,
    },
  },
} satisfies E2EConfig;
```

A bare `StepExecutor` is shorthand for `{ executor }`. `createAgent` accepts
`model`, `system`, and `context`, so `{ executor: createAgent({ model, system,
context }) }` is a complete agent: the options object around it needs no
second `model` or `context` key. `createAgent` also takes `judge`, `tools`,
`providerOptions`, and `maxTurns`, a cap on the model turns of one step; it
defaults to `maxModelCalls` and can only lower it. A string in `model` is
`INVALID_CONFIG` naming the constructor to write, and so is a `model`,
`judge`, or `context` that differs from the one passed to `createAgent(...)`. See
[Custom executors](/executors) and
[A judge of its own](/models#a-judge-of-its-own).

Judgments (`assert`, `waitFor`, `extract`) allow 8192 output tokens per call
and see the instruction and the current screen only.

### model

```ts
/**
 * An AI SDK LanguageModelV2+ instance. Its provider handles transport
 * and credentials.
 */
export interface ModelInstance {
  /** The AI SDK specification the instance implements. */
  readonly specificationVersion: string;
  /** Provider id, recorded per step in the report. */
  readonly provider: string;
  /** Model id, recorded per step in the report. */
  readonly modelId: string;
  /** The generate call every AI SDK language model implements; what tells a live instance from its three id strings. */
  readonly doGenerate: (...args: never[]) => unknown;
}
```

Construct the model in your config with an AI SDK provider. For subscription
sign-in, use the [`e2e/oauth/*` models](/subscriptions).

| Gateway | Constructor | Package | Reads |
| --- | --- | --- | --- |
| [Vercel AI Gateway](https://vercel.com/docs/ai-gateway) | `gateway('openai/gpt-6-luna-fast')` | `ai` | `AI_GATEWAY_API_KEY`, or a Vercel OIDC token without it |
| [OpenRouter](https://openrouter.ai/models) | `openrouter('openai/gpt-6-luna-fast')` | `@openrouter/ai-sdk-provider` | `OPENROUTER_API_KEY` |
| Any OpenAI-compatible endpoint | `createOpenAICompatible({ name, baseURL, apiKey? }).chatModel('llama3.2')` | `@ai-sdk/openai-compatible` | `apiKey`, when the endpoint needs one |
| A provider directly | `openai('gpt-6-luna')`, `anthropic(...)`, ... | `@ai-sdk/openai`, `@ai-sdk/anthropic`, ... | the provider's own variable |

Reports record `provider` and `modelId` per step. Each worker constructs its
own instance from the config module; a digest that differs between the
runner and a worker is `CONFIG_NOT_DETERMINISTIC`. See
[Choosing a model](/models).

## credentials

```ts
/** One `config.credentials` entry: an account whose password is the secret of the entry's name. */
export interface CredentialConfig {
  username: string;
  password: string | SecretProvider;
}

type SecretProvider = () => string | Promise<string>;
```

A `SecretProvider` is called on every authorized fill (a vault lookup, a
freshly computed TOTP) and recorded in the config digest by name only. An
`E2E_USER_*` override wins over it. A static password is at least 6
characters (code points), like a secret, or `INVALID_CONFIG`; a provider
returning fewer fails the fill with `AUTH_CREDENTIAL_UNAVAILABLE`.

`credentials.user(name)` resolves a configured entry into a `Credential`.
The username is a plain string; the password is an opaque `Secret` that test
code cannot read, accepted only by `locator.fill` and `agent.act` params. An
unconfigured name throws `AUTH_CREDENTIAL_UNAVAILABLE`.

A credential's password is registered as the secret of the credential's name,
so a name declared under both `credentials` and `secrets` is `INVALID_CONFIG`.

```ts
/** Named test identity. The password remains an opaque Secret. */
export interface Credential {
  /** The entry's name in `credentials`. */
  readonly name: string;
  /** Plain username. */
  readonly username: string;
  /** Opaque; test code cannot read it. */
  readonly password: Secret;
  readonly [credentialBrand]: true;
}
```

See [Signing in](/authentication).

## secrets

```ts
/** One `config.secrets` entry: the value itself, or a provider computing it at fill time. */
export type SecretConfig = string | SecretProvider;
```

An entry is a static value, or a provider called on every authorized fill (a
vault lookup, a freshly computed TOTP). It is recorded in the config digest by
name only, and an `E2E_SECRET_<NAME>` override wins over both. Every entry
must resolve to a string of at least 6 characters (code points) or a
function; anything else is `INVALID_CONFIG`. The minimum exists for redaction: every occurrence
of a value becomes `<secret:name>`, and a shorter value would take ordinary
text in reports and output with it. A provider's value is held to the same
minimum at fill time, with `SECRET_UNAVAILABLE`.

`secrets.get(name)` returns the opaque `Secret` for a configured entry. It has
no plaintext accessor and is accepted only by `locator.fill` and `agent.act`
params; the runner fills the field, masks the value in every observation, and
redacts it from logs, traces, and the report. An unconfigured name throws
`SECRET_UNAVAILABLE`.

```ts
/**
 * What a secret is for, which decides where it may be filled: a `password`
 * goes only into a password field; a `generic-secret` (an API key, a token,
 * any value from the environment) goes into any editable input.
 */
export type SecretPurpose = 'password' | 'generic-secret';

/** Opaque host-side value accepted only by sensitive input sinks. */
export interface Secret {
  /** The entry's name in `credentials` or `secrets`. */
  readonly name: string;
  /** Where the value may be filled. */
  readonly purpose: SecretPurpose;
  readonly [secretBrand]: true;
}
```

See [Secrets that are not passwords](/authentication#secrets-that-are-not-passwords).

## cache

In `read-write` mode the trace cache records an `agent.act()` only after a
later verification passes, such as a locator assertion or `agent.assert()`.
`read-only` replays existing entries and writes none; `off` disables both.
See [Caching agent steps](/cache).

```ts
/**
 * Trace cache options. Defaults to files under `.e2e/cache/`.
 * A custom store replaces file storage; each worker constructs its own.
 */
export interface CacheConfig {
  /** Default `read-write`; `read-only` in CI when unset. */
  mode?: CacheMode;
  /** Custom entry store; omit it to use the file store at `dir`. */
  store?: TraceCacheStore;
  /** File store directory, resolved against the project root. */
  dir?: string;
  /** Fail a step whose recording no longer replays with `REPLAY_STALE`. Default `false`. */
  strict?: boolean;
}
```

A bare string is shorthand for `{ mode }`. Set `'read-write'` explicitly when
CI restores the cache from its own cache service; `--no-cache` wins over
both. A custom `store` is exempt from the CI demotion and states its own
trust through `writable`. `strict` (or `--strict-cache` for one run) turns a
recording that exists but no longer replays into a `REPLAY_STALE` failure
instead of a hand-off to the agent; see
[Fail on a stale recording](/cache#fail-on-a-stale-recording).

### Commit your traces

`e2e init` adds `.e2e/cache/` to `.gitignore`, so committing entries is
opt-in. Remove that line to share replays with CI and teammates; CI stays
`read-only` unless `cache: 'read-write'` is set. See
[Caching agent steps](/cache#commit-your-traces).

Per-call options may only lower these.

## Environment variables

The runner reads a closed set, listed on the
[Environment variables](/reference/environment) page. `E2E_USER_<NAME>_USERNAME`
and `E2E_USER_<NAME>_PASSWORD` override a credential, `E2E_SECRET_<NAME>` a
secret, and `CI` switches the defaults below.

### Resolution order

| Setting | Order |
| --- | --- |
| Base URL | the engine's declared `url`, else `APP_URL_REQUIRED` at the first navigation. The runner reads no `APP_URL`; the scaffolded config reads it itself |
| Built-in agent model | the model passed to `createAgent({ model })`, then `agents.<name>.model`, then `MODEL_UNAVAILABLE` at `agent` acquisition |
| App vocabulary (`context`) | the value the agent's executor was built with (`createAgent({ context })`), else the agent entry's own `context`; two different values is `INVALID_CONFIG` |
| Model credential | the provider package's own variable or the key passed at construction, read by the provider on the first model call |
| Credential username and password | the `E2E_USER_*` variable, then the config value |

The built-in agent checks for a missing model once per run, when the `agent`
fixture is first acquired, and stops the run with exit 2. A custom executor
can implement `act` and `assert` without a model. `waitFor` and `extract`
still require one.

### CI

CI mode is on unless `CI` is unset, blank, `0`, or `false`.

| Setting | Local | CI |
| --- | --- | --- |
| `retries` | `0` | `1` |
| `workers` | `max(1, floor(availableParallelism() / 2))` | `1` |
| `cache` | `read-write` | `read-only` when unset |
| `test.only` | allowed | `ONLY_IN_CI`, exit code 2 |
| `command.reuseExisting` | honored | ignored, with a notice |
