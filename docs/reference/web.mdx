`@e2e-dev/web` is the browser engine. It drives Chromium and Firefox over
WebDriver BiDi. A web target names it as its engine with `web()`, and it
contributes the `browser` fixture for browser-only work.

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
} satisfies E2EConfig;
```

Import `test` from the package to have `browser` typed:

```ts title="tests/orders.e2e.ts"
import { expect } from 'e2e';
import { test } from '@e2e-dev/web';

test('orders in dark mode', async ({ app, browser, screen }) => {
  await browser.emulateMedia({ colorScheme: 'dark' });
  await app.open('/orders');
  await expect(browser).toHaveURL('/orders');
  await expect(screen.getByRole('heading', { name: 'Orders' })).toBeVisible();
});
```

## Reference

### Options

`web(options)` sets how the engine drives the app. The app itself (its
`url`, `environment`, `identity`, and the command that starts it) is the
target's `app`, documented under
[the app under test](/reference/config#the-app-under-test).

```ts
web({ viewport: { width: 390, height: 844 }, locale: 'de-DE' });
```

| Option | Type | Default |
| --- | --- | --- |
| [`browser`](#browser) | `BrowserName \| BrowserProvider` | `'chromium'` |
| [`viewport`](#viewport) | `ViewportSize \| null` | 1280 by 720 |
| [`screencast`](#screencast) | `WebScreencastOptions` | the viewport's size |
| [`connect`](#connect) | `WebConnectOptions` | launches locally |
| [`headers`](#headers) | `Record<string, string>` | - |
| [`basicAuth`](#basicauth) | `WebBasicAuth` | - |
| [`testIdAttribute`](#testidattribute) | `string` | `'data-testid'` |
| [`userAgent`](#useragent) | `string` | the browser's own |
| [`locale`](#locale) | `string` | the browser's own |
| [`timezoneId`](#timezoneid) | `string` | the machine's |
| [`colorScheme`](#media-emulation) | `'light' \| 'dark' \| 'no-preference'` | the browser's own |
| [`reducedMotion`](#media-emulation) | `'reduce' \| 'no-preference'` | the browser's own |
| [`initScripts`](#init-scripts) | `WebInitScript[]` | - |

- A `web()` target needs `app.url` and refuses the device keys (`bundleId`,
  `appPath`, `launchArguments`). Its `app.permissions` takes `'grant'` only,
  for names its browser grants; see
  [`permissions`](/reference/config#permissions).
- A target with `app.url` is a `browser` target, so `requires: ['browser']`
  selects web targets.
- The full declaration with its JSDoc is [`WebOptions`](#weboptions) under
  Types.

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | An option `web()` does not take (`url` or any other app key included), or an unknown key inside `connect` or `basicAuth`. The message names the nearest known key for a likely typo (`viewprt` is `viewport`), else every key. |
| `INVALID_CONFIG` | `connect.reconnectEndpoint`, which is not supported. |

#### `browser`

The browser to launch, or a provider that leases hosted browsers.

```ts
web({ browser: 'firefox' }); // default: 'chromium'
```

- `'chromium'` or `'firefox'`. [Installing browsers](#installing-browsers)
  has the builds.
- A `BrowserProvider` leases hosted browsers instead, one per worker slot for
  the run, or one per attempt with `scope: 'attempt'`. The engine drives
  each one as chromium over CDP, whether it is Chromium or another CDP
  server such as [Lightpanda](/integrations/lightpanda).
- With `scope: 'attempt'`, each attempt runs in the leased browser's own
  context, so `app.clearState()` and saved sessions throw
  `UNSUPPORTED_CAPABILITY`.
- [Hosted browsers](/browser#hosted-browsers) has the `BrowserProvider`
  contract and an example provider.

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | Any other browser name, `'webkit'` included. |
| `INVALID_CONFIG` | `browser: provider` together with `connect`. |

#### `viewport`

The initial viewport of every attempt's page.

```ts
web({ viewport: { width: 390, height: 844 } }); // default: { width: 1280, height: 720 }
```

`null` emulates no size, so the page fills the browser window
([`WebOptions`](#weboptions)). [`browser.setViewport`](#setviewport) still
fixes one.

#### `screencast`

How the engine's own screencast records an attempt that records video.

```ts
web({ screencast: { size: { width: 800, height: 450 }, quality: 60 } });
```

- `size` takes whole pixels, each side at least 1. `quality` is an integer.
- Which attempts record is the config's [`video`](/reference/config#video)
  mode.

```ts
/** The engine's screencast of the page: the frame size and the JPEG quality of the frames it encodes. */
export interface WebScreencastOptions {
  /** Frame size in pixels; default the viewport's, or the window's under `viewport: null`. A smaller size makes a smaller file. */
  readonly size?: ViewportSize;
  /** JPEG quality of each captured frame, 0 through 100; the browser's default when unset. */
  readonly quality?: number;
}
```

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | Any other `size` or `quality` value, or another key, at config load. The old `web({ video })` spelling is also refused, naming `screencast`. |

#### `connect`

Attaches to a remote Chromium over CDP instead of launching one locally.

```ts
web({ connect: { cdpEndpoint: async () => 'ws://127.0.0.1:9222' } });
```

- `cdpEndpoint(signal)` resolves when a worker first needs the browser, and
  again when an attempt starts after the connection dropped.
- Each attempt gets a new browser context on the remote browser.
- `reconnectEndpoint` is not supported. A connection that drops fails the
  attempt, and the next attempt attaches again through `cdpEndpoint`.

```ts
interface WebConnectOptions {
  cdpEndpoint(signal: AbortSignal): string | Promise<string>;
  reconnectEndpoint?(signal: AbortSignal): string | Promise<string>;
}
```

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | A `connect` without `cdpEndpoint`, or with one given as a string, at config load. Also `connect` beside a `browser` provider, a `browser` other than chromium, or any `reconnectEndpoint`. |

To reuse one sign-in across files,
[sign in once in a setup test](/authentication#sign-in-once-in-a-setup-test).
A saved session carries it, not a shared browser.

#### `headers`

Headers added to requests within the app's site, including subdomains.

```ts
web({ headers: { 'x-preview-token': process.env.PREVIEW_TOKEN ?? '' } });
```

- A [continued](#route) request bound for the app's site still carries them.
- `headers` and `basicAuth` are how a test reaches a
  [protected preview](/web#protected-previews).

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | A `user-agent` entry beside [`userAgent`](#useragent), or an `accept-language` entry beside [`locale`](#locale). |

<Note>
`headers` enables request routing, which disables the browser's HTTP cache and
blocks service workers.
</Note>

#### `basicAuth`

HTTP basic authentication. The browser answers a `401` challenge with these
credentials on any origin.

```ts
import { secrets } from 'e2e';

web({ basicAuth: { username: 'staging', password: secrets.get('staging-password') } });
```

A `secrets.get(name)` password resolves when each attempt starts and is
redacted like any configured secret. So is the base64 credential of the
`Authorization` header it becomes.

```ts
/** HTTP basic authentication the browser answers a `401` challenge with. */
export interface WebBasicAuth {
  /** The user name; `:` is not allowed in one (RFC 7617). */
  readonly username: string;
  /** The password, or `secrets.get(name)` for one in `config.secrets`. */
  readonly password: string | Secret;
}
```

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | A `:` in the user name, or an unknown key. |

<Warning>
The secret protection is text only. A page that renders the password on
screen is not masked in screenshots or model pixels
([Security rules](/reference/security#secrets-in-engine-options)).
</Warning>

#### `testIdAttribute`

The attribute that carries an element's test id: what the `testId` query
(`screen.getByTestId`) resolves and what `SemanticNode.testId` reports.

```ts
web({ testIdAttribute: 'data-test' }); // default: 'data-testid'
```

#### `userAgent`

The `User-Agent` every attempt's context sends and `navigator.userAgent`
reports, for an app that switches into a test mode on a marker in the agent
string.

```ts
web({ userAgent: 'Mozilla/5.0 e2e' }); // default: the browser's own
```

#### `locale`

The locale every attempt's context runs in, a BCP 47 tag: what
`navigator.language`, `Intl` formatting, and the `Accept-Language` header
report.

```ts
web({ locale: 'de-DE' }); // default: the browser's own
```

#### `timezoneId`

The IANA time zone every attempt's context runs in: what `Date` and `Intl`
resolve local time against.

```ts
web({ timezoneId: 'Europe/Berlin' }); // default: the machine's
```

#### Media emulation

`web({ colorScheme, reducedMotion })` sets the media features every page of
every attempt reports.
`browser.emulateMedia(media)` changes them for one attempt.

```ts
web({ colorScheme: 'dark', reducedMotion: 'reduce' }); // default: the browser's own
await browser.emulateMedia({ colorScheme: 'light' });
```

- The page's `@media` rules and `matchMedia` read them from the first paint.
- `emulateMedia` applies for the rest of the attempt, on every open tab and
  every tab opened after them, through `app.restart()` and `app.clearState()`.
- It works before the first navigation, so the next `app.open` loads with
  them.
- A feature it leaves out keeps its value.
- A tab the app opens itself gets a test's change as it appears, so a
  script it runs at load may still read the configured values.

```ts
/** User preferences a page reads through `@media` rules and `matchMedia`. */
export interface WebMedia {
  /** `prefers-color-scheme`. */
  readonly colorScheme?: 'light' | 'dark' | 'no-preference';
  /** `prefers-reduced-motion`. */
  readonly reducedMotion?: 'reduce' | 'no-preference';
}
```

| Throws | When |
| --- | --- |
| `INVALID_CONFIG` | A feature or value outside `WebMedia`, in `web()`. |
| `INVALID_ARGUMENT` | A feature or value outside `WebMedia`, in `emulateMedia`. |

#### Init scripts

An init script runs in every document before the page's own scripts, in every
tab and frame. `web({ initScripts })` applies to every test;
`browser.addInitScript` adds one for the rest of the test.

```ts
await browser.addInitScript((value) => { Math.random = () => value; }, 0.5);
await app.open('/raffle');
```

- A function cannot close over test variables. Pass a JSON `arg` instead.
- A script added after the page opened runs from the next navigation or
  reload.
- `browser.addInitScript` takes the same three forms, or a function with its
  JSON `arg`. Its overloads are on [`Browser`](#browser-interface).

```ts
/** JavaScript source, a file relative to the project root, or a function. */
export type WebInitScript = string | { readonly path: string } | (() => unknown);
```

#### Limits

| Limit | Why |
| --- | --- |
| No WebKit | WebKit has no WebDriver BiDi endpoint. |
| `connect` and browser providers are Chromium only | They attach over CDP. |
| `connect.reconnectEndpoint` is `INVALID_CONFIG` | A dropped connection is not recovered mid-attempt. The next attempt attaches again. |
| `app.clearState()` and saved sessions throw `UNSUPPORTED_CAPABILITY` with a `scope: 'attempt'` provider | The attempt runs in the fresh browser's own context, which they would replace. |
| Pointer actions in a rotated, skewed, or mirrored iframe throw `NOT_ACTIONABLE` | Points are mapped through a frame's scale only. |
| Selectors are CSS or XPath only, with no `>>` chains or `text=` and `nth=` engines | The browser runs the selector itself. |
| HTML5 drag and drop drops no data on Firefox | [Firefox bug 1515879](https://bugzilla.mozilla.org/show_bug.cgi?id=1515879). Pointer drags work. |
| `setInputFiles` throws `UNSUPPORTED_CAPABILITY` with a browser provider, and so do downloads when the provider serves none | The files are on another machine. |
| A saved session throws `UNSUPPORTED_CAPABILITY` for an IndexedDB value that is not JSON or a `Date` | A `Blob` or class instance can't be restored. |

### The browser fixture

`browser` is the whole browser, showing one active tab.

- What reads or acts on a page acts on the active tab: `goto`, `reload`,
  `back`, `forward`, `url`, `title`, `waitForURL`, `locator`, `frameLocator`,
  `evaluate`, `waitForResponse`, `waitForDownload`, `keyboard`, `mouse`, the
  `expect(browser)` matchers, and every `screen` query.
- What belongs to the browser covers every tab: `cookies`, `setCookies`,
  `clearCookies`, `route`, `unroute`, `unrouteAll`, `onDialog`, and
  `addInitScript`.
- `setViewport` sizes the active tab and every tab opened after it, and
  `emulateMedia` sets its media the same way.
- A tab the app opens itself, from a `target="_blank"` link or `window.open`,
  is not followed. The active tab stays the one the attempt opened. Assert on
  what that tab shows, or open the link's URL with `browser.goto`.
- Every `browser` call is a recorded `browser.<method>` step, except
  `locator` and `frameLocator`. They build a locator without touching the
  page, and the action or assertion on it is the step.
- A relative URL resolves against the target's `app.url`, else
  `APP_URL_REQUIRED`.
- Declare `requires: ['browser']` in a suite that also runs on other
  platforms.
- `expect(browser)` returns the `BrowserExpectation` the engine attaches:
  `toHaveURL`, `toHaveTitle`, and `toHaveClass`. See
  [browser matchers](/reference/expect#browser-matchers).

| Member | Returns |
| --- | --- |
| [`goto`](#goto) | `Promise<void>` |
| [`reload`](#reload-back-forward) | `Promise<void>` |
| [`back`](#reload-back-forward) | `Promise<void>` |
| [`forward`](#reload-back-forward) | `Promise<void>` |
| [`url`](#url-title) | `Promise<string>` |
| [`title`](#url-title) | `Promise<string>` |
| [`waitForURL`](#waitforurl) | `Promise<void>` |
| [`locator`](#locator) | `Locator` |
| [`frameLocator`](#framelocator) | `FrameScreen` |
| [`evaluate`](#evaluate) | `Promise<T>` |
| [`addInitScript`](#init-scripts) | `Promise<void>` |
| [`route`](#route) | `Promise<void>` |
| [`unroute`](#unroute) | `Promise<void>` |
| [`unrouteAll`](#unrouteall) | `Promise<void>` |
| [`waitForResponse`](#waitforresponse) | `Promise<WebResponse>` |
| [`cookies`](#cookies) | `Promise<Cookie[]>` |
| [`setCookies`](#setcookies) | `Promise<void>` |
| [`clearCookies`](#clearcookies) | `Promise<void>` |
| [`setViewport`](#setviewport) | `Promise<void>` |
| [`emulateMedia`](#media-emulation) | `Promise<void>` |

| [`waitForDownload`](#waitfordownload) | `Promise<{ path, absolutePath, … }>` |
| [`waitForDownloads`](#waitfordownloads) | `Promise<{ path, absolutePath, … }[]>` |
| [`keyboard`](#keyboard) | `{ press, down, up, type }` |

The [config](/reference/config) sets each member's budget:

- `goto`, `reload`, `back`, and `forward`: [`timeout`](/reference/config#timeout),
  the same budget `app.open()` uses.
- `waitForURL`: [`assertionTimeout`](/reference/config#assertiontimeout).
- Every other member: [`actionTimeout`](/reference/config#actiontimeout).
  `locator` and `frameLocator` touch no page and take none.

A `{ timeout }` option overrides the budget on `goto`, `reload`, `back`,
`forward`, `waitForResponse`, `waitForDownload`, and `waitForDownloads`, capped
by the test deadline (`cleanupTimeout` in `afterEach`); `0` waits until it. `url`, `title`, `evaluate`, `addInitScript`, `route`,
`unroute`, `unrouteAll`, `cookies`, `setCookies`, `clearCookies`, `setViewport`,
`emulateMedia`, `onDialog`, `keyboard.*`, and `mouse.*` take no override.

#### `goto`

Navigates the active tab to a URL.

```ts
await browser.goto('/dashboard', { waitUntil: 'networkidle' }); // default: 'load'
```

`waitUntil` is `'load'`, `'domcontentloaded'`, or `'networkidle'`.

| Throws | When |
| --- | --- |
| `POLICY_DENIED` | A URL whose scheme is not `http:` or `https:`. `about:blank` is admitted. |
| `APP_URL_REQUIRED` | A relative URL, on a target that declares no `app.url`. |
| `ACTION_FAILED` | The navigation failed. |

#### `reload`, `back`, `forward`

`reload` reloads the current document. `back` and `forward` navigate browser
history once.

```ts
await browser.reload();
await browser.back({ timeout: 10_000 });
```

| Throws | When |
| --- | --- |
| `ACTION_FAILED` | The navigation failed. |

#### `url`, `title`

Return the active tab's current URL and title.

```ts
const url = await browser.url();
const title = await browser.title();
```

#### `waitForURL`

Waits for the current URL to match, polling every 100 ms. It is the same poll
as `expect(browser).toHaveURL`.

```ts
await browser.waitForURL(/\/orders\/\d+$/, { timeout: 15_000 });
```

- A relative string resolves against the base URL and matches exactly after
  normalization.
- A `RegExp` tests the full URL.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | A pattern that is not a string or `RegExp` (a predicate function, say), or an option other than `timeout`, such as Playwright's `waitUntil`. |
| `ASSERTION_FAILED` | The URL did not match before the timeout. |

#### `locator`

Creates a web-only locator from a CSS or XPath selector.

```ts
const conditions = browser.locator('[data-testid="row"]').nth(2).getByTestId('conditions');
```

- The selector is CSS by default. `xpath=`, a leading `/`, or a leading `..`
  makes it XPath, and `css=` forces CSS.
- CSS reaches into open shadow roots.
- There are no `>>` chains or `text=` and `nth=` engines. Chain `nth` and
  the screen queries instead, as in the example.
- Use `filter({ has })` for an element that contains another.

| Throws | When |
| --- | --- |
| `INVALID_LOCATOR` | An empty selector, or one that is not valid CSS or XPath. |

<Note>
Every `screen` query searches its scope and each closed shadow root the page
attached under it, with Playwright's role, name, text, label, and
attribute rules and each node found once. A control the observed tree
lists inside a closed root resolves and takes actions and reads. `locator`,
`frameLocator`, and `filter({ hasText })` stop at a closed root; the [browser guide](/browser#shadow-dom) has the details.
</Note>

#### `frameLocator`

Creates a screen query scope inside one iframe.

```ts
const payment = browser.frameLocator('#payment-frame');
await payment.getByLabel('Card number').fill('4242424242424242');
```

It returns a `FrameScreen`, a `Screen` whose queries answer from inside the
frame. Use the frame's `locator` only when the control has no accessible
name, label, placeholder, or test id. The
[browser guide](/browser#reach-into-an-iframe) shows when that applies.

```ts
export interface FrameScreen extends Screen {
  /** Creates a web-only CSS or XPath locator inside this frame. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside an iframe nested in this frame. */
  frameLocator(selector: string): FrameScreen;
}
```

The errors are the same at the page and inside a frame:

| Throws | When |
| --- | --- |
| `INVALID_LOCATOR` | An empty selector, here or in the frame's `locator`. |
| `LOCATOR_NOT_FOUND` | No frame matches. |
| `LOCATOR_AMBIGUOUS` | Several frames match. |

#### `evaluate`

Evaluates trusted test code in the page and returns its result.

```ts
const count = await browser.evaluate(() => document.querySelectorAll('li').length);
const flag = await browser.evaluate(
  (name: string) => window.localStorage.getItem(name),
  'featureFlags',
);
const title = await browser.evaluate<string>('document.title');
```

- The function runs in the page and cannot access variables from the test.
  e2e serializes it by its source and inlines it into the page, so it must
  not close over anything outside its own body. Helpers declared inside the
  body work. Pass outside values through `arg`.
- A string is evaluated as a single expression, not as statements. If it
  evaluates to a function, that function is called with `arg`. Else its
  value is the result.
- A promise, from either, is awaited.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | `arg` or the return value is not a [`JsonValue`](#jsonvalue). A class instance, such as a `DOMRect` or an element, is not: return `rect.toJSON()` or the fields you need. |
| `EVALUATE_FAILED` | The evaluated code threw, or the page replaced a JavaScript built-in such as `Map` that the engine needs. The error carries the message. |
| `OPERATION_TIMEOUT` | The evaluation did not settle in time. |
| `ENGINE_FAILURE` | The page closed or the context was lost. |

#### `route`

Adds an attempt-scoped network route.

```ts
await browser.route('**/api/quote', async (route) => {
  await route.fulfill({ json: { cents: 4200 } });
});
```

`route.fetch()` returns the upstream `{ url, status, headers, body(), text(), json() }`
with the site's headers, under the action timeout, without deciding the route.
It does not follow redirects, which could take it past the navigation rule.

- The pattern is a string or a `RegExp`, both tested against the full URL. In
  a string, `*` matches within a path segment, `**` across `/`, `?` any one
  character, and `\` escapes the next. `unroute` and `waitForResponse` take
  the same patterns.
- A route survives `app.restart()`, `app.clearState()`, and session restore.
- Routes run newest first.
- The handler must decide exactly once, with `fulfill`, `continue`,
  `fallback`, or `abort`, each described on `WebRoute` below.
- A `continue` URL goes through the same rule as `goto`. A `continue` header
  set to `undefined` is dropped, also on redirects.
- A `fulfill` body is a string or bytes (`Buffer`, `Uint8Array`), sent as is.
- To set several cookies, join them with `\n` in one `set-cookie` header, as
  `route.fetch()` headers report them. Any other line break in a header is refused.
- A handler that throws (a failed `expect` on the request, say) fails the
  next step with that error, or the attempt at its end when no step follows.
  A step the handler made fail, such as the `goto` whose request it left
  aborted, fails with the handler's error. A `goto` whose request a handler
  aborted on purpose fails with `ACTION_FAILED`.
  A handler still running then gets the cleanup budget to finish. Whatever it
  throws after the budget is dropped.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | A predicate function as the pattern. Also an option a decision does not take (Playwright's `abort(errorCode)`, a misspelled key): the request is aborted and the next step fails. |
| `ACTION_FAILED` | The handler decided twice or not at all. |
| `POLICY_DENIED` | A `continue` URL with a forbidden scheme. |
| `CLEANUP_TIMEOUT` | A handler outlived the cleanup budget. It fails the attempt. |

```ts
/**
 * One of `json`, `body`, or `path`, or none for an empty body. `path` names a
 * file relative to the project root; its `Content-Type` follows its
 * extension unless `contentType` or a `content-type` header sets one.
 */
export type RouteFulfillResponse = {
  status?: number;
  /** Response headers; `set-cookie` may join several cookies with `\n`, as `route.fetch()` reports them. */
  headers?: Record<string, string>;
  /** Sets the `Content-Type` response header. */
  contentType?: string;
} & (
  | { json: JsonValue; body?: never; path?: never }
  | { body: string | Uint8Array; json?: never; path?: never }
  | { path: string; json?: never; body?: never }
  | { body?: never; json?: never; path?: never }
);

/** What `continue` changes about the request before it goes to the network. */
export interface RouteContinueOverrides {
  /** Resolved against the base URL like `goto`; must keep the request's scheme. */
  url?: string;
  /** Request method. */
  method?: string;
  /** Replaces every request header; `undefined` drops one, and the configured `headers` for the app's site are added on top. */
  headers?: Record<string, string | undefined>;
  /** Request body. */
  postData?: string;
}

export interface WebRoute {
  /** The intercepted request. */
  readonly request: {
    readonly url: string;
    readonly method: string;
    readonly headers: Readonly<Record<string, string>>;
    readonly postData?: string;
  };
  /** Reads upstream without deciding the route or following redirects. */
  fetch(): Promise<WebResponse>;
  /** Fulfills the intercepted request once. */
  fulfill(response: RouteFulfillResponse): Promise<void>;
  /** Sends the intercepted request to the network once, skipping every other route. */
  continue(overrides?: RouteContinueOverrides): Promise<void>;
  /** Hands the intercepted request to the route registered before this one, or the network when none matches. */
  fallback(): Promise<void>;
  /** Aborts the intercepted request once. */
  abort(): Promise<void>;
}
```

#### `unroute`

Removes the attempt-scoped routes that match a pattern, in the
[`route`](#route) pattern syntax.

```ts
await browser.unroute('**/api/quote');
```

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | A predicate function as the pattern. |

#### `unrouteAll`

Removes every route registered by the browser fixture, preserving configured
site headers.

```ts
await browser.unrouteAll();
```

#### `waitForResponse`

Waits for a response that matches a pattern, in the [`route`](#route) pattern
syntax.

```ts
const response = await browser.waitForResponse('**/api/orders');
expect(response.status).toBe(201);
```

- The deadline bounds the match: the response resolves as soon as its headers
  arrive.
- `body()`, `text()`, and `json()` wait for the body on a budget of their own,
  `config.actionTimeout` capped by the test deadline.
- `url`, `status`, and `headers` are always readable.
- A genuinely empty body reads as an empty `Buffer` from `body()` and `''`
  from `text()`; `json()` rejects it.

| Throws | When |
| --- | --- |
| `INVALID_ARGUMENT` | A predicate function as the pattern. |
| `ACTION_FAILED` | Nothing matches inside the deadline. From `body()`, `text()`, and `json()`: a body still streaming when their budget runs out, or a body the browser could not read (a connection reset short of the declared `Content-Length`, a request the page aborted, or a redirect, whose body the browser never keeps), instead of an empty string. |

```ts
export interface WebResponse {
  /** Response URL. */
  readonly url: string;
  /** HTTP status. */
  readonly status: number;
  /** Response headers, lower-cased names; `route.fetch()` joins several `set-cookie` values with `\n`, `waitForResponse` leaves cookie headers out. */
  readonly headers: Readonly<Record<string, string>>;
  /** Waits for the body and returns its bytes. */
  body(): Promise<Buffer>;
  /** Waits for the body and parses it as JSON. */
  json<T = unknown>(): Promise<T>;
  /** Waits for the body and reads it as text. */
  text(): Promise<string>;
}
```

#### `cookies`

Returns the cookies visible to the current context.

```ts
const cookies = await browser.cookies();
```

#### `setCookies`

Validates every cookie, then sets them.

```ts
await browser.setCookies([{ url: 'http://localhost:3000', name: 'tz', value: 'UTC' }]);
```

- A relative `url` resolves against the base URL, as `goto` resolves it.
- For the `domain` form the scheme follows the base URL, and a leading `.` is
  stripped.

| Throws | When |
| --- | --- |
| `POLICY_DENIED` | An unparseable target or a forbidden scheme. Nothing is set. |

```ts
export interface CookieFields {
  /** Cookie name. */
  name: string;
  /** Cookie value. */
  value: string;
  /** Unix timestamp in whole seconds. */
  expires?: number;
  /** HttpOnly flag. */
  httpOnly?: boolean;
  /** Secure flag. */
  secure?: boolean;
  /** SameSite attribute. */
  sameSite?: 'Strict' | 'Lax' | 'None';
}

/** `url`, or `domain` with an optional `path`, never both. */
export type Cookie = CookieFields &
  (
    | { url: string; domain?: never; path?: never }
    | { url?: never; domain: string; path?: string }
  );
```

#### `clearCookies`

`clearCookies({ name?, domain?, path? })` removes cookies matching every
filter given. Strings match exactly; RegExp matches the field. With no
options it removes every cookie. Other storage stays.

```ts
await browser.clearCookies({ name: /^session/, path: '/' });
```

```ts
export interface CookieFilter {
  name?: string | RegExp;
  domain?: string | RegExp;
  path?: string | RegExp;
}
```

#### `setViewport`

Sets the viewport size and records the new size on the report.

```ts
await browser.setViewport({ width: 390, height: 844 });
await app.open('/');
```

- It works before the first navigation too, as Playwright's
  `setViewportSize` does. The next `app.open` loads at that size, so a
  phone-sized test never renders the desktop layout first.
- The size holds for the rest of the attempt, through `app.restart()` and
  `app.clearState()`.

#### `onDialog`

Registers an attempt-scoped handler for native dialogs and returns an
unsubscribe function.

```ts
const off = await browser.onDialog('accept');
await screen.getByRole('button', 'Delete').tap();
await off();
```

- The handler is `'accept'`, `'dismiss'`, or a function that receives the
  `Dialog`.
- A function handler must call `accept` or `dismiss`. One that does neither
  has the dialog dismissed, as an unhandled dialog does.
- A handler that throws fails the next step with its error, or the attempt
  at its end when no step follows. One that throws before answering has its
  dialog dismissed.

The errors surface on the next step, not on `onDialog`:

| Throws | When |
| --- | --- |
| `APP_NOT_OPEN` | A function handler answered neither way, or no handler took the dialog. |
| `ASSERTION_FAILED` | The handler's `expect` failed. |
| `ENGINE_FAILURE` | The handler threw an unclassified error. |

```ts
/** A native dialog as a test's handler sees it. */
export interface Dialog {
  /** The native dialog kind, independent of its message. */
  readonly type: 'alert' | 'confirm' | 'prompt' | 'beforeunload';
  /** The dialog's text. */
  readonly message: string;
  /** Accepts the dialog once. */
  accept(text?: string): Promise<void>;
  /** Dismisses the dialog once. */
  dismiss(): Promise<void>;
}

export type DialogHandler = 'accept' | 'dismiss' | ((dialog: Dialog) => void | Promise<void>);
```

#### `waitForDownload`

Runs a trigger and waits for the download it starts.

```ts
const file = await browser.waitForDownload(() =>
  screen.getByRole('link', 'Export CSV').tap(),
);
```

- It registers the file as a `download` artifact and returns its relative
  `path`, the runner-side `absolutePath`, and `suggestedFilename`.
- Use `absolutePath` with file APIs to inspect the contents.
- The wait includes the trigger's own time.

| Throws | When |
| --- | --- |
| `UNSUPPORTED_CAPABILITY` | The browser comes from a browser provider without [`downloads`](/browser#downloads-on-the-provider). |
| `ACTION_FAILED` | The download did not complete in time. A trigger that resolved in time but started no download fails with `no download started within <n>ms; the trigger resolved after <m>ms`. |

A trigger still running at the timeout fails with the step timeout. One that
throws fails with its own error.

#### `waitForDownloads`

`waitForDownloads(trigger, { count })` calls the trigger once and returns
`count` files in start order, each its own artifact, under the same timeout.
When fewer start in time, the error names both counts; extra downloads are ignored.

#### `keyboard`

Viewport-level keyboard input, for whatever has focus.

```ts
await browser.keyboard.press('Escape');
await browser.keyboard.type('hello');
```

- `type(text)` types plain text only, never a `Secret`.
- Prefer `locator.press` and `locator.fill` when a target exists.
- [`Browser`](#browser-interface) describes each method.

#### `mouse`

Viewport-level pointer input from test code, independent of agent
observations.

```ts
await browser.mouse.move(120, 240);
await browser.mouse.down();
await browser.mouse.move(320, 240);
await browser.mouse.up();
```

[`Browser`](#browser-interface) describes each method, `wheel` included.

## Installing browsers

The engine runs pinned builds: Chrome for Testing 157.0.8103.38 for
`chromium` (the headless shell for headless runs, full Chrome for headed
ones) and Firefox 159.0.1 for `firefox`. A missing browser downloads once
per run, before the run's clock starts. To install browsers as their own
step, in CI or a container image, run the package's command:

<CodeGroup>
```bash npm
npx @e2e-dev/web install chromium --with-deps
```

```bash pnpm
pnpm exec e2e-web install chromium --with-deps
```

```bash bun
bunx @e2e-dev/web install chromium --with-deps
```
</CodeGroup>

- Name `chromium`, `firefox`, or both. With none named it installs
  `chromium`.
- `--headed` installs the full Chrome build a headed run launches.
- `--with-deps` also installs the system libraries the browsers need on
  Debian and Ubuntu, with `apt-get`, through `sudo` when not run as root.
- Browsers go to `E2E_BROWSERS_PATH`, else the user cache:
  `~/Library/Caches/e2e/browsers` on macOS, `$XDG_CACHE_HOME/e2e/browsers`
  or `~/.cache/e2e/browsers` on Linux, `%LOCALAPPDATA%\e2e\browsers` on
  Windows. Every project on the machine shares it.
- `chromium` also needs an ffmpeg with `libvpx-vp9` to record video:
  `E2E_FFMPEG_PATH`, else `ffmpeg` on the `PATH`, else a pinned download
  into the browser cache.
- The command exits non-zero when an install fails.

### `WebOptions`

```ts
/**
 * Options of the browser engine: how it drives the app. The app itself
 * (its `url`, `environment`, `identity`, and the command that starts it) is
 * the target's `app`.
 */
export interface WebOptions {
  /**
   * Browser to launch, `chromium` (default) or `firefox`, driven over
   * WebDriver BiDi. A `BrowserProvider` leases hosted browsers instead, one
   * per worker slot, each attached to over CDP and released when the run
   * ends. A provider implies chromium and excludes `connect`.
   */
  readonly browser?: BrowserName | BrowserProvider;
  /**
   * Initial viewport of every attempt's page; default 1280 by 720. `null`
   * emulates no size: the page fills the browser window, whatever size the
   * window has (a hosted browser's live view, a headed run), and
   * `browser.setViewport` still fixes one for the rest of the attempt.
   */
  readonly viewport?: ViewportSize | null;
  /**
   * How the engine's own screencast records an attempt that records video.
   * A browser provider that records (`BrowserProvider.record`) records in
   * its place, and ignores these. Which attempts record is the config's
   * `video`, not an engine option.
   */
  readonly screencast?: WebScreencastOptions;
  /**
   * Attach to a remote browser over CDP instead of launching locally. Requires
   * the chromium browser (the default). Wired by a hosted-browser engine.
   */
  readonly connect?: WebConnectOptions;
  /**
   * Headers added to requests within the app's site, including subdomains.
   * Useful for preview-protection tokens. Other sites never receive them.
   * Names are case-insensitive and replace existing headers of the same name.
   * This enables request routing, disables the browser's HTTP cache, and
   * blocks service workers.
   */
  readonly headers?: Readonly<Record<string, string>>;
  /**
   * HTTP basic authentication. The browser answers a `401` challenge with
   * these credentials on any origin.
   */
  readonly basicAuth?: WebBasicAuth;
  /**
   * The attribute that carries an element's test id: what the `testId` query
   * (`screen.getByTestId`) resolves and what `SemanticNode.testId` reports.
   * Defaults to `data-testid`.
   */
  readonly testIdAttribute?: string;
  /**
   * The `User-Agent` every attempt's context sends and `navigator.userAgent`
   * reports, for an app that switches into a test mode on a marker in the
   * agent string. Defaults to the browser's own. A `user-agent` entry in
   * `headers` beside it is `INVALID_CONFIG`.
   */
  readonly userAgent?: string;
  /**
   * The locale every attempt's context runs in, a BCP 47 tag such as
   * `de-DE`: what `navigator.language`, `Intl` formatting, and the
   * `Accept-Language` header report. Defaults to the browser's own. An
   * `accept-language` entry in `headers` beside it is `INVALID_CONFIG`.
   */
  readonly locale?: string;
  /**
   * The IANA time zone every attempt's context runs in, such as
   * `Europe/Berlin`: what `Date` and `Intl` resolve local time against.
   * Defaults to the machine's.
   */
  readonly timezoneId?: string;
  /** The `prefers-color-scheme` every page reports. See [Media emulation](#media-emulation). */
  readonly colorScheme?: WebMedia['colorScheme'];
  /** The `prefers-reduced-motion` every page reports. See [Media emulation](#media-emulation). */
  readonly reducedMotion?: WebMedia['reducedMotion'];
  /** Scripts every document runs before the page's own. See [Init scripts](#init-scripts). */
  readonly initScripts?: readonly WebInitScript[];
}
```

### `Browser` interface

```ts
/**
 * The browser the attempt drives, showing one active tab. Navigation, reads,
 * `locator`, `frameLocator`, `evaluate`, `waitForResponse`, `waitForDownload`,
 * the keyboard and mouse, `expect(browser)`, and `screen` act on the active
 * tab; cookies, routes, and dialog handlers cover the whole browser, every
 * tab included. A tab the app opens itself (a `target="_blank"` link,
 * `window.open`) is not followed: the active tab stays the one the attempt
 * opened.
 */
export interface Browser extends Expectable<BrowserExpectation> {
  /** Navigates to an allowed URL. */
  goto(
    url: string,
    options?: {
      waitUntil?: 'load' | 'domcontentloaded' | 'networkidle';
      timeout?: number;
    },
  ): Promise<void>;
  /** Reloads the current document. */
  reload(options?: ActionOptions): Promise<void>;
  /** Navigates browser history back once. */
  back(options?: ActionOptions): Promise<void>;
  /** Navigates browser history forward once. */
  forward(options?: ActionOptions): Promise<void>;
  /** Returns the current URL. */
  url(): Promise<string>;
  /** Returns the current title. */
  title(): Promise<string>;
  /** Waits for the current URL to match. */
  waitForURL(url: string | RegExp, options?: { timeout?: number }): Promise<void>;
  /** Creates a web-only CSS or XPath locator. */
  locator(selector: string): Locator;
  /** Creates a screen query scope inside one iframe. */
  frameLocator(selector: string): FrameScreen;
  /** Evaluates trusted test code in the page: a function, or a string expression whose value is returned, called first if it is a function. */
  evaluate<T extends JsonValue>(fn: string | (() => T | Promise<T>)): Promise<T>;
  /** Evaluates trusted test code with one required JSON-safe argument. */
  evaluate<T extends JsonValue, Arg extends JsonValue>(
    fn: string | ((arg: Arg) => T | Promise<T>),
    arg: Arg,
  ): Promise<T>;
  /** Adds a script every document runs before the page's own, from the next navigation on. */
  addInitScript(script: string | { path: string } | (() => unknown)): Promise<void>;
  /** Adds an init script function called with one JSON argument. */
  addInitScript<Arg extends JsonValue>(script: (arg: Arg) => unknown, arg: Arg): Promise<void>;
  /** Adds an attempt-scoped network route. */
  route(
    pattern: string | RegExp,
    handler: (route: WebRoute) => void | Promise<void>,
  ): Promise<void>;
  /** Removes matching attempt-scoped routes. */
  unroute(pattern: string | RegExp): Promise<void>;
  /** Removes all routes registered by this browser fixture, preserving configured site headers. */
  unrouteAll(): Promise<void>;
  /** Waits for a matching response. */
  waitForResponse(
    pattern: string | RegExp,
    options?: { timeout?: number },
  ): Promise<WebResponse>;
  /** Returns cookies visible to the current context. */
  cookies(): Promise<Cookie[]>;
  /** Sets cookies after URL validation. */
  setCookies(cookies: readonly Cookie[]): Promise<void>;
  /** Removes matching cookies only; without filters removes every cookie, preserving other storage. */
  clearCookies(options?: CookieFilter): Promise<void>;
  /** Sets the viewport size. */
  setViewport(size: { width: number; height: number }): Promise<void>;
  /** Emulates CSS media features on every open tab and every tab opened after them. */
  emulateMedia(media: WebMedia): Promise<void>;
  /** Registers an attempt-scoped dialog handler and returns an unsubscribe function. */
  onDialog(handler: DialogHandler): Promise<() => Promise<void>>;
  /** Runs a trigger and waits for its download. */
  waitForDownload(
    trigger: () => Promise<void>,
    options?: { timeout?: number },
  ): Promise<{ path: string; absolutePath: string; suggestedFilename: string }>;
  /** Runs one trigger and waits for the requested number of completed downloads. */
  waitForDownloads(
    trigger: () => Promise<void>,
    options: { count: number; timeout?: number },
  ): Promise<readonly { path: string; absolutePath: string; suggestedFilename: string }[]>;
  /** Viewport-level keyboard, for whatever has focus. */
  readonly keyboard: {
    /** Sends one key. */
    press(key: string): Promise<void>;
    /** Holds one key until up; repeated down calls send a repeat event. */
    down(key: string): Promise<void>;
    /** Releases a held key. */
    up(key: string): Promise<void>;
    /** Types plain text. */
    type(text: string): Promise<void>;
  };
  /**
   * Direct pointer input from test code, independent of agent observations.
   * After CDP recovery, test code can read current geometry with `evaluate`
   * before starting a pointer sequence.
   */
  readonly mouse: {
    /** Moves the pointer. */
    move(x: number, y: number): Promise<void>;
    /** Scrolls the pointer wheel. */
    wheel(deltaX: number, deltaY: number): Promise<void>;
    /** Presses the primary pointer button. */
    down(): Promise<void>;
    /** Releases the primary pointer button. */
    up(): Promise<void>;
  };
}
```
