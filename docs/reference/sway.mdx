---
title: Sway provider reference
description: Native resource ownership, persistent input and failure semantics.
---

`sway(options)` returns a native `TernProvider`; `swayDisplay(options, request)` leases the same display directly. `binaries` requires absolute paths for `sway`, `swaymsg`, `tern`, `grim`, and the explicitly built `input` executable. Optional `size` defaults to 1280 by 900; optional `env` passes only explicitly declared variables into an otherwise curated environment. `root` must be a short private absolute prefix because Unix sockets have bounded paths. Default journals use the normalized runtime prefix plus `-j`, as a sibling rather than a child even when the runtime prefix ends in `/`. Explicit equal, nested or symlink-resolved nested journal prefixes are rejected before writes. Staging, publication and private cleanup claims require the same filesystem; there is no copying fallback.

The resource exposes `id`, `directory`, `controlBinary`, `seat`, `output`, `env`, `spawn`, `focusClient`, `type`, `press`, `pointer`, `capture`, and idempotent `release`. `controlBinary` is the leased native CLI and must be used instead of the raw Tern executable; sandboxed resources route it into the exact owned guest. `spawn` is supervised; client focus is internal to the newly owned compositor. Never use it to target an operator window. An `OwnedWaylandParent` is supplied by an explicit containment provider, not inferred from ambient display variables.

Native input persists across operations and advertises both capabilities before Tern connects. Key grammar comes from `e2e/engine.parseKey`; Linux ControlOrMeta means Control. Unsupported or unauthorized input fails closed. Acknowledgment means the compositor consumed the protocol request, not that the app performed the intended action; assert real semantic effects. No application turn, key save or permission grant is part of readiness.

Release closes only recorded process generations and their descendants. Pidfds prevent PID reuse from targeting another process. A failed cleanup remains an error with ownership records retained; no wildcard kill or forced borrowed shutdown occurs. Input and control sockets disappear with their owned directory. Target finish repeats the exact scoped sweep after an interrupted worker. Raw output capture is available only by explicit resource call and contains no secret masking.

Set `journalRoot` to a host-private directory outside every guest-visible writable path or ancestor when using a sandboxed parent. Runtime/profile paths can be shared; cleanup journals and supervisor identities cannot. Even the run root is staged privately, with immutable allocation metadata published atomically before external publication. Group and attempt publication share the native closing fence, so a late publisher or supervisor cannot publish/fork after closing. Trusted records stay outside runtime trees during cleanup, including after an interrupted recursive deletion.

Descendant cleanup pins the child with pidfd and rechecks both generation and owned-parent relationship before recursion/signaling. Input cancellation is rechecked after asynchronous guards and at socket connection; the retained injector detects peer disconnection even with buffered UTF-8 and releases keys/buttons. Fractional in-bounds pointer coordinates are floored into the measured pixel extent. Negative native fixtures require structured deliberate terminal errors and a real deadline after passed native visibility, not just exit status and acquisition receipts.

The native provider requires `state.gate.phase === 'off'` and `state.gate.error === null` before app input and before/after capture and guarded operations. It accepts `applies === false`, or the native 0.6.1 signed-in beta state with `applies === true && signed_in === true`; applicability alone does not mean a covering gate. Missing required fields, applicable signed-out states and active/error phases fail closed. AX beneath a covering sign-in cannot prove visibility. The provider does not automate accounts, copy host authentication or bypass gates.

For the concrete disposable containment fixture, `parent.guest` supplies the independently pinned compositor generation and an explicit absolute `nsenter`; `configurationRoot` is host-created and mounted read-only, and `journalRoot` is outside every guest bind. The source helper opens and pins user/mount/net/IPC/UTS namespace and filesystem-root descriptors, rechecks generation and pidfd liveness, and enters those descriptors. Numeric-only `nsenter --target`, PID-namespace entry, arbitrary command-prefix routing and host fallback are not used. Tern server, SDK apps, native CLI, capture and IPC execute inside that guest; only private supervisors and cleanup authority remain outside.

Profiles are built in private staged trees and their device/inode identity is saved before no-replace publication. Cleanup atomically claims each runtime/run root into a same-filesystem host-private quarantine, resolves both source and destination parents without symlinks and rechecks the claimed inode. It never deletes through a cached guest-writable pathname. A mismatch is preserved/restored without deletion; private claims are resumable and unvalidated claims retain their records.

`parent.recover` returns `PROCESS`, `NEVER_LAUNCHED` or `UNKNOWN`. A mapped tagged process still needs exact containment and pinned kernel ancestry. `NEVER_LAUNCHED` requires successful closing of the host-private dispatch fence and absence of its private potential-dispatch receipt; a missing guest receipt or an old unfenced record is not proof. Pre-parent-save and pre-dispatch interruption can therefore complete cleanup without inventing a child PID, while uncertain dispatch retains evidence. Kernel namespace/root and actual app-runtime assertions remain required real-fixture checks, not inferred from routing source.
