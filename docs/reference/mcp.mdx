title: MCP server (e2e mcp)
description: Let a coding agent inspect and interact with your app over MCP.

```bash
npx e2e mcp [--config <path>] [--target <name>] [--headless]
```

`e2e mcp` lets coding agents such as Claude Code and Cursor inspect your app,
try locators, and take masked screenshots before writing tests. It runs over
stdio and uses the project's configured engine.

Four MCP tools manage the session and call its available app tools. The app
tool catalog reloads from the config whenever a session opens.

## Setup

The server ships with `e2e`. `e2e init` offers to register it in
`.mcp.json` (Claude Code) and `.cursor/mcp.json` (Cursor). By hand:

```bash
claude mcp add e2e -- npx e2e mcp
```

For clients that use a `mcpServers` config, add:

```json
{
  "mcpServers": {
    "e2e": { "command": "npx", "args": ["e2e", "mcp"] }
  }
}
```

Start the server in the project directory. Config discovery works like
`e2e run`. Set `--config` for another location, or pass `config` to
`open_session` for a single session.

| Flag | Behavior |
| --- | --- |
| `--config <path>` | The config every session loads unless `open_session` names one. Configs are reloaded on every `open_session`. |
| `--target <name>` | The target every session opens on. Otherwise `open_session` names one, or the only target is used; several targets and no name is `TARGET_REQUIRED`. |
| `--headless` | Hide the browser or simulator. Sessions are headed by default outside CI. |

Operator output goes to stderr, prefixed `e2e mcp:`. Stdout carries only the
protocol; anything a config module writes to stdout is redirected.

## Tools

| Tool | Arguments | Result |
| --- | --- | --- |
| `open_session` | `target` (optional), `config` (optional path) | Loads the config, starts the app command, boots the engine, starts one attempt, opens the app URL when the engine can navigate. Returns the session id, the catalog, and the first observation. |
| `tools` | `tool` (optional), `session` (optional) | The catalog, one line per tool. With `tool`, its full description and argument schema. |
| `call` | `tool`, `args` (optional), `session` (optional) | Runs one catalog tool. Arguments are validated against the tool's closed schema first: a wrong type or an argument the tool does not declare is `INVALID_ARGUMENT`, and nothing runs. |
| `close_session` | `session` (optional) | Saves a recording still running, ends the attempt, disposes the engine, stops the app processes the session started. |

Only one session can be open at a time. The `session` argument is optional;
when supplied, it must match the current session or the call fails with
`NO_SESSION`.

### The catalog

What `call` can run depends on the session's target:

| Catalog tool | Arguments | Result |
| --- | --- | --- |
| `observe` | none | A fresh observation, one node per line as `#id role "name" ...`, with the current path and revision. A link's `href` is its path when it is on the page's origin, else origin and path. `…` marks what is left out: `?…` a query, `#…` a fragment, a trailing `…` a target cut at 256 characters. |
| `tap`, `double_tap`, `long_press`, `right_click`, `hover`, `type`, `press`, `select`, `check`, `scroll`, `scroll_to`, `drag`, `upload`, `navigate`, `back`, `type_secret` | A node id from the newest observation, plus the value, key, `checked` state, direction, drop target, project-relative `files`, URL, or secret name | The action's summary and what changed on screen. A verb the engine does not declare is not in the catalog. `upload` refuses a path outside the project, a hidden file, or a file under a hidden directory with `POLICY_DENIED`. `type_secret` is listed when the config declares `credentials` or `secrets`; the plaintext never reaches the agent. |
| `locate` | Exactly one of `role` (with optional `name`), `text`, `label`, `placeholder`, `testId`; `exact` | How many nodes match, which, and the `screen.*` call to write. Zero or several matches name the error a test would get. What it shows of a node passes the secret ledger, as `observe` does: a filled secret reads `<secret:name>`. |
| `screenshot` | none | The masked viewport as an image. From then on every action result carries a fresh screenshot. Once a secret has been filled it answers `PIXEL_TAINTED` instead, for the rest of the session. |
| `tap_at` | `x`, `y` in the latest screenshot's pixels | Taps that point: a listed control under it by id, otherwise the bare point through the engine's `performAt`; without `performAt` the point must land on a listed control. Listed when the engine declares `tap` or `performAt`. |
| `hover_at` | `x`, `y` in the latest screenshot's pixels | Hovers that point the same way: a listed control under it by id, otherwise the bare point through `performAt`'s `hover` kind. Listed when the engine declares the `hover` action or pointer kind. |
| `type_at` | `x`, `y`, `value`; `replace` on an engine with a keyboard | Fills a listed input under the point by id. With a keyboard, anything else is tapped to focus it and typed into, at the caret unless `replace` is set; without one, a point on nothing listed fails. Listed when the engine declares `type` or a keyboard. |
| `press_at` | `x`, `y`, `key` | Sends the key to a listed control under the point by id; with a keyboard, anything else is tapped to focus it and the key goes through the keyboard. Listed when the engine declares `press` or a keyboard. |
| `select_at` | `x`, `y`, `value`, the option's visible label | Picks the option in the listed select-like control under the point; nothing listed there fails. Listed when the engine declares `select`. |
| `start_recording` | `name` (optional; up to 64 letters, digits, `-`, and `_`, starting with a letter or digit) | Starts a video of the app. One recording at a time; a second start reports the one running. Listed when the engine records video. |
| `stop_recording` | none | Stops the recording and returns the absolute path of each video file. Listed when the engine records video. |

The five point tools answer `PIXEL_TAINTED` once a secret has been filled.
Before the session's first `screenshot` each answers with the line that says
to take one, at no cost.

Project tools passed to `createAgent({ tools })` follow in the catalog under
their own names, scoped to the target's platform. A mobile project that
passes `mobileTools(...)` also gets `open_app`, `swipe`,
and `alert`. A project tool named like a built-in is not served. An unknown
name fails with `UNKNOWN_TOOL` and the list of names.

### Recording

A session records only between `start_recording` and `stop_recording`, as
many times as needed; the configured [`video`](/reference/config#video)
mode applies to runs, not sessions. Each recording is saved to
`.e2e/videos/<session>/<n>[-<name>].webm` (`.mp4` on mobile), where `n`
counts the session's recordings. A web recording that spans a restart or a
state reset has one file per page, `-part2`, `-part3`, and so on, in play
order. A browser or device provider that records the lease itself records
the session instead: [Kernel](/integrations/kernel) downloads its replay,
saved here as `<n>[-<name>].mp4` like any other file, and a provider that
keeps its recordings is listed by URL instead of a file. `close_session`, the idle timeout, and the session
TTL save a recording still running, and the close result lists its files.

Recordings are not masked and are not withheld after a secret was filled:
they are files for a person to watch, and no tool returns their pixels. A
secret typed into a plain input while recording is readable in the video,
and a recording stopped after a secret was filled says so.

A session is one attempt on one target. A second `open_session` fails with
`SESSION_OPEN`; a `call` without a session fails with `NO_SESSION`. A session
closes on `close_session`, after 30 idle minutes, after 4 hours, when the
client disconnects, and on SIGINT or SIGTERM.

Sessions enforce what tests enforce. Node ids are valid only against the
newest observation. A secret fills only through `type_secret`; once one has
been filled, `screenshot` and the point tools (`tap_at`, `hover_at`,
`type_at`, `press_at`, `select_at`) stay in the catalog but answer
`PIXEL_TAINTED` for the rest of the session. Every text a `call` returns, a node `locate` found,
an action's result, or an error, passes the attempt's secret ledger. Nothing a
session does is recorded as a test result or into the trace cache; its
artifacts land under `.e2e/artifacts/<target>/sessions/`, its videos under
`.e2e/videos/`.

## Exit codes

`e2e mcp` exits 0 when the client disconnects or a signal ends it, and 2
when the command line is invalid. Config and engine failures come back as
tool errors with the same codes the CLI prints.
