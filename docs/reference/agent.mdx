---
title: agent
description: Run agent actions, check conditions, and extract structured data.
---

Use `act` to interact with the app, `assert` to check the current screen,
`waitFor` to wait for a condition, and `extract` to read structured data.
Each call starts with a fresh observation and has its own timeout and model-call
budget. Acquiring the fixture without a configured model fails with
`MODEL_UNAVAILABLE`.

```ts
export interface Agent {
  /** Plans and executes a bounded multi-action flow; resolves with what the step did. */
  act(instruction: string, options?: ActOptions): Promise<ActResult>;
  /** Polls a natural-language condition until true or timed out. */
  waitFor(condition: string, options?: WaitForOptions): Promise<void>;
  /** Extracts and validates structured screen data. */
  extract<Schema extends StandardSchemaV1>(
    instruction: string,
    options: ExtractOptions<Schema>,
  ): Promise<StandardSchemaV1.InferOutput<Schema>>;
  /** Judges a natural-language assertion against a fresh observation. */
  assert(assertion: string, options?: AssertOptions): Promise<void>;
}
```

## Budgets

Model calls count every model request including repair rounds. Action steps
count committed engine actions. Every timeout is additionally capped by the
remaining test timeout.

| Method | Model calls | Action steps | Default timeout |
| --- | ---: | ---: | --- |
| `act` | `agents.<name>.maxModelCalls`, 25 | `agents.<name>.maxSteps`, 25 | `config.timeout`, 120000 ms |
| `waitFor` | `agents.<name>.maxModelCalls`, 25 | 0 | `agents.<name>.timeout`, 30000 ms |
| `extract` | 2 | 0 | `agents.<name>.timeout`, 30000 ms |
| `assert` | 2 | 0 | `agents.<name>.timeout`, 30000 ms |

`actionTimeout` limits engine operations, not model calls. Per-call budgets
must be positive integers and can only lower the configured limits. All
durations are in milliseconds.

The `assert` row holds for the built-in agent. When the selected agent has a
custom `executor`, `assert` is dispatched to it as a step: its budget is the
agent's `maxSteps` and `maxModelCalls`, its default timeout is
`config.timeout`, and `vision` or `screenshot` on the call is
`UNSUPPORTED_CAPABILITY`.

## agent.act

```ts
act(instruction: string, options?: ActOptions): Promise<ActResult>;
```

Plans and executes one bounded multi-action flow. A passing verdict resolves
with an `ActResult`; a failing or blocked one throws an `AgentError` whose
`code` and `blocked` flag say why.

`instruction` is 1 through 8192 UTF-8 bytes after NFC normalization. An
unknown `agent` name is `INVALID_ARGUMENT` before the step opens.

Values come from your code through `options.params`, never from the model. The
model sees a `Secret` as its name and purpose only. The runner fills the value
under the same rules as `locator.fill`: the field must be an enabled editable
input, and a password goes only into a password field.

```ts
await agent.act('invite {email} as an editor', { params: { email: 'ada@example.test' } });

const member = credentials.user('member');
const { summary, cache } = await agent.act('Sign in', {
  params: { username: member.username, password: member.password },
});
```

The result carries the step's `summary`, the `modelCalls` and `actions` it
spent, and `cache`: how the [trace cache](/cache) took part
(`self-finalized`, `agent-concluded`, or `missed` with a `reason`; absent when
caching is off).

### Pixel tools: screenshot and the point verbs

`act` reads the semantic tree and requests screenshots when it needs them.
A screen with no listed interactive nodes, such as a canvas, opens with a
screenshot. The same model reads the tree and screenshots; there is no
`vision` option for `act`.

The built-in agent offers these tools while no secret has been filled:

| Tool | What it does |
| --- | --- |
| `screenshot()` | Returns a masked viewport screenshot and includes a fresh screenshot after every later action in the step. |
| `tap_at({ x, y })` | Taps the control at the point by node id, or taps the coordinates directly when no control is listed. |
| `type_at({ x, y, value, replace? })` | Replaces a listed input's value. For an unlisted input, taps to focus and types at the caret unless `replace` is set. Unlisted inputs require keyboard support. |
| `press_at({ x, y, key })` | Sends a key to the control at the point. If no control is listed, taps to focus and uses the engine's keyboard. |
| `select_at({ x, y, value })` | Selects an option by visible label in the control at the point. |

Coordinates refer to the latest screenshot. The model must take a screenshot
before using a point tool and should prefer node ids for listed controls.
The runner checks each point against the tree. A point on a listed control
uses the same policy checks and [trace cache](/cache) recording as an action
by id.

Once screenshots are in use, the post-action wait also detects pixel changes,
including canvas redraws. Screenshots have a maximum long side of 768 px;
older images are removed in batches, keeping the newest two.

On engines with a keyboard, including the browser and device engines, `type`
and `press` can omit `target` to act on the focused field. `type` inserts at
the caret; `replace: true` clears first. The browser engine rejects typing
when no editable field has focus. Device engines also offer `dismiss_keyboard`.

If semantic capture times out, an engine that proves masking independently
can return a fresh screenshot with an explicit unavailable-tree warning.
Every `act` observation with unavailable semantics includes that image and
warning automatically. Earlier node ids are invalid, and the next successful
semantic capture presents the whole tree again. The screenshot shows the
current viewport; an unavailable tree does not prove that a control or
message is absent.

If semantic capture fails, trace replay stops and the step cannot record a
new trace entry, even if the tree later recovers.

A secret filled during the step withholds every later screenshot
(`PIXEL_TAINTED`), and a step that opens on a tainted viewport offers none of
the five pixel tools. `tap_at` needs an engine whose `actions` or
`pointerActions` include `tap`; without the pointer kind the point must land
on a listed control. A bare-point tap
replays from the [trace cache](/cache) only on a viewport of the recorded
size, or at the same place inside the listed node that contained it. A step
that sent pixels records `visionInput: true` and `metrics.pixelBytes`.

Throws `ACTION_FAILED` for a failed verdict with no more specific code; a
blocked code (`AUTH_CREDENTIAL_UNAVAILABLE`, `ENVIRONMENT_UNAVAILABLE`,
`SEED_DATA_MISSING`, `TEST_SETUP_FAILED`, `AUTOMATION_UNSUPPORTED`) when the
step could not reach a product verdict; `STEP_BUDGET_EXHAUSTED` and
`STEP_TIMEOUT` when a budget or the deadline ran out; `INVALID_ARGUMENT` for
a malformed instruction, oversized `params`, or an unknown option; and
`UNSUPPORTED_CAPABILITY` for `schema` or `vision`, which `act` does not take.

## agent.assert

```ts
assert(assertion: string, options?: AssertOptions): Promise<void>;
```

Checks one fresh observation without polling. The judge sees only the
assertion and current observation, never prior steps or `act` summaries.
It answers `holds`, `fails`, or `inconclusive`.

Throws `ASSERTION_FAILED` on a false judgment and `ASSERTION_INCONCLUSIVE`
when the screen did not show enough to decide. Both carry the explanation
and, when permitted, a screenshot path. No evidence is captured with
`screenshot: false` or once a secret has been filled in the attempt.
`screenshot` controls failure evidence attached after the judgment; `vision`
controls what the model is shown before it.

```ts
await agent.assert('the dashboard shows a trial badge');
```

## agent.waitFor

```ts
waitFor(condition: string, options?: WaitForOptions): Promise<void>;
```

One observation per interval, and a judgment when the screen changed.
Succeeds on the first judgment that holds; a false or inconclusive round
keeps waiting.

Throws `STEP_TIMEOUT` on deadline expiry and `STEP_BUDGET_EXHAUSTED` on
budget exhaustion, each carrying the last judgment, and `INVALID_ARGUMENT`
for an out-of-range option or one `waitFor` does not take.

```ts
await agent.waitFor('the upload progress reports completion', { interval: 500 });
```

## agent.extract

```ts
extract<Schema extends StandardSchemaV1>(
  instruction: string,
  options: ExtractOptions<Schema>,
): Promise<StandardSchemaV1.InferOutput<Schema>>;
```

Takes one fresh observation, requests structured output, validates it, and
returns the validated value. It performs no app actions.

The budget is two model calls: one extraction and one repair round for
output that failed validation. Throws `INVALID_ARGUMENT` for a schema that is
not Standard Schema v1, and `MODEL_OUTPUT_INVALID` when validation still
fails after the repair.

```ts
const summary = await agent.extract('the workspace name and plan', {
  schema: z.object({ name: z.string(), plan: z.string() }),
});
```

## Vision

`assert`, `waitFor`, and `extract` accept `vision`. Screenshots require a
judge model that accepts images.

| `vision` | Evidence sent to the judge |
| --- | --- |
| `false`, the default | Semantic tree |
| `true` | Semantic tree and a masked screenshot |
| `'only'` | Masked screenshot only |

Use `'only'` for visual checks, such as whether an overlay covers a form or a
chart looks correct. Screenshots show the current viewport, so scroll to the
relevant content first. `act` requests its own screenshots and does not take
this option.

Pixels are withheld and the tree sent alone when a secret fill has tainted
the viewport (`visionDegraded: "PIXEL_TAINTED"` on the step), when the engine
masked fewer regions than the secure fields it observed (`MASKING_UNPROVEN`),
or when the engine cannot capture pixels (`UNSUPPORTED_CAPABILITY`). In
`'only'` mode those cases fail with `POLICY_DENIED` instead.

With `vision: true` or `'only'`, a recoverable semantic-capture failure can
use a fresh screenshot when the engine proves masking independently. With
`vision: false`, or after a secret fill, the capture failure stops the
judgment before any model call. A missing tree cannot support a judgment
about an empty screen.

If capture fails before a judgment, the report records zero model calls and
omits `observationRevision` and `explanation`. The step error describes the
capture failure.

## Types

```ts
/**
 * Parameters and budgets for one `act` call.
 */
export interface ActOptions extends AgentOption {
  /**
   * JSON-safe values the instruction refers to, at most 64 KiB and 32 levels
   * deep. A `Secret` reaches the model by name only; the runner fills it.
   */
  params?: AgentParams;
  /** Step deadline in milliseconds; defaults to the test timeout. */
  timeout?: number;
  /** Action budget; defaults to `agent.maxSteps` and can only lower it. */
  maxSteps?: number;
  /** Model-call budget; defaults to `agent.maxModelCalls` and can only lower it. */
  maxModelCalls?: number;
}

/** The configured agent (`agents.<name>`) one call runs with, in place of the test's. */
export interface AgentOption {
  agent?: string;
}

/** `assert` options: one judgment plus one repair round, within `timeout`. */
export interface AssertOptions extends VisionOption, AgentOption {
  /** Deadline in milliseconds; defaults to the agent's `timeout`, 30000. */
  timeout?: number;
  /** Attach a redacted screenshot to the step; on by default, denied after a secret fill. */
  screenshot?: boolean;
}

/** `waitFor` options: a judgment at most once per `interval` until `timeout`. */
export interface WaitForOptions extends VisionOption, AgentOption {
  /** Deadline in milliseconds; defaults to the agent's `timeout`, 30000. */
  timeout?: number;
  /** Least time between two judgments, in milliseconds; 100 through 60000, default 3000. */
  interval?: number;
  /** Judgment budget; defaults to `agent.maxModelCalls` and can only lower it. */
  maxModelCalls?: number;
}

/** `extract` options: one extraction plus one repair round, validated against `schema`. */
export interface ExtractOptions<Schema extends StandardSchemaV1> extends VisionOption, AgentOption {
  /** Any Standard Schema v1 validator; the output is validated against it, with one repair round. */
  schema: Schema;
  /** Deadline in milliseconds; defaults to the agent's `timeout`, 30000. */
  timeout?: number;
}

export interface VisionOption {
  /** What the judge is shown; `false` by default. */
  vision?: VisionMode;
}

/**
 * Evidence for `assert`, `waitFor`, and `extract`.
 *
 * - `false`: the tree.
 * - `true`: the tree and a screenshot, on every call.
 * - `'only'`: the screenshot, and not the tree.
 *
 * When pixels cannot be safely captured, `true` falls back to the tree;
 * `'only'` fails with `POLICY_DENIED`.
 */
export type VisionMode = boolean | 'only';

/** What one passing `act` step did, as the report records it. */
export interface ActResult {
  /** The executor's one-line account of the step, or the replay's when the cache finished it. */
  readonly summary: string;
  /** How the trace cache took part; absent when caching is off for the step. */
  readonly cache?: StepCacheInfo;
  /** Model calls the step spent; 0 when a cached replay finished it. */
  readonly modelCalls: number;
  /** Grammar actions and mutating tool calls the step performed. */
  readonly actions: number;
}

/** Values an `act` instruction refers to. */
export type AgentParams = Readonly<Record<string, AgentParam>>;

/** A JSON-safe value or a `Secret`. */
export type AgentParam =
  | JsonPrimitive
  | Secret
  | readonly AgentParam[]
  | { readonly [key: string]: AgentParam };
```

## AgentError

Every failure is an `AgentError` with a closed `code`, an `explanation`, an
optional `screenshot` path, and a `blocked` flag. Check it with
`isAgentError(error)` from `e2e`, not `instanceof`. The class and
every code are in [Errors](/reference/errors#agenterror).
