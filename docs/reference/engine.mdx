---
title: e2e/engine
description: The engine contract a target's surface implements, and the fixture context it contributes through.
---

`e2e/engine` is the authoring import for an engine. `defineEngine`
validates the body at config load, freezes it, computes its capability set,
and returns the handle a target accepts.

```ts
import { defineEngine, type EngineHandle } from 'e2e/engine';

export function defineEngine(spec: Engine): EngineHandle;
export function isEngineHandle(value: unknown): value is EngineHandle;
```

An engine drives one user interface: a browser, a simulator, a desktop shell.
The contract is platform-neutral vocabulary (semantic nodes, locator
expressions, action kinds, an error taxonomy). The world around the UI (an
inbox, an API, a database) is not an engine's to model; it enters a test as a
fixture through `test.extend`.

Validation fails with `INVALID_CONFIG` for:

- a missing or empty `version`, or a `spiVersion` other than `1`;
- an unknown top-level key on an object literal (a class instance's own
  fields are not checked);
- `perform`, `locate`, or `tapAt` without `observe`;
- `perform` without `actions` or the reverse; an `actions` list that is
  empty, repeats a kind, or names one outside `LOCATOR_ACTION_KINDS`;
- a `state`, `artifacts`, or `session` manifest with an unknown key or a
  non-function member. `state` needs both `capture` and `restore`;
  `artifacts` needs `screenshot`; `startTrace`/`stopTrace` and
  `startVideo`/`stopVideo` come in pairs;
- an `app` declaration with an unknown key or a function;
- a fixture name that is not a lower-camel identifier or shadows `agent`,
  `app`, `screen`, `platform`, or `session`.

Every function on the handle is bound to the spec it came from, so a class
instance is as valid a body as an object literal.

## Engine

```ts
export interface Engine {
  readonly name: string;
  readonly version: string;
  readonly spiVersion: 1;
  readonly platform?: Platform;
  readonly workers?: number;

  observe?(context: OperationContext, options?: EngineObserveOptions): Promise<EngineSnapshot>;
  perform?(ref: NodeRef, action: LocatorAction, context: OperationContext): Promise<void>;
  readonly actions?: readonly LocatorActionKind[];
  locate?(expression: LocatorExpression, context: OperationContext): Promise<readonly SemanticNode[]>;
  tapAt?(point: ViewportPoint, context: OperationContext): Promise<void>;
  readonly fixtures?: Readonly<Record<string, EngineFixtureFactory>>;
  readonly state?: EngineStateCapability;
  readonly artifacts?: EngineArtifacts;
  readonly app?: EngineAppDeclaration;
  readonly session?: EngineSession;

  prepare?(info: EnginePrepareInfo): Promise<void | EnginePrepareResult>;
  init?(info: EngineInitInfo): Promise<void>;
  startAttempt?(context: EngineAttemptContext): Promise<void>;
  endAttempt?(context: EngineCleanupContext): Promise<void>;
  dispose?(context: EngineCleanupContext): Promise<void>;
}
```

`version` is recorded in the report and is part of the trace cache identity,
so an engine that resolves nodes differently never replays another version's
traces. `spiVersion` is `1`; additive optional members never bump it.

`platform` labels what the engine drives. The runner recognizes `web`, `ios`,
and `android` for platform-scoped tool packs and reporting; any other label
is the engine's own. A target that names a platform must agree with it.

Every call carries an `OperationContext`. `origin` says who is acting:
`'test'` for a deterministic step or a trace replay, `'agent'` for the model
acting on a screen it observed. An engine may act at once for `'test'`, since
`expect` verifies the outcome, and let a transition end first for `'agent'`,
since the model reads the screen right after.

```ts
export interface OperationContext {
  readonly signal: AbortSignal;
  /** Remaining operation budget when the call starts. */
  readonly timeoutMs: number;
  readonly runId: string;
  readonly attemptId: string;
  readonly origin: 'test' | 'agent';
}
```

`workers` caps the workers per target, such as the size of a device pool. The
scheduler never starts more for that target, whatever `config.workers` says.

| Member | Capability | Requires | Unlocks |
| --- | --- | --- | --- |
| `observe` | `observation` | - | judgment tier, prompt snapshots, trace replay, the viewport swipe's root |
| `perform` + `actions` | `actions` | `observe` | the agent's grammar verbs (`tap`, `type`, `press`, `select`, `type_secret`, `scroll`, and `tap_at` when the point lands on a listed node) and the `screen`/`Locator` action set with platform actionability checks, each only for a kind listed in `actions` |
| `locate` | `location` | `observe` | `screen`, `Locator`, `expect(locator)` |
| `tapAt` | `pointer` | `observe` | the agent's `tap_at` verb when the point lands on nothing the tree lists: a tap at one viewport point in the CSS pixels of `SemanticNode.rect`, with no node behind it |
| `fixtures.<name>` | `<name>` | - | a contributed fixture; `requires: ['<name>']` gates at selection |
| `state` | `state` | - | `test.setup` sessions and the `session:` option |
| `artifacts` | `artifacts` | - | `app.screenshot()`, assertion evidence, `artifacts: ['trace']`, `artifacts: ['video']` and `--video` |
| `app` | - | - | data only: the app under test, its origin policy, identity, and process |
| `session` | - | - | `app.open()` and the agent's `navigate` verb (`open`), `app.back()` (`back`), `app.restart()` (`restart`), `app.clearState()` (`reset`) |

The agent offers the model only what `actions` declares: `tap` needs the
`tap` kind, `type` and `type_secret` need `fill`, `press` needs `press`,
`select` needs `selectOption`, `scroll` needs `swipe`, `navigate` needs
`session.open`, `tap_at` needs `tap` or `tapAt`. An undeclared verb is absent
from the toolset, and a `screen`/`Locator` method for an undeclared kind
fails with `UNSUPPORTED_CAPABILITY` before reaching the engine.

`engine.capabilities` is the computed `ReadonlySet` of capability names and is
what selection, the report, and `UNSUPPORTED_CAPABILITY` messages read.

```ts
export type EngineCapability =
  | 'observation' | 'actions' | 'location' | 'pointer' | 'state' | 'artifacts'
  | (string & {}); // one per contributed fixture
```

## Lifecycle

| Hook | When | Budget |
| --- | --- | --- |
| `prepare(info)` | once per run and target, in the runner process, before any worker starts: install a browser, boot the devices for `info.slots` worker slots. Lines passed to `info.log` print as `notice` events. The run's clock starts after every target is prepared | none; only `info.signal` (the run's interrupt) cuts it short; failure ends the run before any test |
| `init(info)` | once per worker, before the first attempt; runs again after `dispose` when the handle outlives an in-process worker | `launchTimeout`; failure is infrastructure |
| `startAttempt(context)` | before every attempt; `context.artifactsDir` is where artifacts go | `launchTimeout`; on failure or timeout `context.signal` aborts and `endAttempt` runs |
| `endAttempt(context)` | after every attempt, idempotent, and safe after a failed `startAttempt` | `cleanupTimeout`; `context.signal` aborts when the budget is spent; failure marks cleanup failed, the test keeps its status |
| `dispose(context)` | worker shutdown, whether or not `init` ran | `cleanupTimeout`; `context.signal` aborts when the budget is spent; failure is a run error |

```ts
/** `workers` lowers the target's cap for this run to what prepare provisioned, `1` to `info.slots`. */
export interface EnginePrepareResult {
  readonly workers?: number;
  /** Variables every worker of this target is spawned with; the run's own win on a clash. */
  readonly env?: Readonly<Record<string, string>>;
}

export interface EnginePrepareInfo {
  readonly runId: string;
  readonly targetName: string;
  /** Worker slots the run starts for this target, `0` to `slots - 1`: the run cap, `workers`, and the units selected, whichever is smallest. */
  readonly slots: number;
  /** The run's environment, the one every worker starts with. */
  readonly env: Readonly<Record<string, string | undefined>>;
  readonly signal: AbortSignal;
  readonly log: (line: string) => void;
}

export interface EngineInitInfo {
  readonly runId: string;
  readonly targetName: string;
  /** Directory relative paths in the config resolve against. */
  readonly projectRoot: string;
  readonly app: EngineAppInfo;
  /** This worker's environment: the run's plus this target's `prepare` result `env`. Never read `process.env` for it. */
  readonly env: Readonly<Record<string, string | undefined>>;
  /** Whether the run asked for a visible surface (`--headed`). */
  readonly headed: boolean;
  /** 0-based slot among the target's workers; the lowest one free at spawn. */
  readonly workerSlot: number;
  readonly signal: AbortSignal;
}

export interface EngineAppInfo {
  /** The site of the app's `url`, its registrable domain; absent for an app without a URL. */
  readonly site?: string;
}

export interface EngineAttemptContext {
  readonly attemptId: string;
  readonly artifactsDir: string;
  readonly signal: AbortSignal;
}

export interface EngineCleanupContext {
  readonly signal: AbortSignal;
  readonly timeoutMs: number;
}
```

`prepare` and `init` receive the run's environment as `info.env`, not
`process.env`; a host may hand the run a different environment.

`init` never learns the app URL. `EngineInitInfo.app` carries the site only,
for the two decisions an engine makes with it: which nested documents enter
an observation, and which requests carry injected headers. URLs arrive through
`session.open`. File options resolve against `projectRoot`, never
`process.cwd()`.

## Observation

```ts
export interface EngineSnapshot {
  readonly location?: string;
  readonly root: SemanticNode;
  readonly viewport: { readonly width: number; readonly height: number; readonly scale: number };
  readonly pixels?: ObservationPixels;
  readonly maskedRegionCount?: number;
}

export interface EngineObserveOptions {
  /** Requests masked viewport pixels for the same revision as the tree. */
  readonly pixels?: boolean;
}
```

Return the surface as it is right now. The runner mints the revision, stamps
it onto every ref, redacts registered secret values, bounds the byte size, and
checks that `maskedRegionCount` covers every `secure` node when `pixels` are
present.

The root's id must be stable across observations: `perform(root, { kind:
'swipe' })` is the viewport swipe, addressed from an earlier observation. A
platform with several top-level elements wraps them in a root of its own. A
pixels-only snapshot (a childless root plus `pixels`) is valid.

`location` is an opaque address: a URL on a document platform, the foreground
screen on a device, the front window on a desktop. The runner shows it to the
model and the report and anchors trace replay on it. Omit it when the platform
has no current location.

`viewport` is the space `SemanticNode.rect` and `ViewportPoint` are measured
in.

## Actions

```ts
export type LocatorAction =
  | { kind: 'tap' | 'doubleTap' | 'check' | 'uncheck' | 'clear' | 'focus' | 'hover' | 'scrollIntoView' }
  | { kind: 'longPress'; durationMs?: number }
  | { kind: 'fill'; value: string; sensitive: boolean }
  | { kind: 'press'; key: Key }
  | { kind: 'selectOption'; value: SelectOption }
  | { kind: 'setInputFiles'; paths: readonly string[] }
  | { kind: 'dragTo'; target: NodeRef }
  | { kind: 'swipe'; direction: ScrollDirection; momentum?: Momentum };

export type LocatorActionKind = LocatorAction['kind'];

/** The closed list of action kinds, in contract order. */
export const LOCATOR_ACTION_KINDS: readonly LocatorActionKind[]; // tap, doubleTap, longPress, fill, clear, press, check, uncheck, focus, hover, scrollIntoView, selectOption, setInputFiles, dragTo, swipe
```

`perform(ref, action, context)` performs one action on a ref this engine
minted, from the newest observation or from `locate`, with the platform's
actionability checks. The agent's verbs and the `screen` actions both end
here. Throw a retryable `NODE_STALE` when the ref no longer binds and
`ACTION_MAY_HAVE_COMMITTED` when input may have reached the app; the runner
never repeats an uncertain mutation.

`actions` lists the kinds the engine honors, drawn from
`LOCATOR_ACTION_KINDS`, each once. `perform` may still throw
`UNSUPPORTED_CAPABILITY` for a declared kind one node cannot take (a `check`
on a toggle whose state is unknown).

A `swipe` on the observation root is the viewport swipe; on any other node it
scrolls within that node.

`tapAt(point, context)` is the one action addressed by a point: a
`ViewportPoint` in the CSS pixels of `SemanticNode.rect`, already clamped to
the viewport. Dispatch the pointer as given; there is no element to wait on.

The grammar is closed. Anything beyond it is an agent-side `defineTool`.

### Keys

`press` takes zero or more modifiers and one key, joined by `+`.

```ts
export type Key = string;

export const KEY_MODIFIERS = ['Shift', 'Control', 'Alt', 'Meta', 'ControlOrMeta'] as const;
export const KEY_NAMES = [
  'Enter', 'Escape', 'Tab', 'Backspace', 'Delete', 'Insert', 'Space',
  'ArrowUp', 'ArrowDown', 'ArrowLeft', 'ArrowRight', 'Home', 'End', 'PageUp', 'PageDown',
  'F1', 'F2', 'F3', 'F4', 'F5', 'F6', 'F7', 'F8', 'F9', 'F10', 'F11', 'F12',
] as const;

export interface ParsedKey {
  readonly modifiers: readonly KeyModifier[];
  readonly key: { kind: 'named'; name: KeyName } | { kind: 'char'; char: string };
}

export function parseKey(key: string): ParsedKey | undefined;
```

| Part | Spelling |
| --- | --- |
| Modifiers | `Shift`, `Control`, `Alt`, `Meta`, `ControlOrMeta` (Control on Windows and Linux, Meta on macOS) |
| Named keys | those in `KEY_NAMES`: `Enter`, `Escape`, `Tab`, `Backspace`, `Delete`, `Insert`, `Space`, `ArrowUp`, `ArrowDown`, `ArrowLeft`, `ArrowRight`, `Home`, `End`, `PageUp`, `PageDown`, `F1` to `F12` |
| Characters | any single printable character (`a`, `A`, `1`, `$`), typed as itself |

`Shift++` presses `+` with Shift held. `parseKey` returns `undefined` for a
spelling outside the grammar. A platform without a key throws
`UNSUPPORTED_CAPABILITY`; it never reinterprets the spelling.

## App

`app` declares what the engine knows about the app under test. Every member
is data; a function here is `INVALID_CONFIG`.

```ts
export interface EngineAppDeclaration {
  readonly url?: string;
  readonly environment?: 'test' | 'staging' | 'production';
  readonly identity?: string;
  readonly command?: CommandConfig;
  readonly readyUrl?: string;
  readonly services?: readonly ServiceConfig[];
}
```

A browser engine passes its `url` and `command` options through; a device
engine declares the bundle id it pins as `identity`. The runner resolves the
declaration once per target at config load and owns everything built on it:
the app's site, cache and session identity, the report's target record, and
the app process. Every field is documented under
[the app under test](/reference/config#the-app-under-test). The site comes
back to the engine as `EngineInitInfo.app.site`; `sameSite` from
`e2e/engine` applies it to a URL.

## Session

`session` holds the hooks behind the `app` fixture and the agent's `navigate`
verb. Node actions are `perform`, never here.

```ts
export interface EngineSession {
  /** Opens one URL the harness already resolved against the base URL. */
  open?(url: string, context: OperationContext): Promise<void>;
  /** Navigates back once in the surface's history. */
  back?(context: OperationContext): Promise<void>;
  /** Recreates the execution context, keeping persisted state. */
  restart?(context: OperationContext): Promise<void>;
  /** Clears persisted client state and recreates the execution context. */
  reset?(context: OperationContext): Promise<void>;
}
```

| Hook | Behind | Absent |
| --- | --- | --- |
| `open(url)` | `app.open()`, the agent's `navigate` verb, the reopen after `restart` and `reset` | a surface without addressable locations; `app.open()` fails with `UNSUPPORTED_CAPABILITY`, the agent has no `navigate` |
| `back()` | `app.back()` | `app.back()` fails with `UNSUPPORTED_CAPABILITY` |
| `restart()` | `app.restart()` | `app.restart()` fails with `UNSUPPORTED_CAPABILITY` |
| `reset()` | `app.clearState()` | `app.clearState()` fails with `UNSUPPORTED_CAPABILITY` |

`open` receives a URL the runner already resolved. `restart` and `reset` end
at a blank surface; the runner reopens the app through `open` when the target
has a URL. An engine without `open` (a device with a pinned app) relaunches
the app inside `restart` and `reset` itself.

## Errors

```ts
export class EngineError extends Error {
  constructor(code: EngineErrorCode, message: string, options: { retryable: boolean; cause?: unknown });
  readonly code: EngineErrorCode;
  readonly retryable: boolean;
}

export const ENGINE_ERROR_CODES: readonly EngineErrorCode[];
export const RETRYABLE_ENGINE_ERROR_CODES: ReadonlySet<EngineErrorCode>; // NODE_STALE, FRAME_NOT_FOUND

export type EngineErrorCode =
  | 'NODE_STALE' | 'FRAME_NOT_FOUND' | 'FRAME_AMBIGUOUS' | 'NOT_ACTIONABLE'
  | 'ACTION_MAY_HAVE_COMMITTED' | 'OPERATION_TIMEOUT' | 'CANCELLED'
  | 'UNSUPPORTED_CAPABILITY' | 'INVALID_STATE' | 'ENGINE_FAILURE';
```

| Code | Runner mapping | Retryable |
| --- | --- | --- |
| `NODE_STALE` | re-resolve, then `LOCATOR_NOT_FOUND` | yes |
| `FRAME_NOT_FOUND` | re-resolve, then `LOCATOR_NOT_FOUND` | yes |
| `FRAME_AMBIGUOUS` | `LOCATOR_AMBIGUOUS` | no |
| `NOT_ACTIONABLE`, `ACTION_MAY_HAVE_COMMITTED`, `OPERATION_TIMEOUT` | `ACTION_FAILED` | no |
| `CANCELLED` | infrastructure `CANCELLED` | no |
| `UNSUPPORTED_CAPABILITY` | configuration `UNSUPPORTED_CAPABILITY` | no |
| `INVALID_STATE` | `APP_NOT_OPEN` | no |
| `ENGINE_FAILURE`, any non-`EngineError` | infrastructure `ENGINE_FAILURE` | no |

A retryable claim on any code outside `RETRYABLE_ENGINE_ERROR_CODES` is
coerced to a non-retryable `ENGINE_FAILURE`.

A contributed fixture method fails a step with the runner's own error
classes, exported from the same entry:

```ts
export class TestError extends Error {}            // a test failure: ASSERTION_FAILED, INVALID_LOCATOR, ACTION_FAILED, ...
export class ConfigurationError extends Error {}   // POLICY_DENIED, APP_URL_REQUIRED, UNSUPPORTED_CAPABILITY, ...
export class InfrastructureError extends Error {}  // the surface itself failed: BROWSER_INSTALL_FAILED, ...
```

## Shared semantics

Behavior every engine must reproduce exactly is exported rather than
re-implemented per engine:

| Export | Use |
| --- | --- |
| `matchesText(actual, pattern)`, `toTextPattern(match, { exact? })`, `describePattern(pattern)` | `TextPattern` matching for `locate` and text matchers |
| `urlMatches(current, expected, baseHref)` | `toHaveURL`-style comparison |
| `pollCondition({ deadline, signal, negated, evaluate, onTimeout })`, `Deadline` | Assertion polling and the negation grace window |
| `validateJsonValue(value, label)` | Rejects `undefined`, `NaN`, and cycles in a value a fixture returns |
| `obj`, `raceAbort`, `withTimeout`, `withinCleanupBudget` | See [Contributed fixtures](#contributed-fixtures) |

## State

```ts
export interface EngineState {
  readonly format: string;
  readonly version: number;
  readonly data: unknown;
  readonly expiresAt?: string;
}

export interface EngineStateCapability {
  capture(context: OperationContext): Promise<EngineState>;
  restore(state: EngineState, context: OperationContext): Promise<void>;
}
```

A snapshot is a credential. The runner encrypts it at rest with a per-run
AES-256-GCM key, binds it to run, target, engine, and app identity, and
deletes it at run end. An engine must not persist, log, or echo a snapshot.
`restore` replaces the persisted state rather than merging into it.

## Artifacts

```ts
export interface EngineArtifacts {
  screenshot(label: string | undefined, context: OperationContext): Promise<string>;
  startTrace?(context: OperationContext): Promise<void>;
  stopTrace?(context: OperationContext): Promise<string | readonly string[]>;
  startVideo?(context: OperationContext): Promise<void>;
  stopVideo?(context: OperationContext): Promise<readonly VideoSegment[]>;
}

export interface VideoSegment {
  /** Relative to the attempt artifact directory. */
  readonly path: string;
  /** When the segment started recording, as an ISO timestamp; its first frame is at or just after it. */
  readonly startedAt: string;
}
```

Every returned path is relative to the `artifactsDir` of `startAttempt`.
`screenshot` masks secure fields at the source.

The runner starts the video, then the trace, right after `startAttempt` (and
after a session restore) under the launch budget, and stops them before
`endAttempt` under the cleanup budget. Video comes first so an engine that
records both through one screencast sizes it for the recording a person
watches. `stopVideo` returns every segment in order, one per page the
attempt showed. `stopTrace` returns the trace's path, or every archive in
order when the trace had to be cut because the context was replaced. When a
secret was filled in the attempt, every text entry of each archive is
rewritten through the secret redactor; if that fails the archives are deleted
and the attempt records `TRACE_WITHHELD`. Recordings mask nothing and are
recorded with `redaction: 'incomplete'`.

## Contributed fixtures

```ts
export type EngineFixtureFactory = (context: EngineFixtureContext) => object;

export interface EngineFixtureContext {
  readonly targetName: string;
  fixture<T extends object>(name: string, surface: T, operations: FixtureOperations<T>): T;
  readonly app: EngineAppInfo & { resolveUrl(url: string): string };
  readonly timeouts: { test: number; action: number; assertion: number };
  readonly signal: AbortSignal;
  operation(timeoutMs?: number): OperationContext;
  attachArtifact(kind: 'screenshot' | 'trace' | 'video' | 'download' | 'log', relativePath: string): void;
  attachViewport(viewport: { width: number; height: number; scale: number }): void;
  locator(expression: LocatorExpression): Locator;
  screen(scope: (expression: LocatorExpression) => LocatorExpression): Screen;
  expectable<T extends object, E extends object>(target: T, factory: () => E): T & Expectable<E>;
}
```

`context.fixture(name, surface, operations)` declares which methods are
recorded steps. Each operation names a `kind: 'resource' | 'assertion'`, an
optional `label(...args)`, an optional `timeout` (milliseconds, a function of
the arguments, or `false` when the method owns its deadline), and optional
`verifies`. The default timeout is `actionTimeout`; assertions verify by
default. Nested maps describe namespaces. Recording decorates the object in
place, so create a fresh surface in each factory invocation.

The runner opens the step before calling a declared method, so attachments
and failures from synchronous and asynchronous work land on the same step.
Work arriving after its step has closed cannot attach to a later one.

A factory must return the surface it declared through `context.fixture`; a
plain surface is `INVALID_CONFIG` the first time a test reaches for it.
`expectable` attaches an expectation surface so `expect(fixture)` returns it;
declare matcher recording with `context.fixture('expect', matchers,
operations)`. Type the fixture with `test.extend<{ name: Type }>()`.

`app.resolveUrl` resolves a navigation target against the base URL the runner
owns. It throws `APP_URL_REQUIRED` when the engine declared no URL and
`POLICY_DENIED` for a `file:`, `data:`, or `javascript:` URL.
`attachArtifact` registers a file the current step produced.

The entrypoint also exports `obj(value)`, which drops `undefined`-valued keys
so a result built from optional inputs satisfies exact optional property
types, plus `raceAbort(work, signal, label)`, `withTimeout(promise,
timeoutMs, onTimeout)`, and `withinCleanupBudget(promise, { signal,
timeoutMs })`. Pass a thunk to `raceAbort` to check cancellation before
dispatch.

## Vocabulary

`OperationContext`, `TextPattern`, `SemanticQuery`, `LocatorExpression`,
`NodeRef`, `SemanticNode`, `ViewportPoint`, `ObservationPixels`,
`LocatorAction`, `LocatorActionKind`, `Key`, `KeyModifier`, `KeyName`,
`ParsedKey`, `ENGINE_SPI_VERSION`, `LOCATOR_ACTION_KINDS`, `KEY_MODIFIERS`,
`KEY_NAMES`, `parseKey`, `ENGINE_ERROR_CODES`, `RETRYABLE_ENGINE_ERROR_CODES`,
`OBSERVED_NAME_LIMIT` and `OBSERVED_TEXT_LIMIT` are exported from
`e2e/engine`. The `selector` expression kind carries a
platform-native selector string; `frame` scopes a query into a nested
document.

```ts
export interface SemanticNode {
  readonly ref: NodeRef;
  readonly role?: string;
  readonly name?: string;
  readonly text?: string;
  readonly value?: string;
  readonly testId?: string;
  readonly inputPurpose?: 'username' | 'password' | 'one-time-code' | 'generic-secret' | 'none';
  readonly states?: Partial<Record<'checked' | 'disabled' | 'selected' | 'expanded' | 'focused' | 'hidden' | 'secure', boolean>>;
  readonly attributes?: Readonly<Record<string, string>>;
  readonly rect?: { x: number; y: number; width: number; height: number };
  readonly selector?: string;
  readonly framePath?: readonly string[];
  readonly children?: readonly SemanticNode[];
}

export type QueryKind = 'role' | 'label' | 'placeholder' | 'text' | 'displayValue' | 'testId';
```

`testId` is the platform's test id: the engine's test-id attribute on a
document platform, an accessibility identifier on iOS, a resource id on
Android. `screen.getByTestId` resolves against this field.

`rect` is the node's box in the top-level viewport's CSS pixels, including
for nodes inside nested documents. `name` and `text` are cut at
`OBSERVED_NAME_LIMIT` (256) and `OBSERVED_TEXT_LIMIT` (512); single-node reads
carry the full value.

A `SemanticQuery` with `visible: true` must match only nodes whose
`states.hidden` is false, by the same predicate the engine reports on
`SemanticNode`, so `getByText('x', { visible: true })` and `toBeVisible()`
never disagree. Apply it wherever the query sits in the expression, under a
scope, filter, or index too.
