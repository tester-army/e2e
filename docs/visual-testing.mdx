`toHaveScreenshot` compares what the app shows against a PNG stored next to
the test file. It works on every engine that captures pixels, so one test
checks a browser, an iOS simulator, and an Android emulator.

```ts title="tests/checkout.e2e.ts"
import { test, expect } from 'e2e';

test('checkout looks right', async ({ app, screen }) => {
  await app.open('/checkout');
  await expect(screen).toHaveScreenshot('checkout.png');
  await expect(screen.getByRole('button', { name: 'Pay' })).toHaveScreenshot('pay-button.png');
});
```

`expect(screen)` compares the whole screen; `expect(locator)` compares the
box of its one match, scrolled into view first.

## Stored screenshots

Commit the screenshots with the tests. The first run has nothing to compare
against: it writes the screenshot and fails. Look at the image, commit it,
and run again.

```text
tests/checkout.e2e.ts
tests/checkout.e2e.ts-snapshots/checkout-web-linux.png
tests/checkout.e2e.ts-snapshots/checkout-ios-darwin.png
tests/checkout.e2e.ts-snapshots/pay-button-web-linux.png
```

Each target and operating system keeps its own file, since fonts and
rendering differ between them. Without a name, the screenshot is named after
the test: `checkout-looks-right-1-web-linux.png`.

When the app changes on purpose, rewrite the screenshots that differ. A
missing one is written too, and the run passes:

<CodeGroup>
```bash npm
npx e2e run --update-snapshots
```

```bash pnpm
pnpm exec e2e run --update-snapshots
```

```bash bun
bunx e2e run --update-snapshots
```
</CodeGroup>

## In CI

Screenshots must come from the machine that renders them in CI: a Linux
runner for the web and an Android emulator, a macOS runner with the same
simulator for iOS. A CI run never writes into the project. A missing
screenshot fails the test, and the run puts it in the test's results at
`snapshots/<path in the project>`, so it can be downloaded and committed.

To write them all at once, run the suite with `--update-snapshots` in a job
like the test job and keep what it wrote:

```yaml title=".github/workflows/screenshots.yml"
name: Update screenshots
on: workflow_dispatch
jobs:
  screenshots:
    runs-on: ubuntu-latest
    steps:
      # the same checkout, setup, and install steps as the test job
      - run: npx e2e run --update-snapshots
      - uses: actions/upload-artifact@043fb46d1a93c77aae656e7c1c64a875d1fc6a0a # v7.0.1
        with:
          name: screenshots
          path: tests/**/*-snapshots/
```

Download the artifact into the project, review the images, and commit them.

## When it fails

The matcher takes screenshots until one matches or the assertion timeout
(`assertionTimeout`, 5 s) runs out. On a mismatch the failure says how many
pixels differ and where it put three images in the test's results: `-diff`,
with the changed pixels in red, `-actual`, and `-expected`.

```text
2173 pixels (0.24% of the image) differ from tests/home.e2e.ts-snapshots/screen-web-darwin.png; run with --update-snapshots to keep this run's
diff: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-diff.png
actual: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-actual.png
expected: .e2e/results/home-1a2b3c4d5e6f7a8b/attempt-1/screenshots/screen-expected.png
```

A screen that never holds still for two screenshots in a row fails too, with
the last two and their diff.

## Tolerance and masks

```ts
await expect(screen).toHaveScreenshot('dashboard.png', {
  maxDiffPixelRatio: 0.01,
  mask: [screen.getByTestId('last-updated')],
});
```

| Option | Default | Meaning |
| --- | --- | --- |
| `threshold` | `0.2` | How far one pixel's color may drift and still count as the same, 0 to 1 |
| `maxDiffPixels` | `0` | How many pixels may differ |
| `maxDiffPixelRatio` | `0` | What share of the pixels may differ, 0 to 1 |
| `mask` | none | Locators painted over before comparing, for content that changes between runs |
| `maskColor` | `#ff00ff` | Color of the mask boxes |
| `timeout` | `assertionTimeout` | Assertion budget in milliseconds |

On the web, animations are stopped and the text caret is hidden. On iOS and
Android, the status bar is held in a fixed state, so the clock and battery
read the same on every run.

Secure fields are masked in every screenshot, and after a test fills a
secret the matcher fails with `POLICY_DENIED`, like every other screenshot.
