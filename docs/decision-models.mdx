title: Decision models
description: Run bounded actions with a decision model and a small text model instead of a full LLM agent.

`@e2e-dev/decision` runs `agent.act` and `agent.assert` through a decision
model instead of an LLM agent. For each action, the decision model picks an
operation, then an element, from the goal, the recent actions, and the
newest semantic tree. It never writes free text: a small text model writes
field values. The runner still authorizes every action.

Any AI SDK decision model that answers `choice` questions with probabilities
works, such as TypeSafe Jev or OpenAI `gpt-6-luna`.

## Install and configure

Install the package, a decision model provider, and a text model provider.
Decision models need `ai` 7.0.134 or later.

<CodeGroup>
```bash npm
npm install -D @e2e-dev/decision @ai-sdk/typesafe-ai @openrouter/ai-sdk-provider
```

```bash pnpm
pnpm add -D @e2e-dev/decision @ai-sdk/typesafe-ai @openrouter/ai-sdk-provider
```

```bash bun
bun add -d @e2e-dev/decision @ai-sdk/typesafe-ai @openrouter/ai-sdk-provider
```
</CodeGroup>

Set the executor on the agents entry:

```ts title="e2e.config.ts"
import type { E2EConfig } from 'e2e';
import { web } from '@e2e-dev/web';
import { decisionExecutor } from '@e2e-dev/decision';
import { typeSafeAi } from '@ai-sdk/typesafe-ai';
import { openrouter } from '@openrouter/ai-sdk-provider';

export default {
  targets: [{ engine: web(), app: { url: 'http://localhost:3000' } }],
  agents: {
    default: {
      executor: decisionExecutor({
        model: typeSafeAi.decisionModel('jev-latest'),
        textModel: openrouter('inception/mercury-2.5'),
      }),
    },
  },
} satisfies E2EConfig;
```

Tests are plain `agent.act` and `agent.assert` calls:

```ts title="tests/todos.e2e.ts"
import { test, expect } from 'e2e';

test('adds a todo', async ({ app, screen, agent }) => {
  await app.open('/todos');
  await agent.act('Add a todo named Buy coffee, and verify it is listed.');
  await expect(screen.getByTestId('todo')).toContainText('Buy coffee');
  await agent.assert('The todo list contains Buy coffee.');
});
```

`evaluationModel()` instances also work. A model id string or a language
model in `model` fails the config load with `INVALID_CONFIG`.

## What the model can do

Each turn offers the operations the engine supports on the elements of the
newest screen: `tap`, `type`, `typeSecret`, `submit`, `select`, `check`,
`upload`, `hover`, `secondary_tap` (a right-click), `double_tap`,
`long_press`, `drag`, `scroll_to`, `scroll_up`, `scroll_down`, and `back`.
Hover, right-click, drag, and scroll-to also reach labeled nodes that are
not controls, such as a card that opens a menu on hover. On an engine that
can dismiss the keyboard, such as the mobile engine, the executor offers
`dismiss_keyboard` while an on-screen keyboard shows, to reach the controls
it covers.

Every target question has a `none` option, so a provider with no fitting
target answers `none` instead of refusing. `none` blocks the step.

## How text gets typed

When the decision model picks `type`, the text model writes the value from
the goal, the params, the field's label, and the page text. The executor
types exactly that string. With no value in the goal, nothing is typed and
the decision model picks again. For `upload`, the text model lists the
project-relative paths the goal or params name, and the runner authorizes
each one. Model output never becomes a selector, a URL, or a key.

Password fields never reach the text model. Only `typeSecret` fills a
secret, from its declared handle.

The text model also answers `waitFor` and `extract`. Instead of
`textModel`, you can set `model` on the agents entry. With neither, the
executor never offers `type`, `upload`, or `tap_at`.

## Finishing a step

When the decision model answers `done` or `failed`, the executor checks the
claim on a fresh screen with one question: is the step's task complete? The
check sees the non-secret params, the actions taken with their non-secret
values, and the page with the text of its status regions. It never sees
model reasoning or a secret.

A confirmed `done` passes the step, and a confirmed `failed` fails it with
`ACTION_FAILED`. An unconfirmed claim goes back to the decision model as
history. A second one ends the step: `ACTION_FAILED` when the screen
contradicts the goal, else `blocked` with `AUTOMATION_UNSUPPORTED`.

## Gates

Both gates are off by default, so the executor follows the most probable
choice. Set `minProbability` or `minConfidence` to block weaker actions,
reject weaker completion checks, and fail weaker assertions as
inconclusive:

```ts title="Executor setup"
const executor = decisionExecutor({ model, minProbability: 0.9, minConfidence: 0.8 });
```

Probability is the chosen option's share of the answer distribution.
Confidence is the provider's own statistic. A model that reports no
confidence counts as 0. Measure accuracy on your own tests before you set a
threshold. OpenAI rounds both values to two decimals, so a gate between two
hundredths acts as the next hundredth.

## Vision

`vision: true` adds a masked screenshot to every observation. Assertions and
completion checks see it, so the model can judge drawn content the tree
doesn't show. The operation and target questions read the tree only.
`agent.assert(..., { vision: true })` and `vision: 'only'` work too. After a
secret fill in the attempt, the executor gets no pixels.

The model must accept images and answer `score` questions, as
`openai.decisionModel('gpt-6-luna')` does. A text-only model such as Jev
refuses the screenshot. Vercel AI Gateway rejects it too, so keep `vision`
off there.

With a text model, vision also offers `tap_at` for a control the tree
doesn't list. The text model names the control, such as "the 3 key on the
keypad". The decision model finds it with score questions on the screenshot,
then on a zoomed crop. A point tap costs three decide calls and one text
call. A repeat tap on a control that a tap already hit on that page costs
one of each.

## Provider options

`providerOptions` go with every decide call, completion checks included,
and reach the decision model only. Use them for options such as zero data
retention on Vercel AI Gateway:

```ts title="Executor setup"
import { gateway } from 'ai';

const executor = decisionExecutor({
  model: gateway.decisionModel('typesafe-ai/jev'),
  textModel: gateway('openai/gpt-4.1-nano'),
  providerOptions: { gateway: { zeroDataRetention: true } },
});
```

The text model takes the agents entry's `providerOptions`. So a setting
for one model, such as a gateway fallback list, never reaches the other.

## Limits

- No `navigate`. In-app navigation is a `tap` on a link. URLs belong in
  test code (`browser.goto`, `app.open`).
- No multi-select `listbox`, no `scrollUntil`, and no typing at a point
  (`type_at`).
- The text model that names a drawn control reads the page text and the
  goal, not the pixels. It can't follow an instruction that exists only as
  drawn text, such as a wizard that paints "tap the circle".
- Every decide call and text call counts against `maxModelCalls`.
- Three actions in a row that fail or change nothing block the step with
  `AUTOMATION_UNSUPPORTED`.
- A question the provider refuses fails the step with `MODEL_OUTPUT_INVALID`.
- A question has at most 255 options (TypeSafe's limit; OpenAI documents
  none). On a larger screen, nodes in the viewport come first and the rest
  count as omitted, so the model can scroll.
